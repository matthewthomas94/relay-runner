# v0.4.0 — Relay Actions + sub-agent orchestrator

First release where Claude can drive the screen, and the first release where the main session can dispatch autonomous sub-agents from inside Relay Runner. Five PRs land on top of v0.3.0; the headline pieces are Relay Actions (voice-driven computer control, with a hardware confirmation gate) and the orchestrator MVP.

## Relay Actions — voice-driven screen control

A new bundled MCP server (`relay-actions-mcp`) gives Claude eight stdio tools for UAT walkthroughs and dense-dashboard configuration: `screenshot` (ScreenCaptureKit), `click` / `type` / `key` / `scroll` (CGEvent), `frontmost_app` / `list_windows` (NSWorkspace + AX), and `propose_action` (the confirmation gate) ([#30](https://github.com/matthewthomas94/relay-runner/pull/30)).

- **Hardware-gated confirmations.** State-changing tools route through `propose_action(risk: medium|high)`, which blocks until the user double-taps Option (yes) or Control (no). It's a hardware gesture, not voice — TTS audio cannot spoof it. `risk: low` auto-confirms with a brief visual flash so read-only flows stay fast. Server-side keyword guard escalates `medium → high` when the action summary contains destructive verbs (delete / send / submit / pay / etc.).
- **Perimeter overlay.** A purple dot-matrix perimeter band (reusing the existing `.tts` theme) appears on every connected screen whenever any Relay Action fires, and pulses brighter while a confirmation is pending. Decays 10 s after the last tool call.
- **Per-parent permission wizard** ([#31](https://github.com/matthewthomas94/relay-runner/pull/31)). TCC grants Accessibility / Screen Recording to the *parent* of `claude` (Terminal, Warp, VS Code, Claude.app), not to Relay Runner. The wizard surfaces the first time the voice loop starts under a new parent, names the parent explicitly, deep-links to both Settings panes, and walks through the two-restart flow (relaunch the parent, start a fresh `claude` session, re-run `/relay-bridge`). Acknowledged parents are tracked in UserDefaults; revocation re-fires the wizard automatically.
- **Pre-flight TTS warnings** ([#31](https://github.com/matthewthomas94/relay-runner/pull/31)). Before the first AX-gated `CGEvent` or screen-capture call per session, Relay Runner speaks a TTS warning naming the action and the app the OS will reference, then sleeps 1.5 s so the user hears it before the dialog blocks the screen.
- **Screenshot coord-space fix** ([#31](https://github.com/matthewthomas94/relay-runner/pull/31)). `SCDisplay` reports active-mode logical points on scaled displays, so previously clicks landed off by the backing-scale factor. Screenshot output is now always native pixels, matching what `pointFromPixel()` reverses.
- **Cancel is silent again.** Double-tap Control during TTS used to loop: cancel → `__INTERRUPT__` → "Still here." → user cancels that → repeat. The skill instruction now stays silent on `__INTERRUPT__`, and the skill `.md` is reinstalled on every Start Session so existing installs aren't stuck on stale text.
- **Renamed Computer Actions → Relay Actions** ([#32](https://github.com/matthewthomas94/relay-runner/pull/32)) throughout user-facing copy, the macOS Screen Recording permission prompt, onboarding strings, and the spec file.

## Sub-agent orchestrator (MVP)

`relay-runner` is now its own dogfood: the main Claude Code session acts as the orchestrator, and `mcp__relay-orchestrator__dispatch_issue` spawns autonomous `claude -p` sub-agents in isolated git worktrees ([#33](https://github.com/matthewthomas94/relay-runner/pull/33)).

- **Daemon** (`services/orchestrator.py`): SQLite-backed run history, TOML project links, HTTP API on `127.0.0.1:7634`, `claude -p` worker spawn with stream-json parsing, launchd-managed lifecycle.
- **Swift MCP proxy** (`Sources/relay-orchestrator-mcp/`): exposes 7 tools (`link_project` / `unlink_project` / `list_projects`, `dispatch_issue` with a `context` arg for cold-start background, `list_runs` / `get_run` / `cancel_run`) over stdio.
- **Workflow template** (`services/orchestrator_workflow.md`): default sub-agent prompt with a `{{caller_context}}` slot the orchestrator fills in per dispatch.
- **Installer** (`scripts/relay-orchestrator`): launchd plist, MCP registration, three slash commands (`/relay-link-project`, `/relay-orchestrate`, `/relay-workflow`). Bridge bootstrap detects missing pieces.
- **Build pipeline:** the `relay-orchestrator-mcp` binary is bundled, codesigned, and shipped in the DMG.
- **Docs:** user reference at [`docs/orchestrator.md`](../orchestrator.md). Repo-level `CLAUDE.md` codifies the orchestrator workflow as the default for sessions inside this repo.

Limits: single-host, no autonomous ticket pickup (every dispatch is an explicit user/orchestrator decision), concurrency is uncapped at the daemon level (bound by Anthropic rate limits), and `relay/<id>` branches stay local — humans review and integrate.

## Start Session unification

- **Start Session… now opens an interactive Claude Code window** with `/relay-bridge` fired as a positional prompt arg, instead of running `voice_bridge.py` directly ([#29](https://github.com/matthewthomas94/relay-runner/pull/29)). The user gets the full TUI (model picker, slash commands, thinking stream) and voice in the same terminal — the menu button finally matches the manual `claude` + `/relay-bridge` flow.
- **Settings → General: model picker.** Default / Opus / Sonnet / Haiku selector for the launched session. Default omits `--model` entirely so Claude Code uses the user's account-level default.
- **`general.bypass_permissions` toggle** (default on) controls whether the launch passes `--dangerously-skip-permissions`, with a Settings row explaining the trade-off.
- **Skill self-heal.** The launcher reinstalls the bridge skill `.md` if it's gone missing — the slash command can't fire without it.
