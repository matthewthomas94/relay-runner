# Phonon 2 transcription migration

Draft specification, 17 October 2026. Source inspected at Relay commit `38bfecdb597f4c5b8b66b5ee2429ad77bc94d0bc`.

Replace the default English recognizer with Fermion Research's Phonon 2 in both ordinary voice sessions and Note Taker. Keep transcription local, retain the existing controls and saved-note contract, and validate the change against Relay's current Parakeet behavior before changing the default.

The recommended implementation uses the native `PhononCoreML` Swift package inside Relay. It avoids introducing a Python speech service or a second microphone owner. **The proposed platform floor is macOS 15; this remains a product decision.** Relay currently targets macOS 14 in both its package and app metadata. Retaining macOS 14 requires a separately scoped compatibility approach: a macOS 15 helper with IPC and a legacy backend on 14, or a different validated runtime. An availability check alone does not resolve the package's higher deployment target.

Phonon is documented for English. Preserve explicitly selected Parakeet v3 configurations for multilingual use in the first release, and keep Parakeet available for an explicit rollback. Removing every Parakeet option would additionally retire existing multilingual support and requires a separate decision. [Fermion model information](https://www.fermionresearch.com/models/phonon-2/)

**Verified upstream inputs.** The native package requires Swift 6 / Xcode 16 and macOS 15. Its public API accepts mono 16 kHz samples and returns text with word timestamps; it is an utterance/window API, so Relay must continue producing live partials from bounded snapshots. First-use preparation can take one or two minutes. Relay's CI already selects Xcode 16, but release compatibility still needs verification. [Native package](https://github.com/fermionresearch/phonon-coreml/tree/bf59e574639b060e30ee1a3f9c0e003fed5744c8)

**Recognition boundary.** Introduce one small local recognition interface for preparation and transcription of mono 16 kHz Float32 samples. Its result contains text, timed words, and measured processing duration. Use explicit model identifiers (`phonon-2`, `parakeet-tdt-v2`, `parakeet-tdt-v3`) and reject unknown identifiers. Keep capture, gestures, note persistence, and provider delivery outside this interface.

Use the same backend implementation and asset cache in both workflows, with a recognizer instance owned by the active workflow. Do not require a global concurrent inference service. Serialize calls to the native recognizer off the main thread and audio callback. Phonon's API is synchronous and exposes mutable timing state; task cancellation must invalidate pending/result delivery even when a native call cannot be interrupted immediately. Its initializer also supports load-progress callbacks and explicit encoder preparation. Warm the functions required by both short commands and long command chunks before reporting readiness; benchmark the memory cost. [Transcriber source](https://github.com/fermionresearch/phonon-coreml/blob/bf59e574639b060e30ee1a3f9c0e003fed5744c8/Sources/PhononCoreML/Transcriber.swift)

**Model installation and readiness.** Download only the pinned encoder package, decoder tables, manifest, and required notices using native networking. Package executable decoder code through SwiftPM; do not download and execute the model repository's scripts or dylib at runtime. Store assets outside the signed app bundle, atomically mark a complete verified download usable, and deduplicate preparation. Handle interrupted downloads, corrupt/mismatched files, unavailable network, insufficient disk, and retry without deleting a working legacy installation. A cached installation must transcribe offline. Report actual download progress and named preparation phases without inventing compile percentages. Readiness requires a successful local fixture transcription; it must not open the microphone.

**Ordinary voice sessions.** Preserve toggle start/stop/cancel, non-toggle capture, tutorial isolation, microphone ownership, media settling, reference-audio suspension, and final command delivery. Keep bounded snapshot recognition rather than assuming native streaming. Check input lengths near every encoder boundary and command-chunk rollover, including delayed processing that grows a snapshot. Do not let a stopped session, changed device, or superseded model-load operation publish stale text or reopen capture. Maintain the existing bridge/intent protocol and test delivery with both Codex and Claude. Evaluate the current silence/hallucination filter using Phonon outputs; do not copy assumptions about Parakeet's noise behavior without evidence.

**Note Taker.** Preserve separate microphone and system-audio streams, their shared timeline and source labels, all durable checkpoints, and current bounded queues. Feed each existing producer window to the recognizer; do not pass an entire meeting to Phonon's separate long-file segmentation algorithm. The producer remains the owner of final segment boundaries and overlap decisions.

Normalize both recognizers into whole timed words before the producer's ownership filter. Phonon's public words have text/start/end and no confidence field; do not fabricate confidence or feed whitespace-free words into the current subword concatenation logic. Keep punctuation attached and convert window-relative seconds to the existing note timeline once. Assign a word by its onset in the owned half-open interval, matching current source behavior. The older capture document describes midpoint ownership and must be corrected when this change lands. Test genuine repeated speech, overlap seams, and final tails explicitly. [Phonon word contract](https://github.com/fermionresearch/phonon-coreml/blob/bf59e574639b060e30ee1a3f9c0e003fed5744c8/Sources/PhononCoreML/Words.swift)

Record the selected backend, runtime/model revision, and relevant decoding identity in new local recovery journals. Freeze that identity for a recording and its pending tail. Maintain decoding compatibility with existing journals; a legacy journal with no model identity must retain its saved text and expose any necessary backend choice before re-transcribing its unsaved audio. Never re-transcribe completed notes automatically. A later setting change applies to the next recording, and switching to a work session waits for the existing note finalization boundary.

Keep note IDs, artifact references, global-library location, canonical save APIs, and title/summary behavior intact. Recording speech remains document content: it must not enter the voice FIFO, start a foreground provider/messenger, or create/dispatch work. Existing post-save metadata generation remains a separate lifecycle. Source labels remain microphone/system; this change does not add speaker diarization, echo cancellation, or cross-source deduplication.

**Settings and migration.** Offer Phonon 2 as the recommended English model after validation. New installations use it by default. For existing Parakeet v2 users, prepare Phonon successfully before a one-time switch at an idle boundary; retain the previous choice for rollback and record that migration so an explicit rollback is not immediately undone. Preserve an explicit Parakeet v3 selection. Apply the same rules in Swift and Python, including legacy Whisper aliases. Surface the active model if setup fails; never silently run Parakeet while showing Phonon. Do not change an active recording's backend. Keep existing caches until a separate cleanup decision.

**Acceptance and release gates.** The following numerical limits are proposed acceptance targets, not measured results. Record the test Mac, OS, power mode, model/runtime revisions, corpus, and both cold/warm runs. Fix the baseline corpus and thresholds before comparing implementations.

| Area | Required evidence |
| --- | --- |
| Recognition quality | Paired command and meeting corpora covering Australian English, technical terms, names, numbers, short replies, quiet/noisy speech, and overlapping sources. Proposed gate: no more than +1 absolute percentage point normalized WER versus the corresponding Parakeet baseline on either corpus; review punctuation separately; zero new action-changing errors in the fixed critical-command cases. |
| Command responsiveness | Measure capture-to-first-partial and release-to-final separately from model-only time. Proposed warm p95 release-to-final at most 500 ms and no regression versus the measured baseline. Retain the current partial cadence without an accumulating recognition backlog. |
| Continuous notes | At least 60 minutes of real-time-paced two-source input on a representative lower-end supported Mac. Zero silent audio drops, missing acknowledged tails, new overlap duplicates, or unbounded queue/memory growth. Proposed steady-state p95 final recognition lag at most two seconds after a window closes. |
| Lifecycle and recovery | Cancel during loading/inference; repeated start/stop; work ↔ notes transitions; permission denial; device changes and sleep/wake; crash/relaunch; offline saves and retries; old/new journal replay. Saved segment identity, ordering, and content remain intact. |
| Setup and rollback | Fresh install, interrupted/corrupt download, warm restart, cached offline start, safe settings change, failed Phonon preparation, and explicit rollback. No repeated migration after rollback and no microphone capture merely because a model is ready. |
