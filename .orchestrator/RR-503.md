## Description

Follow-up from the RR-501 spike (run 380); read its findings in RR-501 before starting.

In `worker.rs` `start_process`, give worker and reviewer provider processes their own process group. Signal and terminate with `killpg`. When the provider exits, `killpg` any survivors straight away instead of first waiting for pipe EOF.

## Acceptance criteria

- [ ] Worker and reviewer providers start in their own process group, for both Claude and Codex.
- [ ] Cancel, timeout and normal exit all kill the whole group.
- [ ] Tests use fake claude and codex providers that leave a background child, and show the child is gone after the run ends.
