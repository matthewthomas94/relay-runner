## Description

`activate_project` / `activate_general` (`Sources/relay-actions-mcp/ActivateProjectTool.swift`) land in `AppState.activateProject` (~2787) / `activateGeneral` (~2823). Today, with a session running, they queue a context *replacement* and may forward a `continuation` into the new session after it launches (`reserveContextContinuation` ~1869, `reconcileContextContinuation` ~1893–1950).

With per-project sessions:
- `activate_project` on a project with a running session focuses it; on a project without one it opens its board (browse) and does not start a session, unless the established contract requires starting one for a continuation — decide and document which.
- A `continuation` is delivered to the destination project's session (existing or newly started), still bound to the original turn's authority, submitted once, never replayed after uncertainty.
- The source session is no longer stopped.
- Update the `services/instructions/` chunks describing context changes and continuation forwarding, re-run `scripts/build-instructions`, and commit the regenerated CLAUDE.md / AGENTS.md / compact payloads.

## Acceptance criteria

- [ ] `activate_project` on a running project focuses it and leaves the source session running.
- [ ] `activate_project` on a non-running project without continuation starts no process.
- [ ] A continuation is submitted exactly once to the destination session with its original authority; uncertain delivery still requires review.
- [ ] `services/instructions/` chunks and all generated outputs describe the new semantics; the generated block check passes.
- [ ] Behaviour is identical for Codex and Claude foreground sessions.
