## Description

After RR-186 moves every onboarding entry point to the dedicated intro overlay, remove Settings' ability to host or route the walkthrough. Today `SettingsWindow` and `WorkspaceSettingsPanel` bind `appState.onboarding.presentation`; while active, `SettingsContent` forces Status selection, swaps in an onboarding header/root/footer, and standalone Settings routes toward Workspace Settings. That is the behavior shown in `/var/folders/xs/qtmf4y_s3_l3dd6b_2mxjj4c0000gn/T/TemporaryItems/NSIRD_screencaptureui_GoVcpE/Screenshot 2026-07-22 at 5.10.32 pm.png` and it should no longer exist.

Settings must always remain ordinary post-onboarding management UI. Status continues to manage permissions and runtime health. General continues to manage provider, model, reasoning effort, and workspace. The `Re-run Setup Walkthrough…` action may remain, but it must launch the dedicated intro overlay over the app; it must not replace Settings content. Remove the onboarding-specific Settings bindings, forced category selection, conditional detail/header/footer, Workspace routing, and any now-unused presentation plumbing from Settings. Retire legacy onboarding view/state code only where it is genuinely unused after RR-186; extract shared prompt presentation/view types first if the intro still depends on them, and do not perform unrelated Settings redesign.

## Acceptance criteria

- [ ] `SettingsWindow`, `WorkspaceSettingsPanel`, and `SettingsContent` no longer bind or branch on `OnboardingPresentationState`.
- [ ] Settings never swaps its header, detail, sidebar selection, scroll target, or footer for onboarding content and never routes a walkthrough from standalone Settings into Workspace Settings.
- [ ] Status remains the management surface for permission/runtime state; General retains provider, model, reasoning effort, and workspace controls for both Codex and Claude.
- [ ] `Re-run Setup Walkthrough…` invokes the intro overlay while Settings itself remains normal management UI underneath.
- [ ] Remove onboarding-only Settings helpers and tests made obsolete by the decoupling. Leave dormant legacy code only when still required by shared intro types; avoid broad unrelated refactoring.
- [ ] Tests assert that Settings has no onboarding host/interception path and that ordinary navigation/header/footer behavior remains unchanged while the intro is active.
- [ ] Full `swift test` and `RELAY_SKIP_APPLICATIONS_REFRESH=1 ./scripts/build-dmg.sh` pass.
