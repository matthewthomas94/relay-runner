## Description

Fix the notch hover interaction for the rotating glyph that reveals reasoning traces. When the user hovers the glyph, the notch should expand smoothly to show the reasoning trace surface. When the pointer leaves the glyph/expanded hover region, the notch should contract smoothly back to its default state.

The current behavior appears unstable: the notch repeatedly jumps between expanded and contracted states, and the bounds can change abruptly without an intentional cursor enter/exit. A video review described this as two related problems:

- Hover/event triggers are unreliable: the view appears to change layout or bounds without a matching mouseEntered or mouseExited transition from the glyph.
- Animation interpolation is missing or bypassed: when the bounds change, they snap rather than easing between the contracted and expanded frames.

Investigate the hover target geometry, expanded hit area, state transitions, and animation transaction used by the notch status surface. Keep the existing notch transformation style and reasoning trace intent; the fix should stabilize the hover lifecycle rather than removing the interaction.

## Acceptance criteria

- [ ] Hovering the rotating notch glyph expands the reasoning trace surface exactly once per enter state, without repeated expand/contract oscillation while the pointer remains in the intended hover area.
- [ ] Moving the pointer out of the glyph/expanded hover area contracts the surface exactly once per exit state.
- [ ] Expansion and contraction use smooth easing/interpolation rather than snapping bounds immediately.
- [ ] The expanded reasoning trace surface remains reachable without the pointer crossing a dead zone that triggers premature collapse.
- [ ] Existing notch states such as listening, response ready, active worker/status labels, and compact glyph-only states still render and animate correctly.
- [ ] The fix is scoped to notch hover geometry/state/animation and does not regress the current notch shape styling.
- [ ] Focused Swift tests or view-model tests cover the hover state transition logic where practical.
- [ ] Build and focused notch tests pass; if visual behavior needs manual validation, record the exact manual hover check or screenshot/video review in the run log.
