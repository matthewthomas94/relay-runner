## Description

The Relay Remote iPhone app gets a Workspace tab (`docs/design/relay-remote-ios/26-workspace.jpg`): tickets grouped as In progress, Queued and Backlog, each with the agent that owns it, and a strip of project tabs (All, then one per project). RR-532 added `workspace_command` and `workspace_state` to the protocol and left a stub handler on the Mac. This ticket fills it in.

**Wanted**

- `workspace_command` `list` returns every registered project (id and display name, the same list the desktop Workspace shows, including general-tasks if the desktop shows it) and the open tickets across them: id, title, status mapped to `in_progress` (including verification-blocked), `queued` (ready, waiting on dependencies or a worker slot) or `backlog`, project id, and the owning agent's slug when a ticket was dispatched or claimed by an agent. Done and cancelled tickets are not sent.
- Use the same source the desktop Workspace board reads (`Sources/relay-runner/Board/OrchestratorClient.swift` and the orchestrator daemon's HTTP API, `docs/specs/orchestrator-http-api.md`), so the phone and the desktop always agree.
- After a `list`, the Mac pushes a fresh `workspace_state` to that phone when the board changes, coalesced to at most one push every couple of seconds, until the phone disconnects.
- Only the fields above leave the Mac: no ticket bodies, no file paths, no repository paths.
- Cap the payload (for example 200 tickets, newest activity first) and say in the frame when the list was truncated.

## Acceptance criteria

- [ ] A scripted `workspace_command` `list` against a test board returns the projects and tickets with the status mapping above and no done or cancelled tickets.
- [ ] A ticket dispatched by an agent carries that agent's slug; a ticket with no owner carries none.
- [ ] Changing a ticket's status on the board produces a pushed `workspace_state` to a subscribed phone within a few seconds, and a burst of changes produces one push, not one per change.
- [ ] The frames contain no ticket body text and no filesystem paths (asserted in a test).
- [ ] With the orchestrator daemon unreachable, the reply is a well-formed error the phone can show, not a hang.
- [ ] `docs/specs/relay-remote.md` documents the feed, its limits and its privacy boundary.
- [ ] `swift build`, `swift test` and `cargo test` pass.
