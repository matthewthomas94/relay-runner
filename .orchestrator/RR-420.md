## Description

Spec: `docs/specs/relay-remote.md` (Relay Remote: iOS voice over SSH), committed as `2a64cc0d` on branch `claude/ios-relay-ssh-tcp-spec-ddb8f2`. The spec is not on `main` yet; if the file is missing from your worktree, read it with `git show 2a64cc0d:docs/specs/relay-remote.md`. Read these sections first: Architecture, Pairing and trust, Verified upstream inputs, Open questions.

Relay Remote carries text frames between a native iOS app and the user's Mac over one persistent SSH connection to the Mac's own OpenSSH server; there is no relay server. The spec assumes one `exec` channel running the forced command `relay-remote-shell --device <device_id>` with NDJSON over the channel's stdin and stdout, and names a `direct-tcpip` forward to the bridge socket as the fallback. Settle that choice before the iOS transport (RR-428) and the helper (RR-425) are built.

Answer these questions by reading source and documentation only (swift-nio-ssh, swift-nio-transport-services, Citadel, Apple's background execution and network documentation). Pin every citation to a commit SHA or a dated document.

1. Can a swift-nio-ssh client open an `exec` channel with a writable stdin and no PTY, and keep it open as a long-lived bidirectional stream? Name the channel type, request, and handler types involved.
2. Which delegate or hook validates the server host key against a key pinned at pairing, and what does it receive (key type, raw bytes, fingerprint)?
3. Can the public half of `NIOSSHPrivateKey(secureEnclaveP256Key:)` be exported in `ecdsa-sha2-nistp256` authorized_keys format so the Mac can install it, and what is the fallback on a device without a Secure Enclave?
4. Does Citadel (the higher-level client built on swift-nio-ssh) add anything Relay Remote needs (exec with stdin, forwarding, reconnection) or only cost?
5. What does the `direct-tcpip` fallback cost compared with `exec`: extra `sshd` options (`AllowTcpForwarding`, `AllowStreamLocalForwarding`), interaction with `restrict` in `authorized_keys`, and client complexity?

Also list the iOS channel edge cases RR-428 must test: suspension and resume, network path changes (Wi-Fi to cellular), keepalive intervals that survive NAT timeouts, and what the app can rely on while in the background.

This is read-only research: do not write prototype code into the repository.
