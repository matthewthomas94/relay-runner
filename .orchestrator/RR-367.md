## Description

After the user selects a project, show the existing Start Session action alongside a new action with the exact label Start Note Taker. Start Note Taker uses that project's recording coordinator without creating a normal agent or voice bridge session. Keep the selected project explicit and bind a running recording to its original project.

Add Notes immediately before Backlog in the existing project board. The resulting lanes are Notes, Backlog, Queued, In progress and Done. Notes are document cards labeled by their IDs (for example RR-N1), with useful date/recording/save metadata, and open their Markdown transcript. They are not Ticket values with a new dispatchable status. Expose recording progress, Stop/finalization, local save status and pending/conflicted remote sync within this existing flow.

No generated title, summary, calendar integration, meeting bot, automatic meeting detection, separate app/repository/bundle, launcher handoff or new agent-session type belongs to this ticket. A searchable separate session workspace and broad rich-text editing are not prerequisites for the scoped feature.

While actively capturing a note, keep the existing notch glyph expanded and reuse its orange rotating listening appearance with the exact visible status Taking notes. While Caps Lock has paused that same note, keep it expanded, show exactly Paused and use the existing standard white-only glyph appearance. Preserve the existing animation and reduced-motion conventions; do not invent a paused effect. These are the only note-recording overlays: no normal voice-transcript pill, conversation/session overlay, active agent-session UI or substitute recording panel. Stop controls and transcript inspection belong in the existing project/Notes flow. Tie the glyph to actual recorder state, clear Taking notes as soon as capture is no longer active, and release note presentation ownership on stop/error/teardown.

Foreground work sessions and note-taking are mutually exclusive. Start Note Taker ends the existing foreground work session through its established End Session lifecycle, waits for bridge/audio/TTS/UI ownership to be released, and then begins local note capture. Start Session from either recording or paused note mode stops capture, drains the accepted final tail and durably saves the same note to its original project before launching the requested work session. These explicit start actions authorize the switch without a second confirmation. A save or teardown failure blocks the destination mode and preserves recovery state; remote sync alone does not block a locally saved switch. Unrelated daemon worker runs are unaffected.

One authoritative transition owner serializes mode changes and rejects stale callbacks. Snapshot the destination project when the start action is accepted while retaining the source note's original project. Repeat clicks, project changes, start failures and delayed teardown must never leave both foreground modes active or misfile a note.

Within note mode, actual Caps Lock ON pauses capture and OFF resumes the same note. Paused speech from every source is excluded from both retained audio and later transcription; preserve already accepted content and the pre-pause tail. Pause does not finalize, allocate a new ID or launch an agent. Read the actual key state at startup, so Caps Lock already ON starts paused before accepting audio. Route the key exclusively to the active mode; paused notes still own note mode. Synchronize rapid/repeated changes and restore ordinary work-mode key behavior after teardown.
