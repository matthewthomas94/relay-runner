## Description

Spec: `docs/specs/relay-remote.md` (Relay Remote: iOS voice over SSH), committed as `2a64cc0d` on branch `claude/ios-relay-ssh-tcp-spec-ddb8f2`. The spec is not on `main` yet; if the file is missing from your worktree, read it with `git show 2a64cc0d:docs/specs/relay-remote.md`. Read these sections first: Architecture, Wire protocol, Mac-side integration with the voice contract.

Add `services/relay_remote.py`, a module owned by `voice_bridge.py`, that accepts remote device sessions and feeds their utterances into the existing voice command path with the same command identity and ordering guarantees as the microphone.

- Listen on the Unix socket `/tmp/relay_remote.sock` (mode 600). On each connection, read the peer uid (`LOCAL_PEERCRED` on macOS) and refuse any uid other than the bridge's own before reading a frame; the forced-command helper (RR-425) is the only expected client and it runs as the same user.
- The helper's first frame identifies the device; sessions are keyed by `device_id`. A second connection for the same device replaces the first.
- Use the Python twin from RR-422 for framing, `client_id` de-duplication and the replay buffer. Answer `hello` with `welcome` and replay from `resume_after_seq`.
- Put accepted `utterance` frames on an ingress queue that wakes the bridge's FIFO select loop, so remote and microphone commands share one ordered path through `_begin_relay_command` and get normal `relay_command_seq` and `relay_command_id` values. Carry `input_source: "remote"` and `device_id` through the spool `.meta` file, the voice command state file and `RelayCommandMetadata` in `services/pm_frontstage.py`; microphone commands keep their current metadata unchanged.
- Reply `accepted` with the assigned `relay_command_seq` and `relay_command_id`; reply `error` for rejected input (oversize, unknown type, no running session).
- Map `control` actions one to one onto the FIFO tokens the bridge already dispatches: stop to `__TTS_STOP__`, interrupt to `__INTERRUPT__`, cancel to `__CANCEL__`, play to `__PLAY__`, replay to `__REPLAY__`. No new control semantics.
- Answer `ping` with `pong`.

Out of scope: speech back to the device (RR-424), the helper binary (RR-425), Mac UI and microphone gating (RR-427).

## Acceptance criteria

- [ ] A test drives a scripted device through the socket while FIFO commands arrive and asserts the bridge processes both in arrival order with correct `relay_command_seq` assignment.
- [ ] Remote commands carry `input_source` and `device_id` in the spool `.meta` file and the state file; microphone command metadata is unchanged and existing fixtures pass.
- [ ] A connection from a different uid is refused before any frame is read (mocked peer credential).
- [ ] Each of the five `control` actions is tested to reach its existing FIFO token path.
- [ ] A retried `utterance` with a known `client_id` gets one `accepted` and is not queued twice.
- [ ] A `hello` with `resume_after_seq` receives the missed frames in order; existing bridge tests pass.
