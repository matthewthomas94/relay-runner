## Description

Investigate and fix a production playback race affecting ordinary incoming Relay messages, independent of onboarding. A new response becomes visible in the message-waiting pill with the instruction to double-tap Option. If the user performs that first gesture promptly, Relay may play or expose only the notification chime/tick and fail to start speech; a second Option double-tap then plays the message. Establish one authoritative readiness/gesture handoff across foreground reply delivery, messenger speech proposal, `TTSWorker` pending text/speculation, pill `message_waiting` publication, the FIFO `__PLAY__` control, and the speech coordinator. Once the UI tells the user playback is available, the first valid Option gesture must be retained and must start that exact response as soon as it is playable, even if it lands on a narrow enqueue/speculation boundary. Preserve explicit user-controlled playback, exact-once delivery, cancellation, replay, stale-response rejection, and both Codex and Claude paths.

## Acceptance criteria

- [ ] Add a deterministic regression reproducing a first Option `__PLAY__` control arriving at each boundary around authoritative reply receipt, messenger proposal, TTS pending-text enqueue, waiting-pill publication, notification chime, and speculative audio readiness.
- [ ] Once the message-waiting pill displays a response as playable, the first Option double-tap starts that exact response without requiring a second gesture.
- [ ] A play request that arrives slightly before pending speech is atomically playable is retained or safely coordinated and fulfilled once; it is not silently dropped.
- [ ] The notification chime/tick never satisfies, consumes, masks, or cancels a speech play request.
- [ ] Rapid or duplicate Option gestures do not double-start playback, overlap audio, replay stale text, or advance newest-message ownership incorrectly.
- [ ] If a newer response supersedes a pending one, any retained play intent follows the documented newest/current speech policy and cannot play stale content.
- [ ] Control cancellation, explicit replay after completion, auto-play mode, speculative synthesis, empty-message handling, and completion-hook/messenger exact-once behavior remain correct.
- [ ] The waiting pill is not surfaced before its backing response has a safe first-gesture playback path, or the path explicitly latches an early gesture until readiness.
- [ ] Codex and Claude app-owned sessions share the same fix and user-visible behavior.
- [ ] Focused Python tests cover FIFO `__PLAY__`, chime and enqueue races, speech coordinator ownership, speculation readiness, cancellation, supersession, and exact-once playback; relevant Swift gesture/pill integration tests also pass.
