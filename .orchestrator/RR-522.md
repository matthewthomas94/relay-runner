## Description

Relay Runner now has four fixed agents (see RR-519): Puck, Isabella, George and Sky. Each running session belongs to one agent; its provider process has `RELAY_SESSION_AGENT=<slug>` and its spool directory (`/tmp/relay-sessions/<session key>/`) has a `session_agent` file with the slug.

Work style (auto, direct or orchestrated) decides whether a change request is done in the session or goes to the ticket board. Today it is one choice for the whole session, picked from the chevron menu on the Start Session button. The user wants it to be a setting of each agent instead, configured in Settings, so that for example Puck is always direct and George always orchestrated. A separate ticket turns the Start button's menu into an agent picker; this ticket gives work style its new home first.

Settings also has an agent card: a panel beside the settings with a particle orb, one agent name and a status line. It shows a single agent. The user wants it to show all four, as a grid of four cards (or four separate cards) that takes up the same space the one card does now. Each card is where that agent's work style is set.

### How it works today (verify before relying on it)

- `ProjectWorkStyle` and `SessionWorkStyleStore.shared` in `Sources/relay-runner/Board/ProjectWorkStyle.swift`; the store file is `relay-runner/session-work-style.json` (override `RELAY_SESSION_WORK_STYLE_FILE`).
- The Start button's chevron menu writes `SessionWorkStyleStore.select` (`ProgramSessionPrimaryButton` in `Board/ProgramBoardOverlayView.swift`, also used by the Terminal empty state in `Terminal/EmbeddedTerminal.swift`).
- The Rust router reads the style on every request (`rust/relay-services/src/command_actions.rs`, around lines 577-660): `RELAY_WORK_STYLE` env, then the session file, then the project's `.relay-runner.toml` `work_style`, then auto.
- Voice ("switch to direct mode", `WORK_STYLE_SWITCH_RE`) calls `set_session_work_style`. The `/work-style` skill and `rust/relay-rs/src/work_style.rs` read and set it from inside a session.
- The agent card is `SettingsAgentCard` in `Sources/relay-runner/Settings/SettingsAgentCard.swift`, mounted at the trailing edge of the Settings row in `Settings/SettingsWindow.swift` (width 280 in the Settings window, `SettingsAgentCardLayout.width` in the Workspace, frosted with `panelGlass` there). Its name comes from `SettingsAgentPresentation.voiceName(config.tts)` and its status line from `SettingsAgentPresentation.subtitle` and the one global overlay state. `SettingsAgentParticleHostView` draws the orb. Tests: `tests/RelayRunnerTests/SettingsAgentCardTests.swift`.
- The provider instructions describe it as a choice "for the whole session from the Start button's menu" (`services/instructions/`, generated into `Sources/relay-orchestrator-mcp/Instructions.generated.swift`, and `services/instructions/commands/relay-work-style.md`).

### What to build

1. **Four agent cards.** Replace the single agent card with four cards, one per agent in table order (Puck, Isabella, George, Sky), laid out as a two-by-two grid inside the frame the single card occupies now, in both the Settings window and the Workspace. Keep the outer width rules, the card corner radius, border and the Workspace's panel glass, with the spacing the Settings panels already use between cards. Each card shows:
   - the agent's name, from the agent definition and not from the voice setting;
   - a status line. A stopped agent reads "Not running". The active agent uses the existing `subtitle` wording for the overlay state. A running agent that is not active reads "Working" or "Standing by" if the app knows that per session, otherwise "Standing by";
   - a Work style picker with Auto, Direct and Orchestrated, default Auto.
   **Layout inside each card.** The cards are not centred like today's card, and the two columns of the grid mirror each other.
   - Left column (Puck, top; George, bottom): the name and, under it, the status line sit in the top-left corner, left-aligned. The Work style picker sits in the top-right corner.
   - Right column (Isabella, top; Sky, bottom): the mirror image. The name and status sit in the top-right corner, right-aligned. The picker sits in the top-left corner.
   So the pickers face each other across the gap between the columns and the names sit at the grid's outer edges. Name block and picker share the same top inset, and the insets from the card's top and side edges are equal in both columns.
   The picker looks and behaves like the Add project control on the Workspace board (`ProgramAddProjectMenu` in `Sources/relay-runner/Board/ProgramBoardOverlayView.swift`): one button showing the current style, a divider and a chevron, whose click always opens a `SettingsDropdownPresenter` menu of the three styles. Unlike Add project, the menu shows a checkmark on the current style. The menu opens aligned to the picker's edge nearest the card's corner (trailing in the left column, leading in the right) and stays inside the Settings frame. A long name or status truncates before it reaches the picker.
   Keep the particle orb on each card if four of them hold the frame rate; the active agent's orb follows the live theme and the others stay on the idle theme. If four animated orbs cost too much, animate only the active agent's and say so in the run log. Respect Reduce Motion as the card does now. Each card is one VoiceOver element named for its agent with the status as its value, and its picker is reachable.
   The work style saves through the same path as other settings and is readable and settable through `mcp__relay-app__get_settings` / `set_settings`.
2. **Per-agent resolution.** A request is routed with the work style of the agent whose session it belongs to. Two agents running at once with different styles each get their own. The per-agent setting takes the place of the session-wide choice in the existing precedence (`RELAY_WORK_STYLE` still wins; a project's `.relay-runner.toml` and the built-in auto still come after). Check how an explicit session choice of Auto interacts with a project's `work_style` today and keep that behaviour for an agent set to Auto.
3. **Changing it mid-session.** "Switch to direct mode" by voice and `/work-style` change the setting of the agent they are addressed to, and only that agent. The change is the same stored setting, so Settings shows it at once and it is still in force the next time that agent starts.
4. **Remove the old control.** Remove the work-style chevron menu from the Start Session button in Workspace and in the Terminal empty state, leaving a plain Start Session button for now (the start-menu ticket replaces it). Retire the session-wide store file; an existing file is ignored.
5. **Text.** Update the provider instructions and the `/work-style` command text to say the style belongs to the agent and is set in Settings, by voice or with `/work-style`.
