## Description

Extend the release pipeline so tagged releases publish Sparkle-compatible OTA artifacts in addition to the existing DMG.

The current `.github/workflows/build-dmg.yml` builds, signs, optionally submits the DMG for notarization, uploads it as an artifact, and attaches it to GitHub Releases on tags. OTA updates require a signed/notarized update archive plus an appcast generated with Sparkle EdDSA signatures.

Target release shape:

- DMG remains the first-install artifact.
- Sparkle archive is used for installed-app updates.
- Appcast is hosted at a stable HTTPS URL.
- `CFBundleVersion` is monotonically increasing and is the version Sparkle compares.

Implementation guidance:

- Decide whether to serve update archives as `.zip`, `.dmg`, or Apple Archive. Prefer the simplest Sparkle-supported regular app bundle update that works with this SwiftPM packaging path.
- Update `scripts/build-dmg.sh` or add a focused release script so CI can produce both `RelayRunner.dmg` and a Sparkle update archive from the same signed app bundle.
- Ensure Sparkle framework/helper code is signed correctly inside the app bundle before archive generation.
- Add CI steps to generate or update the appcast using Sparkle's tooling and repository secrets for the EdDSA private key.
- Keep PR builds useful without release secrets: they should still build/test packaging paths but may skip appcast signing/upload.
- Document required GitHub secrets and the expected artifact hosting path.

## Acceptance criteria

- [ ] CI can produce a Sparkle-compatible update archive from the signed Relay Runner app bundle.
- [ ] Tagged releases publish both the DMG and OTA update artifact.
- [ ] Tagged releases generate or update a valid Sparkle appcast with EdDSA signatures.
- [ ] The appcast URL matches the `SUFeedURL` configured in the app.
- [ ] Missing signing/notary/appcast secrets degrade clearly on PR builds without false release success.
- [ ] `CFBundleVersion` monotonicity is checked or explicitly documented in the release flow.
- [ ] Release documentation explains how to rotate Sparkle keys and what must not change in the same update.
- [ ] Packaging validation covers code signing, notarization readiness, and archive/appcast sanity.
