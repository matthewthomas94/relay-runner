## Description

Restore the registry-v2 Projects header action specified by RR-273. The control must be labeled **Add project** and cover both supported project-registration paths: adding an existing Git repository and creating a new project folder. Reuse the existing project-management handlers so their folder panels, validation, Workspace suspension/restoration, and cancel semantics remain authoritative.

Also prevent the registry-v2 Workspace from rendering legacy registry projects. A project card shown in registry-v2 must be backed by the same registry used to confirm Start Session scope.

## Acceptance criteria

- [x] In registry-v2, the Projects header shows **Add project** instead of **Select all**.
- [x] The action offers both **Add existing project** and **Create new project** and routes to the existing supported flows.
- [x] Existing-project selection still validates a Git repository, and successful add/create returns with the new project selected.
- [x] Cancel leaves project and Workspace state unchanged; the Workspace is restored after either external panel closes.
- [x] Registry-v2 Workspace snapshots never display legacy-only project cards.
- [x] The bounded compatibility-off path retains its legacy behavior without weakening the registry-v2 scope gate.
- [x] Focused Swift tests pass, and the rebuilt installed app is ready for mounted interaction verification.
- [ ] The mounted Projects header and Add project menu match the specified label and choices, and cancel visibly restores Workspace without changing project state.
