## Description

Restore the registry-v2 Projects header action specified by RR-273. The control must be labeled **Add project** and cover both supported project-registration paths: adding an existing Git repository and creating a new project folder. Reuse the existing project-management handlers so their folder panels, validation, Workspace suspension/restoration, and cancel semantics remain authoritative.

Also prevent the registry-v2 Workspace from rendering legacy registry projects. A project card shown in registry-v2 must be backed by the same registry used to confirm Start Session scope.

The empty-registry state must show only its heading and the two project actions, without a repeated subtitle or manual Refresh action. The populated header action must use the native dropdown interaction with a visible disclosure chevron and a split-button face: a text segment, a dedicated disclosure segment, and a divider inside one rounded outline. Open and Save panels must activate Relay Runner only after Workspace completes its standard dismiss animation, and Workspace must use its standard reveal animation when either panel closes.

The populated split control must reuse the same secondary-button surface palette and interaction opacities as Settings. Its visible rounded face must be the native Menu label's hit target, including the outline, divider, and disclosure segment. Mouse activation must not leave a latched selected/focused appearance after the menu closes; native Menu keyboard semantics remain authoritative.

Primary prominence is reserved for the pure-white permission-onboarding actions. Every button rendered inside Workspace, including its embedded Settings content, must use the secondary treatment even when it is the logical default action.

The Create Ticket modal must use the same bounded panel shell as ticket detail instead of growing beyond the Workspace. Its project, title, execution-mode, description, image, Cancel, and Save controls must use the app's dark field surfaces and secondary action treatment. Ticket detail, creation, editing, and follow-up modals must darken only the Workspace surface behind them, preserving the Workspace outline and leaving the desktop outside it unaffected.

The Create Ticket form must also keep Images and the footer actions visible without scrolling the whole modal. Use sentence-case labels throughout, a compact single-line title field with regular field typography, execution-mode options at the shared secondary-button height, and a shorter description editor that scrolls its own overflowing text.

Registry-v2 Workspace must render the complete available registered-project catalog even while one project is actively selected. The active project remains selected and continues to scope mutable actions, but other projects registered through either Add Existing or Create must remain visible and selectable in the Projects column. Legacy single-repo routing must retain its existing one-project scope.
