## Description

Restore the registry-v2 Projects header action specified by RR-273. The control must be labeled **Add project** and cover both supported project-registration paths: adding an existing Git repository and creating a new project folder. Reuse the existing project-management handlers so their folder panels, validation, Workspace suspension/restoration, and cancel semantics remain authoritative.

Also prevent the registry-v2 Workspace from rendering legacy registry projects. A project card shown in registry-v2 must be backed by the same registry used to confirm Start Session scope.

The empty-registry state must show only its heading and the two project actions, without a repeated subtitle or manual Refresh action. The populated header action must use the native dropdown interaction with a visible disclosure chevron, while retaining the established compact Workspace styling. Open and Save panels must activate Relay Runner after Workspace is suspended so the system panel becomes frontmost without a separate app click.
