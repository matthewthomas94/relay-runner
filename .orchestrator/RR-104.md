## Description

Wire the worker-sizing metadata from RR-103 into the actual dispatch path so tickets cannot be sent to a sub-agent without a deliberate model/effort choice.

Relay Runner should reject or hold `ready` tickets that lack the required sizing metadata, with an actionable reason on the board/log instead of silently starting a default worker. When metadata is present, the daemon should apply it to the worker command using the verified provider-specific mechanism from RR-102.

Likely touch points:

- `services/orchestrator.py`
- `services/program_status.py`
- `Sources/relay-runner/Board/Ticket.swift`
- `Sources/relay-runner/Board/ProgramBoardStatus.swift`
- `tests/test_orchestrator.py` or nearby Python orchestrator tests
- `tests/RelayRunnerTests/*Board*` for visible skipped/held state if the UI exposes it

## Acceptance criteria

- [ ] `dispatch_ticket` and the ready-ticket sweeper refuse to dispatch a `ready` ticket missing required worker-sizing metadata.
- [ ] The refusal reason is visible through existing run/skip/status surfaces so the user can refine the ticket instead of wondering why nothing happened.
- [ ] Codex workers receive the selected model and reasoning effort using the verified `codex exec` command shape.
- [ ] Claude workers receive the verified model/tier control where supported, or the daemon records a documented provider limitation while preserving the required sizing rationale.
- [ ] Run metadata captures the selected provider, model/tier, effort, and sizing rationale for Program Board/status visibility.
- [ ] Tests cover missing metadata, valid Codex metadata, valid Claude metadata or documented omission, and dependency auto-dispatch behavior.
- [ ] Provider parity is explicit: Codex and Claude dispatch behavior share the same sizing requirement even when their launch flags differ.
