## Description

Today only the focused session speaks (RR-401). A final reply from any other session goes into that session's unread badge instead: `_record_background_reply` in `services/voice_bridge.py`, called from the `_is_background_target(origin)` branch of reply delivery. The app then shows blue unread counts on the session wheel and the session tabs. Switching focus away while a reply is playing also stops it and moves it into the badge (`_cut_off_unfocused_speech`).

The user wants every reply heard by voice, and no blue badges.

Change it so that:

- A final reply from an unfocused session is spoken. It waits its turn: it queues behind whatever is playing or already queued, and never cuts in.
- Switching focus no longer turns an unheard reply into a badge. A reply that was playing or queued is still heard. Keep existing stop and barge-in controls working.
- The blue unread badges and counts are removed from the session wheel and the session tabs, along with any other place that shows `voice_reply_badge.json` counts (see `ProgramBoardOverlayView.swift`, `ProgramBoardStatus.swift`, `ProgramBoardOverlayController.swift`, `OverlayController.swift`, `EmbeddedTerminal.swift`, `WorkspaceTerminalSurface.swift`, `VoiceSessionSpool.swift`, `AppState.swift`). Remove badge state that nothing reads any more; keep any read-out or replay of the last reply that still works without the badge.
- Stale-command rules still apply: a reply superseded by a newer command in its own session is not spoken.

This depends on RR-480, which restructures speech in the bridge, so build on its merged version.

## Acceptance criteria

- [ ] With two sessions open, a reply that finishes in the unfocused session is spoken once, after the current speech, with no badge.
- [ ] Two replies arriving close together from different sessions are both spoken, in arrival order, neither cut off.
- [ ] Switching focus while a reply is playing or queued does not lose it.
- [ ] No blue unread badge or count appears on the session wheel or the session tabs.
- [ ] Bridge tests cover the new routing (the unfocused reply, ordering and the focus switch), the RR-480 speech contract suite still passes, and `swift test` passes.
- [ ] The run log names any remaining live voice check that only the user can do (Claude only).
