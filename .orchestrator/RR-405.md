## Description

The note-taker is moving from live transcription to "record now, transcribe after Stop" (MVP chain RR-404 and RR-405 → RR-406). This ticket adds the **post-stop batch transcription engine** only. RR-406 wires it in. The current live path must behave exactly as before after this merges.

Today `MeetingTranscriptProducer` (`Sources/relay-runner/Notes/MeetingTranscriptProducer.swift`) does three things:

- It cuts each source into 6 s windows with 1 s overlap and assigns word ownership by token onset.
- It emits deterministic segment IDs (`"<epochID>-S<relativeStart>"`).
- It submits partial windows once `firstPartialMilliseconds` and `partialIntervalMilliseconds` thresholds are met, writes a durable checkpoint through `durableCheckpointSink` on every ingested chunk, and fails capture with `backpressureExceeded` when its window queue is full.

Reuse that windowing and ownership logic rather than writing a second implementation. Add an offline mode or configuration, or a thin `MeetingRecordingTranscriber` that drives the producer, that:

- **Takes recorded audio as input.** Input is an ordered sequence of `MeetingAcceptedAudio` chunks per source, plus their timing epochs, behind a small protocol. It must not depend on RR-404's recorder type; tests use in-memory chunks, and RR-406 adapts the recorder's reader and legacy `.f32` recovery chunks to it.
- **Emits only final revisions.** It emits only final `MeetingTranscriptSegmentRevision`s, with the same segment IDs, millisecond bounds, text and `sourceID` speaker attribution that the live producer emits for the same audio. It never submits partial windows.
- **Skips per-chunk checkpoints.** It does not call the per-chunk durable checkpoint sink. RR-406 decides how progress is journaled.
- **Waits instead of failing.** Offline input waits for queue capacity rather than failing with `backpressureExceeded`. The window queue stays bounded.
- **Loads the model lazily.** It prepares the transcriber (`FluidAudioMeetingTranscriber.prepare`) only when a batch starts. It releases the loaded model when the batch finishes or fails, so the ASR model is not resident between notes. Add a release or unload method to `MeetingWindowTranscribing` if needed; FluidAudio `AsrManager` exposes cleanup.
- **Reports progress.** It reports model state (`MeetingLocalModelState`) and monotonic progress, as processed milliseconds out of total milliseconds, through a callback for UI.
- **Cancels promptly.** It honours Task cancellation and emits no further revisions after cancellation.
- **Fails with a typed error.** A transcriber failure surfaces a typed error. The caller keeps the recording, so no partial transcript is presented as complete.

## Acceptance criteria

- [ ] A golden test feeds the same synthetic multi-epoch two-source input, using the existing fake transcriber, through today's live producer and through the offline path. The final segment IDs, start and end ms, text and speaker are identical. The offline path emits zero non-final revisions.
- [ ] With a deliberately slow fake transcriber, offline input never fails with `backpressureExceeded`, and queue depth never exceeds the configured bound.
- [ ] Offline mode never invokes the per-chunk durable checkpoint sink. All existing `MeetingTranscriptProducerTests` pass unchanged, which proves live mode is unaffected.
- [ ] The fake transcriber records one prepare at batch start and one release at batch end. Release also happens on failure and on cancellation.
- [ ] The progress callback is monotonic and ends at 100%. Cancelling mid-batch stops promptly with no further revisions.
- [ ] A 60-minute synthetic fixture keeps retained producer audio bounded and independent of recording length, measured as in the existing 60-minute test.
- [ ] `swift build` and the Notes test suites pass.
