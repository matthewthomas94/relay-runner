## Description

Make Relay voice-work arbitration operate on ordered, durable item-level intent records rather than treating every new utterance or abandoned thought as authority over the whole turn. A single voice turn may contain several independently actionable project-work items, and later turns may add, refine, or cancel one of them. Persist each recognized item with stable identity, source command sequence and ID, order, target project or ticket when known, disposition, and lifecycle state so recovery and provider handoff preserve the same decisions.

Accepted project work is additive by default. New compatible items join the project work queue in their spoken order and do not replace work that was already accepted, queued, claimed, or running. If the user starts describing a later idea and abandons it before accepting it, only that incomplete item is discarded. A targeted cancellation or correction revokes only the named item or ticket. Preemption of other accepted work requires an explicit global cancellation whose resolved scope is all accepted work; ambiguity must not silently broaden a local cancellation into a global one.

Carry item identity and cancellation scope through durable intent storage, claim/checkpoint metadata, project mutation authorization, dispatch, recovery, messenger context, and provider completion handling. Stale output suppression may hide superseded conversation, but it must not revoke unrelated accepted project mutations. Codex and Claude must observe the same item ordering and authorization semantics.

Add a regression for the concrete sequence that exposed the bug: first, existing RR-263 is accepted for dispatch; second, the automatic-compaction work now captured as RR-266 is accepted as an additional item; third, the user begins a separate idea and abandons only that third item in the same turn. The result must retain the accepted RR-263 and compaction work in order, discard no earlier work, and create or dispatch nothing for the abandoned third idea.

## Acceptance criteria

- [ ] Every recognized voice-work item has a durable stable identity, source command sequence and ID, within-turn order, target when known, disposition, cancellation scope, and lifecycle state.
- [ ] Multiple accepted project-work items from one or more turns are appended to the appropriate project queue in deterministic spoken order instead of replacing one another.
- [ ] An incomplete or explicitly abandoned in-turn idea cancels only its own item record and cannot revoke earlier accepted, queued, claimed, or running work.
- [ ] A targeted cancel, correction, redirect, or replacement affects only the resolved item or ticket and preserves every unrelated accepted item.
- [ ] Only an explicit global cancellation with an all-work scope preempts unrelated accepted work; ambiguous wording requests clarification or remains scoped rather than widening cancellation authority.
- [ ] Stale user-visible reply suppression is separate from mutation authorization, so a newer additive turn cannot invalidate an older accepted ticket edit or dispatch.
- [ ] Durable recovery, app relaunch, duplicate delivery, and provider handoff preserve item identity, order, status, and cancellation scope without replaying completed mutations.
- [ ] Messenger context and lifecycle events report item-scoped acceptance, queueing, cancellation, and completion without implying that unrelated work was stopped.
- [ ] Codex and Claude app-owned sessions apply equivalent ordered-item and scoped-cancellation behavior across prompt delivery, completion hooks, interruption, failure, and recovery.
- [ ] A regression begins with existing RR-263 accepted for dispatch, then accepts RR-266 compaction as additive work, then abandons a third in-turn idea; RR-263 and RR-266 remain accepted in that order and no ticket, dispatch, or revocation is produced for the third item.
- [ ] Additional focused tests cover multi-item turns, later additive turns, targeted cancellation by item and ticket, ambiguous cancellation, explicit global cancellation, duplicate delivery, crash recovery, stale completions, and concurrent project queues; relevant Swift and service tests plus `git diff --check` pass.
