## Description

Prevent an empty voice recording from terminating an otherwise healthy app-owned Relay session when the embedded provider is idle.

The live failure occurred after a successful first turn. Speech capture produced no final transcript, so Relay queued the existing `__INTERRUPT__` control. The terminal consumer acknowledged the control as intended by the preceding control-intent fix, but it also wrote Ctrl-C into an idle Codex prompt. Codex exited cleanly with code 0 at the same instant, leaving the bridge alive without an embedded provider for the next turn.

Treat `__INTERRUPT__` as a provider interruption only while a Relay-correlated provider turn is active. When no provider turn is active, consume and acknowledge the control without writing Ctrl-C or any other terminal input. Preserve stale-command checks, ordered-inbox release, normal prompt delivery, active-turn preemption, and the shared Codex/Claude behavior.

Do not add Sentry or broader telemetry in this ticket.

## Acceptance criteria

- [ ] A focused regression test fails on current `main` because an idle `__INTERRUPT__` writes Ctrl-C to the terminal.
- [ ] With no active provider turn, `__INTERRUPT__` writes no terminal bytes, publishes the claimed metadata, and writes the manual consumer acknowledgement so the ordered inbox can advance.
- [ ] With an active provider turn, `__INTERRUPT__` still writes exactly one Ctrl-C and receives the same claimed/manual acknowledgement behavior.
- [ ] The idle and active cases are exercised for both Codex and Claude metadata, with no provider-specific divergence unless explicitly documented.
- [ ] Normal text prompts, explicit replacement preemption, stale-command handling, and one-event acknowledgement behavior remain covered and unchanged.
- [ ] Focused `RelayVoiceCommandDeliveryTests` and `EmbeddedTerminalSessionTests` pass, along with `git diff --check`.
