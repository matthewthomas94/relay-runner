## Description

Complete Phonon 2 support in the standard voice workflow using the model resolver and preparation path from RR-412. Cover both Caps Lock toggle and non-toggle capture loops in Sources/relay-runner/STT/STTEngine.swift and the accumulation logic in STT/TranscriptAccumulator.swift. Parakeet remains usable on macOS 14 and as an explicit supported-system selection.

Preserve 500 ms refinements, 25-second recording chunks, one-second chunk overlap, gestures, partial/final text, tutorial isolation, microphone ownership, media settling and reference-audio suspension. Use bounded snapshot inference; do not assume native streaming. Preserve the existing FIFO/bridge/intent contract and final command delivery for both Codex and Claude.

## Required inputs

- [ ] Confirm an authorized live dictation test window and input device on a supported Mac; use public/consented fixtures from RR-411 for repeatable recognition checks.
- [ ] Confirm test sessions authenticated through the user's subscriptions for both Codex and Claude before checking actual downstream delivery; automated bridge-contract tests alone do not establish live parity.

## Acceptance criteria

- [ ] Both capture loops transcribe through the selected resolver result and finalize once, retaining the established toggle/non-toggle start, stop, cancel and tutorial behavior.
- [ ] Real-model boundary checks cover short utterances, near/beyond 15 seconds, chunk rollover at 25 seconds, delayed-processing overshoot, punctuation and genuine repeated speech. Accumulation neither loses acknowledged text nor invents overlap duplicates.
- [ ] Test the existing silence/hallucination filter with measured Phonon silence/noise outputs and short valid utterances; make only evidence-supported adjustments without weakening Parakeet handling.
- [ ] Stop, cancel, device changes, superseded model loads and work-to-notes transitions invalidate stale results and cannot reopen capture or deliver canceled text. Reference-audio/media suspension and tutorial ownership remain isolated.
- [ ] STTRecordingAccumulationTests and STTCaptureOwnershipTests pass, with focused regressions for changed behavior; record cold/warm live dictation evidence separately.
- [ ] Capture-to-first-partial and warm release-to-final measurements are recorded against RR-411's baseline and agreed gates, with no growing inference backlog. The proposed warm p95 finalization target is at most 500 ms and no regression versus baseline; do not silently relax an agreed limit.
- [ ] The same final text reaches the existing command path once for Codex and Claude. Provider auth, command classification, cancellation authority and subscription-only access are unchanged; no new raw audio/transcript diagnostics or STT uploads are introduced.

## Scope boundary

Required hardware or provider access that becomes unavailable must be recorded as exact verification blockers rather than replaced with an unverified success claim.
