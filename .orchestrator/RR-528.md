## Description

The user redesigned two parts of the Settings surface in Figma and wants them in the app. Both are in `Sources/relay-runner/Settings/`. Everything needed is described here; the worker does not need Figma access.

### 1. Settings categories: new order, new names, one new icon

`SettingsCategory` in `Sources/relay-runner/Settings/SettingsWindow.swift` lists the sidebar categories. Change what the user sees:

| Order | Title shown | Case (unchanged) | Icon |
|---|---|---|---|
| 1 | General | `.general` | `settings` (unchanged) |
| 2 | Permissions | `.permissions` | `shield-check` (unchanged) |
| 3 | Hearing | `.speechToText` (was "Speech-to-Text") | `mic` (unchanged) |
| 4 | Speech | `.textToSpeech` (was "Text-to-Speech") | `volume-2` (unchanged) |
| 5 | Sight | `.awareness` (was "Awareness") | Lucide `laptop-minimal` (was `eye`) |
| 6 | Relay Remote | `.relayRemote` | `smartphone` (unchanged) |

- The sidebar, keyboard up/down movement and the skeleton loader follow the new order.
- Settings opens on the first category, General, when no category was requested (it opened on Permissions only because that was first). A requested category (`requestedSettingsCategory`, onboarding, `navigate`) still wins.
- `laptop-minimal` is not bundled yet. Add it to `ICONS` in `scripts/generate-lucide-icons.py` and re-run the script as its header describes; do not edit `LucideIcons.generated.swift` by hand.
- Update each renamed category's hover descriptor (`hoverAction`) and accessibility label to the new name.
- Keep identifiers stable: the enum cases and raw values, config keys (`stt`, `tts`, `awareness`), and the Relay App `navigate` `settings_page` values (`speech_to_text`, `text_to_speech`, `awareness`, ...) do not change. Where a tool description or doc lists those values, say which page each one opens by its new name.
- Find other user-facing text that names a renamed page (for example "Settings > Speech-to-Text" in app strings, onboarding, instructions under `services/instructions/` and docs) and update it to the new name. Regenerate any generated instruction files the way the repo does it. Do not rename section headings inside the pages (for example "Particle Field" stays) or the "Speech-to-Text model" row on the Permissions page, which names the model.

### 2. Agent cards: a state line and a short description

Today each agent card (`SettingsAgentCard.swift`) shows one centred line under its orb: what the agent last said it was working on (`set_working_on`, up to 60 characters), or "Last worked on <project>". Replace that line with a two-line block:

- **Line 1, the state**, fixed text chosen by the app, never by the agent:
  - "Currently working on" when the agent is running and it set its description during its current running session;
  - "Last worked on" otherwise (the agent is not running, or it is running but the stored description is from an earlier session, or only its last project is known).
- **Line 2, the description**: what the agent said it is working on; if it never said, its last project's name; if neither exists, the card shows no block at all.

Layout and style:

- The block sits at the bottom-left of the card. Its leading edge lines up with the agent name's leading edge, and its distance from the card's bottom edge equals that same leading inset. It keeps the same inset on the trailing side.
- Both lines are left-aligned, the caption size the current line uses, one line each with tail truncation, 2 pt apart. Line 1 uses the secondary text colour; line 2 uses the primary text colour.
- The orb must not overlap the block: keep the orb centred and shrink its reserve if a small card needs it. The name and Work style picker at the top are unchanged.
- VoiceOver reads the state and description as part of the card.

The description becomes much shorter, two to four words:

- Change the agent instruction (`SessionAgent.workDescriptionInstruction`) and the `set_working_on` tool description (`Sources/relay-app-mcp/AppTools.swift`) to ask for two to four words naming the work, with an example such as "Settings dropdown dividers", and to say the card already shows "Currently working on" above it, so the description should not repeat that or start with a verb like "Working on".
- `set_working_on` refuses a description of more than four words or more than 40 characters, with a message telling the agent to shorten it. Fewer than two words is accepted.
- A longer description stored by an earlier version still displays, truncated to one line.
- Update `docs/specs/relay-app.md` and any other doc or generated instruction that states the 60-character rule.

How the app knows a description belongs to the current session is the worker's choice (for example recording when it was set and comparing with when the agent's session started). Keep the decision in a pure function so it can be tested.
