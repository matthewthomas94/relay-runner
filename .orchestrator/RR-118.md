## Description

The Program Board is showing the workspace folder itself as a project. In the observed UI, the project list includes:

- `dev` with path `/Users/matthewthomas/dev`

That path is the workspace root containing child git repos, not an active project board. Program Board should list only real child projects and should not create or display a parent workspace root as a project card.

Investigate the project registration/indexing path that feeds Program Board summary rows. Keep the workspace-root behavior consistent with Relay Runner's intended model:

- workspace folders with child git repos open the read-only Program Board,
- single git repos open their local project board,
- non-git parent workspace roots should not become `.orchestrator/` projects or summary cards.

## Acceptance criteria

- [ ] Program Board no longer shows `/Users/matthewthomas/dev` or other workspace roots as project cards when they are only containers for child repos.
- [ ] Child git repos under a workspace root still appear as projects with their normal ticket counts and provider labels.
- [ ] The project count in the Program Board header excludes workspace roots.
- [ ] Existing single-repo project activation still shows that repo as the project.
- [ ] Add or update tests covering workspace-root summary filtering and single-repo preservation.
