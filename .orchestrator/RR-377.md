## Description

Automatically generate a descriptive title and concise summary for each saved Relay Runner note using the configured Codex or Claude CLI in an isolated, noninteractive one-shot subprocess. Trigger background work after a new note is durably saved, relevant transcript/content changes are saved, and Stop durably publishes its final transcript. Saving and Stop must not wait for generation. Present the title and summary on the existing Backlog note card and note detail, and persist both in the same project-owned Git-backed Markdown note through the canonical artifact writer.

This is the user's new automatic-title-and-summary decision, superseding the first cut's exclusion of automatic generation. It does not revive canceled RR-369. Notes keep their stable unpadded PREFIX-N IDs, immutable artifact identities, raw transcript, existing document type, and nondispatchable behavior. No new Notes column, app, foreground Relay session, interactive provider terminal, messenger, or work-ticket worker is involved in runtime generation.

## Provider commands and evidence

Verified against installed CLI help on 2026-09-22 and official documentation:

- Codex uses `codex exec`, not `codex -x`. `--output-schema <FILE>` constrains the final response; `--output-last-message <FILE>` captures it. `--ephemeral` avoids retained session files. Reuse configured authentication. Reference: https://learn.chatgpt.com/docs/non-interactive-mode
- Claude uses `claude -p` / `--print`, with `--output-format json --json-schema <schema>`; parse the `structured_output` field. Installed help also exposes `--no-session-persistence`, `--tools` and `--strict-mcp-config`. Reference: https://code.claude.com/docs/en/headless
- Reconfirm supported flags for the resolved binaries during implementation. Isolate from project instructions, inherited MCP servers and tool execution; do not enable file, shell, network research or other agent actions for this text transformation. Use supported provider controls and verify isolation. Do not use Claude `--bare` blindly: its authentication behavior differs from normal OAuth/keychain discovery. Preserve configured auth without logging credentials or launching login UI automatically.
- These are provider-backed generation calls, distinct from on-device recording/STT. Only the selected note's necessary text is supplied to the configured provider; no repository sweep or automatic injection of other notes. No live generation was performed while authoring this ticket.

## Acceptance criteria

- [ ] A saved nonempty synthetic note receives both a useful descriptive title and a concise summary on its existing card/detail without Start Session. An app-owned prompt identifies the input as Relay-captured notes and requests faithful, grounded output without invented decisions, owners or facts. Instruction-like note content remains data and cannot invoke tools or change behavior.
- [ ] Both configured providers execute via noninteractive one-shot CLI processes and return validated structured strings for title and summary. Validate shape, types, size and nonempty meaningful output in the app even when a provider supports JSON Schema. No foreground session, terminal, messenger, ticket dispatch or command execution is created by generating metadata.
- [ ] Successful new-note save, relevant content save and final durable Stop publication schedule generation asynchronously. Frequent checkpoints coalesce; only one current request per note is active, newer content gets a bounded follow-up, and save plus Stop with identical source content does not duplicate completed work. Metadata-only writes cannot retrigger generation.
- [ ] Persist the source-content revision/hash and generation provenance with the derived fields. Before publishing, compare current note identity and source revision atomically through the canonical writer; discard stale output after newer content, deletion or archival. Metadata writes and concurrent transcript checkpoints preserve each other's data. User-authored title/summary changes, if supported, are explicitly distinguished and not silently overwritten; preserve existing editing conventions.
- [ ] Empty/whitespace-only notes make no provider call and retain the existing deterministic note-label fallback with no fabricated summary. Short but meaningful content is supported. Inputs beyond supported limits produce a visible recoverable state rather than silent truncation presented as a complete summary.
- [ ] Missing CLI, unavailable auth, provider errors, timeout, cancellation or malformed output preserve the transcript and any last valid metadata. Show an unobtrusive generation failure/pending state in existing note UI and an explicit retry action using the latest durable content. Never report recording/save failure merely because generation failed, and never block Stop or ongoing capture on provider availability.
- [ ] Raw segments, note ID/artifact ID, recording state, capture timing and document type remain intact. Derived fields survive reload and canonical Git sync and are readable by ordinary project-note APIs without making notes dispatchable. Older notes remain readable without migration data loss.
- [ ] Add focused deterministic tests for both command adapters and structured parsing, trigger coalescing, identical save/Stop deduplication, final-tail inclusion after successful Stop, out-of-order results, concurrent checkpoint/metadata publication, manual-edit preservation, empty/oversize inputs, failure/retry and prompt-injection-like content. Use synthetic fixtures only.
- [ ] Separately record installed-app evidence for card/detail updates and responsive save/Stop without a foreground session, plus real noninteractive Codex and Claude synthetic-fixture generation with configured auth. Source tests, installed UI, live provider output and actual remote persistence are separate evidence. If a provider or installed check cannot run, retain the exact named verification blocker; the prior first-cut Claude waiver does not apply to this ticket.
