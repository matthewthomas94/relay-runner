## Description

Fix app-owned voice delivery in the integrated terminal. After RR-162, Codex and the bridge start successfully, but SwiftTerm terminal-protocol replies emitted during TUI startup flow through the same delegate as keyboard input. `RelayTerminalInputTracker` counts printable bytes inside those escape sequences as unsubmitted user text, so `/tmp/voice_cmd_ready` remains queued forever while the heartbeat misleadingly stays healthy.

Distinguish terminal-emulator response traffic from actual user-originated PTY input before updating the partial-prompt tracker. Preserve protection for genuinely typed or pasted prompts, normal return/backspace/clear behavior, app-owned command injection, and Codex/Claude parity.

## Acceptance criteria

- [ ] Terminal-protocol replies generated during Codex or Claude TUI startup do not mark the prompt as partially typed.
- [ ] Real typed and pasted prompt text still defers voice-command delivery until it is submitted or cleared.
- [ ] A voice turn in a live integrated session is claimed and submitted to the foreground provider.
- [ ] The app heartbeat and delivery claim accurately reflect a usable foreground consumer.
- [ ] Focused regression tests, the full Swift suite, Python tests, and a signed installed-app smoke test pass.
