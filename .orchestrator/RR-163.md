## Description

Finish the app-owned integrated-terminal architecture so it behaves like a normal interactive Codex or Claude terminal and remains the authoritative Relay orchestrator.

Bridge startup and ready-file claiming now work, but the claimed voice text is sent as one `text + carriage-return` PTY write. The live Codex 0.144.5 session rendered the command in its multiline composer with the blue cursor still active, never started a provider turn, and therefore produced no model response, reasoning summary, tool call, or requested screen action. The independent tool-free messenger still spoke, making the session sound responsive even though the authoritative foreground agent had not executed anything. Deliver prompt text and the submit key as distinct terminal events with enough separation that each provider interprets the second event as Submit rather than pasted content.

App-owned sessions also launch the provider with no Relay foreground instructions because RR-162 removed the blocking `relay-bridge` bootstrap prompt entirely. Add provider-native developer/system instructions for app-owned sessions only. They must preserve the foreground PM/orchestrator command-action contract, newest-intent metadata, public reasoning/lifecycle trace mirroring, authoritative final-reply routing, Relay Actions/Vision usage, and typed-turn behavior without launching a foreground polling loop or exposing setup prose in the composer. Use equivalent Codex and Claude mechanisms and keep provider-specific flags contained in launch generation.

Finally, close the gap between SwiftTerm defaults and expected macOS terminal editing. Option-Left/Right must navigate by word and Command-Left/Right must navigate to line boundaries in both Codex and Claude TUIs without corrupting the partial-prompt tracker. Preserve native copy/paste, selection, Return, Backspace, Control-U/C, terminal-protocol replies, and provider-negotiated Kitty input.
