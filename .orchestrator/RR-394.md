## Description

Relay Runner is moving from one session at a time to at most one running session per project, each in its own Workspace terminal tab (tabs UI is RR-395). This ticket is the model and launch layer, implementing slices A and B of the RR-393 spike report (read it: `git show refs/heads/relay/artifacts:.orchestrator/RR-393.md`, section `## Spike report`).

Today `AppState` owns a single `EmbeddedTerminalSession` (`Sources/relay-runner/App/AppState.swift` ~239/242) and a single `activeContext`. `newSession` (~2022) saves the old context, kills the bridge, ends the terminal and relaunches in the target project (~2128–2134). `endSession()` (~1163) ends the single session. `AssistantSessionStore` (`Process/AssistantSessionStore.swift`) already keys `Binding` per context (`project:<id>`) but has one `activeContext`; `select()` marks the previous context saved.

### Session model (AppState)
- `AppState` holds a map of context id → `EmbeddedTerminalSession`, plus `focusedContextID` (or `focusedSessionKey`).
- `newSession(for:)` starts a session for a context with none; if that context already has a live session it only focuses it (never a second process).
- `endSession(context:)` stops only that context's session, its PTY and its spool; other sessions keep running. No global `pkill -f voice_bridge.py` on per-session stop — limit `killBridge`/global stop to app quit or the last session ending.
- Remove the stop-old/start-new replacement path (`requestContextSelection` → `newSession` replacement, `pendingContextSelection` replacement semantics). Keep any queueing still needed for continuation forwarding; RR-397 reworks continuation semantics.
- `AssistantSessionStore` tracks running/saved lifecycle per binding; no single `activeContext` that implies the others are stopped.
- A process that exits or fails marks only its own context not running.
- Soft cap of 4 concurrent sessions: starting a fifth is refused with a user-visible message naming the cap.

### Per-session voice spool (spike slice A)
- Add a `VoiceSessionSpool` (Swift, and the matching Python path resolution where Python reads these files) giving each session a directory keyed by a stable session key (e.g. its transport/app session id). Move into it: `voice_cmd_ready` + `.meta`, `voice_cmd_claimed.json`, `voice_cmd_manual_ack.json`, `voice_command_state.json`, `voice_command_authorizations.json`, `voice_provider_session_id`, `relay_terminal_manual_submission.json`, `relay_terminal_delivery_events.jsonl`, the bridge launcher `.command`.
- `prepareNewSession` / `launchScript` export `RELAY_SESSION_KEY`, `VOICE_CMD_FILE`, `VOICE_COMMAND_STATE_FILE`, `VOICE_COMMAND_CLAIM_FILE`, `VOICE_COMMAND_AUTHORIZATION_FILE`, `VOICE_MANUAL_CLAIM_ACK_FILE` into the agent and MCP env. Use the env names the Python side already honours (`services/voice_bridge.py` ~369–407, `services/relay_reply.py` ~17–19); add overrides where a path is still fixed.
- Shared resources stay shared: `voice_in.fifo`, `voice_bridge.sock`, `tts_in.fifo`, `tts_control.sock`, `voice_state.sock`, the daemon and its port.

### Per-tab delivery (spike slice B)
- Each `EmbeddedTerminalSession` builds its own `RelayVoiceCommandDelivery` from its spool `Paths` (the struct is already injectable, `Terminal/EmbeddedTerminal.swift` ~1053–1070) and writes only to its own PTY. This removes the `moveItem` claim race on the single global ready file — a terminal can only claim commands from its own spool.
- The bridge still targets one provider session at a time; publish voice commands into the spool of the session the bridge currently targets (the focused one at launch). Live bridge re-targeting on focus change (`__FOCUS__`), session-scoped intent inbox, reply route-or-badge, messenger partitions and per-session daemon/MCP authorization are **out of scope** — they are follow-up tickets from the spike. Don't regress single-session voice.

`.externalTerminal` launch destination has no production caller; leave it alone unless it blocks the refactor.

## Acceptance criteria

- [ ] With sessions in projects A and B, starting or focusing B does not end A's process (unit test on AppState with a fake terminal session).
- [ ] `newSession` for a context that already has a live session creates no second process.
- [ ] `endSession(context: A)` ends only A; B's phase stays running, and no global bridge pkill runs.
- [ ] A session process exiting on its own marks only its context not running.
- [ ] A fifth concurrent start is refused with a message; four succeed.
- [ ] Per-context bindings persist and resume correctly across app relaunch for both Codex and Claude.
- [ ] Each session gets its own spool directory and env exports; two sessions' `RelayVoiceCommandDelivery` instances never claim each other's command (test with two injected spools).
- [ ] With a single session, voice commands still flow end to end exactly as before (existing voice delivery tests pass).
- [ ] Existing AppState launch tests pass or are updated to the new semantics; `swift build` and the relevant `swift test` filters pass.
