## Description

`AppState` owns a single `EmbeddedTerminalSession` (`Sources/relay-runner/AppState.swift:239`). `newSession` (~2022) saves the old context, kills the bridge, ends the terminal and relaunches in the target project (~2128–2134). `endSession()` (~1163) ends the single session.

Change the model to at most one running session per project context:
- `AppState` holds a map of context id → `EmbeddedTerminalSession`, plus a `focusedContextID`.
- `newSession(for:)` starts a session for a context with none; if that context already has a live session it only focuses it (never a second one).
- `endSession(context:)` stops only that context's session and its binding; other sessions keep running.
- Remove the stop-old/start-new replacement path (`requestContextSelection` → `newSession` replacement, `pendingContextSelection` replacement semantics), keeping any queueing that is still needed for continuation forwarding (see RR-397).
- `AssistantSessionStore` tracks the active binding per context, not a single `activeContext`; lifecycle (`.saved`, running) is per binding.
- A process that exits or fails marks only its own context not running.
- Enforce a soft cap of 4 concurrent sessions: starting a fifth is refused with a user-visible message naming the cap.
- Wire the voice pipeline to the focused session following the RR-393 report's recommended design.

The `.externalTerminal` launch destination has no production caller; leave it alone unless it blocks the refactor.

## Acceptance criteria

- [ ] With sessions in projects A and B, starting or focusing B does not end A's process (unit test on AppState with a fake terminal session).
- [ ] `newSession` for a context that already has a live session creates no second process.
- [ ] `endSession(context: A)` ends only A; B's phase stays running.
- [ ] A session process exiting on its own marks only its context not running.
- [ ] A fifth concurrent start is refused with a message; four succeed.
- [ ] Per-context bindings persist and resume correctly across app relaunch for both Codex and Claude.
- [ ] Voice input reaches only the focused session's PTY, per the RR-393 design.
- [ ] Existing AppState launch tests pass or are updated to the new semantics.
