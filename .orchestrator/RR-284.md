## Description

Implement RR-273 delivery phase 4 from RR-270's `Synchronization state machine`. Add explicit selection of an existing remote or Local only, exact artifact-ref fetch, validation of project identity, rebase of unpublished Relay-only commits, normal fast-forward push, bounded retry with jitter, and durable local-ahead/conflict states. Never infer or silently modify a remote and never fetch or publish ordinary source commits as part of artifact synchronization.

Handle clean, ahead, behind, unrelated-ticket rebase, same-ticket conflict, delete/edit, attachment collision, config/display-ID collision, push race, offline, authentication, missing/protected/foreign ref, and retry idempotency. Conflict resolution is explicit and three-way; force push, history rewrite, and choosing a winner without evidence are prohibited.

Synchronization remains per-project opt-in and fully functional in `local_only` mode.

## Acceptance criteria

- [ ] Project setup requires explicit existing-remote selection or Local only; Relay never creates, renames, or changes a remote silently and verifies project identity before adopting an artifact ref.
- [ ] Sync fetches only the configured artifact ref, rebases only unpublished Relay-owned commits, and publishes only through a normal fast-forward push with no force, force-with-lease, destructive reset, or source-ref path.
- [ ] State transitions distinguish local-only, clean, ahead, behind, syncing, retryable offline/auth failure, protected/missing/foreign ref, local-ahead fail-closed, and explicit conflict resolution.
- [ ] Event IDs and CAS make retries idempotent across crashes and push races; bounded retry never loops indefinitely or duplicates an artifact event.
- [ ] Two-device fixtures cover unrelated-ticket automatic rebase and same-ticket/config/display-ID/attachment/delete-edit conflicts with deterministic three-way evidence and user-visible recovery steps.
- [ ] Source-isolation assertions prove sync does not alter source HEAD, source refs, index, worktree, staged/unstaged/untracked files, remotes, or ordinary local-ahead commits.
- [ ] Offline use can continue committing locally, and reconnect either fast-forwards safely, rebases Relay-only commits, or stops in an explicit recoverable conflict without data loss.
- [ ] Codex and Claude surface equivalent sync/conflict outcomes and cannot bypass the confirmed project/remote scope contract.
- [ ] Documentation links implementation and rejection cases to RR-270 phase 4, including the absolute no-force-push and no-source-publication invariants.

## Rollback boundary

Switching a project to `local_only` stops network synchronization without discarding unpublished artifact commits or changing remote/source configuration. Rollback retains conflict evidence and never rewrites local or remote history.

## Verification plan

Use disposable bare remotes and two independent clones to script every RR-270 sync matrix case, including injected network/auth/push-race failures. Assert both artifact results and unchanged source refs/index/worktrees after each transition.
