## Description

Design a worker-task preview that appears when the user hovers the working glyph. The notch should extend downward and reveal a compact preview of up to five active worker tasks, giving the user a useful overview without opening the Workspace.

This is a design-only ticket. Do not change Relay Runner source code, implement the interaction, or infer production geometry before the visual and interaction design is reviewed and approved. Produce a reviewable design artifact in Figma or an equivalent format, link or attach it to this ticket, and capture the decisions needed for a separate implementation ticket.

Build on the existing glyph-hover behavior, which expands the notch to expose one reasoning or worker-activity label. Define how the new downward expansion coexists with foreground reasoning, lifecycle messages, and the current compact glyph state. The design must specify which workers appear, their order, the minimum useful information per task, overflow behavior beyond five tasks, and the empty/stale/loading states. It must also cover pointer travel between the glyph and expanded surface without recreating prior hover jitter.

Preserve the notch as a lightweight peripheral surface rather than a second Workspace. Do not add worker controls, ticket mutation, dispatch, cancellation, scrolling, or deep ticket detail unless the approved design explicitly establishes a later requirement. Keep private prompts, hidden reasoning, raw logs, and terminal content out of the preview.

## Acceptance criteria

- [ ] A reviewable visual and interaction design shows the compact glyph, hover entry, downward expansion, populated preview, pointer exit, and contraction states at production-representative dimensions.
- [ ] The expanded notch previews at most five active worker tasks and specifies deterministic selection and ordering when more than five are active.
- [ ] Each task row has a defined information hierarchy using only public worker context, such as ticket id/title, concise activity, lifecycle state, and provider/model when useful; raw logs, prompts, hidden reasoning, and terminal content are excluded.
- [ ] The design defines empty, loading, stale, stalled, failed, awaiting-review, and overflow states without turning the preview into a full board or ticket editor.
- [ ] Foreground reasoning and lifecycle messages have an explicit precedence or coexistence rule so worker preview content cannot obscure a more important current response.
- [ ] Hover geometry includes a continuous pointer-safe region from the glyph into the expanded surface and a deterministic dismissal rule that avoids dead zones, flicker, and repeated expand/collapse oscillation.
- [ ] Motion specifications include expansion, contraction, row appearance, interruption, and rapid worker-list updates, with concrete timing/easing guidance and a Reduce Motion treatment.
- [ ] The design covers notched and non-notched Macs, multi-display placement, constrained widths, VoiceOver reading order, keyboard/accessibility discovery, text truncation, and Dynamic Type or equivalent legibility constraints where applicable.
- [ ] The design identifies the minimum public worker data contract required from the existing run/activity pipeline and calls out any missing fields without implementing them.
- [ ] The artifact is linked or attached to RR-303, reviewed with the user, and records approval or requested revisions. Any production implementation remains a separate follow-up ticket and is not started from this ticket.
