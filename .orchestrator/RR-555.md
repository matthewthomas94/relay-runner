## Description

Relay Remote (the iPhone app) connects to the Mac over SSH. Away from home it can only reach the Mac through the Mac's Tailscale address (`100.64.0.0/10`), so Tailscale now matters for Relay Remote. Today Relay Runner never mentions it. The user asked for a guided Tailscale setup as a step of setting up Relay Remote, so a new user can get Tailscale installed, signed in and starting at login without leaving Relay Runner to find it.

Tailscale cannot be installed silently: its installer needs the admin password, macOS asks the user to allow its network extension, and the user must sign in to a Tailscale account. Do **not** bundle Tailscale's app or installer inside Relay Runner. Download the official package from Tailscale at the moment the user asks for it.

**Mac: a "Tailscale" section in Settings > Relay Remote** (`Sources/relay-runner/Settings/RelayRemoteSettingsTab.swift`). Place it after "Remote Login", built like the Remote Login row: a `SettingsRow` with a title, a description and action buttons, using the existing `SettingsSection`, `SettingsRowLabel`, `SettingsActionButton`, `RelaySwap` and `RelayMotion` styles. Put the state logic in a small testable presentation type, as `RelayRemoteLoginPresentation` does for Remote Login. The states are:

1. **Not installed.** No Tailscale app found. Look for one with bundle id `io.tailscale.ipn.macsys` (the standalone app) or `io.tailscale.ipn.macos` (the Mac App Store app), using `NSWorkspace.urlForApplication(withBundleIdentifier:)`.
   - The description says Relay Remote needs Tailscale to reach this Mac away from home.
   - The button is **Install Tailscale**. It downloads `https://pkgs.tailscale.com/stable/Tailscale-latest-macos.pkg` to a temporary folder and shows progress in the row.
   - Before opening the file, check it with `pkgutil --check-signature`. It must be signed by Developer ID Installer with Tailscale's team id `W5364U7YZB`. That is the team id on the installed Tailscale app (checked 2026-11-28; at that time the latest link pointed to 1.104.7, about 22 MB).
   - If the check passes, open the package with `NSWorkspace` so macOS Installer runs it. If it fails, delete the file and show an error. Never run `installer` with admin rights yourself.
   - The row also has a secondary **Download from Tailscale** link to `https://tailscale.com/download/mac` as a fallback.
2. **Installed but not running.** Button **Open Tailscale**.
3. **Running but not connected.** No interface holds a Tailscale address; reuse the detection in `RelayRemoteHost.interfaceAddresses()` and `isIPv4Tailscale`. The description says to sign in to Tailscale from its menu bar icon. Button **Open Tailscale**.
4. **Connected.** Show the Mac's Tailscale IPv4 address, plus **Start Tailscale at login** with its state.
   - If Tailscale is not a login item, the button **Start at Login** adds `/Applications/Tailscale.app` (or wherever it is installed) as a hidden login item.
   - The proven route on this Mac is System Events: `tell application "System Events" to make login item at end with properties {path:..., hidden:true}`. It works, and reading `name of every login item` confirms it. This needs an `NSAppleEventsUsageDescription` in the root `Info.plist`, which is missing today, and macOS shows a one-time Automation prompt.
   - If you find a supported API that does not need Automation, use it and record why in the run log.
   - If the user denies Automation, show a short message and a button that opens System Settings > General > Login Items.

Every state has a **Check Again** button. Refresh the state when the tab appears and when the app becomes active, so it updates after the user comes back from the Installer or from Tailscale.

**Stale phone addresses.** The pairing code stores the Mac's addresses at pairing time (`RelayRemoteHost`, `ios/RelayRemoteKit/.../PairingPayload.swift`). A phone paired before Tailscale was connected therefore has no Tailscale address. When the state is Connected and a paired device was paired without a Tailscale address, show one line: "Pair <device> again so it can reach this Mac away from home." If the device records do not hold enough to tell, say so in the run log and show that line for every device paired before Tailscale was first seen connected.
- Do not add a new phone-side address refresh in this ticket.

**iPhone.** In the Relay Remote app (`ios/RelayRemote`), when a connection fails with `unreachable` (see `RemoteFailure.swift`), add a **Get Tailscale** link next to the existing message. It opens Tailscale in the App Store: `https://apps.apple.com/app/tailscale/id1470499037`. Check that id before you use it. Match the app's existing glass and button styles and add a tap haptic. Show the link only for `unreachable`.

**Out of scope:**
- embedding Tailscale (tsnet);
- replacing Tailscale with a relay server;
- changing how pairing chooses or restricts addresses;
- onboarding outside Settings > Relay Remote.

## Acceptance criteria

- [ ] Settings > Relay Remote has a Tailscale section after Remote Login, built from the existing Settings components. It shows the four states above with the titles, descriptions and buttons described, and it refreshes on appear, on app activation and on Check Again.
- [ ] The presentation type is unit tested in `tests/RelayRunnerTests/`:
  - Not installed, Installed but not running, Running but not connected, and Connected (both with and without the login item) each map to the right title, description and buttons.
  - A Tailscale IPv4 interface counts as connected and a LAN-only interface does not.
- [ ] Install Tailscale downloads the official latest package and verifies its signature (Developer ID Installer, team `W5364U7YZB`) before opening it with macOS Installer.
  - A package that fails verification is deleted and never opened.
  - The signature check is a function that takes the `pkgutil --check-signature` output (or equivalent), with tests for a good and a bad signer.
  - Nothing runs `installer` or asks for admin rights directly.
- [ ] Start at Login adds Tailscale as a hidden login item, and the Connected row then reports it as on.
  - The root `Info.plist` has an `NSAppleEventsUsageDescription` that explains it is used to add Tailscale to your login items.
  - Denied Automation shows the Login Items fallback rather than failing silently.
- [ ] The re-pair hint appears for a paired device that has no Tailscale address once Tailscale is connected, and never when Tailscale is not connected.
- [ ] The iPhone app shows Get Tailscale (verified App Store link) only on the `unreachable` failure. RelayRemoteKit tests still pass and the RelayRemote scheme builds for the simulator.
- [ ] `swift build` and the existing Relay Remote and Settings test suites pass.
- [ ] Add a short "Tailscale" note to `ios/README.md` covering the Mac setup section, the re-pair hint and the iPhone link.
- [ ] Manual checks for the user are listed in the run log, not claimed:
  - install on a Mac without Tailscale;
  - the Automation prompt;
  - reaching the Mac from the phone over cellular after re-pairing.
