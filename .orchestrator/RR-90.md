## Description

During the parent-app permission wizard, users may need to drag Terminal, Codex, Claude, or another detected parent app into a macOS privacy permission window. The current flow does not make it obvious which visible app item is the thing the user should click and drag.

Add a clear attention treatment around the app item/icon that should be dragged for the active permission step. The user described this as a glow that effectively says "grab me." Use the existing purple particle effect from the microphone UI as the background glow treatment so the onboarding affordance feels consistent with Relay Runner's current visual language. Keep the scope focused on the permission onboarding flow; the affordance should guide the drag action without adding a broader tutorial system.

Provider parity matters. Codex and Claude setup paths should receive equivalent drag guidance, with Terminal included where the permission target list requires it and detected non-default parent apps handled through the same model.

## Acceptance criteria

- [ ] When a permission step requires dragging an app into a macOS privacy window, the relevant app item/icon has a visible purple particle glow based on the existing microphone particle effect.
- [ ] The affordance targets the app or apps for the current permission step, not every app shown in the wizard.
- [ ] The affordance clears when the permission step completes, is skipped, or moves to a different target.
- [ ] Terminal.app, Codex.app, Claude.app, and detected non-default parent apps all use the same guidance behavior when they are required targets.
- [ ] The highlighted state is legible in light and dark mode and does not obscure app names, icons, existing status controls, or the drag target itself.
- [ ] Provider parity is explicit in tests or verification notes for Codex and Claude permission onboarding.
