## Description

Feedback from the user after setting Relay Runner up on a friend's laptop. Three changes. This builds on RR-513 (in-app sign-in), so start from main after RR-513 merges.

1. **Get out of the way when a step needs something outside Relay Runner.** Provider sign-in always opens the browser, and the Relay Runner workspace/onboarding surface sits on top of it. Today there's no reliable way to hide or reopen Relay Runner at that point, so the user gets stuck. Whenever onboarding (or the app generally) sends the user outside Relay Runner, hide the workspace view automatically (don't quit the app). Examples: the browser for sign-in, System Settings for a permission, Finder, or any other app. When the user comes back (the step completes, the app is reactivated, or the readiness recheck passes), show it again at the same step. Find every such hand-off (grep for `NSWorkspace.shared.open`, `open -a`, System Settings URLs and the sign-in flow) and route them through one helper so new ones get the same behaviour.
2. **Persistent Skip button.** A text button fixed in the bottom-right corner of onboarding, with an arrow icon to the right of the label. It's visible on every permissions step and every tutorial step. It skips the rest of the current part: the permissions section moves on past permissions, and the tutorial finishes. The user must still end up in a usable state (Workspace opens; skipped permissions can be granted later from Settings). Use the app's existing button component and design tokens. Persist the skip in the onboarding resume state so a relaunch doesn't return to a skipped step.
3. **Trim the sign-in step's text.** The provider sign-in step has too much copy. Keep the title and one short subtitle, the sign-in action and a "Sign in later" button, and remove everything else. Any notice that still matters (for example subscription-only) folds into the single subtitle or appears only on failure.
