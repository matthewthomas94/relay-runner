## Description

Turn the Program Board's read-only ticket cards into a useful ticket-management surface without losing the safety of project-scoped boards.

RR-57 added the first all-project ticket board with canonical Backlog, Ready, In progress, and Done lanes. The next functional slice should make each ticket card actionable enough that the user can understand and route work from the Program Board without manually hunting through child repos.

The first expected interaction is the same basic affordance the project board already has: clicking a ticket should open or focus a ticket-detail view so the user can read the ticket body, acceptance criteria, state, dependencies, and run metadata.

Keep the scope focused. Program Board actions should still resolve to the child project ticket file and daemon paths; do not create or depend on a workspace-root `.orchestrator/`.

Possible first-version actions include:

- open or focus the owning project board
- reveal/copy the child ticket id/path/branch
- inspect ticket details such as description, acceptance criteria, dependencies, active worker, and awaiting-merge state
- promote eligible backlog tickets to ready through the same project-scoped dispatch path used by project boards

Provider parity matters: Codex and Claude workers should show the same actionable metadata, with provider-specific details only where useful to identify a run.

## Acceptance criteria

- [ ] Program Board ticket cards expose clear actions for at least opening/focusing the owning project and copying or revealing the child ticket identity.
- [ ] Clicking a Program Board ticket opens or focuses the ticket details with parity to the project board's ticket detail behavior.
- [ ] A selected ticket can show enough detail to understand description, acceptance criteria, dependency/blocking state, worker run id/branch, provider, and awaiting-merge state when available.
- [ ] Any action that mutates ticket state routes through the owning child project and the existing daemon path; no parent workspace `.orchestrator/` is created.
- [ ] If promoting tickets to ready is included, the Program Board uses the same ready/dispatch semantics and stale-command guards as project boards.
- [ ] Empty, disabled, and unavailable-daemon states are explicit rather than silently doing nothing.
- [ ] Tests or deterministic view-model coverage prove all-project and project-filtered selections resolve actions to the correct child repo.
- [ ] Codex and Claude worker metadata renders consistently in the actionable ticket details.
