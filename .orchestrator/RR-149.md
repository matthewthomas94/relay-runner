## Description

Add a third **Terminal** tab to the Workspace overlay so a user can start and interact with a Relay Runner agent session without opening an external terminal application.

The v1 implementation is a dedicated session console rather than a general-purpose terminal. It starts in the selected project or configured workspace directory, runs the same setup and provider-specific Codex or Claude launch flow used by **Start Session**, and exposes the interactive process through an embedded terminal emulator. The existing external-terminal path remains available as a recovery or compatibility fallback.

The implementation must define process ownership, tab/window dismissal behavior, session recovery, terminal-emulator dependency choice, and how the project board and program workspace select the launch directory.

## Acceptance criteria

- [x] Workspace exposes a **Terminal** tab alongside **Work** and **System Settings** wherever a session can be launched.
- [x] Starting a session from the embedded tab launches the configured provider in the intended project/workspace directory and pre-fires Relay voice mode.
- [x] The embedded view supports interactive terminal input and output, resizing, scrolling, text selection, copy/paste, and standard control-key sequences.
- [x] Codex and Claude have equivalent user-visible startup, active-session, failure, and exit states.
- [x] Only one Relay voice session owns the bridge at a time; starting, ending, switching tabs, closing Workspace, and reopening Workspace have explicitly tested lifecycle behavior.
- [x] Terminal process exit is visible in the UI and permits a clean restart without reopening Relay Runner.
- [x] An external-terminal launch remains available as a compatibility fallback.
- [x] Automated tests cover tab availability/normalization, launch configuration, and process/session state transitions.
- [ ] The packaged embedded terminal is manually verified with live Codex and Claude sessions.

## Decisions

- Closing or switching away from Workspace leaves the embedded process running; **End Session**, app quit, update relaunch, and unrecoverable bridge failure terminate it.
- The tab is a dedicated Relay session console. It does not expose an idle general-purpose shell.
- **Start Session** defaults to the embedded tab. **Open in Terminal.app** is a secondary fallback and dismisses Workspace after a successful external launch.
- SwiftTerm 1.14 supplies terminal emulation and PTY hosting. Relay Runner owns process lifetime outside the SwiftUI presentation tree and uses the Core Graphics renderer.
- The embedded adapter denies terminal-initiated OSC 52 clipboard reads and writes. Explicit user selection, copy, and paste remain enabled.

## Regression acceptance

- [x] App-started Codex and Claude sessions pass an explicit app-managed marker so the installed Relay bridge skill does not reject the embedded PTY after a sandboxed process lookup.
- [x] Every live Codex discovery surface supports the current `ChatGPT.app` bundled CLI before the legacy `Codex.app` path, while preserving configured-command and `PATH` precedence where applicable.
- [x] A failed first Program Work load shows an actionable error and Retry control instead of a transparent surface.
- [x] A utility-only Workspace opened before the bridge is ready upgrades to the resolved project or Program Work surface without requiring close and reopen.
- [x] Automated tests cover both provider skill templates, daemon binary discovery, Work failure presentation, and utility-route upgrade decisions.
- [x] The release app is rebuilt, installed, and verified against a healthy orchestrator daemon and live embedded Codex bridge startup.
