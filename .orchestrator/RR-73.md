## Description

When the app is configured with a workspace folder such as
`/Users/matthewthomas/dev`, the board trigger should open the Program Board for
that workspace. In the current session, pressing the board trigger opened a
project board instead. Investigation showed:

- `general.working_directory` is `/Users/matthewthomas/dev`.
- The registry has a discovered workspace root for `/Users/matthewthomas/dev`.
- A live bridge activation from `/Users/matthewthomas/dev/relay-runner` set
  `activeProjectID` to that child repo and cleared `activeWorkspaceRootID`.
- `ProjectResolver.resolveBoardRoute()` currently lets the live bridge cwd
  route win, so a child-repo bridge can steal the board hotkey away from the
  configured workspace Program Board.

Fix the routing so the configured workspace remains the Program Board route
when the live bridge cwd is inside that configured workspace, unless the user
has explicitly activated a project. Keep single-repo bridge sessions outside a
configured workspace routing to their project board.

Relevant files/tests:

- `Sources/relay-runner/Board/ProjectResolver.swift`
- `Sources/relay-runner/Board/ProjectRegistry.swift`
- `Sources/relay-runner/Config/WorkspaceFolder.swift`
- `Sources/relay-runner/Process/ProcessManager.swift`
- `tests/RelayRunnerTests/ProjectRegistryTests.swift`
- `tests/RelayRunnerTests/ProcessManagerLaunchTests.swift`

The existing tests already cover workspace roots, parent repos with child repos,
single-project bridge sessions, and explicit parent project activation. Add the
missing regression case for a configured workspace whose live bridge cwd is a
child repo.
