## Description

Relay Runner now has four fixed agents (see RR-519): Puck (`am_puck`), Isabella (`bf_isabella`), George (`bm_george`) and Sky (`af_sky`). Up to four run in parallel. The user wants each agent to always speak in its own voice, so they can tell by ear which agent is talking. The single global voice setting goes away.

RR-519 publishes each running session's agent: the session's spool directory (`/tmp/relay-sessions/<session key>/`) holds a file `session_agent` containing the slug (`puck`, `isabella`, `george`, `sky`), and the provider process has `RELAY_SESSION_AGENT`.

### How speech works today (verify before relying on it)

- One bridge and one `relay-speech` process serve all sessions. `relay-speech` reads `[tts] voice` from config (`rust/relay-speech/src/config.rs`), and `State::selection()` in `rust/relay-speech/src/worker.rs` snapshots voice and rate per reply.
- A speak request carries the session key (`SpeechIntent.session_key`), used for playback control only. The bridge fills it from the reply envelope or, for messenger and lifecycle speech, by looking the command up in the ledger (`session_key_for_command` in `rust/relay-rs/src/bridge/speech.rs`). There is no voice field on the request (`speech_client.rs`).
- Kokoro already loads and caches a style per voice name on first use (`kokoro.rs`), and `Synthesizer::render(text, voice)` takes a voice.
- Relay Remote audio (`voice_remote` in `worker.rs`) reads `config.voice` at synthesis time.
- Settings: the "Standard Voices" section (voice picker, Preview button, preview status) in `Sources/relay-runner/Settings/TTSSettingsTab.swift`; `SettingsAgentCard` shows the configured voice name; `TtsConfig.standardVoices` / `voice` in `Config/Config.swift`, read and written by `ConfigManager`; `STANDARD_VOICES` in `rust/relay-rs/src/bridge/config.rs`, `rust/relay-speech/src/config.rs` and `rust/relay-artifacts/src/config.rs`.

### What to build

1. **Voice follows the agent.** Everything spoken on behalf of a session uses that session's agent voice: final replies, interim replies, messenger hand-offs and progress, worker lifecycle announcements, `read_out`, and the audio sent to Relay Remote. Resolve the voice per utterance from the session key, so two agents speaking in turn each use their own voice from the one shared speech process. Where the mapping lives (the bridge passing a voice on the speak request, or the speech process resolving the session key) is your choice; keep one place that maps agent to voice on the Rust side and pin it against the Swift table with a test or a shared fixture.
2. **No session, no agent.** Speech with no owning session (the tutorial, Settings previews if any remain, a manual `relay-bridge` session with no `session_agent`) uses Puck.
3. **Remove the global voice.** Delete the voice picker, its Preview button and preview status from Settings. Stop reading and writing `[tts] voice`: an existing value in a user's config is ignored and dropped on the next save, the way `custom_voice_id` is handled now. Rate, auto-play and chime stay global. The Settings agent card is replaced by four agent cards in RR-522, so do not redesign it here. If the single card still exists when you start and takes its name from `voiceName(config.tts)`, change only that: show the active agent's name from the agent definition, or Puck when no session is running.
4. **Mid-reply switches.** A reply already playing keeps the voice it started with. `reload_config` no longer needs to stop playback for a voice change.
