## Description

In a Relay voice session two model sessions answer the user: the tool-free **messenger**, which speaks quick acknowledgements and progress, and the foreground **PM**, which has the tools and does the work. The bridge hands every user turn to both.

The user sees them contradict each other. Example: the user asks "Puck, open Chrome". The messenger says it can't open Chrome, and a moment later the PM says it has opened Chrome. The messenger is right that it has no tools itself, but the user wants the two to present as **one agent**: the messenger should know that everything the user asks is passed to the PM, which can act, so from the user's point of view "I" can do it.

The messenger's instructions are in `rust/relay-rs/src/messenger/system_prompt.txt` (included as `MESSENGER_SYSTEM_PROMPT` in `rust/relay-rs/src/messenger/mod.rs`), with per-event instructions (`USER_TURN_INSTRUCTIONS`, `TRACE_INSTRUCTIONS`, `FINAL_INSTRUCTIONS`) in `rust/relay-rs/src/bridge/messenger_runtime.rs`. The prompt currently says "Never use tools, shell commands, files, apps…" without saying that the PM does those things, which is the likely cause of the refusals.

### What to change

1. Reframe the messenger's identity: the messenger and the PM are one assistant speaking with one voice and one name. The messenger never acts itself, but every request it hears also goes to its working self, which can operate the computer, open apps and files, browse the web, change code and run work. So:
   - It never says it can't do something, lacks tools, lacks access, or is "just" a voice layer.
   - For an action request ("open Chrome", "look at my screen", "make a ticket"), it gives the short `__HANDOFF__` acknowledgement naming the action ("Opening Chrome.") and does not claim the action is done until an authoritative event says so. The existing rules against claiming unconfirmed results stay.
   - It never mentions a messenger, a second session, or handing anything to someone else.
   - Keep the existing rules on __ANSWER__ / __HANDOFF__ / __SILENT__, first-person singular, and naming workers.
2. Add the same spoken-form rule as the PM's for anything the messenger itself says: be concise, and say structured text (file paths, URLs, hashes, ids, commands, code) by what it refers to, never verbatim. (A separate ticket adds the PM's rule and a deterministic speech filter; this ticket covers only the messenger's own wording.)
3. If the session's agent name (Puck, Isabella, George or Sky) is already available to the messenger's configuration, include it so the messenger answers to that name. If it isn't available without plumbing beyond the messenger, leave this out and say so in the run log.

Keep the prompt short: it runs on a fast model on every turn.

- [ ] The prompt carries the concise, spoken-form rule for structured text.
