## Description

Relay Runner runs up to four named foreground agents at once (Puck, Isabella, George, Sky). RR-525 added agent presence: the daemon records which repositories each running agent works in, and queues one-way, silent notices that reach another agent at its next turn (appended to its next voice prompt, added by the prompt-submit hook on a typed turn, and returned with presence tool results). Read RR-525's docs and code first; this ticket uses its record, queue and delivery unchanged.

RR-525 only says "George started working in relay-runner". The user wants closer coordination once two agents are in the same repository, so they do not duplicate or undo each other's work. Most of the user's work is in one repository, so two agents sharing it is the normal case. This must therefore stay cheap: notices are tied to actions that can collide, never sent on a timer, and never conversational.

Rules carried over from RR-525 and not to be weakened: notices are one-way (no replies, no acknowledgements), silent (never spoken), delivered at the receiver's next turn, and never start a turn.

### What to build

1. **Overlap.** Two running agents overlap on a repository while it is in both their presence sets. When an overlap begins, each of the two gets one notice naming the other and what is known of its work there: its declared note, and the tickets it has written or dispatched there in this session. When it ends, because one agent stopped or its entry expired, the other gets one notice.
2. **Automatic action notices while overlapping.** For an action by one agent in the shared repository, the other overlapping agents get a notice:
   - a ticket created or edited: its id and title;
   - a ticket dispatched or queued: its id;
   - a run it dispatched merging into the repository's checkout, or failing: the ticket id and the outcome. A merge matters to the others because it changes the shared branch.
   These come from daemon events and need nothing from the agent. An agent with no overlap in that repository gets none of them.
3. **Declared direct work.** Extend RR-525's declare tool, or add one beside it, so an agent states what it is about to change directly in the shared repository: a one-line description and optionally the paths. The other overlapping agents get it as a notice. The tool's result includes the caller's undelivered notices, so an agent learns of a collision at the moment it declares.
4. **Batching.** Notices for one receiver are delivered together in one block at its next turn. Several edits of the same ticket by the same agent between two deliveries collapse into one line. Keep RR-525's cap.
5. **Instructions.** Add to the foreground PM's instructions, for both providers: while it shares a repository with another agent, it declares direct work there before starting it; before it creates a ticket there, it checks the other agent's recent tickets (from the notices or the presence read tool) for the same work; and when it finds the same work or the same files in another agent's notice, it stops that piece of work, tells the user which agent has it, and asks what to do. It never negotiates with the other agent. Regenerate the generated instruction files.
6. **Docs.** Extend RR-525's documentation with overlap and action notices.
