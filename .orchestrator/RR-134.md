## Description

Audit Relay Runner's macOS permission requirements and design the next implementation step for centralizing permission requests and diagnostics through the Relay Runner app rather than leaking responsibility to Terminal, Codex, Claude, or worker subprocesses.

The work should distinguish permissions that Relay Runner can genuinely broker from permissions macOS still binds to a specific executable. The visible product should guide the user through one Relay Runner-owned experience wherever possible, and clearly explain any provider-specific limitation that cannot be centralized.

## Acceptance criteria

- [x] Current permission needs are documented for voice capture, TTS/playback controls, screen observation, screen manipulation, app automation, subprocess launch, and worker execution.
- [x] Each permission is classified as Relay Runner-brokerable, helper-process-brokerable, provider-specific, or unavoidable per-binary macOS state.
- [x] A proposed implementation path covers both Codex and Claude sessions with equivalent user experience where macOS allows it.
- [x] The plan includes the user-facing diagnostics or settings surface needed to show missing permissions and recovery steps.
- [x] The ticket or resulting implementation avoids exposing raw Relay transcripts in visible ticket prose or logs.
