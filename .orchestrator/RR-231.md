## Description

Restore direct ticket-card dragging in the Program Workspace. Eligible cards
can currently be opened with a click, but a deliberate drag does not visibly
begin, identify a destination lane, or move the ticket between Backlog,
Queued, In progress, and Done.

Program Workspace lane movement was added in RR-64 and RR-81, and its mover
and drop-policy tests still exercise the underlying status transition
programmatically. Reproduce the failure through the current mounted
`ProgramWorkColumnPanel` and `DraggableProgramWorkCard` hierarchy inside
`BoardOverlayScrollView`, then fix the smallest responsible gesture or event
routing issue. Treat the AppKit-backed scrolling layer and the card's
tap/edit interactions as likely interaction points, not as a predetermined
root cause.

Preserve the distinction between an eligible card whose drag gesture is
broken and a card intentionally locked by existing policy because an agent
owns it or it is awaiting merge. Do not loosen transition, dependency, or
dispatch rules to make the gesture appear to work.

## Acceptance criteria

- [ ] Add a regression test that fails on current `main` and exercises the
      actual card gesture/event path in the mounted Program Workspace lane and
      scroll hierarchy, rather than invoking the view model's drop methods
      directly.
- [ ] A deliberate pointer drag on an eligible card starts after the intended
      movement threshold and shows the existing source-card, drag-preview, and
      destination-lane feedback.
- [ ] Dropping an eligible card in a valid lane updates the ticket in its
      owning child repository; dropping it in Queued follows the existing
      board auto-dispatch path.
- [ ] Dragging works in both all-project and selected-project views, across
      short and long lanes, and after the lane has been scrolled.
- [ ] Vertical scrolling remains usable and does not accidentally start a
      card drag; a deliberate card drag is not consumed by the scroll view.
- [ ] Clicking a card still opens it, the Edit control still works, and
      neither interaction causes an accidental move.
- [ ] Tickets with an active worker or awaiting-merge state remain
      non-draggable and retain a clear disabled affordance.
- [ ] Invalid, canceled, dependency-blocked, and no-op drops leave the ticket
      unchanged and surface the existing failure feedback.
- [ ] Project Workspace card dragging and scrolling are not regressed.
- [ ] Focused Swift tests and the full relevant Swift and Python test suites
      pass.
- [ ] Verify the fix manually in a freshly built Relay Runner app using real
      pointer drags between each available Program Workspace lane.
