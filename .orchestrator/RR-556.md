## Description

The user likes the chat interface in the Relay Remote iPhone app (`ios/RelayRemote/Agents`: `AgentChatFeed`, `AgentDock`, `ChatStore`, RR-540 and RR-554). They want the same kind of chat on the Mac, as a friendlier alternative to the raw terminal (TUI) in the Workspace terminal panel. Each agent's panel gets two modes:

- **GUI (chat):** the default.
- **TUI (terminal):** today's embedded SwiftTerm terminal, unchanged. It stays available for anything the chat cannot do.

### The mode switch: a tab on the far right of the tab strip

The user chose where it goes. Do not try to draw it inside Claude Code's own prompt box. Claude Code and Codex draw that box themselves inside the terminal, and its position moves.

- **Where:** the Workspace terminal tab strip (`Sources/relay-runner/Terminal/WorkspaceTerminalSurface.swift`) lists the agent tabs and the "+" button, followed by a `Spacer`. Add the switch on the **far right** of that strip.
- **How it looks:** a segmented **GUI | TUI** control inside a tab that is always raised. It uses the same shape and height as the agent tabs and flows into the panel with the same rounded shoulders.
  - `WorkspaceTerminalOutline` currently draws one raised tab (the selected agent's). It must also draw this right-hand tab, and keep the selected agent's tab morph unchanged.
  - Animate the outline and the segment with the existing `RelayMotion` / `.relayControlSwap` styles. Respect Reduce Motion.
- **What it does:** switches the selected agent's panel between chat and terminal. The choice is remembered per agent across relaunches, and GUI is the default.
- **Keyboard:** add a shortcut that does not clash with the existing Command-T or the agent-switch shortcuts, and note it in the run log.

### The chat view

Build it as a native Mac SwiftUI view that sits in the panel where the terminal does. It reuses the structure of the iPhone chat but is designed for a large, resizable window:

- Message bubbles have a comfortable maximum line width. On wide windows they should not stretch edge to edge.
- It uses the Mac's glass and motion styles (`BoardDarkSurfaceStyle`, `PanelGlassUnderlay`, `RelayMotion`) and the app's typography (`AppTypography`).
- The window resizes smoothly.
- New messages scroll into view unless the user has scrolled up. When they have, a "jump to latest" control appears.

**What the chat shows:**
- **The user's turns:** text typed in the chat, voice turns, and turns typed from Relay Remote, each marked with its source the way the iPhone marks it. Include turns typed directly into the TUI if the session can recover them without a provider-specific transcript scraper. If it cannot, say so in the run log and leave them out.
- **The agent's replies:** show the **full final provider message** for each turn, not only the short spoken version the iPhone shows. Render Markdown: headings, lists, bold, inline code, code blocks and links. Paths and URLs should be clickable or copyable.
  - Relay already records this message at turn Stop through the completion hook (`ProcessManager.swift`, `relay-rs` completion hook) and the reply helper.
  - Reuse that record so the chat works the same for Claude and Codex. If only the spoken text is available for some turn, show that.
- **Progress:** while the agent is working, show a compact working indicator. Show the public progress lines (lifecycle and reasoning-summary traces the bridge already carries) as quiet status rows, like the iPhone's `status` rows. Never show hidden reasoning or raw tool output.
- **Status rows:** for things like a ticket being created or a worker being dispatched, where Relay already emits them.
- **Long press or right-click** copies a message, as on the iPhone.

**Input bar at the bottom:**
- a multi-line text field: Return sends, Shift-Return adds a new line;
- the attach button for files and images, with the same behaviour as the iPhone's attachments;
- a Stop or Cancel control while a turn is running, using the existing interrupt path.
- **Sending:** a message goes into the session through the **same path a Relay Remote typed message uses**, not by typing bytes into the terminal. Ordering, claims, the messenger and replies then behave exactly as they do for phone turns. If that path cannot carry a Mac-local message, use the existing PTY submission path (`EmbeddedTerminal` `PendingSubmission`) and explain why in the run log.

**History:** the chat restores each agent's recent history after a relaunch, with the same limit as the iPhone's `ChatStore` (newest 200).

### When only the terminal can answer

Some states can only be answered in the TUI:
- a permission or approval prompt;
- a provider multiple-choice question;
- a slash-command menu or picker;
- sign-in or login;
- a crashed or stopped provider.

When the session is in one of these, the chat shows a clear banner such as "Puck needs you in the terminal" with a **Switch to Terminal** button. Detect these states from signals Relay already has, such as the existing prompt and stall detection in `EmbeddedTerminal.swift` and `PromptSelection.swift`. Do not detect them by regex over arbitrary screen text unless that is already the mechanism. Never switch mode automatically while the user is typing in the chat.

### Provider parity

The chat must work for both Claude and Codex sessions. Record any difference in the run log, for example a Codex prompt state that cannot be detected.

### Out of scope

- changing the TUI itself;
- changing the iPhone app;
- a Board or Notetaker chat;
- multi-agent group chat.

## Acceptance criteria

- [ ] The Workspace terminal tab strip has a raised **GUI | TUI** tab on its far right.
  - The panel outline flows into both that tab and the selected agent's tab.
  - Selecting an agent still morphs only the agent tab.
  - The switch changes only the selected agent's panel, is remembered per agent across relaunch, and defaults to GUI.
  - A keyboard shortcut toggles it.
- [ ] The TUI mode is today's terminal with no behaviour change. Switching back and forth keeps the same live terminal: no restart, and scrollback is kept.
- [ ] GUI mode shows the chat: user turns (chat, voice, phone), agent replies as rendered Markdown from the full final provider message, working and progress rows, and status rows. It survives a relaunch with up to 200 messages per agent.
- [ ] Sending from the chat delivers the turn to the agent and its reply appears in the chat. Attachments and Stop work. Return sends and Shift-Return adds a new line.
- [ ] A terminal-only state shows the "needs you in the terminal" banner with Switch to Terminal. It clears once the state is gone.
- [ ] Layout holds at the smallest and largest supported Workspace sizes: no clipped text and no horizontal scroll, and bubbles keep their maximum width. Reduce Motion is respected.
- [ ] Unit tests in `tests/RelayRunnerTests/` cover:
  - the mode preference (default GUI, per agent, persisted);
  - mapping session events to chat rows (user, agent and status, with the full final message preferred over spoken text);
  - Markdown rendering inputs;
  - the terminal-needed banner state machine.
- [ ] `swift build` and the existing terminal, Workspace and session test suites pass.
- [ ] The run log has screenshots of GUI mode, TUI mode and the banner. It also lists the provider differences and anything left for the user to check by hand, such as a live Codex session.
