## Description

Fix the real drag gesture on the onboarding permission companion. The companion
appears beside macOS Privacy & Security and its tutorial animation demonstrates
dragging Relay Runner into the permission list, but pressing and dragging the
visible app icon does not produce a moving drag image or start an observable
file drag. The user therefore cannot add Relay Runner through the primary
interaction the UI instructs them to use.

Polish the same interaction while correcting the live drag. The tutorial is
currently driven by a 30 Hz timer and looks visibly stepped on modern displays;
hovering the draggable icon repeatedly disturbs or restarts the demo; and the
release phase draws an unwanted green ring/plus over the destination. Drive the
animation at the display's refresh cadence with smooth interpolation, make
pointer entry/movement over the real icon stable, and remove the green drop cue.

RR-172 and RR-177 intended this icon to be a native AppKit file drag source, but
the latest RR-177 run did not rerun the manual System Settings drag smoke. The
current tests cover pasteboard representations and drag-image geometry without
proving that a gesture delivered through the live nonactivating companion panel
reaches `AppFileDragView.mouseDragged` and begins an `NSDraggingSession`. Treat
the installed-app failure as the regression authority rather than accepting the
existing unit coverage as proof that the feature works.

Reproduce the failure from an installed release build through the embedded
onboarding or permission-recovery flow, beginning with Input Monitoring. Trace
the complete route from the SwiftUI tile and `NSHostingView` through panel hit
testing, first-mouse/down/drag delivery, movement threshold, bundle URL
validation, drag-session creation, drag image, and pasteboard writer. Correct
the smallest root cause. The shared implementation must continue to serve
Accessibility, Input Monitoring, and Screen Recording.

Do not redesign the companion, replace the visual-only tutorial animation, or
change permission sequencing, onboarding layout, setup readiness, and unrelated
Settings behavior. macOS TCC approval must remain user-controlled: a successful
drop should add/accept the installed app in the active privacy pane, after which
the user can perform any required system toggle or confirmation. Preserve the
existing non-drag Finder/`+` fallback, permission polling, grant-during-drag
deferral, panel following, Reduce Motion, VoiceOver, and Codex/Claude parity.

## Acceptance criteria

- [ ] A release-build reproduction records where the live gesture currently stops: hit testing/event delivery, drag threshold, bundle validation, session creation, or System Settings drop acceptance.
- [ ] Pressing and moving from the visible Relay Runner icon in the nonactivating companion delivers one real gesture to the drag source and starts exactly one native `NSDraggingSession` after the configured movement threshold.
- [ ] A Finder-like Relay Runner drag image visibly follows the real pointer outside the companion with copy semantics; the source tile may remain in place, but the user must see an unmistakable moving drag representation.
- [ ] The live drag uses a validated installed `.app` URL and standard native file URL plus Finder-compatible file-list representations; invalid or development-only bundle locations do not silently present an enabled but inert icon.
- [ ] Dropping the installed release app into Input Monitoring adds or accepts Relay Runner in the macOS list, and the same shared source path remains valid for Accessibility and Screen Recording.
- [ ] The companion remains interactive without activating or moving its panel, stealing focus from System Settings, allowing the click-through demo overlay to intercept input, or starting duplicate sessions.
- [ ] The visual tutorial is display-synchronised rather than capped at 30 Hz, remains smooth on 60 Hz and higher-refresh displays, and uses eased continuous movement without changing the existing route or overall instructional sequence.
- [ ] Entering, moving within, and leaving the draggable app icon does not flicker, jump, restart repeatedly, reconstruct the interaction surface, or produce an event/timer storm; the demo pauses once for genuine user interaction and resumes once after the existing idle delay.
- [ ] The demo draws no green ring, plus, or other green destination cue when the hand releases the app, including in Reduce Motion mode; the hand and dragged-app ghost still communicate the drop clearly.
- [ ] Ending or canceling the drag clears drag state once, resumes follower/tutorial behavior after the existing idle policy, and preserves grant-during-drag auto-advance deferral.
- [ ] Focused regression coverage exercises the event-to-session boundary through an injectable seam or representative hosted-panel harness, rather than testing only pasteboard types and frame math, and covers timer cadence/hover debouncing plus absence of the drop cue.
- [ ] Existing payload, placement, animation, cleanup, Reduce Motion, VoiceOver, permission coordinator, and provider-parity tests continue to pass.
- [ ] The full Swift test suite and `scripts/build-dmg.sh` pass, followed by an installed-app manual smoke test against at least Input Monitoring; the exact macOS pane, gesture result, and drop result are recorded in the run log.
