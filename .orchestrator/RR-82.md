## Description

Tickets are not editable from the Program Board. Add Program Board editing parity with the project board for tickets that belong to child repos.

The Program Board should let the user open a ticket editor/detail flow, edit the title, priority, status, description, and acceptance criteria, and save back to the owning repo. It should handle all-project and filtered-project modes correctly. If the ticket file is missing, the UI should not show an editable phantom; that stale-deleted-card behavior is covered more directly by RR-85, but this ticket should avoid making it worse.

## Acceptance criteria

- [ ] A Program Board ticket can be opened for editing from its card or detail view.
- [ ] Saving edits writes only the owning child repo's `.orchestrator/<id>.md`.
- [ ] Title, priority, status, description, and acceptance criteria edits persist and refresh the Program Board view.
- [ ] All-project mode requires an owning project before creating or saving a ticket; filtered mode preselects the filtered project.
- [ ] Missing ticket files are surfaced as non-editable stale/missing entries or removed once RR-85 lands; they must not save placeholder data over a deleted ticket.
- [ ] Project Board editing is not regressed.
- [ ] Add Swift tests for Program Board edit request routing and save behavior.
- [ ] Verify with `swift test --skip-update`.
