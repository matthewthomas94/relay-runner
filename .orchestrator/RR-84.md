## Description

Tickets should be organized by most recently modified on each board. Today ordering is not matching user expectation, especially when older done tickets and recently touched backlog tickets are mixed into lanes.

Within each lane, sort tickets by the owning ticket file's last modified time descending. Use a stable fallback such as numeric ticket id descending when modified timestamps are unavailable or equal. Apply the same ordering behavior to the Project Board and Program Board.

## Acceptance criteria

- [ ] Project Board lanes sort tickets by most recently modified first.
- [ ] Program Board lanes sort tickets by most recently modified first across all projects and in filtered-project mode.
- [ ] Sorting uses the owning ticket file's modified time, not run-history timestamps alone.
- [ ] Ties are deterministic, using numeric ticket id descending or an equivalent stable rule.
- [ ] Recently edited tickets move to the top of their lane after the board refreshes.
- [ ] Add Swift tests for lane sorting in both project and program board data models.
- [ ] Verify with `swift test --skip-update`; run Python tests if daemon payloads are changed.
