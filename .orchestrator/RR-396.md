## Description

Implements the user-facing behaviour from the multi-project sessions spec.

Today, tapping a `ProgramProjectCard` (`Sources/relay-runner/Board/ProgramBoardOverlayView.swift` ~1283/1488) goes through `ProgramBoardOverlayController.selectProject` (~1066) to `AppState` (~874) `selectProjectContext(repositoryPath:, startsSession: hasActiveSession)` (~1796), which replaces the running session. The done-column button (~1689–1701) and toolbar button (~450–459) toggle Start/Stop on a single global `hasActiveSession`.

New behaviour:
- Clicking a card for a project **with** a running session focuses that project's terminal tab. Nothing is started or stopped.
- Clicking a card for a project **without** a session shows its tickets only. No tab or process is created, even if another project's session is running.
- The done-column Start session button starts a session for the shown project only, and only when that project isn't running. It stays the only way to start one.
- Stop stops only the shown project's session.
- Each card shows a status dot when its project has a running session.
- No switch button on cards.

## Acceptance criteria

- [ ] With sessions in A and B, clicking B's card focuses B's tab and A's session is still running.
- [ ] Clicking a card for a project with no session shows its tickets and creates no tab or process, while another project's session keeps running.
- [ ] Start session in a non-running project opens exactly one new tab running Relay Runner for that project.
- [ ] Start session in a project that already has a session creates no second one.
- [ ] Stop in project A stops only A; B keeps running.
- [ ] Cards with a running session show the status dot; others don't; the dot clears when that session exits.
- [ ] No switch button exists on project cards.
