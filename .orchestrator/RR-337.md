## Description

Replace the 30-day retention policy with the accepted RR-331 post-spike rule. Every nonterminal ticket remains materialized locally without a count cap. A single combined pool of tickets whose canonical status is Done or Canceled is ordered deterministically, and only its newest 25 members remain materialized. Older terminal tickets become eviction candidates; archived terminal dependencies resolve from catalog metadata without forcing local restoration. This ticket owns policy, schema, migration planning, eligibility, and focused service tests. It does not implement GitHub publication or user-interface work.

## Acceptance criteria

- [x] Retention planning always materializes every nonterminal ticket, including backlog, ready or queued, in progress, verification-blocked, awaiting-review, merge-conflict, and tickets with active worker or reviewer lifecycle state; none of these consume one of the 25 terminal slots.
- [x] Done and Canceled tickets share one terminal pool. The newest 25 across that combined pool remain materialized, using canonical activity time and an immutable deterministic tie-breaker; tests cover mixed Done and Canceled ordering at 24, 25, and 26-plus terminal tickets.
- [x] A restored or reopened terminal ticket leaves the terminal pool while nonterminal and is materialized immediately; a later Done or Canceled transition re-enters the pool with canonical activity ordering.
- [x] Older terminal dependencies remain satisfiable from the archive catalog without being permanently exempted or eagerly restored.
- [x] Any over-25 terminal materialization is temporary and attributable only to a live lease, unpublished content, an in-flight journaled transaction, or a retryable verification failure; the planner emits exact ticket IDs and reasons and converges after the blocker clears.
- [x] The active 30-day cutoff and age-derived eligibility fields are removed from policy, configuration, preview, scheduling, metrics, documentation hooks, and migration state. Time is used only for deterministic terminal recency ordering.
- [x] Migration is previewable, versioned, idempotent, and fail-closed for missing legacy activity. It reports all nonterminal materializations, the retained terminal 25, exact eviction candidates, temporary blockers, and rollback data before applying changes.
- [x] The policy explicitly scopes deletion to materialized ticket Markdown and Relay-owned attachments. It does not promise removal of reachable Git objects, rewrite history, force-push, or run destructive garbage collection.
- [x] Focused Python tests cover mixed statuses, equal and missing timestamps, reopen and re-terminalize flows, dependency catalog resolution, leases, concurrent mutations, projects below the limit, and deterministic migration replay.
- [x] Codex and Claude workers observe identical retention eligibility, ordering, migration, and failure semantics.
