## Description

Update Start Session and bridge launch behavior so a Relay Runner session starts from the configured workspace folder while still activating the correct Program Manager scope.

Launching from a workspace root should let the agent operate from that folder and let Program Manager discover or activate child projects. Launching from a single-project repo should keep the current project-board behavior. The bridge cwd should be interpreted using the workspace/project classifier from RR-47 rather than blindly treating the cwd as the active project.

This ticket should preserve existing `/relay-bridge` behavior for repo-local sessions while adding the workspace-root path.

Provider parity matters. Codex and Claude session launch commands, cwd handling, auth/login recovery, and active-project metadata should behave equivalently where possible.

## Acceptance criteria

- [ ] Start Session launches the selected provider from the configured workspace folder by default.
- [ ] `/tmp/voice_bridge.cwd` or equivalent bridge metadata is resolved as either a workspace root or a project repo using the shared classifier.
- [ ] Repo-local bridge launches still activate that repo and initialize its `.orchestrator/config.toml` when appropriate.
- [ ] Workspace-root bridge launches do not create a parent `.orchestrator/` and instead activate Program Manager discovery for child repos.
- [ ] Codex and Claude launch paths both respect the workspace folder and document any intentional provider-specific differences.
- [ ] Tests cover workspace-root session launch, single-project session launch, and provider metadata for Codex and Claude.
