## Description

Replace the remaining Settings-hosted first-run walkthrough with an intro-owned sequence. The current implementation correctly owns the cinematic, permissions, and workspace prompt in `OnboardingIntroController`, but workspace success calls `OnboardingController.show(... .agentChoice ...)`, which opens `OnboardingView` inside Workspace Settings. The supplied reference `/var/folders/xs/qtmf4y_s3_l3dd6b_2mxjj4c0000gn/T/TemporaryItems/NSIRD_screencaptureui_GoVcpE/Screenshot 2026-07-22 at 5.10.32 pm.png` shows that unwanted takeover, including model and reasoning controls the user does not want in onboarding.

Keep all required first-run work on the dedicated intro overlay. Preserve the user's earlier requirement that workspace selection is the final onboarding step. The intended sequence is:

1. cinematic (fresh automatic launches only);
2. missing privacy permissions in `PermissionKind.guidedSetupOrder`;
3. coding-agent choice;
4. selected-provider runtime preparation and login;
5. workspace selection, visibly and behaviorally last;
6. direct completion without opening Settings.

Add purpose-built intro treatments for coding-agent choice, runtime preparation/retry, and agent login. Reuse the established onboarding hero title + white action language from permission screens: centered `.onboardingHero` title, compact 195×50 actions, and the same spacing/corner treatment. The agent screen should ask which coding agent Relay Runner should start with and provide Codex and Claude actions. Selecting a provider must persist only the provider through the existing `setAgentProvider`/`GeneralConfig.selectProvider` boundary; do not show or write model/reasoning preferences from onboarding. General Settings remains the place to change those later.

Runtime preparation currently lives in `OnboardingView` and must not be lost. Keep it intro-owned, visible, retryable, and complete it before launching login so the selected provider CLI exists. Make readiness selected-provider-aware: choosing Claude on a Mac where only Codex is installed must not falsely satisfy the runtime gate. Codex and Claude may use different binary checks/install behavior, but the user-visible sequence and recovery must match.

For unauthenticated providers, show a title such as `Sign in to Codex /` or `Sign in to Claude /` with a `Sign in` action. The full intro panel is at screen-saver level, so finish its dismissal and clear the onboarding notch override before opening Terminal. Poll the provider-neutral auth probe and advance only after authentication succeeds. If Terminal launch fails, sign-in is cancelled, or the app becomes active again without auth, restore the intro login treatment with a working retry instead of leaving onboarding hidden. An already-authenticated selected provider may skip the external login action. Persist `.agent-choice-v1` only after the selected provider is authenticated; persisting it on the initial provider click can strand an interrupted upgrade user.

Restyle the final workspace treatment to match the established intro composition shown by the other screens. The current result is captured at `/var/folders/xs/qtmf4y_s3_l3dd6b_2mxjj4c0000gn/T/TemporaryItems/NSIRD_screencaptureui_SJZ9vV/Screenshot 2026-07-22 at 5.08.00 pm.png`: it uses a wide, left-aligned Settings-style section. Replace that composition with the hero title directly above a centered path-field + `Browse…` action row. Keep Browse adjacent to the field, constrain the path field to 640 points (50% of the previous 1280-point treatment), retain middle truncation and the established 52-point control height, and keep useful supporting copy quiet and bounded. Browse must retain RR-185's exact `dismiss complete → notch override false → folder chooser` order. Cancel restores this final intro step; selection persists once and finishes onboarding directly.

All public onboarding entry points must remain intro-owned: pristine, Reduce Motion, interrupted, a previously-onboarded upgrade missing the versioned agent-choice flag, manual `showAlways`, and the missing-microphone setup action. Remove `!hasRunSession` as a reason to re-open onboarding after successful completion, since the final workspace is now confirmed before `.onboarded` is written. Returning onboarded users and later permission loss remain ordinary Status/General Settings management cases.

Do not reset or mutate the developer's real onboarding flags, provider configuration, auth credentials, workspace, or macOS permissions during tests.
