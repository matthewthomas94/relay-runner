## Description

Make the Program Board scroll behavior match the project board when tickets stack up inside lanes.

The current Program Board can crop ticket content at the top or bottom, and the Backlog lane does not always appear scrollable when it has more tickets than fit on screen. The board should preserve the same practical behavior as the project board: stable column headers, lane bodies that can scroll through their ticket stacks, and no clipped first or last cards.

Keep the fix scoped to Program Board layout and scrolling behavior. Do not change ticket state semantics or introduce new board data paths unless required to make the existing lanes lay out correctly.

## Acceptance criteria

- [ ] Program Board lane scrolling matches the project board behavior when tickets exceed the visible lane height.
- [ ] Backlog, Ready, In progress, and Done lanes can each scroll independently when their ticket stacks overflow.
- [ ] The first and last visible cards are not cropped at the top or bottom of the lane.
- [ ] Column headers, board title, project filter, and any board-level controls remain usable while lane content scrolls.
- [ ] The layout works in All-project and selected-project views.
- [ ] Dense ticket stacks, empty lanes, and narrow window sizes do not produce overlapping or unreachable ticket content.
- [ ] Tests, snapshots, or a documented manual verification path compare Program Board scrolling against the project board behavior.
