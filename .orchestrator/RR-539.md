## Description

Build pairing as part of onboarding, screens 12–14 (`docs/design/relay-remote-ios/README.md`, section "Pairing"; images `12-pair-start.png`, `13-pair-scan.png`, `14-pair-check-fingerprint.png`; Figma [2139:39807](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39807), [2139:39826](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39826), [2139:39855](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39855)). Replace the placeholder body of `PairingFlowView` from RR-533, using its hero layout. Reuse the existing pairing logic: `AppModel.pair(code:)`, `ios/RelayRemote/PairingView.swift` and the kit's `PairingClient`, `PairingPayload` and `HostKeyPinning`. Do not change the pairing protocol.

**Steps**

1. **Start:** "Now let's pair with your Mac /", the hint "Relay Runner › Settings › Relay Remote", and a full-width primary "Scan pairing code".
2. **Scan:** "Scan the code on your Mac /", a live camera viewfinder that reads the pairing QR code, and a secondary "Paste code" that pairs from the clipboard (or a text field, as the current `PairingView` allows). If camera access is denied, show the paste route and one line saying how to allow the camera.
3. **Check:** "Check it matches your Mac /", a card with the Mac's name and its host-key fingerprint in three groups, the line "Waiting for your Mac · Expires in 9:42" with a live countdown from the pairing code's real expiry, and Cancel, which returns to Start.

When the Mac approves, the flow continues to the tutorial (first run) or into the app (when the user arrived here because the phone was not paired). Pairing steps have no Skip. A failed, denied or expired pairing returns to Start with one short line saying what happened.

## Acceptance criteria

- [ ] Scanning a valid pairing QR code moves to the Check step, showing the Mac's name and the fingerprint grouped as in the design.
- [ ] "Paste code" with a valid code does the same; an invalid code shows a short error and stays on the Scan step.
- [ ] The countdown counts down from the code's real expiry, and reaching zero returns to Start with a message.
- [ ] Approval on the Mac completes pairing and continues to the next stage; denial returns to Start with a message.
- [ ] Cancel on the Check step abandons the attempt and returns to Start.
- [ ] No pairing step shows Skip.
- [ ] After "Forget this Mac" (existing `AppModel.forget()`), the app shows this pairing flow, not the splash or the permission steps.
- [ ] Simulator screenshots of the three steps match the reference images (the viewfinder may show the simulator's camera stand-in).
- [ ] The app builds and all tests pass, including the existing pairing tests; the new flow's state machine has unit tests with pairing faked.
