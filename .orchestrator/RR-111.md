## Description

Fix the Program Board/status path that can show completed tickets as still in progress, and identify the root cause that makes additional stale rows appear over time.

Observed during a live Relay session:

- `RR-67`, `RR-68`, `RR-69`, `RR-70`, `RR-74`, `RR-75`, `RR-79`, `RR-80`, `RR-86`, and `RR-93` are `done` in `.orchestrator/*.md`, but the board can still show them in the in-progress lane.
- `RR-94` was also shown active through Program Status as run `290`, while `get_run(290)` returned 404 and the worker branch already had `status: done` with `run_id: 203`.
- The set of stale rows appears to grow as time passes, so the fix must not be a one-time filter for known tickets. Find the source of drift between ticket files, run records, Graphify/program status nodes, and Program Board lane rendering.
- These stale rows make the user think old completed work is still running and can cause unnecessary cancellation, redispatch, or merge decisions.

Reconcile Program Board lane data against the ticket files and authoritative run store so stale active/in-progress rows cannot be created, and existing stale rows disappear when the ticket is already `done`, when the referenced run no longer exists, or when a worker branch has completed and the main ticket has been updated.

Likely touch points:

- `services/program_status.py`
- Graphify ingestion/reconciliation code
- Program Board status view models
- Program status and Program Board tests

## Acceptance criteria

- [ ] Tickets whose `.orchestrator/<id>.md` frontmatter is `status: done` do not appear in the Program Board in-progress lane.
- [ ] Active-run rows whose referenced run id is missing from the orchestrator run store are pruned or rendered as stale, not active.
- [ ] The implementation explains and fixes the root cause that lets new stale in-progress rows appear over time, not only the currently observed rows.
- [ ] Program Status and Program Board agree on lane placement after reload for completed tickets such as RR-67, RR-68, RR-69, RR-70, RR-74, RR-75, RR-79, RR-80, RR-86, and RR-93.
- [ ] Completed worker branches like RR-94 run 203 do not leave stale active rows after main ticket state is reconciled.
- [ ] Regression tests cover done tickets with stale active run records, missing run ids, and stale Graphify nodes.
- [ ] Provider parity is explicit: Codex and Claude run records use the same stale-row pruning behavior.
