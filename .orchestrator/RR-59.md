## Description

Fix the failure mode where Relay Runner quits completely after new work is committed and merged during an active Codex session, forcing the user to restart `/relay-bridge` manually.

The product behavior should be resilient: merging a worker branch, committing ticket updates, or otherwise changing the repo should not kill the menu-bar app or leave the voice bridge in a dead state. If a restart is unavoidable because the app bundle or helper code changed, Relay Runner should recover deliberately and restore the active session/bridge without making the user perform manual cleanup.

Investigate the root cause first. Likely areas include the menu-bar app process lifecycle, Start Session / bridge launch ownership, `/tmp/voice_bridge.sock` liveness handling, helper script replacement during build/install, worktree/branch switches, and any file watchers that may react badly when `.orchestrator/` or source files are committed and merged.

Prefer an app-owned supervisor or watchdog over relying on the active Codex session to notice and relaunch the bridge. The voice bridge should be treated as a managed session resource with clear liveness, recovery, and user-facing status.

Provider and launch-source parity matter. Codex and Claude sessions should get equivalent resilience across commits and merges, even if their launch commands differ. The same recovery contract should apply whether the active session was launched from the Relay Runner app, from a Codex or Claude terminal process, or from a manually invoked `/relay-bridge` flow.

## Acceptance criteria

- [ ] Reproduce or simulate the failure where a commit/merge during an active Codex relay session causes Relay Runner or the voice bridge to quit.
- [ ] Identify whether the quitting process is the menu-bar app, the bridge daemon, the provider terminal/session, or a combination, and document the root cause in the run log.
- [ ] Committing and merging a worker branch while a voice session is active no longer kills Relay Runner or leaves `/tmp/voice_bridge.sock` missing without recovery.
- [ ] If the bridge daemon exits unexpectedly, the app detects it and either relaunches it for the active session or shows a clear recoverable status without requiring manual `/relay-bridge` cleanup.
- [ ] Recovery preserves enough session metadata, such as workspace cwd and provider, to reopen the correct project or Program Board after restart.
- [ ] The behavior is equivalent for Codex and Claude sessions, with intentional provider-specific differences documented.
- [ ] The behavior is launch-source agnostic: app-launched sessions, terminal-launched sessions, and manual `/relay-bridge` sessions recover through the same user-facing contract.
- [ ] Tests or a deterministic harness cover bridge death during an active session, repo commit/merge activity during a session, and successful automatic recovery.
- [ ] Existing normal start/stop bridge behavior and explicit session cleanup still work.
