## Description

RelayActions today registers both **observation** (`mcp__relay-actions__screenshot`) and **manipulation** (`click`, `type`, `scroll`, `key`, `list_windows`, `frontmost_app`) tools under one namespace. This blurs the conceptual model — "looking at the screen" and "acting on the screen" should be separate tool families so that prompts and CLAUDE.md instructions can address each cleanly.

Move screen-observation into a new MCP server: `mcp__relay-vision__*`. Initial scope: just `screenshot`. The namespace is designed to grow (future tools could include `look_at_region`, `read_text_at`, etc.) but this ticket only moves the existing tool.

After this ticket lands:
- **RelayActions** = manipulation only — `click`, `type`, `scroll`, `key`, `list_windows`, `frontmost_app`.
- **RelayVision** = observation only — `screenshot` (initially).
- **ActionGlow** (renamed in RR-9) = perimeter overlay, pulses on `tool_fired` from *either* MCP server.

The user-facing voice intent "look at my screen" routes to `mcp__relay-vision__screenshot` instead of `mcp__relay-actions__screenshot`. The visual pulse behavior is identical because ActionGlow listens for the same `tool_fired` notification regardless of source.

This ticket depends on RR-9 (overlay rename) so the new `relay-vision` namespace doesn't collide with the legacy `RelayVision` symbol names.
