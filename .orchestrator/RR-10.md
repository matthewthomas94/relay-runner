## Description

RelayActions today registers both **observation** (`mcp__relay-actions__screenshot`) and **manipulation** (`click`, `type`, `scroll`, `key`, `list_windows`, `frontmost_app`) tools under one namespace. This blurs the conceptual model — "looking at the screen" and "acting on the screen" should be separate tool families so that prompts and CLAUDE.md instructions can address each cleanly.

Move screen-observation into a new MCP server: `mcp__relay-vision__*`. Initial scope: just `screenshot`. The namespace is designed to grow (future tools could include `look_at_region`, `read_text_at`, etc.) but this ticket only moves the existing tool.

After this ticket lands:
- **RelayActions** = manipulation only — `click`, `type`, `scroll`, `key`, `list_windows`, `frontmost_app`.
- **RelayVision** = observation only — `screenshot` (initially).
- **ActionGlow** (renamed in RR-9) = perimeter overlay, pulses on `tool_fired` from *either* MCP server.

The user-facing voice intent "look at my screen" routes to `mcp__relay-vision__screenshot` instead of `mcp__relay-actions__screenshot`. The visual pulse behavior is identical because ActionGlow listens for the same `tool_fired` notification regardless of source.

This ticket depends on RR-9 (overlay rename) so the new `relay-vision` namespace doesn't collide with the legacy `RelayVision` symbol names.

## Acceptance criteria

- New Swift package `Sources/relay-vision-mcp/` mirroring the structure of `Sources/relay-actions-mcp/`. Registered in `Package.swift` and built by `swift build`.
- `mcp__relay-vision__screenshot` tool implemented with the **same** input schema and output payload as the current `mcp__relay-actions__screenshot`. Behavioral parity required — a session that previously called the relay-actions version must work identically against the relay-vision version.
- The new MCP server fires the existing `tool_fired` notification (same notification name and payload shape) so ActionGlow pulses on screenshot calls with no overlay changes.
- The old `mcp__relay-actions__screenshot` tool is **removed** from `Sources/relay-actions-mcp/` (clean cut, no shim — per project preference for not keeping backwards-compatibility cruft).
- The new MCP server is registered in the menu-bar app's MCP server list (or whatever discovery mechanism the relay-runner app uses to expose MCP servers — mirror the existing `relay-actions-mcp` registration path).
- Docs updated:
  - `CLAUDE.md` — "### 1. RelayActions — the screen-control tools" section: drop `screenshot` from the tool list, retitle to clarify it's manipulation only. Add a new "### 3. Update the "Looking at the user's screen" behavioral note (added in earlier edit) to reference the new tool path. Update the "Naming notes" section.
  - `AGENTS.md` — same updates.
  - `docs/specs/relay-actions.md` — describe the actions-only scope. Create a new `docs/specs/relay-vision.md` (or extend an existing doc) for the observation namespace.
- Manual verification:
  - Voice "look at my screen" routes to the new tool end-to-end.
  - ActionGlow overlay pulses on the new tool's invocation, identically to before.
  - All remaining `mcp__relay-actions__*` tools (click, type, scroll, key, list_windows, frontmost_app) still pulse ActionGlow.
  - No stale references to the old `mcp__relay-actions__screenshot` symbol in code or docs.
- Don't touch the bundled `.app`'s scripts — DMG-build action is the source of truth.
