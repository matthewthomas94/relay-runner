## Description

Wire **True Whisper** into the live Caps Lock flow. With `stt.true_whisper` on and at least two words enrolled (see RR-450 for the library and RR-451 for the setting and `TemplateStore`), holding Caps Lock must turn the camera on and recognise the mouthed word; the microphone must not be opened at all. With the setting off, or with too few templates, behaviour is exactly today's.

Where it goes: `STTEngine.runCapsLockMode()` (`Sources/relay-runner/STT/STTEngine.swift`). Today `.startRecording` writes `__TTS_STOP__`, opens audio through `audioCapture.start()` and buffers samples; `.stopRecording` finalises the Parakeet transcript and calls `writeVoiceOutput(finalText)`.

Required behaviour when True Whisper is active:

1. On engine start, build a `TemplateClassifier` from `TemplateStore` (use velocity features, the spike default). If the store has fewer than 2 labels, log once and fall back to microphone mode.
2. On `.startRecording`: still write `__TTS_STOP__`; do not start audio capture and do not touch the Parakeet model; start a `LipCaptureSession` (through the `FrameSource` abstraction so tests can inject frames) and collect geometry frames for the whole hold.
3. On `.stopRecording`: stop the frame source immediately (camera off), then classify the collected frames with `predict(maxDistance: 1.5, minConfidence: 0.1)` (the spike's decode defaults). If accepted, send the label through `writeVoiceOutput` exactly as a transcript would be sent, so it reaches the bridge like a spoken word. If not accepted or fewer than 6 frames were collected, send nothing and emit the engine's existing status mechanism with a short reason (no face, no confident match) so live captions can show it.
4. Capture ownership: `AppState.syncCommandCaptureOwnership` / `setCaptureAllowed` keep their meaning; when True Whisper is active the "capture" they allow is the camera, and the microphone backend is never started by the engine. Reference-audio suspension and the tutorial gate in `writeVoiceOutput` still apply.
5. Config changes: toggling `stt.true_whisper` or finishing an enrollment must take effect without relaunching the app, following whatever existing path restarts or reconfigures the STT engine on config save (find it in `AppState.saveConfig` / `startConfiguredSTT`; add a reconfigure hook if none exists).
6. Live captions / notch: while the camera is capturing, reuse the existing recording indicator; add no new overlay.

Telemetry for iteration: log each recognition decision (label, confidence, frame count, accepted or not) at the engine's normal log level; never log frames.

Provider parity: the output is a transcript line on the existing FIFO, so Claude and Codex sessions see identical behaviour.

Live camera access cannot be exercised in the worker environment: macOS attributes a worker's processes to the hosting app, which has no camera entitlement until this work ships. Verify with unit tests and injected frame sources; do not add acceptance items that need a real camera.

## Acceptance criteria

- [ ] With `true_whisper` off, `runCapsLockMode` behaviour and the existing STT tests are unchanged.
- [ ] Unit test: with `true_whisper` on and an injected frame source replaying a stored template, a Caps Lock press/release cycle writes `__TTS_STOP__` then the template's label through the voice-output seam, and the audio capture backend's `start()` is never called.
- [ ] Unit test: frames that match no template within the thresholds write no transcript and emit a status; the frame source is stopped in both cases.
- [ ] Unit test: with fewer than 2 enrolled labels the engine falls back to microphone capture and logs once.
- [ ] Changing `stt.true_whisper` at runtime reconfigures the engine without relaunch (test through the same path `saveConfig` uses).
- [ ] `swift build` and `RelayRunnerTests` pass; the run log states that live camera use was not exercised in the worker and names the manual check for the user: enable True Whisper, hold Caps Lock, mouth "stop", and see "stop" arrive as the transcript.
