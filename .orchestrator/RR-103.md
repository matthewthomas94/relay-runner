## Description

Add a permanent orchestrator check that every dispatchable ticket has an explicit worker-sizing decision before a sub-agent runs.

The foreground orchestrator should decide the expected worker effort as accurately as possible while it still has the full project overview. A cold worker should not have to infer whether it should run on a fast/cheap model, a balanced model, or a high-effort configuration.

Define the smallest durable metadata shape for ready tickets, likely in frontmatter, to record:

- Worker model or model tier.
- Worker reasoning effort where the provider supports it.
- A short sizing rationale that explains why the ticket needs that level.
- Any provider-specific limitation, especially if Claude cannot map the same effort fields directly.

Likely touch points:

- `docs/specs/orchestrator-tickets.md`
- `services/instructions/orchestration-workflow.md`
- `services/orchestrator_workflow.md`

## Acceptance criteria

- [ ] Ready-ticket guidance requires an explicit worker-sizing decision before dispatch.
- [ ] Ticket schema docs define the metadata fields, allowed values, and whether they are required for `ready` tickets.
- [ ] Orchestrator-facing instructions tell the foreground session to choose model/effort based on ambiguity, code blast radius, security risk, test/build cost, and expected implementation depth.
- [ ] Worker-facing instructions explain that the assigned sizing came from the orchestrator and should not be silently weakened.
- [ ] Generated MCP/instruction artifacts are regenerated or verified so Codex and Claude receive the same permanent policy.
- [ ] Provider parity is explicit: Codex reasoning effort and Claude model/tier behavior are both addressed, with intentional limitations documented.
