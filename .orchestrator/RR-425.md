## Description

Spec: `docs/specs/relay-remote.md` (Relay Remote: iOS voice over SSH), committed as `2a64cc0d` on branch `claude/ios-relay-ssh-tcp-spec-ddb8f2`. The spec is not on `main` yet; if the file is missing from your worktree, read it with `git show 2a64cc0d:docs/specs/relay-remote.md`. Read these sections first: Architecture, Pairing and trust, Security model.

Add a Swift executable target `relay-remote-shell` that OpenSSH runs as the forced command for a paired device's key. It has no protocol logic of its own: it copies NDJSON lines between its stdin and stdout (the SSH channel) and a local Unix socket.

- `relay-remote-shell --device <device_id>` connects to `/tmp/relay_remote.sock` (served by the bridge module, RR-423), sends one identification line naming the device, then copies stdin to the socket and the socket to stdout line by line, flushing per line.
- `relay-remote-shell --pair <pairing_id>` does the same against `/tmp/relay_remote_pair.sock` (served by the pairing flow, RR-426).
- `SSH_ORIGINAL_COMMAND` is ignored except for the allow-listed `status` subcommand, which asks the socket for one `status` frame, prints it and exits. Anything else is refused with one `error` frame and exit code 2 without opening a socket.
- Enforce the 64 KiB line limit in both directions: an oversize or unparsable line produces one `error` frame and closes the session, as the spec requires.
- If the socket is absent (the app is not running) write one `error` frame with `code: "bridge_unavailable"` and exit non-zero.
- Exit promptly when either side closes.
- Packaging: embed the built helper in the app bundle and sign it in `scripts/build-dmg.sh`, following how the existing bundled executables are handled there.

Out of scope: `authorized_keys` and the per-user shim (RR-426); the socket servers themselves (RR-423, RR-426).

## Acceptance criteria

- [ ] Unit tests cover both modes against a fake socket server: lines pass in both directions, oversize lines are rejected, closing either side ends the process.
- [ ] A disallowed `SSH_ORIGINAL_COMMAND` exits with code 2 and no socket connection is attempted.
- [ ] The DMG build embeds and signs the helper; `codesign -dv` on the built bundle shows it.
- [ ] A repeatable test script starts a per-user `sshd -D -f <temp config>` on a high port with a throwaway host key and `authorized_keys` entry, and runs the helper end to end through a real SSH connection against the fake socket server.
- [ ] No key material or fingerprints are logged.
