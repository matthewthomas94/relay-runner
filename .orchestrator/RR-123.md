## Description

Prototype the "Project Manager frontstage, orchestrator backstage" architecture discussed in the Relay voice session.

The product goal is perceived responsiveness: the user should hear immediate, useful acknowledgement and live progress while a backstage orchestrator is still thinking, planning, creating tickets, or deciding whether to execute solo or request workers.

For this prototype, avoid a full rewrite. Build the smallest slice that proves the shape:

- The PM/frontstage layer is the user-facing authority for acknowledgement, narration, cancellation/preemption, and dispatch decisions.
- The orchestrator/backstage layer owns technical planning and returns structured outcomes such as `execute_solo`, `delegate_plan`, or `needs_user`.
- Any worker fan-out is requested through a structured delegation plan rather than spawned ad hoc by the orchestrator.
- Public status events are structured and user-safe; do not stream raw hidden reasoning.
- The flow preserves Relay command metadata so stale voice commands cannot create tickets, dispatch workers, or speak outdated TTS.

Prefer reusing existing voice bridge, `voice_state.sock`, TTS FIFO, and orchestrator run/dispatch infrastructure. Keep the prototype behind an experimental path or narrow integration point if enabling it broadly would be risky.
