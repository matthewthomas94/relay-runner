## Description

When a local commit happens while a Relay session is active, Relay Runner appears
to crash, turn off, or drop the active voice bridge. The user then has to restart
`relay-bridge` manually. This appears to happen consistently after local commits
from the foreground Codex session or orchestrator workflow.

Captured user report:

> Whenever a local commit happens, Relay Runner crashes or turns off, and then I
> have to restart relay bridge again. It seems to be happening every time you
> commit something locally.

Investigate whether the app process is actually exiting, the Python
`voice_bridge.py` daemon is stopping, the `/tmp/voice_bridge.sock` and command
state files are being cleaned up, or the session is merely losing its live
bridge metadata. The fix should keep a live Relay session stable across ordinary
local git commits, including commits made by the foreground session and worker
branches.

Relevant areas to inspect:

- `Sources/relay-runner/App/AppState.swift`
- `Sources/relay-runner/Process/ProcessManager.swift`
- `Sources/relay-runner/Board/OrchestratorClient.swift`
- `scripts/relay-bridge`
- `services/voice_bridge.py`
- `services/orchestrator.py`
- Any file-watch, bridge-watchdog, bundled-service-refresh, or ready-sweeper
  path that reacts to repository changes or commits.
