## Description

The folder choosers behind Add existing project, Create new project and the workspace directory setting (`NSOpenPanel` at `Sources/relay-runner/App/AppState.swift:3377`, `Sources/relay-runner/Board/ProgramBoardOverlayView.swift:4256`, `Sources/relay-runner/Config/WorkspaceDirectoryPicker.swift:17`) can open behind the Workspace overlay panel or on a display other than the one the user is working on. The panel is modal, so the user cannot reach it, cannot use other apps, and macOS beeps on every click until they find it.

Make every folder picker in the app go through one shared presenter that:

1. Closes the Workspace and the terminal view if they are showing, the way the Keep Awake approval guide does (`suspendWorkspaceForExternalWindow()` in `AppState.swift:4838`), and activates the app.
2. Presents the panel on the display that contains the mouse pointer (falling back to the key window's screen), in front of every Relay Runner panel.
3. Restores the Workspace to its previous state after the user chooses or cancels.

This is a bug in today's Add project flow and should ship on its own; the project-resolve voice flow in a later ticket reuses the same presenter.

External verification: checks that need the live app, real hardware, or a human run what you can from the worktree without installing, releasing, or restarting the running app. If only those checks remain, finish as `verification_blocked`, naming each remaining check in `verification_blocker` and how to run it in `verification_resume`.

## Acceptance criteria

- [ ] All three `NSOpenPanel` sites use the shared presenter; a source-contract test fails if a new `NSOpenPanel()` is created outside it.
