## Description

Replace prompt-dependent foreground reply delivery with a deterministic
provider-completion path while retaining RR-180's missing-reply warning as a
true last-resort safety net.

RR-180 added explicit `__ORCHESTRATOR_REPLY__` deduplication and a generic
warning when a claimed voice turn does not produce that control envelope. The
same warning recurred on installed Relay Runner v0.4.26. This confirms the
safety net works, but also confirms the primary reply path still depends on the
foreground model remembering to emit a manual control message.

Both supported provider CLIs expose lifecycle hooks for the main agent's
completed turn. Their `Stop` payload includes `last_assistant_message`, so Relay
can recover the authoritative final without parsing terminal escape sequences
or unstable transcript files. Register a Relay-owned, session-scoped hook for
app-owned Codex and Claude sessions. It must compose with existing user and
project hooks and must not persistently modify either provider's global
configuration.

Correlate only Relay-injected prompts. Before submitting Enter to the embedded
PTY, atomically publish the claimed command metadata needed by a
`UserPromptSubmit` hook to bind the provider session and turn to the exact
`agent_prompt`, `relay_command_seq`, and `relay_command_id`. On the matching
main-thread `Stop`, route a non-empty `last_assistant_message` through the
existing authoritative reply handler. Do not speak typed turns, subagent
stops, transcript content, tool output, reasoning, or setup text.

An explicit current `__ORCHESTRATOR_REPLY__` remains valid and must deduplicate
the later provider hook. Newer-intent checks remain authoritative. The generic
warning should be emitted only when a provider turn has completed without a
usable final or the completion transport has failed after a bounded grace
period. A long-running but still-active turn must not be diagnosed as a
missing final merely because 120 seconds elapsed.

Use a bounded, private, session-scoped correlation record and non-blocking
bridge delivery so an unavailable Relay bridge cannot stall the provider's
Stop hook. Preserve concise terminal-visible diagnostics without logging
prompts, final response text, transcripts, secrets, or raw hook payloads.

## Acceptance criteria

- [ ] App-owned Codex and Claude launches register a Relay-owned main-thread completion hook for that session without modifying persistent user or project configuration.
- [ ] Relay's hook registration composes with pre-existing provider hooks instead of replacing, disabling, or suppressing them.
- [ ] Relay-published claim metadata is available atomically before the provider accepts the submitted prompt, removing the current prompt-submit correlation race.
- [ ] `UserPromptSubmit` binds only an exact current claimed Relay `agent_prompt` to its provider session and turn; ordinary typed prompts and subagent turns are never marked for Relay speech.
- [ ] On a matching successful `Stop`, a non-empty `last_assistant_message` is delivered once through the existing messenger/final-reply path with the authoritative `relay_command_seq` and `relay_command_id`.
- [ ] The hook path does not parse provider transcript files, scrape PTY output, or forward reasoning, tool output, setup text, raw hook payloads, or other private content.
- [ ] A current explicit `__ORCHESTRATOR_REPLY__` remains authoritative; the subsequent provider completion hook is deduplicated without speaking the response twice.
- [ ] A provider completion for a superseded voice command is dropped by the existing newest-intent contract.
- [ ] A long-running active provider turn does not emit the “provider did not send a spoken final reply” warning solely because a wall-clock timeout elapsed.
- [ ] A completed turn with an empty final, a failed completion hook, or unavailable completion transport retains a bounded one-time warning and terminal guidance.
- [ ] Provider interruption, API failure, process exit, bridge restart, and app/session shutdown clear or expire correlation state without replaying an old final.
- [ ] Hook delivery is non-blocking when the bridge is unavailable and emits only sanitized diagnostics.
- [ ] Focused tests reproduce the v0.4.26 recurrence and cover successful automatic recovery, explicit-envelope deduplication, typed-turn exclusion, stale-command rejection, long-running turns, empty finals, hook coexistence, bridge unavailability, and session cleanup for both Codex and Claude.
- [ ] Relevant Python and Swift suites pass, including voice bridge preemption, embedded PTY delivery, provider launch construction, messenger routing, and app-managed session lifecycle tests.
