## Description

Remove Relay Runner's distinct project-level kanban board UI. The Program Workspace is now the only Work surface for both a single active repository and a workspace containing multiple repositories. Repo-local `.orchestrator/` ticket files remain the project source of truth and the orchestrator/worker lifecycle remains unchanged; this ticket removes the duplicate single-project presentation and routing layer, not ticket storage.

When a live or explicitly activated single repository is the current scope, open the Program Workspace constrained to that repository and select/present that project naturally. When a workspace root is active, retain the existing multi-project Program Workspace behavior. Project cards and ticket details must stay within the unified surface instead of opening the legacy project board.

Consolidate all Workspace entry points and lifecycle handling around the Program Workspace: menu item, notch glyph, gesture/hotkey, Relay Actions toggle, Start Session terminal opening, Settings, external-window suspension/resume, loading state, dismissal, and route refresh. Preserve the utility-only Terminal and Settings surface before a valid project/workspace route exists; do not expose a misleading Work tab or initialize a board for a non-git folder.

Delete the legacy project-board controller/view/view-model and obsolete routing/tests where they are no longer used. If shared panel, editor, style, scrolling, reveal, ticket parsing, or writer code currently lives beside the legacy view, retain or extract only what the Program Workspace and ticket engine still need. Update current docs and generated provider-neutral instructions so they describe one unified Program Workspace rather than project-board versus program-board routing.

## Acceptance criteria

- [ ] A single-repository session opens the Program Workspace Work surface scoped to that repository; it never constructs or shows the legacy project-level board.
- [ ] A workspace-root session continues to open the Program Workspace across its discovered child repositories without creating a parent `.orchestrator/` directory.
- [ ] Menu, notch, keyboard/gesture, Relay Actions, Terminal, and Settings entry points all use one Workspace overlay controller and preserve current show/hide, Escape, focus, and suspension behavior.
- [ ] Starting an embedded session opens the unified Workspace Terminal tab; external-terminal behavior remains unchanged.
- [ ] With no valid project/workspace route, Workspace still exposes Terminal and Settings as applicable but does not show a Work tab, invent work, run `git init`, or create `.orchestrator/` for a non-git folder.
- [ ] Selecting a project in the Program Workspace filters the unified Work surface and never transitions to a separate project board.
- [ ] Repo-local `.orchestrator` ticket creation, editing, deletion, drag/drop, ready-triggered dispatch, dependency progression, and run status remain functional through the Program Workspace.
- [ ] The legacy `BoardOverlayController`, single-project `BoardOverlayView`/view-model, project/program toggle target, and obsolete route handoff code are removed; shared code needed by the unified surface remains cleanly owned and named.
- [ ] Project resolution still activates/initializes a real single git repository when appropriate and preserves workspace-root discovery semantics, but no UI route distinguishes project board versus Program Board.
- [ ] Loading/notch state uses the unified Workspace loading source without duplicate project/program flags.
- [ ] Codex and Claude have identical unified Workspace behavior and updated generated instructions/documentation no longer promise a project-level board.
- [ ] Focused routing, overlay, Program Workspace, Terminal/Settings, and project-registry tests cover the new behavior; `swift test` and `git diff --check` pass.
