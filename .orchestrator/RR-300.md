## Description

Permanently fix a live regression of RR-275 where app-owned voice commands can remain queued until the user ends and restarts the provider session. The durable intent inbox preserves the commands, but a volatile provider-turn record can remain active after the real foreground turn has completed, so terminal delivery continues treating an idle provider as busy and never claims the next ordered item.

The captured Codex failure has a concrete lifecycle boundary. A Relay-correlated `UserPromptSubmit` hook bound the active command to a transient native session identity. The `Stop` hook for that same physical foreground turn later carried the persisted transcript session identity while retaining the same stable app-owned `RELAY_PROVIDER_SESSION_ID`. `relay_completion_hook._find_turn_record` filtered by the mismatched native session identity before it could terminalize the Relay record, reported that the completion lacked Relay correlation, and left the record `active`. `RelayVoiceCommandDelivery` then kept the next durable item behind `provider_turn` indefinitely. Restart removed the volatile turn record and recovered the unacknowledged inbox lease, after which both queued commands drained in order.

Treat the stable app-owned provider-session boundary as part of the physical ownership model without allowing a broad or ambiguous completion fallback. Reconcile transient-to-persisted native identities only when the completion can be proven to belong to the one outstanding physical foreground turn. A delayed or duplicate Stop from an older turn must never terminalize a newer Relay command or a genuine manual turn. Preserve exact command/intent correlation, provider preemption, stale-current reply suppression, typed and pasted draft safety, ordered durable delivery, and restart recovery.

Do not solve this with a blind timeout, TTL-only release, global clearing of active turns, arbitrary "single active record" matching, or automatic session restart. The normal completion boundary must release the correct turn promptly and deterministically. Privacy-safe diagnostics should make identity reconciliation and rejected ambiguous completions observable without persisting prompt, transcript, response, or other terminal content.
