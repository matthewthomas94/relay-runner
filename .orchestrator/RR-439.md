## Description

`Sources/relay-runner/STT/AudioCaptureLifecycle.swift` (around lines 227–330) captures the microphone with `AVAudioEngine()` plus `inputNode.installTap(onBus: 0, bufferSize: 8_000, …)`. On macOS, `AVAudioEngine` always runs the default **output** device as part of its private aggregate (`CADefaultDeviceAggregate`), so every engine start powers the built-in speaker amplifier and every stop powers it down, even though Relay never plays audio through the engine.

Measured on macOS 27.0.1 (MacBook Pro M4, 2026-10-28, Relay Runner 0.4.82):

- Kernel `AppleEmbeddedAudio` logs "Speaker: streaming audio" within ~30 ms of each relay-runner "setPlayState Started Input {CADefaultDeviceAggregate…}" and "Speaker: off" when the engine stops. Off-gaps as short as 5 s were observed (speaker shuts down, then powers straight back up).
- The engine restarted up to **14 times in one hour** (`AUHAL … SelectDevice` by relay-runner), driven by the `AVAudioEngineConfigurationChange` / `conversion-failure` recovery path (`onConfigurationChange`) and the default-input-device listener (lines ~338–395).

Speaker-amplifier power cycling is a documented source of pops/clicks on MacBooks and needlessly provokes marginal hardware; it also keeps the output device busy and adds work for `coreaudiod`.

Goal:

1. Capture input **without engaging the output device**. Options: an input-only HAL output unit (`kAudioUnitSubType_HALOutput` with `kAudioOutputUnitProperty_EnableIO` input=1 / output=0 and the selected input device set explicitly), or an `AudioQueue` / `AVCaptureSession` audio input. Keep the current contract: native-rate capture converted to 16 kHz mono Float32 and delivered to `sampleHandler` in the same chunking; no extra allocations or locks on the IO thread beyond what exists today.
2. Coalesce configuration-change recovery so steady-state restarts stop: debounce `onConfigurationChange` (e.g. ≥ 500 ms), ignore changes that do not affect the selected input device, and keep the existing explicit recovery reasons (`engine-configuration`, `conversion-failure`).

Keep working: `STTEngine` start/stop and suspend paths (`suspendForRemoteDevice`, `suspendForReferenceAudio`), Caps Lock / push-to-talk gestures, `AppState` `sttEngine` lifecycle, and the ownership tests in `tests/RelayRunnerTests/STTCaptureOwnershipTests.swift`.

External verification: some checks need the live app, physical device changes, listening, or a long soak. Run what you can from the worktree without installing, releasing or restarting the running app. If only those checks remain, finish as `verification_blocked`, naming each remaining check in `verification_blocker` and how to run it in `verification_resume`.
