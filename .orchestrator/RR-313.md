## Description

Use the typewriter treatment only for the opening **Relay Runner** title card. The title should type in grapheme by grapheme, remain fully readable for its intentional settle, and then hand off to **First thing’s first** through the same restrained opacity-and-blur choreography used by the tutorial.

After the opening title has finished typing, every later onboarding text sequence should change as a complete string through fade-out/fade-in plus blur. This applies across **First thing’s first**, permission prompts, provider choice, runtime preparation/readiness/failure, provider login, project/workspace setup, success, retry, error, and the session-controls tutorial. Do not backspace or type later prompts one character at a time. Swap the outgoing and incoming strings at the blurred/low-opacity boundary so there is no sharply legible overlap, cursor-only frame, or partial provider-name remnant.

Reuse one post-title transition policy across AppKit and SwiftUI onboarding surfaces rather than maintaining separate tutorial and non-tutorial animation systems. Preserve existing copy, controls, setup sequencing, interaction gates, the provider-login dwell, and provider routing.

Follow the existing accessibility contract: Reduce Motion must use a deterministic static or short opacity-only alternative without animated blur, while leaving the final copy and controls unchanged.

## Acceptance criteria

- [ ] **Relay Runner** is the only onboarding string rendered with a per-grapheme typewriter animation; Unicode grapheme handling and the existing title entrance cadence remain correct.
- [ ] The fully rendered **Relay Runner** title remains readable for an intentional settle, then fades out while blurring before **First thing’s first** fades in and resolves from blur; it is not erased character by character and there is no abrupt cut.
- [ ] Every text transition after the title card uses the same complete-string fade-and-blur policy across permission, provider choice, runtime, login, project/workspace, success, retry, error, and tutorial phases.
- [ ] No post-title prompt backspaces or types character by character, and no transition exposes a standalone cursor, partial provider name such as `C /`, or sharply legible overlap between outgoing and incoming strings.
- [ ] At the swap boundary, outgoing copy is sufficiently blurred and faded before incoming copy becomes legible; the restrained blur resolves in concert with opacity rather than lingering after the new string is readable.
- [ ] Controls and status content reveal at the appropriate phase without changing setup sequencing, button behavior, or the tutorial’s recording, playback, cancellation, and Workspace interaction gates.
- [ ] The fully rendered provider login prompt remains readable for an intentional dwell of at least 1.25 seconds before its fade-and-blur transition to the next prompt begins.
- [ ] Rapid or interrupted runtime/login updates coalesce to a coherent latest complete string and cannot strand an outgoing prompt, cursor, or blur state.
- [ ] Codex and Claude setup paths produce equivalent post-title transition behavior, including provider-specific preparation, ready, login, retry, and failure copy.
- [ ] Reduce Motion keeps the title and final prompt deterministic, skips animated blur, and uses a static replacement or short opacity-only transition without trapping setup or hiding actionable state.
- [ ] Focused tests cover the title-only typewriter policy, title settle and fade/blur handoff, representative post-title phase mapping, interruption/re-entry, login dwell, provider parity, and Reduce Motion.
- [ ] Relevant Swift tests pass, and a fresh mounted onboarding recording confirms the title card types in once while every later text sequence uses the fade-out/fade-in plus blur treatment.
