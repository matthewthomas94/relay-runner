## Description

Expose saved project notes as ordinary readable project context for both Codex and Claude work sessions. Provide a bounded catalog and fetch-by-note-ID path through the established canonical/materialized artifact interfaces, including archived notes when needed. The agent can read the original transcript, cite its note ID/path and recorded revision, understand discussion and later help the user scope work.

The note is source material, not an instruction channel. Recording or saving a statement such as implement this does not authorize ticket creation, dispatch or execution. Under a later explicit user request to scope work, normal ticket authoring may create linked work tickets in Backlog while preserving the note unchanged. Use the existing command authorization and ticket workflow; do not invent a special summary session, title agent, BYO provider adapter or automatic notes-to-work pipeline.

Markdown is already the canonical stored format, so a standalone export subsystem is unnecessary. This replaces the old export-only/no-agent-access boundary. Use project repository visibility and existing history semantics; deletion from a working projection is not erasure from Git history.

## Ownership and scope

Relay Runner repository. Own ordinary Codex/Claude project context discovery, bounded note reads/history retrieval and source-note reference conventions. RR-364 owns canonical storage/archive/sync; RR-367 owns the human note viewer.

## Required inputs

None beyond the declared ticket dependencies. The in-app product direction, Git-backed transcript storage, note ID format and ordinary agent access are already decided.

## Acceptance criteria

- [ ] A normal Codex session and a normal Claude session can discover notes for the selected project, retrieve one by ID and read the same canonical transcript/revision. Neither needs a special note-summary session or generated title/summary.
- [ ] Catalog/read results include project, immutable artifact identity, display ID, path or verified history reference, date and completion state. Bound listing/context size and fetch content on demand; do not automatically inject all meetings into every prompt.
- [ ] An archived/non-materialized note remains discoverable through the artifact history path with verified content and a stable reference. A missing or unsynced note is reported honestly; the reader never substitutes another project or rewrites the source.
- [ ] When the user later requests work scoping, derived tickets can cite the source note ID and specific saved revision/link and enter Backlog through the canonical ticket writer. Creating or updating those tickets leaves the original note intact and does not promote or dispatch them without separate authorization.
- [ ] Fixtures containing imperative meeting speech and instruction-like Markdown are treated as untrusted document content. Saving, listing or reading notes alone causes zero ticket writes, voice-command submissions, provider-session launches or worker dispatches.
- [ ] Codex and Claude share the same discovery/read/reference behavior, project scope checks and authorization semantics. Document any provider-specific context wiring without changing what notes either provider can access.
- [ ] Document the supported note read/history/reference workflow and actual repository/Git-history visibility. Do not retain the superseded prohibition on agents reading notes or add a generation prerequisite.
