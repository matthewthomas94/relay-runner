## Description

Restore the visible conversation, active context and eligible underlying provider session after Relay Runner restarts or a provider process is interrupted. Build on existing continuity recovery and ordered-intent state instead of creating a second recovery authority. Restoring a session must not replay a completed action, silently dispatch a backlog ticket or repeat an irreversible external effect. Preserve interrupted note capture and its current explicit resume behavior.

## Acceptance criteria

- [ ] After app restart, restore the last global/project context and readable histories even if a provider is offline or awaiting sign-in.
- [ ] Reconcile persisted provider identities against live processes and normal resume support, avoiding duplicate terminals, bridges and provider processes.
- [ ] Recover accepted pending work only through canonical intent/run state; completed actions and external effects are never blindly replayed.
- [ ] A moved, missing or unavailable repository leaves its conversation accessible and asks for re-resolution only when project execution requires it.
- [ ] Authentication recovery uses the existing subscription sign-in flows and rechecks readiness for both Codex and Claude.
- [ ] Existing interrupted notes remain recoverable with stable identity and no automatic recording restart.
- [ ] Tests cover clean restart, app crash, provider crash, stale PID/session identity, interrupted switching and reconnect failure, with installed restart evidence reported separately.
