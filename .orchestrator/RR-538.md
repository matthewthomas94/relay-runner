## Description

Build the permission steps, screens 06–11 (`docs/design/relay-remote-ios/README.md`, section "Permissions"; images `06-permission-microphone.png` to `11-permission-notifications.png`; Figma [2139:39682](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39682), [2139:39701](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39701), [2139:39730](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39730), [2139:39749](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39749), [2139:39768](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39768), [2139:39787](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-39787)). Replace the placeholder body of `PermissionsFlowView` from RR-533, using its hero layout.

**Steps, in order:** microphone, speech recognition, local network, camera, notifications. Each step shows its hero text and one short line of explanation as in its image, a full-width primary button that triggers the iOS prompt, and "Skip →" top right, which moves on without asking. After the user answers the system prompt (either way) the flow moves to the next step. A permission that is already granted or already denied is not asked again; its step is skipped.

- Microphone: `AVAudioApplication.requestRecordPermission` (today requested lazily in `ios/RelayRemote/Voice/SpeechRecognizer.swift`).
- Local network: iOS has no direct request call; trigger the prompt the way the app's Bonjour discovery does (`Discovery.swift` in the kit) and move on when the prompt is answered or after a short timeout.
- Camera: `AVCaptureDevice.requestAccess(for: .video)`.
- Notifications: `UNUserNotificationCenter.requestAuthorization` for alerts and sounds. When granted, turn on the reply-notifications preference from RR-533; when denied or skipped, leave it off.
- Speech recognition: **verify first.** The app transcribes with `SpeechAnalyzer` and `SpeechTranscriber`, and nothing in the code requests speech-recognition authorisation today. Establish from Apple's documentation and a simulator run whether that API needs the `SFSpeechRecognizer` authorisation prompt. If it does, build step 08 with `SFSpeechRecognizer.requestAuthorization`. If it does not, leave step 08 out, remove `NSSpeechRecognitionUsageDescription` from `Info.plist` only if nothing else needs it, and say so in your summary and in `ios/README.md`.

The usage strings already in `ios/RelayRemote/Info.plist` stay as they are unless the speech one is removed.

## Acceptance criteria

- [ ] On a fresh simulator install the steps appear in the order above, each primary button raises the matching system prompt, and answering it advances the flow.
- [ ] Skip advances without raising a prompt, and the app still works later: the microphone prompt then appears on first use, as today.
- [ ] A step whose permission was already decided does not appear.
- [ ] The speech-recognition question is answered with evidence in the summary, and step 08 is present or absent accordingly.
- [ ] Granting notifications turns the reply-notifications preference on; denying leaves it off.
- [ ] Simulator screenshots of each step match the reference images for text, layout, button position and Skip position.
- [ ] The app builds and all tests pass (the step-ordering and skip logic has unit tests with the permission calls faked).
