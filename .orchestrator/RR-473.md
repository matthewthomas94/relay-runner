## Description

The embedded PM session in the Terminal tab is ended by the 30-minute idle auto-save even while the user is actively working. On 2026-11-09 two sessions in a row ended with `app_requested_stop` exactly 30m02s after `interactive_provider_readiness` (07:53:30Z → 08:23:32Z and 08:36:12Z → 09:06:14Z), with provider busy/idle activity at 08:47Z and 09:03Z in between (see `embedded-agent-diagnostics/*.events.jsonl` and the `.context-compaction.jsonl` files beside them).

Cause:
- `AssistantSessionStore.saveIfIdle` (`Sources/relay-runner/Process/AssistantSessionStore.swift`, `idleTimeout = 30 * 60`), called from `reconcileAssistantContext` in `Sources/relay-runner/App/AppState.swift`, measures idle time from `binding.lastActivity`.
- During a running session, `lastActivity` only moves forward when `importPublicHistory` imports new entries from the provider transcript at `binding.transcriptPath`.
- For these sessions the transcript never existed. The app expected `~/.claude/projects/-Users-matthewthomas-Library-Application-Support-relay-runner-general-tasks/<session-id>.jsonl` (the provider was launched with `--session-id <id>`), but no file with that id exists anywhere under `~/.claude`. `importPublicHistory` returns early, `transcriptOffset` stays nil, and `lastActivity` stays at launch time, so the session is ended 30 minutes after launch every time.
- Likely reason the transcript is missing (not yet proven): the provider inherited host environment from a Claude Desktop session that launched the Relay Runner dev build. The live provider process had `CLAUDE_CODE_ENTRYPOINT=claude-desktop`, `CLAUDE_CODE_CHILD_SESSION=1`, `CLAUDE_CODE_SESSION_ID=<desktop session id>`, `CLAUDE_CODE_HOST_SESSION_ID`, `CLAUDE_CODE_MESSAGING_SOCKET`, `CLAUDE_AGENT_SDK_*`, `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING` and others. No code in `Sources/` removes these before spawning the provider.

Scope:
1. **Idle check counts real activity.** A running session must not be judged idle while the user or provider is active, even if no transcript can be read. Refresh `lastActivity` from app-observed activity: at least user input written to the PTY, injected or claimed voice turns, and provider busy/idle transitions the app already observes (the same signals that feed the context-compaction `active_context_observed` events). Keep the existing 30-minute timeout and its eligibility conditions. A session that really is idle for 30 minutes must still be saved and ended as today.
2. **Clean provider environment.** When spawning the embedded provider (and any other Relay-launched provider process that shares the spawn path), remove inherited host-session variables that make it act as a child of another Claude session: at least `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_HOST_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_MESSAGING_SOCKET`, `CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_PID` and `CLAUDE_AGENT_SDK_*`. Keep variables Relay Runner sets on purpose (for example `CLAUDE_CODE_AUTO_COMPACT_WINDOW` in `ProcessManager.swift`) and never remove auth. Then confirm whether a provider launched from a Claude Desktop host now writes its transcript at the expected path, and record the finding in the run log.
3. **Visible diagnostic.** If the expected transcript has not appeared some reasonable time after `interactive_provider_readiness`, record a diagnostics event (for example stage `transcript_missing`) in the embedded-agent diagnostics events file, so this failure is visible without manual digging.

## Acceptance criteria

- [ ] Unit test: with a binding that has no transcript (nil or nonexistent `transcriptPath`) and app-observed activity within the last 30 minutes, `saveIfIdle` does not end the session, including more than 30 minutes after launch.
- [ ] Unit test: with no activity of any kind for at least 30 minutes, the session is still saved and ended as today (existing `AssistantContextLifecycleTests` keep passing).
- [ ] User PTY input, claimed voice turns and provider busy/idle transitions each refresh the idle clock, and each has a test or clearly documented manual check.
- [ ] Spawned provider environment no longer contains the listed inherited host-session variables, covered by a test of the env-building code. Relay-set variables and auth are unchanged.
- [ ] A `transcript_missing` (or similarly named) diagnostics event is written when the expected transcript does not appear, covered by a test.
- [ ] Run log records whether the env scrub alone makes the Claude transcript appear when Relay Runner is launched from inside a Claude Desktop session, and whether Codex needs equivalent handling.
- [ ] `swift build` and the relevant Swift tests pass.
