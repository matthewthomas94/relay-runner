## Description

Add a reload control beside the Program Board title so the user can refresh all-project ticket state on demand.

The Program Board now aggregates tickets from registered projects. When the board looks stale, the user should have an obvious refresh affordance in the board header rather than needing to close and reopen the board or guess whether polling will catch up.

Keep this scoped to an explicit reload action for the Program Board surface. It should refresh the same project-filtered and all-project data the board already uses, without creating a parent workspace `.orchestrator/`.

## Acceptance criteria

- [ ] The Program Board header includes a reload button next to the Program Board title.
- [ ] Activating reload refreshes the current Program Board query for both All-project and selected-project views.
- [ ] The control exposes loading, success, and failure states clearly enough that repeated clicks do not look ignored.
- [ ] Reload failures keep the previous board data visible and surface the daemon error without crashing the board.
- [ ] The reload action does not create or depend on a workspace-root `.orchestrator/`.
- [ ] Tests or deterministic view-model coverage verify the reload action calls the expected Program Board data path.
