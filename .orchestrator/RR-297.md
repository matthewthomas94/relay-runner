## Description

Fix the Workspace ticket-detail panel so every ticket can be scrolled to its true first and last content boundaries on displays or Workspace surfaces smaller than the panel's current 560-by-633-point maximum. The current exact frame can extend above and below the visible modal surface; the inner ticket body still scrolls, but content and chrome outside the clipped panel frame remain unreachable.

Constrain the detail panel to the modal's available width and height while retaining the existing maximum dimensions on larger surfaces. Keep the ticket identity, title, close control, and action row visible inside the panel, and let the description, acceptance criteria, metadata, spike report, and attachments use the remaining body height through the existing native scroll container. Preserve mouse, trackpad, keyboard, custom scrollbar, edit/delete/copy/reveal actions, backdrop dismissal, and the existing create/edit modal behavior unless a shared sizing repair is demonstrably required.

## Acceptance criteria

- [x] A mounted regression hosts a long ticket detail inside a modal surface smaller than 560 by 633 points and proves the rendered panel frame stays fully within the available surface.
- [x] At the beginning of the scroll range, the first detail-body content is fully visible below the fixed ticket header and action row with no unreachable negative offset or clipping.
- [x] At the end of the scroll range, the final acceptance-criteria, report, or attachment content plus its intended bottom inset is fully visible above the panel edge.
- [x] Mouse wheel, precise trackpad deltas, Home/End or equivalent keyboard navigation, and the custom scroll thumb can reach the same exact top and bottom offsets without oscillation or forced relayout.
- [x] On surfaces at least 560 by 633 points, the ticket detail retains its existing maximum dimensions and visual hierarchy.
- [x] The identity/title block, close control, available action buttons, backdrop dismissal, and ticket selection remain usable at compact supported sizes.
- [x] Focused Swift tests cover compact and standard panel geometry plus both scroll endpoints using the mounted SwiftUI/AppKit hierarchy, rather than only testing a detached generic rectangle.
- [x] Existing BoardOverlayScrollView and Program Board status tests pass; any unrelated dirty-worktree or full-suite failures are reported without being attributed to this change.
