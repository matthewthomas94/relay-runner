## Description

Rebuild Relay Runner from the current integrated source and reinstall it at
`/Applications/Relay Runner.app`, while resetting Relay Runner to the state a
new user would see on first launch.

The only durable Relay Runner data to preserve is each project's repo-owned
`.orchestrator/` tree, including ticket files, `config.toml`, attachments, and
any repo-local workflow file. Before changing local app state, enumerate every
project known to Relay Runner plus projects discoverable from the configured
workspace, and record a temporary manifest and checksums for their
`.orchestrator/` trees. Abort the reset if any preservation target is ambiguous
or overlaps a deletion target.

Relay Runner-owned preferences, settings, onboarding sentinels, project
registry, run/session history, logs, stale worktrees, downloaded models,
virtual environments, caches, and bundle-scoped permission state are
disposable for this reinstall. Inspect the current source and filesystem first
so the cleanup uses exact app-owned paths rather than a broad home-directory
pattern. Do not touch source repositories, Git branches, Codex or Claude
credentials/history/configuration, unrelated agent skills or plugins, unrelated
application data, or privacy grants for parent apps. Relay Runner-managed
Codex and Claude skills or command shims may be removed and reinstalled if that
is part of the product's normal first-run setup.

Stage and verify the build artifact and a recoverable backup before the
destructive cutover. Account for the fact that the active Relay processes and
worker infrastructure use Relay Runner's Application Support directory: order
shutdown, cleanup, installation, and launch so the reset cannot strand an
unfinished worker or lose the preservation manifest. Do not use a global TCC
reset; only reset services associated with Relay Runner's installed bundle ID.
After verification, remove the old state from the active locations and report
the recovery location for any backup retained in Trash.

Use `scripts/build-dmg.sh` as the source-of-truth build/install path rather than
editing the installed app bundle directly.

## Acceptance criteria

- [ ] The build is produced from the current integrated Relay Runner source, `scripts/build-dmg.sh` succeeds, and the resulting app replaces `/Applications/Relay Runner.app`.
- [ ] Before cleanup, a manifest identifies every registered or workspace-discovered project with a `.orchestrator/` tree and records checksums for its preserved files.
- [ ] Every preserved `.orchestrator/` tree, including tickets, counters, attachments, and repo-local workflow files, is byte-for-byte unchanged after the reinstall.
- [ ] Git status for every preserved project shows no reset-induced changes outside any changes that already existed before this task.
- [ ] Old Relay Runner settings, onboarding state, program registry, run/session databases, logs, stale worktrees, models, virtual environment, caches, and app-specific defaults are absent from their active preinstall locations.
- [ ] Relay Runner's own relevant TCC entries are reset using its exact installed bundle ID; no global TCC reset and no reset of Terminal, Codex, Claude, IDE, or other parent-app grants occurs.
- [ ] Codex and Claude credentials, histories, configuration, unrelated plugins and skills, and other provider-owned files are unchanged; any Relay Runner-managed integration files are restored through the supported installer.
- [ ] Launching the installed app presents the genuine first-run onboarding flow with default settings rather than migrated prior state.
- [ ] The installed bundle is signed, launches from `/Applications/Relay Runner.app`, and remains running without an immediate crash.
- [ ] Any temporary preservation backup is outside Relay Runner's active data paths, its recovery location is reported, and no ambiguous or unverified data is permanently deleted.
- [ ] The final report lists the app-state paths reset, the project board paths preserved, build/install verification evidence, and any recovery or follow-up action.
