## Description

Relay Runner's screen-control and screenshot tools rely on macOS TCC grants that may be attributed to the parent app that launched the agent session, not only to Relay Runner itself. The product should guide the common supported parent apps explicitly.

Treat these as the default parent-app permission targets:

- Terminal.app, always, because the user may run Codex or Claude through the system terminal.
- Codex.app, always, because Codex is a first-class supported provider/app path.
- Claude.app, always, because Claude is a first-class supported provider/app path.

Relay Runner itself still needs its own app permissions where applicable, such as microphone and menu-bar app behavior. Other terminals such as Warp or iTerm can continue to be handled by runtime detection and messaging, but they should not block a simple first-run path for the default supported set.

## Acceptance criteria

- [ ] First-run onboarding or permission guidance clearly distinguishes Relay Runner app permissions from parent-agent app permissions.
- [ ] Terminal.app is included as a default guided target for relevant Screen Recording and Accessibility grants.
- [ ] Codex.app and Claude.app are included as first-class guided targets for relevant Screen Recording and Accessibility grants.
- [ ] The copy explains that macOS may attribute screen control or screen capture to the parent terminal/IDE/app that launched the agent session.
- [ ] Existing runtime detection for non-default parent apps remains intact and can still name Warp, iTerm, VS Code, Cursor, or other detected parents.
- [ ] Provider parity is preserved: Codex and Claude receive equivalent guidance unless a deliberate limitation is documented.
- [ ] Verification covers the visible onboarding/settings copy and the permission-preflight fallback copy.
