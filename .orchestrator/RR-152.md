## Description

Fix the Workspace typography regression visible after RR-151. The installed app screenshot at `/var/folders/xs/qtmf4y_s3_l3dd6b_2mxjj4c0000gn/T/TemporaryItems/NSIRD_screencaptureui_BXjMwr/Screenshot 2026-07-12 at 8.41.37 pm.png` shows headings, project names, ticket titles, metadata, paths, and action text rendering dramatically larger and heavier than the supplied Figma reference.

The RR-151 diff increased project titles from 13 to 16 SwiftUI points, ticket titles from 13 to 16, metadata from 10 to 14, and project paths from 10 to 12 while still using SF system fonts. That literal pixel-to-point translation does not match the installed macOS presentation.

Use the Figma typography families while calibrating SwiftUI point sizes to restore the compact hierarchy seen in the design:

- Root frame: `738:5819`
- Project card: `839:668`
- Ticket card: `843:999`
- Work column: `843:897`
- Reference: https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=738-5819

The exact fonts are already installed in `~/Library/Fonts` and resolve through Core Text:

- `PPMori-Regular` / family `PP Mori`
- `PPMori-SemiBold` / family `PP Mori`
- `PPTelegraf-Regular` / family `PP Telegraf`

Do not commit proprietary font binaries from `/Users/matthewthomas/Documents/Fonts/PP®F Starter Pack 5.2`. Add a small shared SwiftUI typography helper that uses the installed PostScript names when available and falls back to the current system font with the matching weight when they are absent. The code and tests must remain buildable on CI machines without the PP fonts.

### Typography mapping

- Keep the menu-bar Work/Terminal/Settings strip in SF Pro/system typography because the Figma menu-bar component explicitly uses SF Pro.
- Use PP Mori Semibold for Workspace and lane headings, project names, and ticket titles.
- Use PP Telegraf Regular for project paths, ticket ID/project metadata, counts/labels, Edit and session-control text, activity, dependency, error, and supporting copy.
- Restore compact runtime point sizes rather than retaining the literal Figma pixel values. Start from the known pre-regression scale: project and ticket titles around 13pt, lane/Workspace headings around 13–14pt, metadata/body around 10pt, and supporting captions around 9–10pt. Compare the rebuilt app against the Figma screenshot and adjust within that compact range; do not leave any 16pt card/lane titles simply because the Figma token says 16px.
- Keep title line limits and wrapping behavior functional, but common one-line titles such as `brain-stack`, `Backlog`, and `Test Ticket Title` should occupy the compact visual height shown in Figma. Long real ticket titles may wrap without making every card look like a hero card.
- Preserve all RR-151 layout, session state, edit controls, agent activity, drag/drop, selection, accessibility labels, and provider parity.
