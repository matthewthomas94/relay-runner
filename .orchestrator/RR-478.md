## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

Replace `services/relay_completion_hook.py` and `services/relay_reply.py` with Rust, as subcommands of the `relay-rs` workspace from the stage 0 ticket (for example `relay-rs hook ...` and `relay-rs reply`), accepted by the contract suite in `tests/contract/` and `docs/specs/hook-contract.md`.

Requirements:

- Behaviour matches the Python scripts for every case in the contract suite, with `RELAY_HOOK_CMD` and `RELAY_REPLY_CMD` pointed at the Rust binary.
- The SQLite access is compatible with the Python bridge, which keeps writing the same database (`/tmp/relay_intent_inbox.sqlite3`, WAL, `busy_timeout` 5000, `BEGIN IMMEDIATE`). Do not change the schema. Use bundled SQLite via `rusqlite`.
- Both providers switch in the same change: Codex's `-c hooks.*` registration and Claude's `--settings` hooks JSON in `Sources/relay-runner/Process/ProcessManager.swift`, the `--record-process`, `--record-codex-startup` and `--context-continuation` call sites, and `$RELAY_REPLY_HELPER` with every instruction and skill template that names `/usr/bin/python3 "$RELAY_REPLY_HELPER"` (`ProcessManager.swift`, `scripts/relay-bridge`, `services/instructions/`; regenerate with `scripts/build-instructions`).
- Rollback: one setting or environment variable makes the app register the Python hook and helper instead, for both providers. Keep the Python scripts bundled for this release.
- Update the Swift tests that assert on hook command text (`ProcessManagerLaunchTests`, `BridgeRestartDeliveryTests`, `WatchdogSessionRecoveryTests`).

Provider parity: no behaviour a Claude session sees may differ from what a Codex session sees beyond the differences that exist today; list those differences in the run log.

## Acceptance criteria

- [ ] The contract suite passes against the Rust binary and still passes against the Python scripts.
- [ ] A concurrency test runs the Rust hook against a database that a Python writer is updating and shows no lost or duplicated turn transitions.
- [ ] Claude and Codex sessions launched by the app register the Rust hook, and the rollback switch restores the Python hook for both.
- [ ] Measured median hook latency is lower than the Python figure recorded in the contract-suite ticket; both numbers are in the run log.
- [ ] `swift test`, `python3 -m unittest discover -s tests` and `cargo test` pass.
- [ ] A live check with each provider confirms a spoken reply is delivered once per turn; if a provider cannot be exercised on the worker machine, the ticket ends `verification_blocked` naming that check.
