## Description

Add a lightweight status command that shows current program/agent status in the existing response overlay without routing through speech or a provider model.

The user wants a quick way to pull the current state of workers/tickets and show it visually. This should not send a prompt to Codex, Claude, or any other LLM. It should not use TTS. It should query Relay Runner's own program/orchestrator status data and render the result as text inside the normal purple response overlay/pill.

Keep the first version narrow. A status command can summarize active workers first, with useful empty/error states. It should be available from a local app command surface such as a menu item, hotkey, or Relay Runner command action, rather than relying on speech recognition.

Provider parity matters only in the data shown: Codex and Claude workers should appear consistently in the summary, but invoking this command should not depend on which provider session is active.

## Acceptance criteria

- [ ] A user can invoke a local Relay Runner status command without speaking and without sending a prompt to Codex or Claude.
- [ ] The command queries local program/orchestrator status data directly, such as the existing Program Manager status path or equivalent daemon endpoint.
- [ ] The result appears in the existing purple response overlay/pill with compact text suitable for quick scanning.
- [ ] No TTS is synthesized or queued for this status response.
- [ ] The status text includes active worker/ticket information when available, including project name, ticket id/title, provider, and run state.
- [ ] Empty, unavailable-daemon, and error states render in the same overlay instead of failing silently.
- [ ] The overlay dismisses or times out using existing response/pill behavior.
- [ ] Tests or deterministic harness coverage prove the command bypasses provider prompts and TTS while rendering status text from local data.
