## Description

Relay Runner currently records raw Relay commands in durable private state and exposes APIs for orchestrator-authored ticket changes, but no autonomous backstage model loop consumes `received` project-work commands and turns them into refined visible tickets. That gap can leave the PM frontstage waiting or force it to author tickets directly.

Implement a real persistent orchestrator ticket-authoring loop so a live Relay session can fan out raw commands to private durable storage, have the backstage orchestrator resolve the target project and author or refine cold-start-safe tickets, and let the PM report concrete outcomes quickly.

## Acceptance criteria

- [x] Raw project-work commands recorded in the private command store advance through explicit durable states such as received, planning, authored, blocked, stale, or failed.
- [x] Authored commands link to the visible ticket id without storing raw transcript text in the ticket body.
- [x] The backstage loop starts or resumes from Relay Runner project activation without requiring the user to manually prime a foreground Codex or Claude session.
- [x] PM frontstage status can immediately report acknowledgement, then ticket-created, clarification-needed, blocked, or failed outcomes without silent waiting.
- [x] Stale-command checks still prevent older voice commands from editing tickets, dispatching workers, or speaking outdated TTS after a newer command arrives.
- [x] Codex and Claude paths provide equivalent behavior, with provider-specific process, auth, model, and effort differences documented in code or user-facing notes.
- [x] Tests cover command ingestion, state transitions, ticket creation without raw transcript leakage, stale-command rejection, and both provider launch paths where practical.
