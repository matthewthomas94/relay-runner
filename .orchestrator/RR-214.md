## Description

Fix Workspace ticket scrolling so users can reliably reach the true beginning
and end of ticket content. The current Work surfaces can stop short of the
first or last ticket or detail section even though more content remains.

Cover both ticket stacks in the board lanes and the scrollable body of an open
ticket detail panel. Reproduce the issue with real trackpad and mouse-wheel
input, then correct document sizing, content insets, clamping, and refresh
behavior so the visible endpoints match the intended layout padding rather
than an unreachable or prematurely clamped offset.

Also remove the `Open Workspace` action from ticket details. Project-specific
Workspace boards have been removed, so the button now advertises an obsolete
navigation model. Remove the corresponding detail-panel callback and
controller plumbing when it has no remaining consumer; retain the normal
Workspace navigation and current project filtering elsewhere.

## Acceptance criteria

- [ ] In every populated ticket lane, the first card can be returned fully to the intended top inset and the last card can be scrolled fully above the intended bottom inset.
- [ ] In ticket details, the first metadata row and the final description, acceptance, or image section can each be brought fully into view.
- [ ] Trackpad, mouse wheel, scrollbar-thumb, and keyboard scrolling reach equivalent top and bottom offsets without sticking short of either endpoint.
- [ ] The custom scroll thumb reaches the visual start and end of its track exactly when the document reaches its minimum and maximum valid offsets.
- [ ] Scrolling never exposes blank overscroll beyond the designed content insets or allows horizontal drift.
- [ ] Dynamic height changes from ticket refreshes, editing, image availability, window resizing, and content expansion recalculate document bounds without making either endpoint unreachable.
- [ ] Short ticket lists and short detail bodies remain aligned to the top with their intended insets and do not become artificially scrollable.
- [ ] Switching lanes, selecting another ticket, closing and reopening details, and changing project filters do not preserve an invalid offset from the previous content.
- [ ] The `Open Workspace` button no longer appears in ticket details.
- [ ] Removing the button also removes dead `onOpenProject` plumbing used only by that detail action, without affecting Workspace tabs, project filters, or opening the owning ticket file.
- [ ] Edit, Delete, Copy ID, Copy Path, Reveal, Close, drag-and-drop, and ticket selection behavior remain unchanged.
- [ ] Automated tests exercise exact minimum and maximum offsets, content insets, dynamic relayout, content replacement, short content, lane stacks, ticket details, custom-thumb position, and absence of the obsolete action.
- [ ] Manual verification covers long Backlog, Queued, In progress, and Done lanes plus a long ticket detail at supported Workspace sizes.
