## Description

Turn Relay Runner's existing static in-window permission drag guide into the supplied HeyClicky-inspired companion for every Relay Runner permission that opens a manually editable macOS Privacy & Security app list: Accessibility, Input Monitoring, and Screen Recording. Microphone remains Apple's ordinary consent dialog and must never show the draggable companion, but it still publishes a `Microphone` setup status in the notch. User Notifications and Apple Events/Automation are separate native system authorizations without an app-drop list; preserve their native-dialog behavior and do not show a misleading draggable helper for them.

When a non-microphone permission step begins, register/prompt the app with the appropriate TCC API, open the exact System Settings pane, and show the supplied 140×142-point borderless black companion with an approximately 16-point radius and no visible border beside the relevant System Settings window. Prefer the empty region about 32 points below the permission list; if that would cover rows or the `+` control, fall back outside the Settings window to its right, left, or bottom and clamp to the usable screen. The companion follows that window when it moves, resizes, or changes display and uses a deterministic bottom-center fallback while the window has not appeared yet. Its primary control is the real Relay Runner app icon at approximately 88–92 points with a short centered `Drag me` label. The icon must be a genuine AppKit file drag source for `Bundle.main.bundleURL`, emitting modern `public.file-url`/copy semantics that System Settings can accept when Relay Runner is absent from the privacy list.

Demonstrate the interaction with a visual-only false cursor and dragged-icon ghost: idle, approach the icon, press, drag toward the permission list/`+` target, release with a small plus/ring cue, hold, fade, and reset in a calm roughly 3.3-second loop. This animation must never move the user's real pointer, synthesize input, steal focus from System Settings, or block real clicks/toggles. Use a click-through transparent demonstration panel separate from the small interactive drag panel so the route can cross screen space without intercepting System Settings. Pause immediately on real hover/mouse-down/drag and resume only after a short idle period.

Use a shared AppState-owned permission coordinator rather than three hardcoded screens. It must sequence the existing prompt/registration calls and deep links without replacing AppState's current `PermissionsManager.onChange` recovery/notification observer. The notch label follows the active setup state (`Getting started`, `Microphone`, `Accessibility`, `Input monitoring`, `Screen recording`) through an explicit foreground override that remains visible for the permission's lifetime instead of retracting after the ordinary two-second working-label reveal. The existing one-second permission polling remains the source of truth, and granting the active permission dismisses the companion and advances the walkthrough automatically after a brief success acknowledgement. Skipping, changing step, closing onboarding, closing the permission-recovery action, or completing setup must tear down all follower/demo panels and timers. Screen Recording may require a relaunch; preserve the resume state and existing explanatory recovery instead of dead-ending when macOS cannot report the grant live.

Wire the shared request path into first-run/re-run onboarding, the existing Settings > Status recovery buttons, and app-hosted Relay Actions/Relay Vision first-use missing-permission callbacks so every explicit Relay Runner request behaves consistently. The tool still returns an actionable permission error to its caller while the app opens the same recovery experience. Refactor or reuse the current `PermissionAppDragGuide` / `AppFileDragView` implementation rather than leaving a second drag implementation or duplicate guide visible in the onboarding window. Do not change the runtime meaning of any permission: microphone gates voice capture; Input Monitoring enables global keyboard features; Accessibility enables app-hosted Relay Actions; Screen Recording enables app-hosted Relay Vision.

## Acceptance criteria

- [ ] Accessibility, Input Monitoring, and Screen Recording requests each register/prompt through their existing macOS API, deep-link to the correct Privacy & Security pane, and show one shared companion implementation; microphone shows only Apple's consent dialog.
- [ ] The companion discovers the on-screen System Settings window without requiring Accessibility permission, anchors outside the permission-list interaction area, follows move/resize/display changes, clamps to the usable screen, and has a deterministic centered fallback while discovery is pending.
- [ ] Window discovery filters the System Settings bundle/PID to a plausible on-screen layer-zero window through `CGWindowListCopyWindowInfo`, converts top-left bounds against the matching `CGDisplayBounds`/`NSScreenNumber` display (not primary-height-only math), and polls only while guidance is active; the helper hides when Settings is minimized, closed, on another Space, or no longer frontmost.
- [ ] The visible Relay Runner icon is loaded from the running `.app` bundle and can be dragged into System Settings as a standard file URL with copy semantics; starting a real drag from the current `mouseDragged` event pauses the tutorial loop and freezes follower movement until the dragging session ends.
- [ ] The nonactivating helper accepts the first mouse for dragging, applies a small movement threshold and one-session guard, stays below screen-saver level on the same Space as System Settings, keeps System Settings key, and disables the payload with clear install/reveal guidance when the running bundle is not a reachable `.app`.
- [ ] A fake cursor plus icon ghost visibly demonstrates pickup, travel toward the list/drop region, release, hold, and reset without changing the real cursor position, posting CGEvents, activating Relay Runner, or intercepting System Settings input.
- [ ] Notch setup labels map exactly to `Getting started`, `Microphone`, `Accessibility`, `Input monitoring`, and `Screen recording`; leaving setup restores the ordinary session/activity presentation rather than overwriting it permanently.
- [ ] Polling a non-microphone permission from missing to granted dismisses its helper and auto-advances once; if the grant arrives during a real drag, dismissal waits for the drag session to end. Step changes, Skip, window close, completion, and deinit clean up every panel, timer, workspace observer, tracking observer, and drag session reference.
- [ ] Settings > Status and app-hosted Relay Actions/Relay Vision first-use failures use the same shared request/companion behavior for missing non-microphone permissions, while microphone and non-list privacy authorizations continue to use their native prompts.
- [ ] The old embedded drag mock is removed or reduced to shared reusable pieces so users never see two simultaneous drag targets or conflicting instructions.
- [ ] The helper remains usable on small and multiple displays, does not cover the target privacy list, follows System Settings across Spaces where macOS permits, and fails gracefully if the Settings window cannot be discovered.
- [ ] Reduce Motion disables the fake-cursor/ghost loop and shows a static directional hint; VoiceOver announces the permission, purpose, draggable app name, and action without narrating animation frames.
- [ ] VoiceOver and keyboard users receive a non-drag alternative that reveals Relay Runner in Finder and explains using System Settings' `+` control; Increase Contrast and Reduce Transparency retain a clear opaque card/outline without relying on the green drop cue alone.
- [ ] Codex and Claude receive identical Relay Runner permission guidance; no parent-app or provider-specific TCC ownership copy is reintroduced.
- [ ] Pure tests cover permission-to-prompt/pane/proxy/notch planning, persistent notch precedence and restoration, follower placement/clamping and top-left-to-AppKit coordinate conversion (including negative multi-display origins), animation phases/Reduce Motion, lifecycle cleanup/one-shot auto-advance/grant-during-drag, hosted-tool callbacks, and drag payload construction; focused and full Swift suites pass.
