## Description

Build deterministic and mounted verification for the complete RR-332 through RR-335 continuity design. Prove that Relay Runner can detect a broken speech-to-work pipeline, launch an isolated continuity agent, recover Relay-owned runtime processing without unrelated side effects, and safely resume or request repetition. Persist a privacy-safe incident report and refined permanent-fix proposals when the core defect remains.

Automated evidence and signed mounted-app evidence must be recorded separately. The ticket may remain verification-blocked when authenticated real-provider or physical audio evidence is unavailable; it must not substitute worker exit, unit tests, or simulated playback for that external proof.

## Acceptance criteria

- [ ] A deterministic fault harness covers transcription dropout, capture interruption, bridge loss, messenger crash, foreground Codex and Claude hang or exit, daemon or IPC loss, stale session ownership, configured provider fallback, simultaneous component faults, and recovery-budget exhaustion.
- [ ] For recoverable cases, evidence shows incident classification, continuity-agent launch, broker actions, restored component health, canonical foreground handoff, and continued work without manual session restart.
- [ ] Verification proves no duplicate command execution, no duplicate TTS, no stale reply, no continuity-agent speech, no unauthorized project mutation, and no credential, transcript, repository, screenshot, raw-log, or external-data exposure.
- [ ] Pre-transcript speech loss produces a healthy listening state and an explicit repeat request; captured recoverable commands retain exact command and intent identity.
- [ ] A signed mounted-app lane correlates real speech capture, transcript or repeat outcome, provider acknowledgement, command lifecycle, and audio playback identifiers for both configured providers where the environment permits.
- [ ] Unresolved incidents persist a sanitized structured report and editable permanent-fix proposals; proposals require individual PM or user acceptance, enter Backlog, and never auto-dispatch.
- [ ] The run log separates automated source evidence, mounted app evidence, physical audio evidence, and any exact verification blocker or resume condition.
