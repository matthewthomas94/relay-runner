## Description

Add optional Settings configuration to connect GitHub later and create or select a private personal file repository, defaulting to <github-login>-rr-files under the authenticated user account. This is optional per the product decision: local sessions, notes and general work remain available without it. Reuse central notes and managed user-file storage, and existing canonical artifact/sync mechanisms where appropriate. The destination is for personal Relay notes and general-task artifacts; project tickets retain their actual repository ownership. Repository creation and upload occur only through the explicit storage-setup flow, not merely because the app was installed.

## Acceptance criteria

- [x] Users can skip GitHub setup indefinitely, connect later from Settings, and see local-only, pending, synced, conflict, auth-failure and disconnected status.
- [x] Authenticate the actual GitHub account, propose <login>-rr-files, and create the repository private only after the user enables this destination. Do not infer the owner from the macOS username.
- [x] Handle an existing name safely: verify repository owner, immutable identity, privacy and intended use before reuse. A public or unrelated repo is never silently adopted or made private.
- [x] Persist destination identity and credential references securely without committing tokens, provider auth, raw terminal traces or operational databases as personal files.
- [x] Sync approved central notes, general-task artifacts and eligible user files with stable identities, verified content revisions, offline queueing and explicit conflicts; project boards and source remotes remain unchanged.
- [x] Account changes, repository renames/transfers and changed remote URLs pause publication for revalidation; disconnect stops new uploads without deleting local or remote content.
- [x] Explain which notes and task files are synchronized and who can access the private storage repository.
- [x] Both providers use the same storage APIs and returned immutable artifact references. Test provisioning retries, name collision, permission loss, offline operation and conflicts without creating a real user repo during unattended tests.
