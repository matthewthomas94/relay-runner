## Description

Most current voice usage goes through Start Session or the `relay-bridge` skill/command, where the agent itself reads `/tmp/voice_cmd_ready` and writes concise TTS responses. That path now supports Codex and Claude.

There is still legacy direct-mode code in `services/voice_bridge.py` and related TTS filtering that is Claude-shaped: comments and class names refer to a persistent Claude session, direct mode shells out to `claude`, and `services/tts_filter.py` primarily strips Claude Code terminal/status output. If this direct mode is still intended to be a supported product surface, it needs Codex parity. If it is not intended to be supported anymore, it should be clearly marked legacy or removed from the user path so future work does not assume it works for Codex.

Make an explicit product/engineering decision and implement the smallest safe follow-through.

## Acceptance criteria

- [ ] Identify whether direct/full voice terminal mode is still reachable from user-facing app/script flows.
- [ ] If direct mode remains supported, add Codex support or document exactly why Claude-only direct mode is intentional.
- [ ] If direct mode is legacy, update script/help/docs/comments so Start Session plus manual `relay-bridge` skill/command are the documented supported paths.
- [ ] If Codex terminal output can flow through `services/tts_filter.py`, add or verify Codex UI/status filtering so speech does not read raw CLI chrome.
- [ ] Do not regress the current relay-mode path used by Codex and Claude skills.
- [ ] Verification includes `swift build` if Swift paths change, and Python syntax/tests or focused smoke checks for any Python changes.
