## Description

The user finds Relay Runner's spoken replies too long, and finds that they read out highly structured text word for word: full file paths, full web addresses, commit hashes, long ids. That is not natural English and is tiring to listen to.

The user wants one general rule, not a fix for paths and links alone: **anything spoken must be concise natural language. Highly structured, non-language text (file and folder paths, URLs, commit hashes, UUIDs, run and command ids, shell commands, code, JSON, long numbers) is never read out verbatim. It is said by what it refers to, the way a person would say it.**

Examples of the intended spoken form:

| On screen | Spoken |
|---|---|
| `/Users/matthewthomas/dev/relay-runner/Sources/relay-runner/Settings/SettingsWindow.swift` | "the Settings window file" or "SettingsWindow.swift" |
| `https://github.com/matthewthomas94/relay-runner/pull/61` | "pull request 61 on GitHub" |
| `d63527b6` | "the merge commit" (or omitted) |
| `11130-1795570645559451000-64` | omitted |
| `~/Library/Application Support/relay-runner/general-tasks` | "the general tasks folder" |

### Where the problem comes from

`rust/relay-rs/src/bridge/messenger_runtime.rs` speaks the PM's authoritative final reply **word for word** (see its module doc and `submit_final`). The only processing before speech is `strip_markdown_for_tts` in `rust/relay-rs/src/bridge/speech.rs`, which removes markdown markers but keeps paths, URLs and ids. So whatever the PM writes as its terminal answer, including bullet lists, full paths and links, is read aloud.

The PM's startup instructions are built in `Sources/relay-runner/Process/ProcessManager.swift` (the block that begins "You are the app-owned foreground Relay orchestrator/PM", around the line "The messenger is tool-free and not authoritative"). The orchestrator's fuller instructions live in the source that generates `Sources/relay-orchestrator-mcp/Instructions.generated.swift` (find the generator; do not hand-edit generated output), in the "Voice turns" section.

### What to change

1. **PM instructions (both providers).** In the PM startup prompt and the "Voice turns" section of the orchestrator instructions, add the spoken-form rule above, plus:
   - The spoken final for a voice turn is one to three short sentences in natural language: the outcome and the next step, nothing else.
   - When the terminal answer needs detail (lists, paths, links, ids, test counts), the PM keeps that detail in its terminal message and pipes a short spoken version through the session's reply helper as its last reply of the turn, which the existing contract already makes the authoritative spoken final. The terminal answer is not shortened by this rule.
   - Keep the wording short; these prompts are already long.
2. **A deterministic safety net in the speech path.** Add a function (for example `speakable_text`) in `rust/relay-rs/src/bridge/speech.rs`, applied after `strip_markdown_for_tts` wherever text is turned into speech, so it also covers messenger output and worker lifecycle speech, not only PM finals. Check every path that submits text to speech and apply it once in the shared path. It rewrites, at minimum:
   - URLs (with or without a scheme, including `www.`) into the site name, for example "github.com"; GitHub pull request and issue links into "pull request N on GitHub" / "issue N on GitHub".
   - Absolute, home-relative (`~/`) and long relative file paths into their last component (the file or folder name).
   - Hex strings of 7 or more characters that look like commit hashes, UUIDs, and long numeric or dash-joined ids are removed, then the leftover spacing and punctuation tidied.
   - It must leave ordinary speech alone: version numbers like 0.8.0, times, decimals, dates, sentence punctuation, abbreviations such as "e.g.", and words that contain a slash in normal prose ("and/or", "on/off").
   - The notch's display text (`display_text`) keeps the original text; only the spoken text changes.
