## Description

For George (the user asked for this to go to George). In the Relay Remote iPhone app (`ios/RelayRemote`), when Replies is set to Queue (not auto-play), a new reply currently appears as a "New reply from <agent>" card with a Play button (`AgentChatFeed`, `AgentsScreenState.WaitingReply`, `AgentsScreenActions.play`), and Play morphs that card into the reply's chat bubble. The user no longer wants that.

**New behaviour:**
- A queued reply's text arrives straight into the chat as a normal agent message bubble, the same as an auto-played reply, with no "New reply" card and no card-to-bubble morph.
- The dock's existing Replay control plays it. While the selected agent has a reply that has not been played yet, that control plays the newest unplayed reply (the same playback as today's Play: `SpeechPlaybackQueue.play(seq:skipping:)`, skipping only that agent's older unplayed replies). While it has not been played, the control reads **Play** with the play icon; once it has played, it reads **Replay** with the replay icon and behaves as Replay does today (sends `replay` for the selected agent). The swap uses `.relayControlSwap`.
- Stop, Cancel, the talk button and auto-play mode are unchanged. Notifications and the agent tab marks for unplayed replies keep working.
- Remove the now-unused "New reply" card, its morph and any state that only served it.
- Tutorial: the "Wait for a reply, then tap Play" step (`TutorialView`, design screen 18) points at the dock's Play control instead of the card, and advances when it is tapped.
- Update the debug samples that show the waiting card (`--agents-sample=ready`, `play-demo`, the tutorial play step) and the tests that assert the card.

**Overlap:** RR-553 lists "the New reply card turning into the reply on Play" among the transitions to smooth; this ticket removes that card, so skip it there. Both touch the Agents files, so do them one after the other.

Figma (file `IGjwpE5m7vLaCThHgoy0cw`, section "Relay Remote (iOS) · Final") still shows the card on screens 21 and 18; this ticket's behaviour wins.

## Acceptance criteria

- In Queue mode a new reply shows as a normal chat bubble at once; no card appears.
- The dock control reads Play while the selected agent has an unplayed reply, plays it, then reads Replay; Replay then replays as today.
- Switching agents shows Play or Replay for that agent's own state.
- Auto-play mode, Stop and Cancel behave as before.
- The tutorial's play step works with the dock control.
- Existing iOS tests pass, updated where they asserted the card, with tests for the Play-then-Replay control state.
