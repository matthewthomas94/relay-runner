## Description

Large pieces of work often get split into several tickets, but not every ticket in the set should dispatch at the same time. Some tickets are known, refined, and intended to run next, but must wait for predecessor tickets to finish first to avoid worktree collisions or sequencing problems.

The board should represent that state more accurately. Tickets that are ready for development but blocked by explicit `depends_on` predecessors should be able to live in the Ready for Dev column as queued work, rather than being pushed back into Backlog. Backlog should remain the place for unrefined or not-yet-actionable ideas; Ready for Dev should include work the orchestrator already understands and intends to dispatch once dependencies clear.

This needs to reconcile with the current rule that moving a ticket to Ready for Dev triggers dispatch. A dependency-gated Ready ticket should not launch a worker until all dependencies are done. Instead, it should visibly wait on those dependencies and then dispatch automatically when the dependency chain clears.

Provider parity matters. The queued/dependency-gated behavior should be provider-neutral for Codex and Claude workers, with provider-specific launch details remaining outside the board-state model.

## Acceptance criteria

- [ ] A ticket with `status: ready` and unsatisfied `depends_on` predecessors can remain visible in Ready for Dev without being dispatched immediately.
- [ ] Project Board and Program Board clearly mark dependency-gated Ready tickets as waiting, including which predecessor ticket or tickets are blocking them.
- [ ] Moving or saving a ticket into Ready for Dev with unsatisfied dependencies does not produce a failed dispatch error or move the ticket back to Backlog.
- [ ] When all dependencies become `done`, the queued Ready ticket dispatches through the existing worker path without requiring the user to move it again.
- [ ] Backlog remains reserved for unrefined or not-yet-actionable work; dependency-gated but otherwise refined work is not hidden there by default.
- [ ] Codex and Claude workers use the same dependency-gated Ready behavior, with any provider-specific limitation documented if one exists.
- [ ] Add tests covering ready-with-unsatisfied-dependencies, dependency completion auto-dispatch, and board rendering for the waiting state.
