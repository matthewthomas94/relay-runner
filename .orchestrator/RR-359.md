### Smallest coherent product

The user opens a standalone app, sees local storage/model readiness, explicitly selects microphone plus computer audio, and starts a session after seeing capture scope. A persistent recording indicator and independent source meters remain visible. During recording, they type manual notes beside an incremental timed transcript. Stop ends capture first, finalizes queued local transcription and leaves an editable session. History/search, manual transcript/speaker corrections, optional generated notes, Markdown export, audio retention, delete and interrupted-session recovery complete the workflow.

No account or LLM is needed to take notes, record or read a session. A missing model may allow a clearly labelled record-for-later mode after confirmation; it must never silently upload audio. Microphone-only degraded recording is an explicit choice when system permission is unavailable. No automatic meeting detection/recording in MVP.

Non-goals: Git/GitHub/cloud synchronization, collaboration, calendar integrations, bots, cross-app/project memory, source ingestion, web research from notes, automatic ticket creation, meeting-content access for Relay agents, biometrics/global voiceprints, mobile clients, a plugin system, arbitrary agent tools and cloud ASR.

### Canonical data contract

Proposed local application-support root is owned only by the new app and is outside every checkout, .orchestrator directory and Relay artifact repository. SQLite is canonical for structured state; bounded audio chunks are separate files referenced by IDs. Search is a rebuildable local index. The application is the sole writer; Relay never reads the DB directly.

| Record | Stable identity and minimum fields |
| --- | --- |
| Session | session_id UUID; title; UTC created/started/ended; monotonic media timeline; explicit capture/processing states; locale; selected sources; retention choice. |
| Capture epoch / media chunk | media_id UUID and epoch_id; session_id; source mic/system; monotonically increasing sequence; start/end sample positions, rate/channels, relative path, checksum and committed flag. Device changes create epochs and gap events. |
| Transcript segment | segment_id UUID; session_id; media/epoch references; start/end milliseconds on the session timeline; source channel; optional speaker_id; raw recognized text plus separate user correction; engine/model revision and processing generation. Partial results are provisional, not appended as duplicate final rows. |
| Speaker | speaker_id UUID scoped to one session; display label; assignment provenance/confidence. Microphone/system are source labels, not proof of personal identity. Unknown stays unknown; user labels win. |
| Manual note | note_id UUID; session_id; Markdown body, revision, timestamps. Never overwritten by ASR or summaries. |
| Summary | summary_id UUID; session_id; source revision/hash; provider/model/template version; status; generated text with cited segment IDs; separate user edits. Transcript/note changes mark it stale. |
| Job | job_id UUID; session_id; job type; model/source generation; committed processing cursor; state and retry data. Replays are idempotent; cancellation is scoped. |
| Attachment seam | media_id/attachment_id and opaque local reference when needed for the session. General document ingestion is deferred. |

No full event-sourcing platform or sync protocol is required. Establish the small record/API contract once in the foundation ticket so storage, audio, ASR and UI can work independently against deterministic fixtures.

### Recording, durability and deletion contract

State sequence: idle → preparing → recording → stopping → finalizing → complete, with explicit interrupted/recoverable and failed states. Capture-source readiness is separate from ASR readiness. Stop speech playback, stop capture and cancel generation are distinct actions. Closing Relay or ending a Relay agent session does not stop the meeting app.

Write bounded chunks and publish their manifest entries only after file finalization; persist transcript/job cursors transactionally. On restart, reconcile incomplete files and resume from the last committed cursor without duplicate segments or overwriting user edits. Preserve evidence of missing audio and offer recovery/discard; never call an interrupted session complete. Proposed process-crash loss budget is at most one 5-second uncommitted chunk; filesystem/power-loss guarantees must be documented and measured separately.

Proposed default retention is delete raw audio after successful final transcription, with an explicit keep-audio option. Interrupted/untranscribed audio is retained for recovery until success or user discard. Make this visible before capture; the choice is a proposal to confirm in the first ticket. Deleting audio preserves notes/transcript; deleting a session cancels its jobs and removes DB rows, owned media, summaries, search entries and temporary/checkpoint files. A durable deletion marker prevents late callbacks recreating it. Report failure/retry rather than claiming complete deletion. User-created exports and OS backups are outside app-managed deletion; do not promise secure physical erasure.

### Privacy, models and generated notes

Request microphone and system-audio access with purpose strings and a visible start/stop flow. Core Audio taps are an Apple-supported path requiring system-audio disclosure; test actual permission behavior in a stable signed identity. Capture scope is visible, no hidden capture or remote recording command. [Apple capture documentation](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps).

No transcript, note, title, audio or summary enters Relay's FIFO, support bundles, ticket prose or provider logs automatically. Operational logs carry IDs/status/durations, not content. No analytics/session replay or cloud sync in the MVP. Private local storage still inherits the user's filesystem/backup security; application-level encryption of the entire DB/media/index is a separate explicit threat-model decision, not an unverified claim.

Initial optional generation is a user-configured local OpenAI-compatible endpoint, or explicit BYO OpenAI/Anthropic credentials. Before a remote request, show the endpoint, exact model and included transcript/notes; transmit only the selected text. Store credentials in Keychain, disable implicit fallback, retain manual notes when offline and record stale/generated provenance. Local failure never selects a hosted provider. Generation is tool-free; meeting text is untrusted input and cannot send mail, execute commands or create tickets. No automatic use of Codex/Claude CLI sessions or inherited credentials. Relay launch behavior and privacy are identical regardless of which agent provider is active; remote API differences need separate adapter tests.

### Performance evidence and future validation

The pinned FluidAudio [benchmark document](https://github.com/FluidInference/FluidAudio/blob/57551cd90e0bbec342766244358bcf08afb05290/Documentation/Benchmarks.md) reports Parakeet v3 on a 2024 M4 Pro MacBook Pro with 48 GB RAM and macOS 26: its FLEURS English row is 5.4% WER and 207.4x throughput across 350 samples/3442.9 seconds. This is an upstream batch-dataset result. It does not measure simultaneous mic/system capture, meeting overlap, UI latency, thermal contention or the user's Mac; the model artifact hash is not specified in that result. No competitive speed ranking or local performance claim is made here.

The first follow-up must record hardware/OS, app and dependency SHAs, model URLs/hashes/terms/size, fixture consent/provenance and exact commands. Compare short clean speech, jargon/accented speech, overlap and silence, then a 60-minute dual-source fixture; run three repetitions after separate cold/warm setup. Measure p50/p95 first/final text latency, WER, speaker error when applicable, timeline drift, dropped/duplicated audio, queue growth, CPU/GPU/ANE activity where observable, peak RSS, storage growth and thermal behavior. Compare normal capture with Relay voice/TTS active, built-in/wired/Bluetooth devices, sample-rate switches, permission denial/revocation, sleep/wake, app crash and low disk space. Do not interrupt an unrelated live meeting to test.

Proposed decision targets, not measured results: p95 visible transcript under 3 s for the selected live mode; sustained processing faster than incoming audio without unbounded queues; timeline drift under 250 ms over 60 minutes; recover all committed chunks and at most 5 s process-crash loss; no missing tail after Stop; no meeting-content network traffic in local mode. Set fixture-specific accuracy/resource thresholds before running, based on the intended Mac/language scope. If unmet, narrow the product or revise the engine/fork choice and keep downstream work gated.
