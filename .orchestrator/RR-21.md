## Description

The local board should feel repo-scoped from the first use. If the active `/relay-bridge` session is rooted in a repo named `mouse-assist`, new board tickets should be `MA-1`, `MA-2`, etc. In this repo, `relay-runner` already uses `RR-*` through `.orchestrator/config.toml`.

Today the board writer reads `.orchestrator/config.toml` and mints IDs from its `prefix` and `next_id`, but fresh repos do not appear to get that config initialized automatically. `ProjectResolver` also refuses to resolve a project unless `.orchestrator/` already exists, so a brand-new git repo cannot naturally open an empty board and create its first ticket.

Implement first-time board initialization for any active bridge cwd that is a git repo:

- If `.orchestrator/config.toml` already exists and is valid, preserve it exactly.
- If `.orchestrator/` or `config.toml` is missing, create it with a repo-derived prefix and `next_id = 1`.
- For hyphenated or underscored repo names, derive the prefix from word initials: `relay-runner` -> `RR`, `mouse-assist` -> `MA`.
- Keep the prefix override path intact: users can still edit `config.toml` manually before creating tickets.

After this change, starting a bridge from a fresh `mouse-assist` repo and opening the board should show an empty board. Creating the first ticket should write `.orchestrator/MA-1.md` and bump that repo's config to `next_id = 2`.

Likely touchpoints:

- `Sources/relay-runner/Board/ProjectResolver.swift` — allow a live bridge cwd that is a git repo to resolve, even before `.orchestrator/` exists, or initialize before resolving.
- `Sources/relay-runner/Board/TicketWriter.swift` — initialize missing config before claiming `next_id`; centralize the prefix derivation here or in a small shared helper.
- `docs/specs/orchestrator-tickets.md` / `docs/orchestrator.md` — document the actual first-time init behavior.

## Acceptance criteria

- [ ] A live bridge rooted in a git repo without `.orchestrator/` can open the board instead of showing the "No session running" pill.
- [ ] Opening the board or creating the first ticket initializes `.orchestrator/config.toml` with a repo-derived `prefix` and `next_id = 1`.
- [ ] A repo named `mouse-assist` initializes with `prefix = "MA"` and its first minted ticket is `MA-1`.
- [ ] Existing repos with a valid `.orchestrator/config.toml` keep their configured prefix and counter; Relay Runner's existing `RR-*` board is not changed.
- [ ] Missing config is handled gracefully; invalid config should surface a clear log/error and should not silently mint a malformed ticket.
- [ ] Prefix derivation is covered by focused tests or an equivalent small verification harness for at least `relay-runner -> RR`, `mouse-assist -> MA`, and a single-word repo name.
- [ ] `swift build` passes.
- [ ] Manual verification: create a temporary git repo named `mouse-assist`, simulate or run an active bridge cwd there, open the board, create a ticket, and confirm `.orchestrator/MA-1.md` plus `next_id = 2`.
