## Description

Fix the remaining installed-app regression where the first Backlog card does
not reliably receive hover and click events in the Workspace.

RR-254 (`05faba8`) is an ancestor of the currently packaged `main`, and its
stable scroll-document hit-routing code is present in the installed binary.
Its focused synthetic tests passed, but the user has now repeated the missing
hover/click behavior in the real mounted application. Treat that as evidence
that the accepted tests still omit part of the actual window-to-panel-to-scroll
document event path.

Trace the genuine mounted pointer route and make the smallest correction.
Preserve scroll, drag, drop-strip, card identity, selective interception, and
non-draggable card behavior. Do not claim success from direct containment or
isolated `hitTest` calls if the actual mounted event is still routed elsewhere.

## Acceptance criteria

- [ ] A regression test fails on current `main` using the mounted Workspace hierarchy and the same event path used by a real mouse or trackpad.
- [ ] Entering the first Backlog card immediately applies its hover state and expected cursor without requiring a click, scroll, tab switch, or window refocus.
- [ ] Clicking the first Backlog card selects and opens that exact ticket once.
- [ ] Top, center, and bottom regions of the first card resolve to the first card after initial mount and after scrolling.
- [ ] Second and later cards retain correct hover, click, and drag identity; drop strips and non-draggable cards remain distinct.
- [ ] Snapshot replacement, prepend/reorder/height changes, scope changes, tab transitions, and window activation do not leave stale pointer ownership.
- [ ] Coordinate conversion is verified across screen, window, content, clip, document, and flipped-view spaces where they participate in the mounted route.
- [ ] Focused `BoardOverlayScrollViewTests` and `ProgramBoardStatusTests` pass without deleting RR-254 identity-specific lifecycle coverage.
