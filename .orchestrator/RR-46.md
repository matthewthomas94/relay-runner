## Description

Add the smallest useful code-indexing slice for Graphify in the Program Manager MVP.

This is not full semantic code intelligence. Start with a per-project file manifest and text index over important repo files, enough for the program layer to answer basic "what files/docs may be relevant?" questions without live-grepping every repo.

Use RR-37's research recommendation. Defer Tree-sitter symbol graphs, SCIP import/reference graphs, and vector search unless the research says a small piece is cheap and necessary.

Provider parity matters indirectly: code-index data should support both Codex and Claude workers by being provider-neutral context available through the program graph/query layer.

## Acceptance criteria

- [ ] Each registered project can maintain a file manifest with path, size, mtime or hash, language/type, and last indexed time.
- [ ] Re-indexing changed files is incremental and does not rescan unchanged files unnecessarily.
- [ ] Important text files can be searched through the program query layer without ad hoc live `rg` over every repo.
- [ ] Indexed files are linked to Project nodes and, where straightforward, Ticket/Initiative context.
- [ ] The implementation excludes common heavy directories such as `.git`, build outputs, dependency directories, and generated caches.
- [ ] Deep Tree-sitter/SCIP/vector functionality is either absent or explicitly behind a documented extension point.
- [ ] Tests cover initial indexing, incremental re-indexing, ignored directories, and search over indexed content.
- [ ] Existing Program Manager graph/status behavior remains provider-neutral.
