## Description

Integrate terminal-only retention with the orchestrator daemon, archive catalog, dependency model, and Graphify projection. Expose preview, apply, blocked status, history search and detail, restore or reopen, attachment retrieval, and truthful storage metrics. Ensure event-driven reevaluation keeps every nonterminal ticket materialized while older Done-or-Canceled tickets remain discoverable after their local files are removed.

## Acceptance criteria

- [ ] Daemon endpoints expose retention preview, apply, status, exact retained-terminal IDs, eviction candidates, temporary overage reasons, transaction state, and retry actions without requiring direct file inspection.
- [ ] Retention reevaluates after canonical ticket status or activity changes, sync completion, lease changes, dependency transitions, restore or reopen, daemon restart, and recovery from a blocked transaction.
- [ ] History search and detail include terminal tickets removed from local materialization, stream and verify remote-backed content when needed, and do not eagerly recreate Markdown files merely to view a ticket.
- [ ] Restore and reopen are idempotent canonical operations: restore deliberately materializes selected history, while reopen makes the ticket nonterminal and therefore uncapped and immediately materialized.
- [ ] Archived Done-or-Canceled predecessors continue satisfying active dependencies from catalog metadata, with tampered, missing, or unavailable history surfaced explicitly.
- [ ] Graphify retains metadata-only nodes for archived terminal tickets instead of deleting their searchable history when materialized Markdown disappears.
- [ ] Attachment retrieval is explicit, validated, bounded by existing ownership and type policies, and does not permanently exempt an older terminal ticket from the 25-ticket pool.
- [ ] Storage metrics separately report materialized ticket and attachment files, retained terminal count, total nonterminal count, temporary overage, remotely backed history, reachable Git objects, indexes, caches, databases, and run logs.
- [ ] Focused service and client-contract tests cover hundreds of archived terminal records, restart and concurrent reevaluation, offline history, restore and reopen, dependency summaries, Graphify ingestion, and malformed or tampered catalog entries.
- [ ] All APIs and stored states are provider-neutral for Codex and Claude.
