## Description

Change worker completion handling so completed worker tickets go to the persistent orchestrator for technical review, retry/fix decisions, merge, and done-state publication.

The current flow leaves integration to the foreground session or human after a worker succeeds. RR-127 moves technical acceptance to the orchestrator. When a worker completes, the orchestrator should inspect the branch/run evidence, decide whether to accept, request fixes/retries, or split follow-up work, then merge accepted work and move tickets to `done`.

The PM should keep fetching and summarizing status, but should not be the technical reviewer.

## Acceptance criteria

- [ ] Worker run success triggers or exposes a review-needed event for the persistent orchestrator.
- [ ] The orchestrator can inspect worker run logs, ticket run logs, branch diffs, and verification evidence.
- [ ] The orchestrator can request a fix/retry or additional tickets when work is incomplete.
- [ ] When accepted, the orchestrator merges the worker branch, resolves expected ticket-state updates, prunes the worker worktree/branch, and publishes the ticket as `done`.
- [ ] Dependency progression continues to work after orchestrator-owned merge/done publication.
- [ ] PM status fetching reports review, retry, merge, done, and failure states clearly.
- [ ] Add tests/harness coverage for accept, reject/retry, merge conflict handling, done-state publication, and dependency auto-progression.
