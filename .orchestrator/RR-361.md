## Description

The live Workspace board stopped reflecting new tickets and merges, retaining a snapshot whose newest ticket was RR-358 even though RR-360 was canonically Done with merged run 131. Refresh takes too long and eventually cannot retrieve updated status. Diagnose and fix the underlying resource and latency cause rather than only restarting or increasing limits.

Foreground evidence on 2026-09-19: installed orchestrator PID 82892 on port 7634 responds to health and run queries, but GET /v1/program/status terminates the connection without a response. Its stderr records OSError errno 24 Too many open files at graphify_ingest._git -> subprocess.run -> os.pipe during ingest_registered_projects archive-catalog inspection. A bounded lsof snapshot showed 243 TCP sockets: 217 CLOSED, 21 CLOSE_WAIT, four ESTABLISHED and one LISTEN. Open HTTP sockets dominate the resource inventory; this suggests retained or blocked request lifecycles, not proof of a SQLite leak. The exact retention cause remains to be established. The live log is /tmp/relay_orchestrator.err; a one-second native process sample is /tmp/relay-board-refresh-55.sample.txt. These are transient diagnostic inputs, not files to copy into committed artifacts.

Relevant paths: services/orchestrator.py HTTP Handler/_bind_port and program_status/program_dashboard; services/graphify_ingest.py ingest_registered_projects/_archive_catalog_tickets/_git; services/graphify_core.py; Board/OrchestratorClient.swift, ProgramBoardStatus.swift and ProgramBoardOverlayController.swift. Dashboard refresh synchronously sweeps and ingests registered projects; ingestion reads the archive through subprocess calls. Establish which requests retain sockets/threads, whether lock contention, failure handling or retries prolong them, and what repeated ingestion contributes to latency. Inspect the installed/runtime source boundary before attributing behavior solely to checkout code.

Make the smallest proven fix that bounds request/resource lifetimes and makes board refresh promptly reflect authoritative ticket/run changes. Coalesce redundant expensive refresh work or avoid unchanged archive rescans only where measurements establish the need; invalidate correctly on project, artifact and run changes. Preserve canonical artifact history checks, project scope, dispatch and authorization semantics. Surface refresh failure or stale state clearly if the UI currently silently presents old data. Do not weaken verification or hide failures by serving an indefinitely stale cache.

Keep the active foreground voice session and unrelated work intact. Do not edit bundled app scripts, kill/restart the active daemon, raise system limits or alter live databases as an implementation shortcut. Deliver through normal source review/merge. Explicitly identify the safe deployment/restart and installed-app verification needed after merge; if live validation is outside the isolated worker's authority, record that exact outstanding boundary without claiming live recovery.
