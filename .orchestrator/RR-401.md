## Description

Agreed spec: background sessions are silent and their finished replies show as a badge. Today `services/relay_reply.py` sends no session key, and the bridge's `__ORCHESTRATOR_REPLY__` handler (`services/voice_bridge.py` ~3913) checks every reply against the focused session's state and dedupes by (seq,id) only, so a background reply is either dropped as superseded or spoken.

Implement RR-393 slices E and F:
- Add session key and provider_session_id to the reply-helper payload. The bridge validates each reply against its origin session's state, dedupes by (session_key, seq, id), speaks only if that session is focused, and otherwise records a badge entry.
- Per-session badge store: unread count and the last few reply texts with command keys. Project cards and Workspace terminal tabs show the badge; it clears when the session is focused.
- On focus switch while TTS is playing for the old session: stop playback, end that messenger generation, and keep the full reply in the old session's badge. Never cancel the provider command because focus changed.
- Worker lifecycle outcomes (`messenger_outcomes`, polled by repo_path): leave a background project's outcomes undelivered, show their count in the badge, and deliver them as the existing 'N updates accumulated' summary on refocus.
- No automatic spoken replay; add an explicit read-out action that uses `__REPLAY__`.

## Acceptance criteria

- [ ] A reply from background session A is not spoken while B is focused, and A's card and tab show an unread badge.
- [ ] Focusing A clears its badge; nothing is spoken automatically; the read-out action speaks the stored reply.
- [ ] A background reply is validated against A's own command state and is not dropped as superseded by B's newer command (test).
- [ ] Switching focus mid-TTS stops playback and stores the full reply in the old session's badge; the provider command keeps running.
- [ ] Background worker outcomes are counted in the badge and summarised once on refocus.
- [ ] Same behaviour for Codex and Claude sessions; Swift and Python tests pass.
