## Description

Investigate and fix an intermittent notch glyph hover glitch seen while the bridge is in a working/reading state and trace text is being shown.

User-observed behavior: when hovering over the glyph, roughly half the time the notch does not hold its expanded trace carousel state. Instead it repeatedly shoots outward and contracts back in several times while working-state trace text is being read or updated. Other times it behaves correctly: it holds open and carousels through the text. The bad behavior looks like an animation/state-machine oscillation rather than an intentional transition.

Keep this focused on stabilizing the glyph hover and trace presentation interaction. RR-125 covers the broader trace-streaming feature; this ticket should make the resulting hover/expanded state feel steady and intentional.

Likely areas to inspect include the notch/glyph hover state, working-state label updates, trace carousel timing, and any animation transitions that respond to both hover and compact activity changes.

## Acceptance criteria

- [ ] Reproduce or isolate the hover/working-state oscillation with a deterministic test, harness, or documented manual scenario.
- [ ] Hovering the glyph while working trace text is active expands the notch once and holds a stable expanded presentation.
- [ ] Trace text/carousel updates do not cause repeated expand/contract animation loops while hover remains active.
- [ ] The notch collapses only when hover ends or the relevant activity state exits, not on each trace update.
- [ ] The fix preserves the darker notch styling and does not reintroduce liquid-glass visual treatments.
- [ ] Add focused regression coverage where practical, or document why the behavior is only manually verifiable.
- [ ] Add a short verification note describing the manual hover test in a voice/working-state session.
