## Description

Reframe Relay Runner setup around one explicit "Workspace folder" choice instead of asking the model or user repeatedly whether the current folder is a project or multi-project workspace.

The first-run app setup should ask for the provider/model and the workspace folder. Settings should expose the same concept with clear naming such as "Workspace folder" or "Start sessions in". Once set, the app owns that choice and Program Manager discovers projects underneath it.

Keep migration conservative: existing "working directory" settings should continue to work, but should be interpreted through the new workspace/project classifier from RR-47.

Provider parity matters. Codex and Claude setup paths should present equivalent workspace-folder behavior even if their model/provider controls differ.

## Acceptance criteria

- [ ] First-run setup includes a required workspace-folder selection alongside provider/model setup.
- [ ] Settings rename or reframe the existing working-directory control as the workspace folder or session start folder.
- [ ] Changing the workspace folder refreshes Program Manager discovery without requiring model-side classification prompts.
- [ ] Existing persisted working-directory users migrate without losing their configured folder.
- [ ] Copy and UI behavior avoid implying the selected parent folder is always a project repo.
- [ ] Codex and Claude setup paths have equivalent workspace-folder behavior, with documented provider-specific differences if any.
- [ ] UI or integration tests cover first-run setup, settings migration, and workspace-folder changes.
