## Description

Fix the replay experience so a user can see the transcript for a message when replaying it, even if they did not play or hear that message when it first arrived.

The likely product expectation is that transcript text is captured and retained when a message is received, not only when playback is first started. Replaying a queued or previously skipped message should therefore surface the same transcript text that would have been visible during first playback.

Keep the behavior consistent across Codex and Claude Relay sessions. If the providers differ in how message metadata or replay controls are delivered, document the difference and preserve a consistent user-facing result.

## Acceptance criteria

- [ ] Replaying a message that was not played when first received shows the message transcript in the appropriate Relay Runner transcript/status surface.
- [ ] Transcript availability is not coupled to whether first playback was started, completed, interrupted, or skipped.
- [ ] Existing replay behavior for messages that were already played continues to work.
- [ ] The fix handles the relevant Relay controls, including replay and play/resume paths, without exposing raw private command metadata in user-visible transcript text.
- [ ] Codex and Claude voice sessions receive equivalent replay transcript behavior, with intentional provider-specific differences documented if any exist.
- [ ] Tests or documented manual verification cover replaying an unplayed message, replaying a previously played message, and replaying after an interrupt or skipped playback.
