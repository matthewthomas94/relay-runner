## Description

Spec: `docs/specs/relay-remote.md` (Relay Remote: iOS voice over SSH), committed as `2a64cc0d` on branch `claude/ios-relay-ssh-tcp-spec-ddb8f2`. The spec is not on `main` yet; if the file is missing from your worktree, read it with `git show 2a64cc0d:docs/specs/relay-remote.md`. Read these sections first: Mac-side integration with the voice contract, Wire protocol.

When a remote device is the active input, the Mac must stop speaking through Kokoro and send the text to the phone instead. Add a per-device remote sink to `services/speech_coordinator.py`.

- The bridge module (RR-423) registers the sink when a device connects and removes it on disconnect.
- While a device is active, every `SpeechIntent` that would reach Kokoro (`read_out`, messenger handoffs, lifecycle and completion speech) becomes a `speech` frame to that device, in `seq` order, with the intent's `kind`, `source` and `relay_command_seq`.
- Stop and skip decisions, including stale-output suppression when a newer command supersedes an older one, become `speech_control` frames with a `reason` instead of killing a local player.
- A device `ack` with `played: true` calls `record_realization` for that frame, so the coordinator's realization record and played coverage stay truthful. An `ack` with `played: false` records receipt only.
- While the device is disconnected the sink keeps producing into the replay buffer from RR-422; the frames replay in `seq` order when the device reconnects with `resume_after_seq`.
- Kokoro is never started for speech routed to a remote device. The coordinator's event log names the sink used for each intent.

Out of scope: iOS playback (RR-429), the end-to-end loopback test (RR-430).

## Acceptance criteria

- [ ] Routing test: with a remote sink registered, a `read_out` produces one `speech` frame and no local synthesis call.

- [ ] Ack test: `played: true` records a realization; `played: false` does not.
- [ ] Disconnect test: frames produced while disconnected replay in `seq` order on reconnect.
- [ ] The event log names the sink per intent.
