## Description

Implement RR-273 delivery phase 2 from RR-270's `Work-scope state machine` and registry-backed Workspace recommendation. Workspace opens from Relay Runner's fixed app-global home and registry without a Workspace-folder picker. A project-free install is valid: onboarding may finish with an empty registry, Workspace shows Add Existing Project and Create Project, and Settings manages registered projects, grants, availability, and removal instead of a `general.working_directory` preference.

Starting a Codex or Claude session requires an explicitly selected available registered project. The app-support home is never an agent cwd. Cwd, bridge cwd, recent project, or filesystem proximity may suggest a candidate but cannot confirm mutation ownership. Add provider-neutral confirmed-scope tokens and thread inheritance/redirect/cancel handling across UI, voice work intents, ticket authoring, dispatch, archive, restore, and sync entry points.

This ticket consumes RR-281 registry-v2 and retains a reversible compatibility gate. It does not implement the artifact writer or remote synchronization.

## Acceptance criteria

- [x] Workspace can open before a bridge exists using registry-v2, renders an honest empty Projects state, and limits filesystem browsing to Add Existing Project and Create Project flows.
- [x] Onboarding completes without a project, Settings no longer presents a Workspace-folder identity preference, and registered-project management surfaces availability, access regrant, locate, and safe removal.
- [x] Start Session refuses an unconfirmed, unavailable, or app-home target and starts both Codex and Claude only from the explicitly selected registered repository.
- [x] A durable provider-neutral scope token carries project ID plus the minimum ref/path/version data needed to reject stale or redirected mutations; cwd and bridge cwd remain suggestions only.
- [x] Follow-up conversation inherits confirmed scope until explicit redirect, cancel, project removal, availability loss, or identity mismatch; all mutation entry points fail closed when confirmation is absent or stale.
- [x] Voice and UI flows distinguish intentionally unscoped conversation from project work and preserve already accepted unrelated work under the existing intent disposition contract.
- [x] Tests cover app launch without bridge, empty registry, add/create/remove, moved/offline/stale-grant projects, suggestion versus confirmation, follow-up inheritance, redirect, cancellation, and equivalent Codex/Claude outcomes.
- [x] Installed Workspace and session-launch checks verify no folder picker on ordinary open and prove the application-support home is never passed as an agent working directory.
- [x] Documentation links the implementation to RR-270 phase 2 and records the final scope state machine and any intentional provider differences.

## Rollback boundary
