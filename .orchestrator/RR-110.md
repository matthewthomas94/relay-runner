## Description

Improve the short acknowledgement message shown after a user sends a Relay message or voice command.

The current acknowledgement is too static: it reads like the same one-line response every time. Replace it with a small dynamic acknowledgement that reflects the received message enough to show the user it was understood. When it is fast and reliable, skim the message content and echo a concise gist back to the user; when that would add noticeable latency or risk poor wording, fall back to a varied generic acknowledgement.

Add intentional timing for this acknowledgement:

- Wait roughly one to two seconds after the user sends the message before showing the acknowledgement, so it feels deliberate instead of instantaneous boilerplate.
- Auto-dismiss only this acknowledgement-style message. A reasonable default is around three seconds, or a duration derived from message length if that reads better.
- Do not auto-dismiss substantive assistant responses, worker status, errors, or other messages where the user may need time to read details.

Keep the copy concise and conversational. It should validate receipt of the user's intent without exposing raw command-action metadata, internal transcript fragments, provider names, or implementation details.

Likely touch points:

- Voice command or message acknowledgement pipeline
- Response overlay / status overlay timing and dismissal logic
- Any command-action classification code that can provide a safe short gist
- Tests for acknowledgement copy selection, delay, and auto-dismiss behavior

## Acceptance criteria

- [ ] Acknowledgements vary instead of reusing the same fixed one-liner for every user message.
- [ ] When feasible within the latency budget, acknowledgement copy includes a short safe gist of the user's message.
- [ ] If gist generation is unavailable, too slow, or low confidence, the system falls back to a varied generic acknowledgement.
- [ ] The acknowledgement appears after an intentional one-to-two-second delay.
- [ ] Acknowledgement messages auto-dismiss, with a default around three seconds or length-aware timing.
- [ ] No other assistant response type gains auto-dismiss behavior unless explicitly classified as this acknowledgement type.
- [ ] Raw Relay command metadata, private transcripts, provider internals, and implementation details are never shown in the acknowledgement.
- [ ] Codex and Claude sessions use equivalent acknowledgement behavior unless an intentional provider-specific limitation is documented.
- [ ] Tests or deterministic coverage verify dynamic copy selection, fallback behavior, delay timing, and scoped auto-dismiss.
