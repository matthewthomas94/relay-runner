## Description

Change the fresh-install and fresh-configuration defaults for the foreground orchestrator while preserving the separate managed messenger configuration. Codex should default to the stable `sol` model family at `xhigh` effort. Claude should use the provider-equivalent high-capability stable alias, `best`, at `xhigh` effort. Keep persisted user choices authoritative: upgrades and config loading must not overwrite explicit existing model or effort selections. Ensure the Swift app configuration and Python service defaults remain aligned.

## Acceptance criteria

- [ ] A fresh Codex configuration defaults the orchestrator to model family `sol` with `orchestrator_effort = xhigh`.
- [ ] A fresh Claude configuration defaults the orchestrator to model alias `best` with `orchestrator_effort = xhigh`.
- [ ] Selecting or initializing either provider applies its matching orchestrator defaults without producing an invalid model/effort combination.
- [ ] Existing explicit user model and effort choices remain intact when loading or migrating configuration.
- [ ] Messenger model and effort defaults are unchanged and remain independent of orchestrator defaults.
- [ ] Swift configuration tests and Python configuration tests cover fresh defaults, provider parity, and preservation of explicit settings.
