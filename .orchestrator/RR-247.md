## Description

Make foreground orchestrator model and effort choices explicit in the app while preserving the separate managed messenger configuration and the generic sizing vocabulary used for sub-agents. Codex should default to the stable `sol` model family at `xhigh` effort. Claude should default to the explicit `opus` model at `xhigh` effort. Remove the user-facing `Provider managed` orchestrator effort choice and remove Claude’s user-facing `Best` model choice. Migrate legacy generic orchestrator values (`default` effort and Claude `best`) to their explicit equivalents without overwriting already-explicit valid user selections. Keep Swift app configuration and Python service defaults aligned.

## Acceptance criteria

- [ ] A fresh Codex configuration defaults the orchestrator to `sol` with `orchestrator_effort = xhigh`.
- [ ] A fresh Claude configuration defaults the orchestrator to `opus` with `orchestrator_effort = xhigh`.
- [ ] The orchestrator effort picker does not offer `Provider managed`; it offers only explicit supported effort values for the selected provider and model.
- [ ] The Claude orchestrator model picker does not offer `Best`; it offers explicit Claude model choices.
- [ ] Legacy orchestrator `default` effort and Claude `best` values migrate to explicit supported equivalents, while existing explicit valid model and effort selections remain intact.
- [ ] Messenger model and effort behavior remains independently managed and unchanged.
- [ ] Generic tier vocabulary for sub-agent sizing remains unchanged.
- [ ] Swift and Python configuration tests cover fresh defaults, provider switching, legacy migration, and preservation of explicit settings.
