## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

This is the stage 3 epic. It is deliberately not dispatchable as written: when the gate decision is to continue, the foreground PM splits it into tickets of reviewable size and cancels this one.

Scope: replace `voice_bridge.py`, `messenger.py`, `intent_inbox.py`, `intent_arbitration.py`, `intent_qualification.py`, `provider_turn_broker.py`, `pm_frontstage.py`, `relay_remote.py`, `relay_remote_protocol.py`, `voice_audio_lease.py`, `remote_audio.py` and the bridge's use of the continuity modules with a Rust binary, accepted by the voice-bridge contract suite.

Suggested split, each a separate ticket:

1. Typed intent model, inbox and turn broker as a library crate on the existing SQLite schema, with the Rust hook moved onto it.
2. Messenger backends for both providers together (Codex JSON-RPC app-server, Claude stream-json), including model and effort resolution.
3. Relay Remote socket and protocol, checked against the shared Swift vectors.
4. Bridge main loop, FIFO and control-socket dispatch, spool files, orchestrator client and continuity hooks.
5. Cut-over: `scripts/relay-bridge` and `ProcessManager.swift` launch the Rust bridge by default, with a switch back to Python for one release.

Constraints for every part: interfaces in `docs/specs/voice-bridge-contract.md` stay byte-compatible; Claude and Codex change in the same release; no behaviour differs between providers beyond today's documented differences.

## Acceptance criteria

- [ ] The voice-bridge contract suite passes against the Rust bridge for both providers.
- [ ] The app launches the Rust bridge by default and the rollback switch restores the Python bridge.
- [ ] A live session with each provider completes voice turns, interruption, replay and multi-session targeting.

## Required inputs

- [ ] The user has decided to continue past the gate (see the Rust port gate ticket).
- [ ] The foreground PM has split this epic into separately sized tickets.
