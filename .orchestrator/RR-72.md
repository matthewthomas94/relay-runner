## Description

Add focused verification for new-ticket creation from both the single-project board and the Program Board.

This should cover the file-level behavior that can be unit tested and the UI/lifecycle behavior that needs manual verification. Keep tests close to existing board tests, especially `BoardProjectConfigTests`, `ProjectRegistryTests`, and `ProgramBoardStatusTests`.

Provider parity note: the board UI and ticket files are provider-neutral. Verification should explicitly state that Codex and Claude sessions see the same board creation behavior because both route through the same project registry and `.orchestrator/` files.

## Acceptance criteria

- [ ] Tests prove ticket creation claims the correct project's next ID and does not mutate unrelated project configs.
- [ ] Tests cover the Program Board all-projects case where a project must be selected before minting.
- [ ] Tests cover the Program Board single-project filter case where the selected project is preselected.
- [ ] Tests or a verification note cover project-board creation opening the editor and preserving save/delete behavior.
- [ ] Tests or a verification note cover ready-ticket auto-dispatch behavior after a newly-created ticket is saved/promoted.
- [ ] Manual verification notes include Program Board creation from a workspace session and project-board creation from a single-project session.
- [ ] `swift test --skip-update` passes after the implementation tickets land.
