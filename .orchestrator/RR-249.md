## Description

Fix Program Workspace ticket-card hover and cursor feedback.

In the live all-project Workspace, moving the pointer across Backlog cards can
leave several previously visited cards rendered with their hover fill after the
pointer has left them. Eligible cards also retain the normal arrow cursor
instead of showing that they can be grabbed and moved.

The current card interaction is split across two owners in
`ProgramBoardOverlayView.swift`:

- `ProgramWorkCardDragEventView` creates an AppKit `NSTrackingArea` and writes
  each card's SwiftUI `isHovered` state from `mouseEntered` and `mouseExited`.
- `ProgramGrabCursor` observes that separate hover state and pushes or pops the
  process-global `NSCursor` stack.

The existing focused test calls `mouseEntered` and `mouseExited` directly. It
does not cover a tracking area being removed and recreated, a card scrolling
away from a stationary pointer, a dashboard snapshot replacing or reordering
cards, a view leaving its window, or several card instances competing for the
global cursor stack. These lifecycle gaps can preserve stale `isHovered`
values and leave cursor ownership unbalanced even though the direct callback
test passes.

Reproduce the live failure through the mounted Program Workspace scroll/card
hierarchy and make the AppKit event layer the authoritative owner of both
pointer containment and cursor presentation. Prefer cursor rects or cursor
update events owned by the hit-tested card view over independent per-card
`NSCursor.push()` / `pop()` bookkeeping. Clear hover deterministically whenever
the pointer leaves or the tracking/view lifecycle makes the previous hover no
longer valid, without adding visible flicker while a stationary pointer still
rests on the same card.

Eligible tickets should show an open-hand cursor on hover and a closed-hand
cursor while an actual drag is active. Worker-owned or otherwise non-draggable
tickets should keep the normal arrow cursor and must not imply that a forbidden
move is available. Preserve click-to-open, scrolling, drag thresholds, lane
drop policy, and the existing hover/selection visual hierarchy.

## Acceptance criteria

- [ ] Add a mounted regression that moves the pointer across multiple ticket cards in the real Program Workspace scroll hierarchy and proves that at most the card currently under the pointer has hover presentation.
- [ ] A card clears its hover state promptly when the pointer exits, the card scrolls out from under a stationary pointer, its tracking area is replaced, the dashboard snapshot removes or reorders it, its lane changes, or its view leaves the window.
- [ ] Recreating tracking areas or refreshing layout while the pointer remains over the same card does not produce a visible hover-off/hover-on flicker.
- [ ] Hover state does not survive closing and reopening Workspace, switching between all-project and selected-project views, or reusing a card view for a different ticket.
- [ ] Every draggable ticket displays `NSCursor.openHand` while hovered and `NSCursor.closedHand` from drag activation until drag completion or cancellation.
- [ ] Non-draggable tickets, including active-worker and awaiting-review/merge states covered by existing policy, retain the normal arrow cursor and never show a grab affordance.
- [ ] Cursor presentation updates immediately if a ticket's drag eligibility changes while the pointer is over it.
- [ ] Moving rapidly between cards, scrolling, refreshing the dashboard, ending a drag outside a lane, dismissing Workspace, and removing a hovered card leave no unmatched global cursor push/pop state or cursor that persists over unrelated UI.
- [ ] Click-to-open, the drag movement threshold, source-card/preview/drop feedback, valid and invalid lane policy, auto-dispatch from Queued, and vertical scrolling remain unchanged.
- [ ] Direct AppKit event tests cover hover enter/exit plus tracking replacement, window detachment, and drag cancellation; mounted tests cover multiple cards, scrolling, and snapshot replacement rather than invoking callbacks alone.
