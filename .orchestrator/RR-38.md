## Description

Implement the project lifecycle needed for Program Manager mode: resolve a project, register it, activate it for the current session, and ensure its local board exists.

Today the board is initialized as a side effect of `/relay-bridge` resolving `/tmp/voice_bridge.cwd`. This ticket should make project activation a first-class product concept while preserving the existing bridge behavior as one activation path.

Use the MVP spec from RR-36 as the source of truth. Keep changes scoped: project registry/activation only, not the Program Board or graph store.

Provider parity matters: activation should not be Codex-only. Codex and Claude sessions should both have a clear path to set or discover the active project, with intentional differences documented.

## Acceptance criteria

- [ ] A project registry exists in an appropriate Relay Runner data location or documented repo-local location.
- [ ] The registry stores repo path, display name or alias, last seen timestamp, and provider-relevant metadata needed by later tickets.
- [ ] Existing git repos without `.orchestrator/config.toml` get `.orchestrator/` initialized when explicitly activated.
- [ ] Non-git folders do not silently run `git init`; they require an explicit initialization path or documented refusal.
- [ ] Existing `/relay-bridge` cwd resolution still works and can register/activate the current repo.
- [ ] There is a programmatic path for voice/MCP/UI code to activate a project by repo path or known alias.
- [ ] Codex and Claude activation behavior is covered in docs or code comments where provider-specific.
- [ ] Tests or a targeted verification cover activation of an existing repo, initialization of missing `.orchestrator/config.toml`, and refusal/confirmation behavior for non-git folders.
