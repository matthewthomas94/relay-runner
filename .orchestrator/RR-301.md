## Description

Fix a live installed-app regression where Relay Runner displays and makes replayable the warning `I handled that Relay voice turn, but the provider did not send a spoken final reply` while the foreground provider is still visibly working and publishing progress for that same source turn.

Privacy-safe evidence from Relay Runner 0.4.35 (build 39) captured source command sequence 318 splitting into two ordered intents. The first intent completed with an empty provider final and armed the source-command fallback. The second intent was submitted and acknowledged as active, then its lifecycle record became `orphaned` with `release_reason: superseded_by_prompt_submit` while a separate manual-origin record occupied the same stable app-owned provider session. When that manual-origin record reached `completed_manual`, the bridge saw no active record, judged the fallback eligible, and emitted the warning. The embedded Codex transcript continued publishing substantive progress after the warning, proving this was not a genuinely completed turn with no provider output.

The fallback currently deduplicates and checks freshness at source-command scope, but it is armed from an individual completion and relies on point-in-time pending/active checks. Make missing-final arbitration explicit across every intent belonging to one source command. An empty or interrupted sibling must not terminalize the whole source turn while another sibling is queued, claimed, active, being steered, or still owns provider work. Likewise, an alias/rebind/manual-barrier transition must have an explicit outcome; losing an `active` flag is not by itself proof that the provider completed without a final.

RR-300 remains responsible for reconciling native provider identity drift and releasing the correct physical turn. This ticket depends on that ownership repair, then hardens the distinct source-turn reply contract so lifecycle rebinding, ordered multi-item delivery, manual steering, or a delayed valid final cannot produce a false fallback. Preserve the bounded warning for a genuinely terminal current source turn whose complete set of intents produced no explicit or recovered final.

Do not solve this by merely increasing the 120-second delay, scraping terminal text, treating progress text as the authoritative final, disabling the warning, or allowing an old source command to speak after a newer Relay command supersedes it. Keep diagnostics privacy-safe: do not persist raw voice text, provider prompts, transcript content, assistant response text, secrets, or terminal contents.
