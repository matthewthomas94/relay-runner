## Description

Implement the agreed Relay Runner voice architecture with the existing foreground Codex or Claude instance remaining the authoritative orchestrator and a separate fast messenger session owning user conversation.

Start the messenger with the Relay voice bridge and keep it alive until that bridge/session ends. Deliver every user utterance to the messenger and foreground orchestrator concurrently. The messenger must have no tools or repository mutation authority. It may handle ordinary conversation, simple low-risk questions, and status narration, while planning, ticket authoring, dispatch, tool use, implementation decisions, and authoritative project answers remain with the foreground orchestrator.

Use provider-native included-entitlement paths rather than an API-key voice service:

- Codex: a persistent `codex app-server` thread using `gpt-5.6-terra` with low reasoning by default.
- Claude: a persistent `claude --print --input-format stream-json --output-format stream-json` session using `haiku` by default.

Normalize provider behavior behind one messenger event contract. Feed current user turns, provider-visible orchestrator reasoning/progress summaries, structured worker/tool lifecycle events, clarification requests, and orchestrator final responses into bounded messenger context. Do not depend on or expose inaccessible hidden chain-of-thought. The messenger paraphrases context naturally, never invents authoritative work state, and may suppress unimportant trace events.

Remove the early spoken trace acknowledgement. The notch may still show immediate receipt/status, but only the messenger writes spoken responses. The foreground orchestrator should route its final spoken summary through the messenger rather than writing directly to TTS. Preserve stale-command checks, barge-in behavior, local Parakeet STT, local Kokoro TTS, and current session shutdown semantics.

This ticket is being implemented inline at the user's explicit request; do not dispatch a worker run.
