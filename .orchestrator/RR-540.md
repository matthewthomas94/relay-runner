## Description

Build the Agents tab, screens 21–25 (`docs/design/relay-remote-ios/README.md`, section "Agents tab"; images `21-agents-ready.jpg` to `25-agents-mac-unreachable.jpg`; Figma [2139:44056](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-44056), [2139:44337](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-44337), [2139:46237](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-46237), [2139:48749](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-48749), [2139:48996](https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=2139-48996)). Replace the placeholder `AgentsTabView` from RR-533 (which hosts the old `DebugView`), using the design-system components from RR-533 and the kit's per-agent API from RR-532.

**Layout, bottom to top:** the tab bar (from RR-533); the dock; the agent tab strip; the chat feed; the header.

- **Agent tab strip:** horizontally scrollable tabs for Puck, Isabella, George and Sky, styled like the desktop terminal tabs, each with its status glyph next to the name, driven by the per-agent state from the Mac. Selecting a tab switches the whole chat to that agent. The selection persists across launches. No blob or glow inside the tabs.
- **Header:** the agent's orb over the agent's name, nothing else. The orb takes the listening colour while the user is talking to this agent, the playing colour while this agent's reply plays, and navy when idle. It is never dimmed.
- **Chat feed:** the user's messages and the agent's replies for the selected agent, newest at the bottom, fading out at the top and bottom edges with an alpha mask on the feed (not a black overlay), with a transparent background so the glows from RR-541 show through. A reply's text is the text of its `speech` frames. History is kept per agent on the phone (a simple on-disk store, capped at the latest 200 messages per agent) so it survives a relaunch.
- **Dock:** a text box, then a row with Replay (44 pt square), a wide "Hold to talk", and Stop (44 pt square). The dock is pinned just above the tab bar; as text fills the box it grows upward and never overlaps the tab bar. Typing and pressing send sends a text message to the selected agent.
- **Talking:** in Hold mode, pressing and holding "Hold to talk" records; the live transcript fills the text box; releasing sends it to the selected agent as a normal message. In Toggle mode (the talk-mode preference from RR-533), one tap starts, the button reads as active, and a second tap sends. The button uses a plain pressed state, not purple. Remove the hands-free mode from `ios/RelayRemote/Voice/VoiceController.swift` and its endpointer wiring; if `UtteranceEndpointer` in the kit is then unused, leave it and list it in your summary.
- **Replies:** agent-tagged speech is filed under its agent's chat whichever tab is selected. In Auto-play mode (existing `PlaybackModePreference`) a reply plays at once. In Queue mode the feed shows "New reply from <agent>" with a secondary Play button; Play starts it. Stop stops playback and sends the stop control for that agent. Replay replays that agent's last reply. A reply for an agent other than the selected one marks that agent's tab (its glyph shows playing while it plays; in Queue mode its Play appears when the user opens that tab).
- **Agent not running (24):** the feed area shows "<Agent> isn't running", a secondary "Start <Agent>" button (sends `start` for that agent with no project) and "Message <Agent> to start it." Sending a message also starts it; show the glyph's starting state and the dot-split animation when it comes online.
- **Mac unreachable (25):** the floating banner "Mac unreachable" with Retry over everything below the status bar; the chat and controls dim and do not accept input until the connection is back. Retry reconnects.

There is no project picker and no nested chat view. Only one primary button on the screen.

## Acceptance criteria

- [ ] Each of the four agents has its own chat; a message sent on George's tab is sent with `agent: george`, and a reply tagged for Puck appears only in Puck's chat.
- [ ] Per-agent history survives a relaunch and is capped at 200 messages per agent.
- [ ] The tab glyphs follow the Mac's per-agent state (off, starting, ready, working, listening, playing), tested by feeding scripted `session_state` frames.
- [ ] Hold mode: hold records, the transcript fills the text box as the user speaks, release sends. Toggle mode: tap starts, tap sends. No hands-free mode remains in the app or its settings.
- [ ] The dock grows upward as the text box fills to several lines and never overlaps the tab bar (screenshot at one line and at five lines).
- [ ] Queue mode shows "New reply from <agent>" with a secondary Play; Auto-play plays at once. Stop and Replay act on the selected agent.
- [ ] A stopped agent shows the screen 24 state; "Start <Agent>" and sending a message both start it.
- [ ] Losing the connection shows the banner over the content, dims the chat and dock, blocks input, and Retry reconnects.
- [ ] The feed fades at both edges using an alpha mask, and the feed and screen backgrounds let a layer behind them show through.
- [ ] Simulator screenshots of the five states match the reference images for layout, spacing, type and icons.
- [ ] The app builds and all tests pass; the chat store, reply filing, talk modes and state mapping have unit tests against the kit's scripted transport.
