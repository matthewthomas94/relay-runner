## Description

Add selectable GPT-6 Astra and Claude Fable 5.1 support throughout Relay Runner. The requested Claude 5.1 target is interpreted as the publicly documented Claude Code model Fable 5.1 (`claude-fable-5-1`), not invite-only Mythos. Add support without automatically switching the user's current sessions, saved defaults, Messenger workload, or worker tiers to a new flagship.

Today `services/codex_model_catalog.py` recognizes only Sol/Terra/Luna and can normalize an unrecognized GPT family to Sol. Swift model options mirror that restriction. Claude has only a generic `fable` selection across multiple allowlists. Ensure explicit selections survive config normalization, persistence, launch, and worker validation without silently substituting another family/version. Preserve existing family/alias behavior; expose a clearly versioned Fable 5.1 choice whose launch identifier is pinned rather than assuming the generic alias selects it.

Inspect the matching Swift resolver, settings/onboarding, context metadata, ProcessManager launch paths, Python config, Messenger, command_actions, orchestrator worker overrides, and directly related generated documentation. Use the smallest consistent change; do not redesign the registry, alter unrelated models, change authentication, or implement direct-provider API migration. Check CLI compatibility and explain old-client or account-access limitations honestly. Provider catalog availability is not proof of an authenticated generation.

## Acceptance criteria

- [ ] Astra and an explicitly labeled Fable 5.1 appear in applicable model selectors, including foreground and Messenger choices; selecting, saving, and reloading retains the intended model. Existing defaults, selections, and fast/balanced/strong tier mappings remain unchanged.
- [ ] Astra family/concrete identifier recognition works in Swift and Python and resolves to the current provider-advertised Astra model. Explicit Astra never silently becomes Sol. Missing, hidden, incompatible, or unavailable catalog entries fail clearly under existing availability policy; do not bypass access checks.
- [ ] Fable 5.1 selection launches `claude-fable-5-1` consistently for foreground, Messenger, and explicit Claude worker overrides. Legacy `fable`, Opus, Sonnet, and Haiku configurations remain compatible.
- [ ] Both new models are accepted through provider-scoped worker overrides and command validation. Correct model-specific reasoning efforts are exposed and validated using provider catalog/CLI evidence; unsupported effort/provider combinations do not silently launch with unrelated settings. Verify context-window metadata where used without inventing values.
- [ ] Regression coverage spans config round-trips and legacy migration, model catalog selection, missing/hidden models, launch arguments, Messenger configuration, worker/command validation, and supported/unsupported efforts. All tests use isolated sockets, files, logs, and inboxes and cannot reach the live voice session.
- [ ] Relevant Python and Swift tests, generated-instructions checks when affected, and diff hygiene pass. Document tested CLI versions, exact model identifiers, current official sources, intentional provider differences, and any unavailable authenticated verification separately.
- [ ] Implementation is independently reviewed and integrated. Installed-app model selection and authenticated smoke for each new model remain an explicit external gate until actually performed; do not mark unavailable live testing passed. No Apple Developer ID, notarization, or mounted-DMG requirement. Do not rebuild/install over or restart the user's active app/session in this worker.
