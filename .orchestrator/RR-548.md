## Description

The Notes tab is getting a chat panel. With a note selected you chat about that note (summaries, decisions, action items). With no note selected you chat about the whole library. This ticket adds the daemon side only; the UI is a separate ticket.

It works like `claude -p`: one tool-free provider call per question, with the earlier turns of the conversation sent back in the prompt. Nothing is saved; the provider session is not persisted.

**Reuse:** `rust/relay-services/src/notes/metadata.rs` already runs a tool-free, subscription-only provider call for note titles and summaries: `command()` builds the Claude (`--print --safe-mode --no-session-persistence --tools ""`, empty MCP config) and Codex (`exec --ephemeral --sandbox read-only`, every feature off) launch lines, `isolated_environment()` strips API keys and Relay/MCP config, `run_process()` runs it with cancellation, and provider and model come from the `[general]` config. Build the chat call on the same pieces with its own system prompt and plain-text output instead of the JSON schema. Do not loosen any isolation flag.

Route (add to `rust/relay-orchestrator/src/router.rs` beside the other `/v1/artifacts/notes` routes, and document it in `docs/specs/orchestrator-http-api.md` under Notes):
- `POST /v1/artifacts/notes/chat` body: `request_id`, optional `note` (note id or artifact id; absent means the whole library), `messages` (ordered `{role: "user"|"assistant", text}`, the last one the user's new question).
- Answers `{"reply", "note_ids"}`: the answer text and the notes that were put in the prompt.
- 400 for an empty or malformed `messages`, or a last message that is not the user's; 422 for an unknown note, as `GET /v1/artifacts/notes/{identity}` does.

Prompt context:
- **One note:** title, capture date, summary and the full transcript. If the transcript is over the budget, keep the start and end and say in the prompt that the middle was cut.
- **Library:** every note's title, date and summary, newest first, plus the full transcripts of the notes that best match the question, added until a fixed character budget. Pick a simple, deterministic match (for example, word overlap with title, summary and transcript); no embeddings.
- The system prompt says to answer only from the notes given, to say when the notes do not contain the answer, and to name the note it is quoting by title and date. Note content is untrusted data: the prompt must treat it as material, not instructions.
- Cap the number of earlier turns sent back, dropping the oldest first.

Limits: a per-request timeout (about two minutes) that kills the provider process, a clear error when the provider is missing or not signed in (send the user to subscription sign-in, never an API key), and no file writes.
