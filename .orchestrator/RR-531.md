## Description

The Relay Remote iPhone designs (Figma file "Relay-Runner", section "Relay Remote (iOS)", style board "Relay Remote / Styles", node 2103:10050) introduced a danger button the user wants on the desktop app too.

**Today (desktop):** `SettingsActionButton` with `.danger` prominence uses `SharedActionButtonPalette.settingsDanger` in `Sources/relay-runner/Settings/SettingsComponents.swift`: a solid dark red tint fill (`GraphicalTheme.dangerFill`, #371716) with a red label and icon (`GraphicalTheme.dangerForeground`, #e03625). On hover it gets the shadow and a red overlay (around lines 427-434).

**Wanted (mobile design):** a danger button looks exactly like a secondary button (the same `#171a1e` at 75% glass fill and glass treatment as Add project or Locate folder) but its label and icon are red: `GraphicalTheme.error` (#f41509). The red text on the neutral glass marks it as destructive; there is no red fill.

Scope:
- Change the `settingsDanger` palette so its fill and stroke match `settingsSecondary`, and its foreground is `GraphicalTheme.error`.
- Keep the danger hover feedback subtle and consistent with the secondary button's hover. Drop the red overlay unless it is still needed to read as destructive; if you keep a hover tint, make it faint red over the glass, not a solid red fill.
- Every place that resolves to `.danger` picks this up: Settings actions, `GraphicalDialog` destructive actions (`Sources/relay-runner/Board/GraphicalDialog.swift:84`) and destructive buttons on the Workspace board (`ProgramBoardOverlayView.swift` around line 4650).
- Leave the separate red status capsule on the board (`ProgramBoardOverlayView.swift` around line 4780, `dangerFill` background) unchanged. It is a status badge, not a button. Remove `dangerFill` or `dangerForeground` only if nothing uses them any more.

## Acceptance criteria

- [ ] A `.danger` `SettingsActionButton` renders with the secondary button's fill, glass treatment and stroke, and a #f41509 (`GraphicalTheme.error`) label and icon.
- [ ] Destructive actions in graphical dialogs (for example "Remove" in "Remove registered project?") and destructive Workspace board buttons show the same style.
- [ ] Disabled, hover and focus states still work. A disabled danger button dims like a disabled secondary button.
- [ ] The board's red status capsule looks the same as before.
- [ ] `swift build` succeeds and `swift test` passes; update any test that pins the old danger palette.
- [ ] The run log includes a screenshot or a short description of a danger button in Settings and in a destructive dialog after the change.
