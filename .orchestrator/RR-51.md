## Description

Verify the full workspace-folder Program Manager flow and document the migration from the current working-directory behavior.

This ticket should run after the implementation tickets land. It should exercise the real app-level path where a user selects `/Users/matthewthomas/dev` or another multi-repo folder once, then Relay Runner discovers child projects and opens the Program Board without creating a parent project. It should also verify the single-repo case still opens the project board.

Provider parity matters. The final verification should cover or simulate both Codex and Claude session metadata and call out any intentional differences.

## Acceptance criteria

- [ ] A verification report describes the workspace-folder invariant, migration behavior, commands or app flows tested, and residual risks.
- [ ] Existing users with a working-directory setting migrate into the new workspace-folder model.
- [ ] Selecting a multi-repo folder discovers child projects and does not create a parent `.orchestrator/`.
- [ ] Selecting a single repo continues to create or use that repo's `.orchestrator/` board.
- [ ] Start Session and board toggle behavior are verified for workspace root and project repo cases.
- [ ] Codex and Claude provider paths are both verified directly or through documented test doubles.
- [ ] The relevant Python, Swift, and packaging checks are run or explicitly justified if skipped.
