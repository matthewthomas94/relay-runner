## Description

Fix the remaining onboarding completion deadlock after RR-197. The `You’re all set /` surface now reveals and holds for the correct duration, but it closes back to the compact `Getting started` notch instead of opening Workspace. The installed app reproduces this after manual Redo Onboarding, and the same object-lifetime bug can affect a pristine first run.

`OnboardingController.finish()` currently copies `introController` into a local, immediately sets `introController = nil`, and then starts the presenter's asynchronous `dismiss`. In production the controller owns the only strong reference to `OnboardingIntroController`; when `finish()` returns, the presenter deinitializes while dismissal is still animating. Its `deinit` orders the panel out, so the surface appears to close, but the dismiss completion never runs. Consequently the onboarding notch override remains active, the first-run shell lock remains active, and `openWorkspaceAfterCompletion` is never invoked. Existing tests retain their fake presenter in a test-local variable, masking this production ownership failure.

Keep the real presenter alive until its dismiss completion has run, then release it and perform the existing notch unlock, shell unlock, and Workspace opener in deterministic order. Do not replace the animation with a guessed delay.
