## Description

Make double-tap Option playback reliable while Relay Runner is in the
background, including after an event monitor initially fails to attach during
launch or permission recovery. The app currently retains its local NSEvent
monitor but silently drops a nil global monitor, leaving playback dependent on
whether Relay Runner happens to be frontmost.

Keep voice-service tests isolated from a running Relay Runner instance. A
worker running the voice bridge unit suite published its fixture text
`fresh response` to the real `/tmp/voice_state.sock`, replacing the live
response pill with an unplayable test preview. Tests must never publish state
to the live overlay unless an explicit integration harness opts in.

## Acceptance criteria

- [ ] A failed global Option/Control/Shift event-monitor installation is visible in diagnostics and is retried without duplicating local or global monitors.
- [ ] When a later retry succeeds, background double-tap Option events continue through the existing `__PLAY__` path without requiring Relay Runner to be frontmost.
- [ ] Monitor teardown cancels pending retries and removes every installed monitor exactly once.
- [ ] Focused Swift coverage deterministically exercises initial global-monitor failure followed by successful recovery.
- [ ] Voice bridge unit tests stub or redirect waiting-preview publication by default and cannot write fixture text to a live Relay Runner state socket.
- [ ] Focused Python coverage preserves authoritative preview behavior through explicit injected publishers.
- [ ] Existing first-play, replay, stale-response, confirmation, and Workspace double-tap behavior remains unchanged for Codex and Claude sessions.
