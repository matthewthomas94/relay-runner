## Description

Add a Program Board new-ticket button that lets the user create a ticket for a specific child project.

The key product difference from the project board is project selection:

- If the Program Board is filtered to one project, preselect that project for creation.
- If the Program Board is showing all projects, require the user to choose a project before a ticket file is minted.
- The selected project must determine the target repo, `.orchestrator/config.toml`, ticket ID prefix, and ticket file path.

Use the existing Program Board project list/snapshot data where possible. The flow should not create tickets under the workspace root unless the workspace root is itself a registered project selected by the user.

## Acceptance criteria

- [ ] Program Board exposes a clear new-ticket control without crowding existing refresh, close, project filter, or lane controls.
- [ ] When all projects are selected, the create flow asks the user which registered project should receive the new ticket.
- [ ] When a single project is selected, the create flow preselects that project while still making the target visible.
- [ ] Creating the ticket writes only to the selected project's `.orchestrator/` and increments only that project's `next_id`.
- [ ] The user can enter title and description before saving, using the same ticket schema as project-board tickets.
- [ ] The created ticket appears in the Program Board after save/reload with correct project context.
- [ ] Creating a ticket in or moving it to `ready` preserves the existing auto-dispatch semantics and dependency validation.
- [ ] Empty, loading, and error Program Board states do not offer a broken creation path.
