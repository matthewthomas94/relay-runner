## Description

On 2026-11-03 the user stopped hearing the PM's final spoken replies on the Mac while still hearing the messenger's immediate acknowledgement. `/tmp/relay_speech_events.jsonl` shows the cause for two turns (relay command seq 89 and 91):

1. The PM turn ran longer than `FOREGROUND_REPLY_FALLBACK_SECONDS` (120 s; long dispatch turns under a load average of about 45 from four worker Swift builds).
2. `_schedule_foreground_reply_fallback` in `services/voice_bridge.py` judged the reply missing, and `_deliver_missing_foreground_reply` spoke the canned text "I handled that Relay voice turn, but the provider did not send a spoken final reply…" through the messenger as source `messenger`, kind `fallback`, `authoritative=True`.
3. `SpeechIntent` in `services/speech_coordinator.py` gives every `FINAL_KINDS` intent (`final` and `fallback`) the same dedup key `outcome:<seq>:<id>`, and `SpeechCoordinator.submit` checks `_accepted_keys` before any supersede logic. When the real completion final arrived it was logged as `deduplicated` with suppression reason `authoritative_final_direct` and never spoken.

A third turn (seq 90) recorded no PM outcome at all, only the messenger handoff, while the bridge log showed "pending messenger outcome fetch failed: timed out" and "Persistent orchestrator heartbeat failed: timed out". The fix below must also make that case observable.

The fallback exists so a turn that truly produced nothing is not silent. It must not consume the one outcome slot for a turn whose provider is still working.

Required behaviour:

- **A late authoritative final replaces the fallback.** When a `completion`/`orchestrator` `final` arrives for a command whose only accepted outcome is a `fallback`, the coordinator accepts it: if the fallback is still queued or playing it is replaced (same mechanism as `_supersedes`), and if it has already played the final is spoken normally. Give fallback intents a dedup key distinct from the real final (for example `outcome-fallback:<seq>:<id>`) and keep `outcome:<seq>:<id>` for the real final, so a second real final is still deduplicated. A real final must never be replaced by a later fallback.
- **The fallback defers while the provider turn is active.** `_source_turn_reply_arbitration` must return `defer` while the bound provider turn is still running (the provider turn broker or turns ledger shows the turn not terminal, or the messenger shows the PM still producing traces for that command), and only become `eligible` once the turn is terminal without a reply or a hard ceiling is reached. Make the ceiling a separate constant (suggest 15 minutes) so the 120 s timer stays the first check, not the only one. Record the chosen reason in the fallback event so the log distinguishes `provider_turn_active` from `source_not_terminal`.
- **Observability.** When a turn ends without any outcome event, the bridge writes one `missing_outcome` event with the command seq/id and the reason it could determine (hook not received, daemon fetch timed out, reply helper rejected), so a seq-90 style silence can be diagnosed from the speech event log alone.
- Keep the voice contract: stale commands are still suppressed, replay still works for whichever text was actually spoken last, and the Remote sink path (`_submit_remote_locked`) gets the same replacement semantics.

Reproduce first with a unit test that drives `SpeechCoordinator` with a `fallback` then a `final` for the same seq/id and asserts the final is spoken; it fails on main today.

The remote-sink variant in `tests/test_speech_coordinator_remote.py` passes the same cases.
