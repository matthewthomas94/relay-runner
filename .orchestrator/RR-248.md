## Description

Prevent an authoritative foreground reply from being re-ingested as a new
Relay voice command.

A live app-owned Codex session reproduced a protocol mismatch after successful
worker dispatch. The foreground provider wrote a raw JSON object with
`type: __ORCHESTRATOR_REPLY__` directly to `/tmp/voice_in.fifo`, while
`_handle_relay_control_message` recognizes only the canonical
`__ORCHESTRATOR_REPLY__:<json>` control line. The raw object therefore fell
through to normal command handling. Because its reply text mentioned RR-247
and a dispatch outcome, Relay minted a new command sequence and classified its
own reply as another `dispatch_ticket` request.

The duplicate dispatch happened to be harmless because the daemon returned the
already-active RR-247 run. That synthetic turn then emitted another raw reply,
which became a second synthetic command. The second synthetic provider turn
ended with an empty final, so the completion hook correctly reported an empty
turn and the bridge displayed the misleading missing-spoken-final fallback.
The visible warning was therefore a downstream symptom of internal control
feedback, not a failed worker or a missing final for the original user command.

The installed bridge was byte-identical to the current source during the
reproduction, so rebuilding the existing source is not sufficient. Fix the
protocol boundary with defense in depth:

1. App-owned foreground instructions and any reply-producing helper must use
   one canonical encoder or structured API for `__ORCHESTRATOR_REPLY__`,
   including the claimed Relay sequence and id. Do not leave FIFO framing to
   provider improvisation.
2. Before normal intent classification, the bridge must detect a raw top-level
   JSON object whose `type` names a reserved Relay control. Quarantine and log
   it with sanitized metadata instead of treating it as user intent. Do not
   grant noncanonical raw JSON the authority of a valid control envelope; the
   existing provider completion hook can recover the real current final.

Preserve current-command checks, explicit-reply/completion-hook deduplication,
the genuine empty-final fallback, messenger speech ownership, and the manual
`relay-bridge` path. Ordinary user prose that discusses a control token must
remain ordinary conversation rather than being swallowed as a control.

## Acceptance criteria

- [ ] Add a deterministic regression that writes a raw top-level JSON object with `type: __ORCHESTRATOR_REPLY__`, current-looking Relay metadata, ticket/action text, and a newline to the voice FIFO.
- [ ] The raw reserved-control object does not increment `relay_command_seq`, create or enqueue an intent, overwrite current/claimed command metadata, publish a ready-file prompt, invoke command-action classification, or trigger any ticket mutation or worker dispatch.
- [ ] A raw reserved-control object is rejected before normal command handling and produces only a bounded sanitized diagnostic containing no reply text, prompt text, transcript content, tool output, or secrets.
- [ ] A canonical current `__ORCHESTRATOR_REPLY__:<json>` line still reaches the authoritative messenger/TTS path exactly once and suppresses the matching completion-hook replay.
- [ ] App-owned Codex and Claude foreground sessions use one shared, explicit reply-framing contract or helper; generated instructions do not leave the FIFO wire format ambiguous or encourage hand-built alternate JSON envelopes.
- [ ] A provider final that mentions a ticket id, dispatch, create, update, or another command-like outcome cannot feed back into Relay as a new user command.
- [ ] A valid nonempty provider final is still recovered through the completion hook when a malformed explicit reply is quarantined, without emitting the missing-spoken-final warning.
- [ ] A genuinely completed provider turn with no usable final still emits at most one bounded fallback after the existing currentness, pending-delivery, and active-turn checks.
- [ ] Stale, malformed, nested, and unknown control-shaped inputs cannot gain control authority or fall through into project-work classification; ordinary prose discussing `__ORCHESTRATOR_REPLY__` remains normal user input.
- [ ] Existing `__TRACE__`, `__RELAY_COMPLETION__`, TTS control, interrupt, manual bridge, messenger, and speech-coordinator behavior remains unchanged except for the reserved raw-control quarantine.
- [ ] Provider-parity tests cover Codex and Claude app-owned launch/instruction paths, and focused Python tests cover FIFO parsing, command classification exclusion, completion recovery, fallback behavior, and exact-once reply delivery.
- [ ] `scripts/build-instructions --check`, the focused voice-bridge and command-action Python suites, and the relevant Swift launch/embedded-terminal tests pass.
- [ ] A package-equivalent smoke test confirms one user dispatch request produces one foreground command/action and one spoken outcome, with no synthetic follow-up command or false missing-final popup.
