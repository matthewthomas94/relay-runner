## Description

Spec: `docs/specs/relay-remote.md` (Relay Remote: iOS voice over SSH), committed as `2a64cc0d` on branch `claude/ios-relay-ssh-tcp-spec-ddb8f2`. The spec is not on `main` yet; if the file is missing from your worktree, read it with `git show 2a64cc0d:docs/specs/relay-remote.md`. Read these sections first: iOS app, Architecture, Pairing and trust, Reachability, Security model.

Create the native iOS app and its SSH transport, text only for now; speech arrives in RR-429.

- Project: `ios/RelayRemote.xcodeproj` (or an `xcodegen` spec that generates it; decide and document) depending on this repository's Swift package for `RelayRemoteProtocol` (RR-422). Deployment target iOS 18 unless RR-421 has decided iOS 26.
- Transport: swift-nio-ssh over swift-nio-transport-services. Validate the server host key against the key pinned at pairing; a changed key is refused with a visible error and nothing is sent. Authenticate with a per-device key: Secure Enclave P-256 (`NIOSSHPrivateKey(secureEnclaveP256Key:)`) with a Keychain-stored Ed25519 fallback when the Secure Enclave is unavailable. Keys never leave the Secure Enclave or Keychain; fingerprints appear in the UI only, never in logs.
- Channel: one per connection, `exec` or `direct-tcpip` as decided in RR-420, carrying `hello` with `resume_after_seq`, then frames both ways. Reconnect with exponential backoff and jitter; resend unacknowledged `utterance` frames with their original `client_id`; answer every received Mac frame with `ack`.
- Pairing: scan the QR code shown by the Mac (RR-426 defines the payload), connect with the pairing key, send `device_id`, `device_name` and the public device key, then store the host key fingerprint and host candidates.
- Reachability: Bonjour `_ssh._tcp` discovery filtered to the paired host name on the LAN; otherwise the stored Tailscale and LAN addresses in order.
- Info.plist: microphone and speech recognition usage strings (needed by RR-429), `NSLocalNetworkUsageDescription`, and `NSBonjourServices` with `_ssh._tcp`.
- A text-only debug screen: connection state, a field to send a typed utterance, and the received frames.

Out of scope: speech (RR-429).
