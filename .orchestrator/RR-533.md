## Description

The Relay Remote iPhone app is a thin debug shell today: `RootView` in `ios/RelayRemote/RelayRemoteApp.swift` shows `DebugView` when paired and `PairingView` otherwise. The final design is in `docs/design/relay-remote-ios/README.md`. This ticket builds the frame that the rest of the design is poured into, so that the screens can then be built by several workers at once without editing the same files.

**Build**

1. **Project structure.** New Swift files must not require hand edits to `ios/RelayRemote.xcodeproj/project.pbxproj` (XcodeGen is not installed on this Mac, and the project file is committed). Convert the app and test targets' sources to file-system-synchronised folders (Xcode 16 and later), or an equivalent that makes adding a file under `ios/RelayRemote/` enough. Keep `ios/project.yml` truthful or note in `ios/README.md` that the committed project is now the source of truth.
2. **Design system** (new folder, for example `ios/RelayRemote/DesignSystem/`):
   - Bai Jamjuree bundled and registered (the desktop app already ships it; reuse those font files), with text styles for the hero (Regular 28/40) and the UI sizes on the styles board.
   - Colour tokens, the glass panel (`#0c0f13` at 50%, radius 16), and primary, secondary and danger buttons as on the styles board (`styles-board.jpg`). Danger is the secondary surface with a `#f41509` label.
   - Outline Lucide icons for every icon in the designs (mic, play, square/stop, rotate/replay, the three tab icons, and the rest visible on the screens), as template images or shapes. The desktop's set is in `Sources/relay-runner/Board/LucideIcon.swift` and `LucideIcons.generated.swift`; reuse its path data rather than redrawing.
   - The four-dot **status glyph** with states off (one grey `#596069` 3 pt dot), ready (four static white dots), working (spinning), listening (`#f2700c`) and playing (`#2b11e8`), and the off-to-ready split animation. Port it from `Sources/relay-runner/Overlay/NotchStatusController.swift`.
   - The **agent orb**: a SwiftUI port of `buildOrbGrid` in `Sources/relay-runner/Overlay/ParticleFieldRenderer.swift` (three Gaussian lobes on a halftone grid, white core, edge dots tinted orange when listening, blue-purple when playing back, navy `#11161D` when idle), animated as on the desktop, 168 × 112 pt on a 7 pt grid.
   - The **dot field**: a port of `buildDotGrid` from the same file on an 8 pt grid, with a listening style (hue 0.04, saturation 0.95, bottom 32% of the screen) and a playback style (hue 0.68, saturation 0.80, bottom 44%), slightly brightened for the phone, with a fade-in parameter. It only needs to exist and render here; RR-541 wires it to voice state.
   - A floating **banner** component that overlays everything below the status bar.
3. **Onboarding scaffold:** a hero layout used by every onboarding screen: hero text anchored at y 300 that grows downward and never re-centres, the pulsing " /" cursor (50–100% opacity, 0.8 s cycle), "Skip →" top right (optional per screen), a full-width primary button (52 pt tall, 16 pt side margins, 40 pt below it) with an optional secondary action above it, and the line-swap transition (0.24 s fade, blur to 6 pt, scale to 96%). Support inline chips inside hero text (a small button-like chip with an icon and label).
4. **App flow:** replace the root with a flow router: first launch runs splash → permissions → pairing → tutorial → app; later launches go to the app when paired and to pairing when not. Persist "onboarding finished". Each stage is its own view in its own file with a minimal placeholder body (hero text naming the stage and a Continue button) so the flow can be walked end to end: `SplashView`, `PermissionsFlowView`, `PairingFlowView`, `TutorialView`. The pairing placeholder must still let a user pair (it may host the existing `PairingView` for now).
5. **Main app:** the glass bottom tab bar (Agents, Workspace, Settings) as in `21-agents-ready.jpg`, with each tab's content a placeholder view in its own file: `AgentsTabView`, `WorkspaceTabView`, `SettingsTabView`. Until RR-540 lands, `AgentsTabView` may host the existing `DebugView` so the app stays usable.
6. **Preferences:** small UserDefaults-backed types following the kit's `PlaybackModePreference` pattern for talk mode (`hold`, `toggle`) and reply notifications (on or off). Behaviour comes in later tickets.
7. **Reference gallery:** a debug-only screen (reachable by a launch argument) showing every design-system component in each state, for screenshots.

## Acceptance criteria

- [ ] Adding a new Swift file under `ios/RelayRemote/` compiles into the app with no edit to `project.pbxproj`; `ios/README.md` says how.
- [ ] A fresh install walks splash → permissions → pairing → tutorial → app through the placeholders; after that, relaunching opens the app directly when paired and the pairing stage when not.
- [ ] The tab bar switches between the three placeholder tabs and matches `21-agents-ready.jpg` for position, glass style, icons and labels.
- [ ] The gallery shows: text styles in Bai Jamjuree; primary, secondary and danger buttons; the glass panel; the banner; the status glyph in all five states with the split animation; the orb in idle, listening and playing colours; both dot-field styles. A simulator screenshot of the gallery is compared against `styles-board.jpg`, `21-agents-ready.jpg`, `22-agents-holding-to-talk.jpg` and `23-agents-playing-back.jpg`.
- [ ] The orb and dot field animate smoothly in the simulator and stop animating when Reduce Motion is on.
- [ ] The onboarding hero layout keeps the first line of hero text at the same y position for one-, two- and three-line texts (shown by a test or by screenshots).
- [ ] The app builds and the existing app and kit tests pass. Pairing and the existing voice round trip still work through the placeholders.
