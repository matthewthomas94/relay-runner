## Description

Add a daemon- or app-owned recovery broker that lets the RR-333 continuity agent pursue the goal of restoring the speech-to-work processing path. The agent may choose and sequence broad runtime recovery steps, while each concrete action remains validated and executed by the component that owns the affected Relay state.

The phrase “whatever it takes” is scoped to restoring Relay-owned runtime processing. It does not authorize unrelated, destructive, durable project, credential, permission, or external changes. The broker should be broad enough to recover real failures such as dropped transcription, dead bridge or messenger processes, broken IPC, stale session registration, and a failed foreground provider process.

## Acceptance criteria

- [x] The broker exposes a restore-processing objective and validated capabilities for reinitializing speech capture or transcription delivery, restarting or recreating conclusively unhealthy Relay-owned child processes, reconnecting IPC and sockets, restoring heartbeat or session registration, releasing ownership held by a confirmed-dead process, and launching a fresh foreground provider session.
- [x] The continuity agent may sequence multiple broker actions until the RR-332 health objective is satisfied, the attempt or time budget is exhausted, or a hard authorization boundary is reached.
- [x] Every broker call validates exact target ownership and liveness, incident and recovery generation, command phase, idempotency or compensation behavior, attempt caps, cooldowns, and expected postcondition before the owning component executes it.
- [x] The broker rejects actions that edit source, tickets, Git state, configuration, authentication, Keychain, permissions, updates, installs, releases, deployments, databases or durable user data; send messages or create external side effects; cancel live work; kill a merely slow live provider; or switch provider or model without explicit policy.
- [x] Ambiguous command replay, destructive reset, reinstall, permission or authentication changes, and other non-recoverable operations stop automatic recovery and return a concise foreground PM or user escalation.
- [x] Each attempt is auditable and the broker can clean up ephemeral state created by the recovery generation when an action fails or makes health worse.
- [x] Focused tests prove allowed recovery remains possible across all supported components while disallowed operations cannot be reached by either Codex or Claude continuity agents.
