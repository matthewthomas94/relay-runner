## Description

Move ticket solutioning and visible ticket authoring out of the PM frontstage and into the persistent orchestrator.

The orchestrator should synthesize raw user instructions, decide whether one or many tickets are needed, write or edit visible `.orchestrator/RR-*.md` ticket files through an orchestrator-owned path, choose dependencies and worker sizing, and request worker creation from the PM when tickets are ready. The PM should not author, refine, apply, or commit ticket content while handling the user's command.

Worker creation requests should be structured and name the exact ticket IDs, dependency assumptions, worker sizing, and any dispatcher context needed for the worker.

## Acceptance criteria

- [ ] Define a structured orchestrator action protocol for ticket creation, ticket edits, dependency updates, worker sizing, and worker creation requests.
- [ ] The orchestrator can write/edit visible tickets and bump `.orchestrator/config.toml` without the PM composing ticket content.
- [ ] Ticket writes preserve the local board schema in `docs/specs/orchestrator-tickets.md`.
- [ ] The PM can receive worker creation requests and dispatch the named tickets without re-solutioning the plan.
- [ ] Worker dispatches still carry Relay stale-command metadata when applicable.
- [ ] Board auto-dispatch behavior is reconciled with orchestrator-authored ticket writes so ready tickets do not accidentally dispatch before the orchestrator's request is complete.
- [ ] Add tests/harness coverage for ticket creation, multi-ticket fanout, dependency ordering, worker sizing, and duplicate/stale request rejection.
