## Description

Rename the user-facing Board concept to Workspace and turn the current board overlay into a broader Workspace surface. The notch should open and close the Workspace, and the existing ticket/kanban experience should live as one tab inside that Workspace rather than being the whole surface.

Add a tabbed Workspace shell that feels native to macOS while retaining the current dark notch/board styling. The tab system should support the existing work/ticket view and a System Settings area in the same overlay. The normal settings experience should no longer open as a separate window when accessed from the app; it should appear inside the Workspace.

Move the existing settings panels into the Workspace as board-style panels. Start with these settings areas:

- Status
- Speech-to-text
- Text-to-speech
- General
- Awareness

Keep this scoped to the Workspace naming/shell, tab navigation, settings relocation, and visual consistency. Do not redesign unrelated ticket workflows unless they need a small adjustment to fit inside the new Workspace shell.

If a visual reference screenshot is available in the current conversation or clipboard context, use it to guide the tab treatment. If no screenshot is available to the worker, proceed with a restrained macOS-style tab treatment that matches Relay Runner's current dark notch/board surface.

## Acceptance criteria

- [ ] User-facing copy and controls use Workspace language for opening/closing the overlay; obsolete Board labels are removed or retained only in code/internal names where changing them would create unnecessary churn.
- [ ] The notch/menu entry point opens and closes the Workspace, preserving existing overlay placement, keyboard dismissal, and active-session behavior.
- [ ] The existing ticket/kanban UI appears inside the Workspace as a tab and keeps current create, edit, drag/drop, refresh, dispatch, and project/program-board behavior.
- [ ] The Workspace includes a tabbed navigation system with a System Settings tab or equivalent settings destination that feels consistent with macOS tab conventions and Relay Runner's current styling.
- [ ] System Settings no longer opens as a separate normal settings window from the primary app affordance; the primary path renders settings inside the Workspace.
- [ ] Settings panels for Status, Speech-to-text, Text-to-speech, General, and Awareness render as Workspace panels using the current dark board/notch visual language.
- [ ] Existing settings values still load, edit, validate, and persist correctly after being moved into the Workspace.
- [ ] Provider parity is preserved: Codex and Claude sessions see equivalent Workspace language, tab behavior, and settings access.
- [ ] Tests cover the Workspace naming/entry-point behavior, tab selection or routing, settings persistence after relocation, and any view-model logic used by the new shell.
- [ ] Build and focused tests pass; if final visual fit requires manual inspection, record the exact screenshots or manual checks in the run log.
