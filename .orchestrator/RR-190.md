## Description

Correct three regressions visible when exercising the full first-run experience through `Redo Onboarding…`. The shared message-playing point matrix must remain clipped to the black onboarding/notch surface throughout its reveal and cinematic. The cinematic-to-permission handoff must preserve the hero text baseline and use the same cursor/backspace transition language for permission copy rather than jumping directly to a displaced prompt. Permission grant actions must remain functional on every manual onboarding run, including the second and third run in one app process, without stale permission-coordinator state swallowing the click.

Implement this inline as a continuation of the explicitly requested RR-189 onboarding test work; do not dispatch a worker.

- [ ] The intro-to-permission transition keeps the text on the established hero baseline.
- [ ] Permission copy enters through the cursor/backspace animation instead of jumping or moving upward.
- [ ] `Grant permission` starts the appropriate live permission setup on the first, second, and third manual onboarding run in the same process.
- [ ] Stale permission setup state is cleared without disrupting the intentional System Settings handoff.
- [ ] Focused visual-layout, timeline, and repeat-permission regressions pass along with the full Swift test suite.
