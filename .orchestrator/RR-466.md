## Description

The listening (STT, orange) and speaking (TTS, purple) screen overlays are drawn by `ParticleFieldRenderer` (Sources/relay-runner/Overlay/ParticleFieldRenderer.swift) with coverage `.lowerScreen`, driven by the overlay controller. Each dot's radius and alpha follow three diagonal sine waves (lines 385 to 398 at commit 6df2b59a). The user wants those two overlays to also carry the dot-matrix shimmer used by the skeleton loaders and the hover dots: the column-snake rules in `DotColumnSnakeAnimation` (Sources/relay-runner/Overlay/SkeletonLoader.swift, from line 636), where every column is a repeating five-dot snake whose bright head glides one dot along the column each fifth of a 1.2 s cycle, even columns rising and odd columns falling, with the dot opacity gliding linearly between `levels`.

Requested on 2026-11-06. Constraints from the user:

- Keep the existing sine-wave motion. The snake shimmer is layered on it, not a replacement.
- The shimmer runs whenever these overlays are shown. It is not a hover effect.
- Only the listening and speaking screen fields change. The agent orb, the workspace backdrop, the onboarding fields and the perimeter ActionGlow field keep their current look.

The renderer draws with cached CoreGraphics coverage per frame (RR-440), so the shimmer must be computed as a per-dot multiplier from the dot's grid column and row and the elapsed time, not with Core Animation layers.

## Acceptance criteria

- [ ] For `theme == .stt` and `theme == .tts` with `coverage == .lowerScreen`, each dot's alpha is multiplied by a snake factor derived from `DotColumnSnakeAnimation`: the dot's snake position from `position(column:row:)`, its phase delay from `delay(forPhase:)`, and a linear glide through `loopValues` over `cycle`. The sine-wave radius and alpha terms remain exactly as before; the factor is applied on top of them.
- [ ] Other themes and coverages render byte-identical to before. Covered by a test that renders a `.workspace` and an `.agentOrb` frame before and after and compares the pixel buffers, or by asserting the existing render-cost fixtures' checksums are unchanged.
- [ ] The snake timing is shared, not copied: a helper in `DotColumnSnakeAnimation` (for example `opacity(forPhase:at:)`) returns the glided level for a phase at a time, and both the renderer and a new unit test use it. The test checks that at time 0 the head position returns `levels[0]`, that each position lags the previous by a fifth of a cycle, and that the value at `cycle` equals the value at 0.
- [ ] The shimmer is visible at the overlay's resting intensity: with the overlay fully shown, the brightest and dimmest dots in one column differ by at least the ratio `levels[0] / levels[4]` scaled by the wave range, so the snake reads clearly rather than as noise. State the measured ratio in the run log.
- [ ] `ParticleFieldRenderCostTests` still pass within their existing budgets; the per-frame cost increase for the lower-screen field is reported in the run log.
- [ ] Verified by a Relay Vision recording of the listening and the speaking overlay, attached by path in the run log, showing both the diagonal wave and the column snakes.
- [ ] `swift test --filter 'ParticleFieldRenderCostTests|SkeletonLoaderTests'` passes.
