## Description

Make `Redo Onboarding…` survive app termination and relaunch during macOS permission setup. A manual redo currently preserves the existing onboarded and agent-choice flags, so startup incorrectly treats the interrupted redo as complete and never restores the coding-agent or workspace stages. Persist a dedicated manual-redo-in-progress marker, recover that flow before normal already-onboarded launch gating, preserve the selected provider and resume step where applicable, and clear the marker only after the full provider/login/workspace flow finishes. Codex and Claude must receive equivalent recovery behavior.

Implement this inline as a focused onboarding lifecycle correction; do not dispatch a worker.

## Acceptance criteria

- [x] Starting manual redo persists a dedicated recovery marker without erasing existing provider or workspace configuration.
- [x] Relaunch during any permission handoff restores the locked intro onboarding surface and continues from live permission state.
- [x] Once permissions are satisfied, the recovered redo proceeds through coding-agent choice, selected-provider runtime/login, and workspace selection.
- [x] Relaunch from provider, login, or workspace stages honors the saved resume step and still requires workspace completion.
- [x] Completing onboarding clears the manual-redo marker and restores ordinary app-shell access.
- [x] Codex and Claude recovery paths remain equivalent.
- [x] Focused relaunch regressions and the full Swift test suite pass.
- [x] A new DMG and installed app bundle are verified before launch.
