## Description

Separate research execution from structured output permissions. Spike workers must remain read-only against source and external systems, while the daemon may persist a validated final report and the foreground PM may turn accepted recommendations into backlog tickets. Repair result selection so an invalid terminal result cannot be silently replaced by an earlier intermediate candidate. Extend the existing commit-before-reporting guarantee to recovered reports, refined follow-up acceptance, and every canonical ticket authoring or refinement path.

## Acceptance criteria

- [ ] Spike policy explicitly permits a designated structured final report and PM-authored follow-up drafts while continuing to prohibit source, board, desktop, and external mutations by the spike process.
- [ ] The daemon remains the sole writer of canonical spike reports and accepted backlog tickets.
- [ ] Result extraction selects the terminal structured result and reports validation failure instead of falling back to an earlier intermediate candidate.
- [ ] Output schema and validator limits agree, including conclusion, evidence, uncertainty, and recommendation list bounds.
- [ ] An explicit current PM or user authorization can accept refined proposals into backlog; individual review remains the default.
- [ ] Every canonical ticket creation, refinement, recovered report, and accepted follow-up is committed before success is reported, while unrelated dirty changes remain excluded and overlapping authoring paths produce a clear blocker.
- [ ] Tests cover oversized terminal results, earlier valid intermediate candidates, report persistence, proposal creation, ticket acceptance, automatic commit boundaries, dirty-overlap handling, and Codex and Claude parity.
