## Description

Relay Runner runs up to four named foreground agents at once (Puck, Isabella, George, Sky). Each can edit any registered project's checkout directly (for example `~/dev/relay-runner`), run git in it, and cut a release from it. Worker runs are safe from each other because each has its own worktree, but the foreground agents all share the one checkout per project. Two of them editing it at once, or one switching its branch or pushing while another is mid-change, damages work. The daemon also merges reviewed worker branches into whatever branch that checkout has checked out, so a branch switch by one agent affects everyone.

RR-525 added agent presence and one-way, silent notices delivered at an agent's next turn. Notices are advice. This ticket adds the one hard rule: a claim on a project's checkout that the system enforces, so a second agent is refused and told who holds it. Read RR-525's docs and code first and reuse its presence record, session-to-agent identity and notice queue.

### What to build

1. **The claim.** At most one agent holds the claim on a registered project's checkout. It is held in the daemon with the agent, its session key, the repository, a one-line purpose and the time of the last write. It is released when the agent releases it, when its session stops, and after 30 minutes without a write by the holder. The built-in general-tasks project has no claim: every agent keeps small files there.
2. **Taken by writing.** An agent does not have to remember to claim. The first direct write by an agent to a claimable checkout takes the claim if it is free, and each further write refreshes it. Provide orchestrator MCP tools to take a claim explicitly with a purpose (for example before cutting a release), to release it, and to read who holds which claims.
3. **Enforced before the write.** Before a foreground agent's tool call changes a claimable checkout, check the claim; if another agent holds it, refuse the call with a message naming the holder, its purpose and when it last wrote, and telling the agent to stop and ask the user. Cover:
   - file-writing tools whose target path is inside the checkout;
   - shell commands that change the checkout's git state or the remote from it: checkout, switch, commit, merge, rebase, reset, stash, cherry-pick, revert, pull, push, tag, and the project's release scripts, whether run from inside it or with `git -C`.
   Implement this in the provider's pre-tool hook (the relay hook is `rust/relay-rs/src/hook/`; check how hooks are installed for each provider). Shell commands cannot be parsed perfectly: cover the listed git commands by name, document what is not covered, and never refuse a read-only command. Paths inside worker worktrees, the daemon's workspaces and `.claude/worktrees` are not the shared checkout and are never refused.
4. **Provider parity.** Find out whether Codex offers an equivalent pre-tool hook. If it does, enforce the same way. If it does not, Codex agents take the claim through the MCP tool on instruction, the claim still blocks Claude agents, and the difference is stated in the docs and the run log.
5. **Notices.** Taking and releasing a claim sends a notice to the other running agents through RR-525's queue: who, which repository, the purpose. Claims appear in RR-525's presence read tool.
6. **What does not need a claim.** Reading files, searching, running tests or builds that write only to ignored build output, writing tickets through the daemon, and dispatching. Worker runs and the daemon's own merges are unchanged by this ticket.
7. **Instructions and docs.** Tell the foreground PM, for both providers: a refused write means another agent holds the checkout; it must not work around the refusal (no writing through another tool, no copying the checkout, no waiting in a loop); it tells the user who holds the claim and asks. Document the claim, what is enforced and what is not. Regenerate the generated instruction files.

Known gap, to state in the docs and not to solve here: the daemon's merges into the checkout do not take or respect the claim.

## Acceptance criteria

- [ ] Daemon test: the first write by Puck takes a free claim; a write by George to the same checkout is refused with Puck's name, purpose and last-write time; Puck's further writes refresh it.
- [ ] Daemon test: the claim is released by the release tool, when the holder's session stops, and after 30 minutes without a write (injected clock); after each, George's write succeeds and takes the claim.
- [ ] Hook test: a file write inside a claimed checkout by a non-holder is refused before it happens; the same write by the holder, a write inside a worker worktree or `.claude/worktrees`, a write in general-tasks, and a read are allowed.
- [ ] Hook test: each listed git command, run in the checkout and with `git -C <checkout>`, is refused for a non-holder; `git status`, `git log` and `git diff` are allowed.
- [ ] Test: taking and releasing a claim queue one notice each for the other running agents, and the presence read tool shows current claims.
- [ ] The run log states what the Codex investigation found and how Codex agents are handled.
- [ ] The hook adds no noticeable delay to ordinary tool calls: state the measured overhead per call in the run log, and the hook allows the call when the daemon cannot be reached.
