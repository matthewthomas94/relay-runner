## Description

Fix an intermittent regression where audible playback and the response pill present different content. During an active response, the user heard the current message while the pill showed only `bounded final`, an internal-looking generic label, beneath **Double tap Control to cancel**. The clipboard capture confirms the pill's visual state during playback; the audible content is user-attested, so the ticket must preserve that evidence boundary rather than treating the screenshot alone as proof of the audio stream.

This is distinct from RR-343, which fixed truncation of the correct long response. Here, the visible body is missing or belongs to the wrong payload while another utterance is playing. Diagnose the handoff among authoritative final delivery, Messenger realization, speech-intent arbitration, speculative TTS, playback state notifications, and the SwiftUI pill. A waiting preview, semantic brief, prior utterance, fallback, or test-only label must not remain visible after a different utterance becomes current.

Treat the spoken text, display text, utterance identity, and source-command identity as one presentation unit. The pill should show the complete validated display text for the utterance that is actually preparing or playing, with the spoken text as its safe fallback. Preserve privacy filtering, stale-command suppression, exact-once arbitration, replay semantics, cancellation, and interruption behavior.

## Acceptance criteria

- [ ] A deterministic regression reproduces audio playback while the pill is empty, shows an internal shorthand such as `bounded final`, or retains text from a different utterance.
- [ ] Every accepted speech intent carries a non-empty pill body associated with the same utterance ID and Relay command sequence/ID as the audio being prepared or played.
- [ ] The pill uses the intent's complete validated `display_text`; when that field is absent or blank, it falls back to the exact spoken text instead of showing no message.
- [ ] Internal semantic briefs, lifecycle labels, fault-harness fixtures, and compact status summaries cannot become the playback body unless they are deliberately also the user-facing spoken/displayed message.
- [ ] Waiting, preparing, speaking, completed, replay, and post-play hold transitions update the response body atomically with the active speech intent; an older preview cannot overwrite or survive into newer playback.
- [ ] The matching response text is visible no later than audible playback begins and remains readable for the expected playback and post-play presentation lifetime.
- [ ] Superseded, stale, interrupted, and canceled utterances clear or replace both audio and visual presentation together without allowing either channel to leak into the next command.
- [ ] Authoritative final, Messenger-realized final, fallback final, protected lifecycle, ordinary progress, and explicit replay paths retain their existing precedence, deduplication, and semantic roles while sharing the synchronization guarantee.
- [ ] Privacy-safe diagnostics correlate command ID, utterance ID, speech state, and display-state transitions without recording response text, raw transcripts, prompts, or secrets.
- [ ] Codex and Claude app-owned sessions receive equivalent behavior, with provider-specific completion-hook differences covered explicitly.
- [ ] Focused Python tests cover payload/arbitration ordering and stale-preview races; Swift tests cover active playback rendering and response replacement at constrained widths.
- [ ] A mounted signed-app UAT captures the pill during original playback and replay, and a human confirms that the visible response matches the audible content in both cases.
