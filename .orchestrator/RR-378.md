## Description

Introduce an explicit Task / Action / Discussion qualification framework into the existing Relay voice workflow for testing, without an additional inference call. The foreground PM retains authority and Messenger continues starting in parallel. Improve the current phrase-based routing around clear foreground actions and explicit discussion-only constraints. Preserve command identity, accepted-work continuity, scoped cancellation, read-only discussion and existing artifact-backed ticket authorization.

Tasks mean requested project implementation or explicitly tracked/delegated ticket or spike work. Actions mean bounded foreground operations via shell, OS, API or Relay computer use (open Chrome, start a dev server, send a specified email). Discussion includes exploration, feasibility, research, explanation and status before execution; read-only tool use does not make a request a Task. Creating a ticket, requesting dispatch and authorizing implementation remain distinct permissions. Explicit inline implementation remains its existing exception. Bucket labels must not independently authorize external effects.
