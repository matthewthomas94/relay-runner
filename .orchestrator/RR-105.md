## Description

Investigate and harden the Relay Runner voice bridge crash/restart path.

During a live Relay session on June 27, the user reported that Relay Runner or VoiceBridge crashed and had to be restarted. The current restart path clears `/tmp/voice_bridge.log`, so the useful pre-restart evidence was lost. A bounded check after restart found:

- The fresh `/tmp/voice_bridge.log` only showed the new bridge startup and subsequent voice-command classifications.
- No recent Relay/voice crash report appeared under `~/Library/Logs/DiagnosticReports`.
- The fresh startup logged `launchctl did not produce a socket; falling back to direct background launch`, which may be normal recovery or may point at a fragile launchd handoff.

Make the next occurrence diagnosable and fix any concrete restart fragility found during implementation.

## Acceptance criteria

- [ ] Relay bridge restarts preserve the previous bridge log instead of truncating the only evidence; use timestamped rotation or another simple local diagnostic path.
- [ ] Startup records whether launchctl or direct fallback produced the socket, with enough context to debug why launchctl failed.
- [ ] If the app/bridge process exits unexpectedly, the diagnostic path captures exit status or last known failure reason where available.
- [ ] Add tests or a deterministic script check for log rotation/preservation behavior.
- [ ] Document the manual verification path for a forced bridge restart and where to inspect preserved diagnostics.
- [ ] Provider parity is explicit: Codex and Claude relay sessions use the same bridge diagnostics, with provider metadata included only where useful.
