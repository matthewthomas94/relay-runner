## Description

Update Relay Runner's model catalogue and launch compatibility for the current ChatGPT/Codex and Claude Code releases.

The installed ChatGPT app bundles Codex CLI 0.144 under `ChatGPT.app`, with GPT-5.6 Sol, Terra, and Luna plus model-specific `max` and `ultra` effort support. The installed Claude Code 2.1 CLI advertises `fable` and `claude-fable-5` in addition to the established provider aliases. RR-149 added discovery of the current `ChatGPT.app` executable path, but Relay Runner still keeps a static provider-wide effort list and offers only generic Claude Opus/Sonnet/Haiku choices.

Support only models that the corresponding agent CLI can launch. Consumer-only ChatGPT fallback, voice, and application models must not appear in Relay Runner's Codex session picker unless the Codex CLI exposes them.

Use current primary provider documentation and installed CLI catalogues as the implementation-time source of truth. Record the checked provider and CLI versions in verification notes so future model refreshes can distinguish catalogue drift from regressions.

## Acceptance criteria

- [x] Codex executable discovery supports the current `ChatGPT.app/Contents/Resources/codex` path, the legacy `Codex.app` path, configured absolute commands, and `PATH` fallback in a documented order.
- [ ] The Codex picker reflects current launchable Codex models without adding ChatGPT-only fallback, voice, or application models.
- [ ] The Claude picker includes the current Claude Code aliases and any explicitly supported full model IDs chosen for stable user selection, including the Fable 5 launch path advertised by the installed CLI.
- [ ] Model choices clearly communicate preview, entitlement, or provider restrictions that can cause a syntactically valid model to fail for an account.
- [ ] Reasoning-effort choices are derived from the selected provider and model, including model-specific Codex `max` or `ultra` support without exposing unsupported combinations.
- [ ] Default model selection continues to omit `--model`, preserving the user's account-level provider default.
- [ ] Existing saved model and effort values normalize predictably when a model is retired or an effort is unsupported; switching providers cannot leak the previous provider's model or effort.
- [ ] Codex and Claude launch rendering tests cover every newly exposed model/effort combination and reject unsupported combinations.
- [ ] Settings, onboarding, README model lists, and verification notes agree on the supported catalogue and provider-specific limitations.
