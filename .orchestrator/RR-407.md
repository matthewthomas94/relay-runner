## Description

When several project sessions are live, the notch already names the target of a recording. It shows **Listening · <project>** (RR-398):

- `NotchVisualLabelAllowlist.presentation` in `Sources/relay-runner/Overlay/NotchStatusController.swift` (around line 531) builds the label.
- The name comes from `AppState.listeningVoiceTargetName` in `Sources/relay-runner/App/AppState.swift` (around line 1428). It does so only when `sessionRegistry.liveContextIDs.count > 1`, mapping the STT voice-target session key through `sessionRegistry.spool(for:)?.key` to `assistantSessionStore.document.bindings[contextID].context.displayName`.

The `.speaking` state always shows plain **Playing** (around line 547). With several sessions sharing the voice bridge, the user can't tell which project a spoken reply came from.

**Change:** when more than one session is live, show **Playing · <project display name>** for the session whose reply is playing. Keep plain **Playing** when only one session is live or when the reply's session is unknown.

**Where the identity is lost:** `services/tts_worker.py` emits the `speaking` state event (`_notify_state("speaking", ...)` with `_presentation_fields(intent)`, around line 787), and that event carries no session identity. The bridge already knows the reply's session:

- `_SPOKEN_REPLY["session_key"]` in `services/voice_bridge.py` (around lines 962 and 1048, the latter for brought-forward unheard replies);
- Stop-hook completions add `session_key` in `services/relay_completion_hook.py`.

**Suggested plumbing:**

1. Add the originating session key to `SpeechIntent` in `services/speech_coordinator.py`.
2. Include it in `_presentation_fields` so the `speaking` event carries it.
3. Parse it into `SpeechPresentation` in `Sources/relay-runner/Overlay/StateMachine.swift` (around line 23).
4. Resolve it in `AppState` with the same spool-key-to-display-name lookup used for listening.
5. Pass the name to the notch label planner alongside `voiceTargetName`.

An explicit replay keeps the original reply's session. Messenger speech for a turn uses the session that turn targeted when the bridge knows it, and otherwise falls back to plain **Playing**.

**Scope:** this changes only the notch `.speaking` label and its hover label. Leave unchanged:

- the bottom pill's shared `label(for:)` (around line 639);
- "Preparing speech", "Response ready" and other states;
- the Listening behaviour.

Both Codex and Claude sessions reply through the same bridge, reply helper and completion hook, so the result must be provider-neutral.
