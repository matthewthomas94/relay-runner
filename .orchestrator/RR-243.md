## Description

Align `ProgramBoardDropPolicy` with the orchestrator lifecycle so an idle ticket
cannot be manually moved into In Progress. Keep Backlog to Queued eligible and
dispatched, and surface invalid-drop feedback without conflating policy
rejection with event latency.

RR-237 confirmed that an idle ticket can currently be moved into In Progress
even though that lane represents worker-owned lifecycle state.

## Acceptance criteria

- [ ] Backlog to Queued remains eligible and requests dispatch when
      dependencies permit.
- [ ] Manual Backlog, Queued, or Done to In Progress is rejected unless a
      documented orchestrator-owned transition API performs it.
- [ ] Active-worker and awaiting-merge cards remain non-draggable.
- [ ] Mounted tests distinguish rejected-policy feedback from a delayed
      eligible drag and keep eligible feedback below 25 ms p95.
