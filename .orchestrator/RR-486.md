## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

This is the stage 4 epic. It is deliberately not dispatchable as written: when the gate decision is to continue, the foreground PM splits it into tickets of reviewable size and cancels this one.

RR-448 was explicit that this stage will not reduce idle CPU: RR-440 and RR-449 found that cost was design (polling, graph rebuilds, per-call connections), not the interpreter. The reasons to do it are removing Python from the install and compile-time types.

Scope: `orchestrator.py`, the `artifact_*` modules, `automatic_retention`, `tickets`, `followup_tickets`, `program_status`, `program_artifacts`, `graphify_*`, `session_capture`, `command_actions`, `general_work`, `sidecar_lane`, `relay_authorization`, `codex_model_catalog`, `claude_subscription`, `config`, the continuity modules, notes and personal storage.

Suggested split, each a separate ticket:

1. Ticket and frontmatter parsing, `config.toml` handling and the artifact store as a library crate that produces byte-identical commits (keep shelling out to `git`).
2. Artifact lifecycle, sync, retention, migration and verification on that crate.
3. Stores and schemas for the ten SQLite databases, opening existing databases in place.
4. HTTP server with all routes, backed by the above.
5. Worker, review worker, spike and general-task execution for both providers together.
6. Continuity lane, notes, personal storage, program status and graph ingest.
7. Cut-over: the LaunchAgent runs the Rust daemon by default, with a switch back to Python for one release.

Constraints: the HTTP API, database schemas, git output and file formats stay compatible in both directions so rollback needs no migration; Claude and Codex worker launch lines change together.

## Acceptance criteria

- [ ] The daemon contract suite passes against the Rust daemon.
- [ ] A Rust daemon and a Python daemon can be swapped on the same data root in either direction without migration.
- [ ] Dispatch, review, merge and spike runs complete with both providers on a live project.
