## Description

The Workspace board is very slow. The first open after launch sits in the loading sketch for a long time, and a ticket change takes a long time to appear. Make both fast.

How it works today:
- The board's update check, `checkForUpdates` in `Sources/relay-runner/Board/ProgramBoardOverlayController.swift:1094`, runs only once the Workspace is shown. On a first open it blocks the content (`contentLoadBlocked`, `.loadingContent`) until `model.reloadIfIdle` returns.
- After that, `startStatusPoll` (`:1069`) refreshes every 10 s, and only while the Work tab is visible (`statusPollRefreshesDashboard`, RR-440). Per the RR-440 note, each refresh makes the daemon re-sweep every project and rebuild the program graph (`/v1/program/status`, `/v1/program/dashboard` in `services/orchestrator.py`).

Do this:
1. **Measure first.** Time the cold first load, from showing the Workspace to the board content appearing, and break it into app-side and daemon-side parts. Also time the delay from a ticket write on `relay/artifacts` to the board showing it. Record the numbers in the run log.
2. **Warm at start.** Run the board's update check in the background when Relay Runner launches and again when a session starts, so the snapshot is ready before the Workspace is first opened. It must not animate the notch or the loader while the Workspace is hidden.
3. **Show the last snapshot immediately.** When a snapshot already exists, from the warm-up or a previous open, opening the board shows it at once and refreshes in the background instead of showing the blocking loader.
4. **Make updates fast and cheap.** Make a ticket change appear quickly without a full sweep of every project. For example, refresh only the changed project, or have the daemon notify the app when a board's artifact ref changes instead of waiting for the next 10 s poll. Pick the approach from what the measurements show.
5. Fix whatever else the profiling shows is the main cost in the daemon's status and dashboard path, without changing what the board displays.
