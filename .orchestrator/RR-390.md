## Description

Make Workspace feel like one assistant experience with a clear General destination, searchable existing projects, recent contexts and relevant repository suggestions. Repository discovery should use registered projects and bounded user-authorized locations; it must not crawl the whole disk or block session startup. Selection changes the foreground context while existing project tickets retain their repository ownership. Keep global Notes and Files accessible alongside work and conversation.

## Acceptance criteria

- [ ] Start Session is available without a selected repo; General and the active project are clearly visible and switchable from the same Workspace surface.
- [ ] Users can select an existing repository and begin work, inspect its tickets, and return to General without managing provider sessions.
- [ ] Suggest repositories from the registry and explicitly authorized scan roots with bounded asynchronous scanning, deduplication and availability checks.
- [ ] Repository suggestions do not automatically register a repo, change execution scope, initialize a board or dispatch work; stale/missing suggestions are handled clearly.
- [ ] Notes and managed user files are reachable centrally; a project view does not hide global notes or imply their storage belongs to the selected project.
- [ ] History and working-state continuity remain visible across contexts, with accessible keyboard navigation, VoiceOver labels and loading/error states.
- [ ] Source/UI validation covers zero projects, many projects, slow scans, deleted repos and switching with active workers; installed visual verification remains a distinct acceptance gate.
