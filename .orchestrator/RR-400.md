## Description

`services/intent_inbox.py` has no session column. `retire_stale_foreground` (~266) cancels every non-sidecar foreground row whose recovery generation differs, which would cancel other live sessions' intents. `materialize_next` blocks while any foreground row anywhere is unacknowledged and returns early if the single cmd/meta file exists, causing head-of-line blocking across sessions.

Implement RR-393 slice D: add a session key to inbox rows (or one DB per session, justify the choice), migrate existing rows safely, and scope `retire_stale_foreground`, `cancel_scoped` and `materialize_next` to the row's session. Materialize items into that session's spool paths. A scoped `all_work` cancellation means all work in the issuing session only.

## Acceptance criteria

- [ ] Inbox rows record their session key; existing databases migrate without data loss.
- [ ] retire_stale_foreground for session A never cancels session B's rows (unit test).
- [ ] An unacknowledged foreground item in A does not block materializing B's next item (unit test).
- [ ] all_work cancellation from A leaves B's accepted intents untouched.
- [ ] Materialized items land in the owning session's spool files.
- [ ] Python tests for intent_inbox and voice_bridge pass.
