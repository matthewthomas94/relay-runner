## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

Today `services/tts_worker.py` calls `kokoro_onnx.Kokoro(model, voices).create(text, voice=..., speed=1.0, lang="en-us")` one sentence at a time, using `kokoro-v1.0.onnx` and `voices-v1.0.bin` from `~/.local/share/kokoro`, voices `am_puck`, `bm_george`, `bf_isabella` and `af_sky`. Phonemes come from espeak-ng through `phonemizer-fork`, both GPL. No onnxruntime session options or providers are set.

Build a prototype, not production code, under `rust/` as a separate binary crate (for example `relay-speech-proto`):

- Synthesis with the `ort` crate from the same two model files, producing 24 kHz mono 16-bit WAV.
- Phonemisation with a non-GPL Rust crate; start with `misaki-rs` built without its espeak feature. No GPL or AGPL code may be linked. If no non-GPL option gives acceptable output, say so; that is a valid result.
- A fixed corpus committed in the repo: at least 40 sentences covering ordinary replies, code identifiers, file paths, numbers, dates, version strings, ticket ids such as "RR-448", product names and deliberately unknown words.
- A script that renders the corpus with the current Python stack and with the prototype for all four voices into a directory outside the repo, and writes a side-by-side HTML page for listening.
- Measurements on the worker machine for both stacks: model load time, time to first audio for a one-sentence reply, real-time factor over the corpus, peak resident memory, and for Rust the release binary size and how ONNX Runtime is linked. Try the CoreML execution provider and report whether it helps.
- A check that the Rust binary, signed the way `scripts/build-dmg.sh` signs helpers (hardened runtime, no entitlements), starts and synthesises.

Write the results to `docs/investigations/RR-448-rust-speech-prototype.md` with the numbers, the method, the phoneme differences found and a recommendation. Pin every crate to an exact version and record the upstream commit.

## Acceptance criteria

- [ ] The prototype renders the whole corpus for all four voices without linking GPL code; `cargo deny` or the stage 0 licence check passes.
- [ ] The report gives load time, first-audio time, real-time factor, peak memory and binary size for both stacks, with the commands used.
- [ ] The listening page exists and its path is in the run log, with the sentences whose phonemes differ most called out.
- [ ] The signed prototype binary runs under the hardened runtime, or the report states exactly why it does not.
- [ ] The report ends with a clear recommendation: proceed, proceed with a named mitigation, or do not proceed.
