## Description

Implement the deterministic detection layer proposed by RR-322 for failures that prevent Relay Runner from turning speech into continuing project work. Observe the speech-capture, transcription, bridge, messenger, foreground PM/provider, daemon, and session lifecycles; distinguish transient symptoms from a genuinely stalled or recurring processing incident; and emit a sanitized recovery objective that can safely launch continuity recovery.

This ticket defines evidence and classification only. A transient symptom that clears inside its native grace period remains log-only. Recovery must not start from one weak signal or during an explicit stop, update, reset, or already-completed command.

## Acceptance criteria

- [ ] A deterministic state machine identifies supported continuity failures including transcription capture or delivery loss, bridge or messenger loss, a stalled foreground provider session, and an accepted command whose processing lifecycle stops advancing.
- [ ] Transient, stalled, and recurring classifications use explicit grace periods, multiple liveness samples or failed native recovery, stable incident fingerprints, cooldowns, and suppression during explicit stop, update, reset, or completed work.
- [ ] The emitted incident envelope names opaque session, command, component, provider, recovery-generation, phase, health, and timing evidence without raw audio, transcript text, prompts, source commands, repository data, credentials, screenshots, or provider output.
- [ ] The recovery objective states which user-visible processing capability is unavailable and what health evidence will prove normal operation has returned.
- [ ] Codex and Claude use the same normalized incident contract, with provider-specific signals translated only through allowlisted adapters.
- [ ] Focused tests cover false-positive suppression, dropped transcription before command creation, captured-but-undelivered input, component loss, stalled accepted work, recurrence, and recovery cooldown behavior.
