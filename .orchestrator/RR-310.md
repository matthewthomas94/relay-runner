## Description

Implement a Relay-owned, local-first observability foundation for first-run and Workspace failures. It must produce a privacy-safe, cross-process incident timeline spanning the Swift app, shell launchers, Python services, and provider processes. A user-facing Workspace failure should expose a stable incident identifier, retry linkage, and a previewable diagnostics export that remains useful when the daemon, provider, or network is unavailable.

Apple Unified Logging, signposts, MetricKit, native crash reports, and retained dSYMs should complement the Relay journal. Do not make a remote vendor SDK the only source of evidence. Evaluate a tightly scrubbed, explicit-consent Sentry pilot only after the local bundle is usable.

## Acceptance criteria

- [x] A versioned allowlisted event schema carries app session, incident, retry attempt, and cross-process correlation identifiers without raw transcripts, repository paths, credentials, prompts, audio, screenshots, or provider output.
- [x] Setup, orchestrator launch, Workspace readiness, and provider readiness write bounded local events and safe stderr/error summaries with clear phase and outcome fields.
- [x] Workspace failures show an incident ID, support retry attempts linked to that incident, and offer diagnostics creation without relying on Python or a provider process.
- [x] The diagnostics preview and generated bundle document included data, exclusions, and redaction counts; they exclude raw command captures, repositories, worker logs, screenshots, credentials, and full temporary-directory contents.
- [x] Journal and bundle retention limits, path/token redaction, and redaction tests are implemented and documented.
- [x] Release builds retain matching dSYMs and the project has an explicit crash/symbol verification contract.
- [x] If a remote reporting pilot is added, it is opt-in, client-side allowlisted, supports consent revocation and offline behavior, and is verified for both Swift and Python reports.
