## Description

Follow up the completed RR-179 permission companion work using evidence from an
installed-app smoke test. The real Relay Runner app drag now works and the app
can be added to the macOS permission list, but the instructional animation does
not play as a continuous idle loop. Only disconnected fragments appear around
pointer entry and exit on the draggable app icon. Hovering or dragging should
pause the demo cleanly, but the animation must already be advancing while idle
and must resume from the frozen point without jumping, resetting, or requiring
another hover transition.

The animated hand also passes behind the black draggable-app card when it
approaches the icon. The demo panel is currently ordered below the interactive
panel during repeated settings-window polling, so artwork drawn by the demo is
occluded by the card. Correct the composition so the hand and carried icon are
visually above the black card while the interactive drag surface remains fully
clickable and draggable. Preserve the working native file drag and the removal
of the green drop ring from RR-179.

## Acceptance criteria

- With the companion visible and untouched, the full approach, press, drag,
  release, hold, and reset loop advances continuously at the display refresh
  cadence; it does not depend on hover entry or exit to start or advance.
- Pointer entry over the draggable icon freezes the current demo frame once.
  Pointer exit resumes after the intended idle delay from the frozen timeline,
  without a partial-phase jump, reset, duplicate display link, or timer storm.
- A real drag still starts exactly once and pauses/hides the synthetic demo as
  appropriate. Ending or canceling the drag resumes the normal idle loop using
  the established hover semantics.
- The synthetic hand and carried app icon render above the black companion card
  throughout approach, press, and drag. The overlay used to achieve this must
  remain transparent to mouse input so the real app icon stays draggable.
- Repeated 5 Hz settings-window polling preserves the correct panel ordering
  and does not restart the animation timeline or display link.
- The green release/drop ring remains absent.
- Add focused tests for initial display-link advancement, hover freeze/resume
  continuity, and panel ordering/input transparency. Retain the existing hosted
  native-drag regressions.
- Run the focused permission companion tests and full `swift test` suite.
  Build the release artifact with `RELAY_SKIP_APPLICATIONS_REFRESH=1
  scripts/build-dmg.sh`.
- Perform an installed-app smoke test when the available Relay tool surface can
  exercise hover without disturbing the native drag. If it cannot, document
  the exact manual check still required instead of weakening the automated
  criteria.
- Provider parity: verify the shared change applies equally to Codex and Claude
  onboarding and recovery flows, or document any intentional difference.
