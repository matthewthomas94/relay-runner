## Description

Tickets are draggable in the project board, but not in the Program Board. Add drag-and-drop lane movement to Program Board ticket cards.

The Program Board must write changes to the owning child repo for each ticket. Moving a card to `ready` must use the existing board dispatch path rather than bypassing the orchestrator. Invalid moves should be rejected consistently with project-board rules, including canceled tickets, already-claimed tickets, and tickets with unsatisfied dependencies.

## Acceptance criteria

- [ ] Program Board cards can be dragged between Backlog, Ready, In Progress, and Done lanes where the transition is allowed.
- [ ] The status update is written to the ticket file in the owning project repo, not to the workspace root.
- [ ] Moving a ticket into Ready triggers the same board-dispatch behavior used by the project board.
- [ ] Invalid moves show the user a clear failure state and leave the ticket unchanged.
- [ ] Project Board drag behavior is not regressed.
- [ ] Add Swift tests for Program Board drop resolution and request routing.
- [ ] Verify with `swift test --skip-update` and relevant Python tests if daemon endpoints are touched.
