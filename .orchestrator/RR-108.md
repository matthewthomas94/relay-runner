## Description

Add Settings controls that let the user configure model and reasoning-effort behavior separately for the foreground orchestrator session and dispatched sub-agents.

The foreground orchestrator controls should cover the agent session Relay Runner launches from Start Session. The existing Codex reasoning-effort setting from RR-101 should be folded into this model rather than leaving a parallel one-off setting. Preserve provider-specific behavior: Codex uses `--model` plus `model_reasoning_effort`, while Claude uses its model and `--effort` surface.

For sub-agents, add a policy setting with two modes:

- Orchestrator decides: keep the current ticket-level `worker_model` and `worker_effort` sizing workflow from RR-103/RR-104.
- User default: let the user choose default sub-agent model/tier and effort in Settings, and apply those defaults when new/refined tickets are created or queued unless a ticket already carries an explicit sizing decision.

Keep this scoped to settings, persistence, launch/default propagation, and tests. Do not redesign the board, ticket lifecycle, or provider picker beyond what is needed to expose these controls cleanly.

Likely touch points:

- `Sources/relay-runner/Config/Config.swift`
- `Sources/relay-runner/Config/ConfigManager.swift`
- `Sources/relay-runner/Settings/GeneralSettingsTab.swift`
- `Sources/relay-runner/Process/ProcessManager.swift`
- Board ticket creation/editing paths that mint or refine worker sizing metadata.
- `services/config.py`
- `services/orchestrator.py` or command-action/ticket-creation helpers if they need to read the default sub-agent policy.
- Relevant Swift and Python config, launch, board, and orchestrator tests.

## Acceptance criteria

- [x] Settings exposes orchestrator model and effort controls for supported providers, with Codex and Claude using their provider-appropriate vocabulary and launch mechanisms.
- [x] Existing Codex reasoning-effort behavior is migrated or normalized into the orchestrator controls without breaking existing config files.
- [x] Settings exposes a sub-agent sizing policy switch: orchestrator decides versus user default.
- [x] When user default is selected, new or refined tickets get default `worker_model` and `worker_effort` values unless the ticket already has an explicit sizing decision.
- [x] When orchestrator decides is selected, existing RR-103/RR-104 ticket-level sizing behavior remains unchanged and ready-ticket dispatch still refuses missing sizing metadata.
- [x] Start Session and worker dispatch apply the selected values with shell-safe quoting and provider-specific flags/config.
- [x] Config load/save and migration tests cover absent, invalid, Codex, and Claude values for orchestrator and sub-agent settings.
- [x] UI or view-model tests cover the settings controls, policy switch, and provider-specific visibility/normalization.
- [x] Provider parity is explicit: Codex and Claude both get coherent controls, and any intentional difference is documented in code, tests, or verification notes.
