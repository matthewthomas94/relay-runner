## Description

Add a program-level project filter and "All" tickets board to the Program Board.

The current Program Board summarizes projects and shows aggregate work lanes. The user wants the Program Board to behave like the project boards, but scoped by selection:

- clicking `All` shows tickets from every registered project
- clicking a specific project shows only that project's tickets
- the ticket board uses the same four lanes as project boards: Backlog, Ready, In progress, Done

Add an `All` control on the right-hand side of the Projects header or an equivalent nearby affordance, and make project cards/selectors filter the same ticket board to one project.

Keep the first version focused. This can be read-only if that is the smallest coherent implementation: the main job is to make every ticket visible at program scope with enough project context to understand where it lives. Editing, drag-to-ready, and dispatch controls can remain project-board responsibilities unless they fall naturally out of the RR-55 program dispatch work.

Do not create or rely on a workspace-root `.orchestrator/`. The all-tickets view should aggregate child project ticket files and run metadata through the existing project registry / Program Board status model.

Provider parity matters. Codex and Claude-dispatched tickets and workers should appear the same way in this view, with provider metadata shown only where it helps identify active work.

## Acceptance criteria

- [ ] Program Board exposes an `All` control near the Projects header or another clear top-level affordance.
- [ ] Activating `All` shows tickets from all registered child projects without opening each project board.
- [ ] Selecting a specific project filters the ticket board to only that project's tickets.
- [ ] The ticket board uses the same four lanes as project boards: Backlog, Ready, In progress, and Done.
- [ ] The Program Board no longer uses Discovery, Blocked, or other aggregate work columns as the primary ticket board in this view.
- [ ] Each ticket row/card shows project name or path when `All` is selected, plus ticket id, title, status, priority, dependency/blocking state where available, and active/awaiting worker state where available.
- [ ] The view stays usable for multi-project work, with project selection and the four canonical lanes providing the first version of grouping/filtering.
- [ ] The all-tickets view does not create a parent workspace `.orchestrator/` and does not mutate child project tickets in the read-only V1.
- [ ] Returning from a project-specific selection to `All` restores the all-project ticket board without losing refresh state.
- [ ] Codex and Claude provider metadata renders consistently for active workers and completed/awaiting-merge work.
- [ ] Tests or deterministic view-model coverage verify aggregation across at least two child projects, empty-state behavior, and no-parent-`.orchestrator` behavior.
