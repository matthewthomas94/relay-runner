## Description

Add a program-level "All" tickets view to the Program Board.

The current Program Board summarizes projects and shows aggregate work lanes. The user wants a direct way to see all tickets across registered projects without opening each project board one by one. Add an "All" control on the right-hand side of the Projects header or an equivalent nearby affordance. Activating it should show a program-level ticket surface that includes tickets from every discovered project.

Keep the first version focused. This can be read-only if that is the smallest coherent implementation: the main job is to make every ticket visible at program scope with enough project context to understand where it lives. Editing, drag-to-ready, and dispatch controls can remain project-board responsibilities unless they fall naturally out of the RR-55 program dispatch work.

Do not create or rely on a workspace-root `.orchestrator/`. The all-tickets view should aggregate child project ticket files and run metadata through the existing project registry / Program Board status model.

Provider parity matters. Codex and Claude-dispatched tickets and workers should appear the same way in this view, with provider metadata shown only where it helps identify active work.

## Acceptance criteria

- [ ] Program Board exposes an "All" control near the Projects header or another clear top-level affordance.
- [ ] Activating the control shows tickets from all registered child projects without opening each project board.
- [ ] Each ticket row/card shows project name or path, ticket id, title, status, priority, dependency/blocking state where available, and active/awaiting worker state where available.
- [ ] The view supports enough grouping or filtering to stay usable for multi-project work, such as grouped-by-status columns, grouped-by-project sections, or a simple segmented control.
- [ ] The all-tickets view does not create a parent workspace `.orchestrator/` and does not mutate child project tickets in the read-only V1.
- [ ] Returning from the all-tickets view restores the normal Program Board project overview without losing refresh state.
- [ ] Codex and Claude provider metadata renders consistently for active workers and completed/awaiting-merge work.
- [ ] Tests or deterministic view-model coverage verify aggregation across at least two child projects, empty-state behavior, and no-parent-`.orchestrator` behavior.
