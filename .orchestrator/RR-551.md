## Description

On the Relay Remote iPhone app's Workspace tab (RR-543), tapping a ticket does nothing. The user wants to tap a ticket and read it. Today the Mac sends only each ticket's id, title, status, project and owning agent (RR-535), so the phone has no ticket text to show. This ticket adds the request for one ticket's text on both sides of the wire and the screen that shows it.

**Protocol and Mac**

- Add a second `workspace_command` action, `get`, carrying `project_id` and `ticket_id`. The Mac answers with one new frame, `workspace_ticket`: `project_id`, `ticket_id`, `title`, `status` (the same three lanes as the list, plus `done` for a ticket that finished while it was open), `agent` when the ticket has an owner, `markdown` (the ticket's body: everything after the frontmatter, unchanged), `truncated` when the body was cut, and `error` in place of the body when it cannot be served.
- Add the frame and the action to both codec twins (`Sources/RelayRemoteProtocol/Frames.swift` and `rust/relay-rs/src/remote/protocol.rs`), to the helper's app-command routing (`Sources/relay-remote-shell/main.swift`, the same route `list` takes), and to the phone kit beside `requestWorkspace()` in `ios/RelayRemoteKit`.
- Serve it from `Sources/relay-runner/Remote/RelayRemoteWorkspaceFeed.swift`, from the same source the desktop Workspace uses to show an open ticket, so the phone and the desktop show the same text.
- Privacy boundary, replacing RR-535's "no ticket bodies leave the Mac": a body is sent only for the one ticket the phone asks for, only for a ticket in a registered project that the `list` feed would also expose (or one that has since become done), and never in the list or in pushed `workspace_state` frames. Frontmatter is not sent. No filesystem or repository paths are added by the Mac; text that the ticket author wrote in the body is sent as written.
- Cap the body at 64 KB of UTF-8, cut on a character boundary, and set `truncated`.
- Errors the phone can show, each as a well-formed `workspace_ticket` with `error`: unknown project or ticket, ticket no longer exists, orchestrator daemon unreachable.
- Older peers: a Mac without this change must leave the phone showing one short "not available on this Mac" line, not a spinner; a phone without it never sends `get`. Document both in `docs/specs/relay-remote.md`, with the new frame, its limit and the changed privacy boundary.

**iPhone modal**

The ticket opens in a modal. The user asked for a custom modal built from the app's established styles, so do not use a system sheet (`.sheet`, `.fullScreenCover`, presentation detents, a drag indicator) or a pushed navigation screen, and do not introduce new colours, type, radii or materials. There is no Figma screen for it; build it from the existing design system in `ios/RelayRemote/DesignSystem` and the rules in `docs/design/relay-remote-ios/README.md`.

- Tapping a row on the Workspace tab opens that ticket in the modal, over the Workspace tab.
- The modal is one glass panel: the standard panel surface (`GlassPanel` / `relayGlass(.panel)`, `#0c0f13` at 50% with the glass effect, corner radius `RelayMetrics.panelRadius`, 16). It sits `RelayMetrics.screenMargin` (16 pt) in from each side, starts 16 pt below the status bar, and ends 40 pt above the bottom of the screen, the same bottom gap as the full-width buttons. It hugs its content when the ticket is short and is centred vertically in that space; a long ticket fills the space and scrolls inside the panel.
- Behind it, a black scrim at 60% covers the whole app, including the tab bar, the project tab strip and any state glow, but not the status bar. The list stays visible through the scrim and does not scroll or take taps while the modal is open.
- Close: a 44 pt glass secondary icon button with a stroke X icon (Lucide, not filled) at the panel's top right, pinned so it does not scroll away. Tapping the scrim also closes it, and so does dragging the panel down past about a third of its height or with a fast flick; while dragging, the panel follows the finger and the scrim fades with it. Closing returns to the list at the same scroll position and project tab.
- Motion: open and close use the app's standard swap, `RelayMotion.swap` (0.24 s; the panel fades and scales from 96%, the scrim fades). With Reduce Motion, fade only.
- Build the modal as one small reusable piece in the design system (for example `RelayModal`), since it is the app's first modal, and add it to the design gallery. Keep it to what this screen needs.
- Banners still float over everything except the status bar, so the "Mac unreachable" banner sits above the modal and its scrim.
- Accessibility: the modal is a modal for VoiceOver (focus moves into it and stays there, the escape gesture closes it), the close button is labelled "Close", and text respects Dynamic Type.
- Header inside the panel, top to bottom, to the left of the close button: the ticket id and project name on one small line; the title; one line with the status in words ("In progress", "Queued", "Backlog", "Done") and the owning agent's name when there is one. No page title, no coloured status pills or lights.
- Below it the ticket body, rendered from Markdown: headings, paragraphs, bulleted and numbered lists, task-list items as unticked or ticked boxes (read-only), inline code, code blocks (scroll sideways, do not wrap), bold, italics and links (open in the system browser). Type and colours come from the design system: Bai Jamjuree, white on black.
- The body scrolls inside the panel, under the fixed header, and fades out at its top and bottom edges with an alpha mask, as the chat does; do not use a black overlay.
- States: loading (title, status and agent from the list row show at once; only the body waits); error (one short line and Retry, a secondary button; the modal has no primary button); truncated (one short line at the end, "Open on your Mac to read the rest."); Mac unreachable (the same floating banner as the other tabs, with the last loaded text dimmed beneath it).
- The body is requested each time the ticket is opened and on pull to refresh. While it is open, a pushed `workspace_state` updates the status and agent in the header; if the ticket leaves the open list, the header shows "Done" and the text stays.
- Read-only: no editing, dispatching, cancelling or commenting from the phone.
