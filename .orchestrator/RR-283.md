## Description

Implement RR-273 delivery phase 3 using RR-270's `Target topology`, `Project repository`, and content-classification rules. Create the project-owned orphan-style `refs/heads/relay/artifacts` store, a single per-project writer, typed allowlisted operations, immutable event IDs, private-index Git plumbing, compare-and-swap ref updates, and repo-root `.orchestrator/` write-through materialization excluded through `.git/info/exclude`.

The artifact ref is the only canonical writable project store. Materialized files and app-global databases are projections. Preserve existing display IDs while adding immutable artifact identity. Reject traversal, symlinks, submodule entries, cross-ticket attachments, unsupported content, and non-allowlisted paths. A successful operation commits exactly one logical event and rematerializes atomically without changing the user's source branch, index, staged/unstaged/untracked files, remotes, ordinary commits, or source refs.

Ship behind per-project opt-in and local-only operation. Remote synchronization, retention archival, and legacy source cutover belong to later tickets.

## Acceptance criteria

- [x] Initialization creates or adopts a verified project-owned `refs/heads/relay/artifacts` orphan tree with schema/project identity and never duplicates source files into artifact commits.
- [x] One serialized writer accepts typed ticket/config/attachment/program operations, validates immutable event IDs for idempotency, writes required Relay commit trailers, and uses CAS `update-ref` so concurrent-base mismatches fail without lost updates.
- [x] Git plumbing uses a private temporary index and strict allowlist for the RR-270 paths; traversal, symlink, submodule, catch-all staging, source paths, cross-ticket attachments, oversized/unsupported files, secrets fixtures, raw audio, and raw transcripts are rejected.
- [x] Repo-root `.orchestrator/` is atomically materialized from the verified artifact head, records its base object IDs, is locally excluded without editing committed `.gitignore`, and detects manual-edit/ref divergence instead of silently choosing a winner.
- [x] Failure injection before commit, during CAS, after ref update, and during materialization is recoverable and idempotent; restart reconstructs materialization from the canonical ref.
- [x] Dirty, staged, unstaged, untracked, detached, and local-ahead source fixtures remain byte-for-byte and status-for-status unchanged across artifact initialization and mutations.
- [x] Attachment ownership, MIME, filename, byte-size, and project-total policies match RR-270 and produce actionable fail-closed errors.
- [x] Codex and Claude fixtures receive identical snapshots and typed operation results; raw provider traces and hidden reasoning never enter the artifact ref.
- [x] Targeted unit/integration tests and source-isolation fixtures pass, and documentation links every implementation boundary to RR-270 phase 3.

## Rollback boundary

Opt-out stops the new writer and returns to the pre-cutover direct-file path while leaving any artifact ref intact for audit/recovery. Never delete or rewrite an artifact ref automatically; removing an unpushed disposable-test ref is an explicit test-only operation.
