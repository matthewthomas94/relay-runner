## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

Implement the speech service in Rust as a production binary in the `rust/` workspace, serving the protocol in `docs/specs/speech-service-protocol.md` and accepted by the speech contract suite in `tests/contract/`. Build on the findings in `docs/investigations/RR-448-rust-speech-prototype.md`.

- **Synthesis:** `ort` with `kokoro-v1.0.onnx` and `voices-v1.0.bin`, the phonemiser chosen by the prototype, the same four voices, sentence splitting equivalent to `tts_worker.py`, next-sentence rendering while the current one plays, and speculative first-sentence rendering. Model download behaviour matches today's (same files, same locations, `VOICE_MODELS_DIR` honoured), without `huggingface_hub`.
- **Playback:** AudioToolbox AudioQueue through FFI, matching `services/speech_player.py`: one persistent queue per reply, 20 ms buffers, time-pitch playback rate clamped 0.5 to 2.0, a 20 ms fade before stop, stall and idle handling, and the cold-start click mitigation from RR-438. The refill callback must not allocate or lock.
- **Coordinator:** the queueing, supersede, staleness, replay, focus and lease rules of `services/speech_coordinator.py`, the `voice-audio.lock` lease, the control socket, state datagrams, the tutorial stdin mode, the voice preview command used by `ProcessManager.swift`, and Relay Remote synthesis (AAC via `/usr/bin/afconvert` as today).
- **Packaging:** built, bundled and signed by `scripts/build-dmg.sh`; the app and bridge launch the Rust service by default with a switch that falls back to the Python service for one release. When the Rust service is the default, first-run setup no longer needs `numpy`, `onnxruntime`, `kokoro-onnx` or `huggingface_hub`; keep them installable only for the fallback and say so in `docs/fresh-install.md`.
- Update `THIRD_PARTY_NOTICES.md`; no GPL code is linked.

Provider parity: speech behaviour is provider-neutral; confirm nothing in the change branches on provider.
