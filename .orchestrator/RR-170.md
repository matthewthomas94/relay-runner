## Description

Treat the Workspace tab as Relay Runner's canonical product design language and rework only the Settings tab so it feels like part of the same application. Audit every visible Settings element rather than applying a superficial color pass: information architecture, sidebar navigation, headings, sections, rows, controls, status treatments, feedback, scrolling, save state, hover/focus/disabled states, empty/error/loading states, spacing, typography, surfaces, borders, and corner radii must each be evaluated against both the Workspace implementation and sound macOS desktop UX heuristics.

Preserve all existing Settings capabilities and configuration semantics. Reuse or derive from existing Workspace design primitives where that creates genuine consistency, but do not change the Workspace tab itself, introduce a general app-wide redesign, or refactor unrelated code. Keep the standalone Settings window functional as well as the Settings panel embedded in Workspace.

The implementation should favor a restrained dark hierarchy, clear scan paths, predictable control alignment, visible but non-distracting interaction feedback, accessible labels/help/focus, and explicit save-state communication. Purple remains semantic emphasis for selected/focused/active or dirty actions; success/error colors remain semantic and must not become decoration. Controls should remain recognizably native and usable on macOS while their surrounding composition matches Workspace.

RR-168 delivered an initial Settings uplift, so start by reviewing the current implementation rather than recreating that ticket. A read-only parity audit of the post-RR-168 code found these concrete gaps to verify and resolve where appropriate:

- Settings currently hides the vertical scroll indicator entirely, while Workspace uses a quiet, discoverable scrollbar that appears during hover/scroll. Long categories need a visible overflow affordance without disturbing the fixed sidebar/header/footer.
- The Settings navigation rail keeps inactive labels comparatively bright and uses a louder purple fill/ring than Workspace's subtle inactive/hover/selected/focused progression. Preserve clear selection without making the rail compete with the detail pane.
- Settings collapses secondary and muted text into variants of the same color and uses separate red/green values. Restore a useful primary/secondary/muted/disabled hierarchy based on the Workspace palette while keeping explanatory copy at least 11 points.
- The native bordered-prominent Save button is visually disconnected from Workspace's compact, plain, bordered interactive surfaces. Restyle the surrounding action chrome while preserving disabled semantics and the default keyboard action.
- Settings hover/focus/disabled states do not yet share Workspace's deterministic precedence, restrained 150 ms non-layout motion, or Reduce Motion behavior. Apply these principles to custom Settings navigation/action surfaces without overriding familiar native input behavior.
- Review one-option, icon-only, conditional, dependent, destructive/risk-bearing, loading, transient-success, and error controls for honest affordance, accessible non-color feedback, and stable layout. Do not add speculative functionality merely to fill gaps.

## Acceptance criteria

- [ ] The Settings information architecture, navigation, header, content sections, rows, footer, and every category tab have been audited and deliberately retained or reworked; the result shares Workspace's dark nested-surface hierarchy, spacing rhythm, typography, borders, corner radii, and restrained accent use.
- [ ] Changes are confined to Settings source/tests and any narrowly necessary shared Workspace style primitives; Workspace behavior and non-Settings screens are unchanged.
- [ ] Status, Speech-to-Text, Text-to-Speech, General, and Awareness retain every existing setting, action, live state, error message, and configuration binding.
- [ ] Sidebar selection, hover, keyboard focus, and inactive states have deterministic precedence and match the quiet interaction vocabulary of Workspace without restoring large native focus halos.
- [ ] Long detail categories expose a quiet but discoverable scroll affordance; sidebar, category header, and save footer remain fixed while only detail content scrolls.
- [ ] Settings rows and controls form a clear, consistent scan grid; long labels/descriptions wrap safely, controls do not jump or truncate at supported window sizes, and scrolling remains available where content exceeds the detail area.
- [ ] Section grouping and dividers communicate relationships without excessive boxes or decoration; headers and explanatory text establish useful hierarchy without duplicating labels.
- [ ] Save feedback clearly distinguishes clean and dirty state, the primary action is disabled when no changes exist, Command-Return/default action behavior remains intact, and external config changes still refresh the draft.
- [ ] Status and validation feedback use semantic success/error/idle/loading presentation, remain legible in dark mode, and do not rely on color alone.
- [ ] Interactive elements have appropriate hit targets, hover/focus/disabled feedback, accessibility labels or native labels, and useful help text where icon-only actions need it.
- [ ] Custom interaction transitions do not move layout, complete in roughly 150 ms with restrained easing, and are removed or reduced when Reduce Motion is enabled.
- [ ] The standalone Settings window and Workspace-embedded Settings panel both render correctly from the same implementation, including their intended sizing and chrome differences.
- [ ] Provider-facing behavior is identical for Codex and Claude; no provider, daemon, board, ticket-schema, voice, or orchestration behavior changes.
- [ ] Focused deterministic tests cover new presentation/state decisions where practical; existing Settings tests, `swift test`, and `git diff --check` pass.
