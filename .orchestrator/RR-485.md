## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

`services/orchestrator.py` serves 76 method-and-path routes from `Handler._route` (around lines 12264-12896) on `127.0.0.1`, writes the port to `/tmp/relay_orchestrator.port`, keeps ten SQLite databases under `~/Library/Application Support/relay-runner/orchestrator/`, and commits tickets, notes and program events to `refs/heads/relay/artifacts` in each project. No test starts it as a process and there is no API specification; the Swift clients (`Sources/relay-orchestrator-mcp/Tools.swift`, `Sources/relay-runner/Board/OrchestratorClient.swift`) are the de facto contract.

- Write `docs/specs/orchestrator-http-api.md` (or an OpenAPI file plus prose): every route with request fields, response shape, status codes and error mapping, taken from the handler and checked against what the Swift clients send and decode. Mark the routes with no non-test caller.
- Add any missing way to run the daemon fully isolated: data root, port file, config, registry and `/tmp` paths all redirectable by environment variable or config, without changing defaults.
- A suite under `tests/contract/` that starts the daemon command from an environment variable (default: the Python daemon) against temporary git repositories and fake `claude`, `codex` and `gh` executables on PATH, and covers: every route's success and principal error cases; ticket write, claim-next-id, delete and attachments, asserting the resulting commit tree, file bytes and commit message on `refs/heads/relay/artifacts` and the `.orchestrator/` projection; dispatch of an implementation ticket and a spike with scripted worker output through review, merge and dependency progression; queue drains and the ready sweep; notes create, update, archive and metadata; retention preview and apply; the `runs.json` file that `RunStateStore.swift` reads; restart with runs in flight; and opening databases created by the previous release.
- Golden files for git output and JSON responses, with volatile fields (timestamps, ids, ports) normalised by documented rules.

Do not change daemon behaviour beyond the isolation switches.

## Acceptance criteria

- [ ] The suite passes against the Python daemon and imports nothing from `services/`.

- [ ] Artifact-ref commits produced in the suite are compared byte for byte against golden trees.
- [ ] The suite runs in isolation without touching the real Application Support directory or `/tmp/relay_orchestrator.port`, verified by a test.
