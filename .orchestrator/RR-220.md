## Description

The Program Workspace lane scroll views can no longer return to their true top endpoint. In the supplied live screenshot, the Backlog lane's first card is clipped beneath the header and the Done lane's first card is almost entirely hidden even though both columns are at their apparent top position. The large Done list and shorter Backlog list demonstrate that the failure is not limited to one lane or one content length.

Treat this as a regression of RR-214. Diagnose the real `ProgramColumnTicketScrollView` and `BoardOverlayScrollContainer` layout rather than relying on generic fixed-height rectangle tests. Correct flipped clip-view coordinates, document/hosting sizing, content insets, per-lane offset retention, and refresh clamping as needed so every lane can reach its first complete card with the intended top padding.

The full clipboard screenshot is not attached because it contains unrelated application and transcript content. Its relevant evidence is: at the top of Program Workspace, Backlog's first card begins mid-title, while Done shows only the bottom dependency line of its first card before the next complete ticket.

## Acceptance criteria

- [ ] Backlog, Queued, In progress, and Done can each return to a top position where the first card is fully visible below the header with the intended inset.
- [ ] A lane with hundreds of tickets and a lane with only a few tickets both expose the same correct top endpoint.
- [ ] Trackpad, mouse wheel, keyboard, and custom-thumb movement reach the identical minimum offset; the thumb is at the top of its track at that point.
- [ ] Independent lane offsets never bleed between columns or leave one lane clamped to another lane's content geometry.
- [ ] Adding, removing, reordering, or refreshing tickets recalculates the document bounds and clamps or preserves the offset intentionally without making newly prepended content unreachable.
- [ ] Opening Workspace, switching tabs, changing project filters, selecting all projects, and closing/reopening do not restore an invalid offset that crops the first card.
- [ ] The last card remains fully reachable above the intended bottom inset, preserving RR-214's bottom-endpoint behavior.
- [ ] Short and empty lanes stay top-aligned and do not gain artificial scrolling or blank overscroll.
- [ ] Automated tests render the real lane stack with its drop indicator, padding, variable-height cards, and dynamic content replacement; generic rectangle-only coverage is not sufficient.
- [ ] Manual verification with live Program Workspace data confirms the first Backlog and Done cards are fully visible at the top at supported Workspace sizes.
