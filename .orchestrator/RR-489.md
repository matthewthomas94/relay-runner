## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust; read its `## Spike report` first (inventory, interfaces, staged plan; `scripts/relay-ticket-history show RR-448` if archived). On 2026-11-13 the user decided to port the rest to Rust. This ticket is one part of the split of epic RR-484; read that epic for the shared constraints.

Port `intent_inbox.py`, `intent_arbitration.py`, `intent_qualification.py` and `provider_turn_broker.py` to a library crate in `rust/` that works on the existing SQLite schema in place, and move the Rust hook (`relay-rs hook`, RR-478) onto it. The Python bridge keeps running against the same database until the cut-over, so both must interoperate. Known risk from 2026-11-13: once, a claimed intent was never acknowledged after an empty-hold `__INTERRUPT__` and the queue stalled (the empty-hold interrupt has since been removed in 8449804a); cover claim → ack under concurrent writers.

Constraints: interfaces in `docs/specs/voice-bridge-contract.md` stay byte-compatible; Claude and Codex change in the same release; no provider-visible behaviour differs beyond today's documented differences. Product decisions to keep: a reply talked over before it starts playing returns to the queue and plays again; replies are spoken, not badged, once RR-488 has landed.

## Acceptance criteria

- [ ] Typed model, inbox and broker match the Python behaviour on the existing schema; the voice-bridge contract cases for the inbox and turn ledger pass against them.
- [ ] The Rust hook uses the crate, and its RR-477 contract suite still passes for both providers.
- [ ] A test drives Python and Rust writers on one database concurrently with no lost or stuck claims.
