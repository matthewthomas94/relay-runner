## Description

Change Relay command intake so raw private STT/user instructions are delivered to both the PM frontstage and the persistent orchestrator in parallel.

Today `services/voice_bridge.py` resolves a command action and publishes a single formatted prompt for the foreground agent. `services/command_actions.py` also says the foreground session is the orchestrator and asks it to refine/create visible tickets. RR-127 changes that model: the PM should acknowledge and manage the user, while the orchestrator receives the same raw instruction for solutioning.

Keep raw command captures private. Visible board tickets must receive refined content from the orchestrator, not copied transcripts.

## Acceptance criteria

- [ ] Voice/STT intake records a newest-intent Relay command once, with seq/id metadata shared by both PM and orchestrator paths.
- [ ] The PM acknowledgement path can respond immediately without waiting for orchestrator planning.
- [ ] The persistent orchestrator receives the raw private instruction and metadata in parallel with the PM.
- [ ] The PM path no longer formats project-work commands as "foreground orchestrator" prompts that ask the PM to create/refine tickets.
- [ ] New instructions received while work is already running also fan out to the orchestrator promptly.
- [ ] Stale-command handling remains provider-neutral and suppresses stale TTS, notch traces, dispatches, and orchestrator actions.
- [ ] Add tests for parallel fanout, raw transcript privacy, and stale-command rejection.
