## Description

Integrate the FluidAudio revision accepted in RR-411 and provide one small explicit model resolver used by ordinary STT and Note Taker. Replace both substring-based selectors: phonon-2 maps to .phonon2, parakeet-tdt-v2 to .v2, and parakeet-tdt-v3 to .v3. Today an unrecognized name silently falls through to v2.

Keep the macOS 14 app target. Reject Phonon on macOS 14 before any model download/load; preserve existing Parakeet behavior there. Permit Phonon on macOS 15+, retain v2/v3 for existing configurations and rollback, and reject unknown identifiers with an actionable error. This ticket enables explicit selection but does not change production defaults.

Primary files: Package.swift, Package.resolved, Sources/relay-runner/STT/STTEngine.swift, Sources/relay-runner/Notes/FluidAudioMeetingTranscriber.swift, and the existing preparation/readiness call sites. Reuse FluidAudio's recognizer, cache, loader and progress APIs, with workflow-owned recognizer instances. Keep inference serialized and off the main thread.

## Required inputs

- [ ] The PM has reviewed RR-411 and accepted a viable runtime revision, immutable model identity and measured compatibility results; a completed feasibility ticket alone is insufficient.

## Acceptance criteria

- [ ] Both workflows use the shared explicit resolver. Focused tests cover all three identifiers, unknown names, macOS 14 rejection before I/O, and macOS 15+ selection; no substring fallback remains.
- [ ] Dependency pins and notices match the accepted feasibility result. Existing Parakeet v2/v3 behavior remains available and the macOS 14 deployment target is unchanged.
- [ ] Preparation records the verified model/runtime identity, keeps model data outside the signed bundle, reuses existing cached assets, and addresses only integrity/revision/recovery gaps demonstrated in RR-411.
- [ ] Concurrent preparation requests are deduplicated without sharing unsafe inference state. Cold preparation, warm reuse, offline cached transcription, interrupted/corrupt downloads, unavailable network, insufficient disk and retry have explicit verified outcomes.
- [ ] The UI receives real download progress and named preparation phases; it never fabricates compilation percentages. A failed preparation does not delete working Parakeet assets or report Phonon ready.
- [ ] A prepared model passes a local smoke fixture before readiness is published. Readiness alone never opens the microphone; the existing eight-minute setup timeout changes only if measurements justify it.
- [ ] Cancellation, superseded loads and stale inference completions cannot publish text/readiness for an invalidated workflow, overwrite the selected model, or reopen capture. Native operations that cannot cancel immediately are safely ignored on completion.
- [ ] Targeted resolver, readiness and capture-ownership tests pass, along with an app build and real cached inference using the accepted model. Report synthetic tests and real-model evidence separately.

## Scope boundary

Keep capture controls, producer windows, provider bridge semantics and note persistence behavior intact. Do not add a second speech runtime, helper IPC, general backend framework or parallel downloader. The runtime is local and provider-neutral; no subscription/API credential or provider session is required to prepare STT.
