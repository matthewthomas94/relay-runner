## Description

Make meeting notes a distinct project-owned Markdown artifact in the existing Relay Runner artifact system. Extend the typed operations and verified path allowlist deliberately; use `.orchestrator/notes/<NOTE_ID>.md` in the canonical artifact ref and its disposable projection. A note has immutable artifact identity, project identity, an unpadded display ID, creation/capture metadata and transcript content. Recording/completion metadata is independent of ticket workflow status.

Allocate `<project prefix>-N<positive integer>` from a persistent per-project note counter, separate from the work-ticket `next_id`. RR-N1 is followed by RR-N2 and can grow through RR-N1000 and beyond. The ID is the filename stem and card label; there is no generated title or summary field requirement. Preserve issued-number history even when a note is archived or removed from the current projection.

Canonical transcripts intentionally belong to the selected project's Git-backed repository and can sync to its configured GitHub remote under the established artifact policy. Local save must work offline; remote synchronization is a separate state. Existing transcript restrictions for ticket/Program payloads must not be globally weakened: introduce the explicit meeting-note content type and its policy. Raw audio, private provider traces and source history remain outside the artifact allowlist. Define a note-specific text size budget suitable for long meetings instead of accidentally inheriting the ticket limit.

## Ownership and scope

Relay Runner repository. Own the typed note schema, canonical writer/API, materialization, allocation, catalog and existing artifact history/sync integration. Publish a small shared note identity and segment/update contract for Swift consumers. RR-368 owns recording checkpoints; RR-370 owns agent-facing discovery and references.

## Acceptance criteria

- [ ] Typed note create/read/update operations preserve immutable artifact and project identity, reject traversal/type confusion, validate the current project scope, and atomically materialize Markdown through the established writer. No direct edits of projected files and no separate canonical SQLite transcript database.
- [ ] The first note in a fresh project is PREFIX-N1. Numeric ordering covers N2 before N10 and N999 before N1000; another project prefix works without RR-specific code. Creating notes leaves the work-ticket counter unchanged and creating tickets leaves the note counter unchanged.
- [ ] Per-project concurrent allocation, retried requests and failed writes have deterministic identity semantics under the existing lock/CAS path. Counter recovery consults persisted issuance/archive history; deleting or archiving the highest visible note cannot cause reuse of an issued ID.
- [ ] Divergent remote/offline writers that collide are detected without overwriting either note. Document and test the existing-store reconciliation/allocation policy, preserving stable artifact identity and source references; do not claim globally coordinated allocation while disconnected.
- [ ] Notes are excluded from ticket parsing, backlog/ready dispatch, dependency progression, worker claims and the newest-25 completed-ticket retention count. Note catalog/history lookup remains available when an older note is not materialized; no automatic destructive note-retention rule is introduced.
- [ ] Local canonical saves succeed without a network or agent session. Existing artifact sync exposes pending/synced/conflict/failure honestly and does not modify the source branch, source index, unrelated artifacts or Git remotes. Markdown is batched into meaningful saves, never one Git commit per partial STT callback.
- [ ] Legitimate meeting transcript Markdown is accepted only through the typed note path. Existing ticket/Program restrictions remain enforced; rejected or over-limit note content produces an actionable save failure without silently losing the recording checkpoint. Test a transcript larger than the current 256 KiB ticket limit and document the note limit.
- [ ] Document the schema, project visibility/Git-history implications, numeric ID contract, archive/history lookup and migration compatibility. Old projects initialize the note counter safely; rollback/unsupported schema errors preserve existing tickets and notes.
- [ ] The shared note identity/segment contract supports recording and paused progress without reallocating the note or changing its original project. RR-368 is the single owner of foreground mode transitions, key routing and recorder state; storage does not start or stop provider sessions.
