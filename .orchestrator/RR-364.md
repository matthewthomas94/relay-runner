## Description

Make meeting notes a distinct project-owned Markdown artifact in the existing Relay Runner artifact system. Extend the typed operations and verified path allowlist deliberately; use `.orchestrator/notes/<NOTE_ID>.md` in the canonical artifact ref and its disposable projection. A note has immutable artifact identity, project identity, an unpadded display ID, creation/capture metadata and transcript content. Recording/completion metadata is independent of ticket workflow status.

Allocate `<project prefix>-N<positive integer>` from a persistent per-project note counter, separate from the work-ticket `next_id`. RR-N1 is followed by RR-N2 and can grow through RR-N1000 and beyond. The ID is the filename stem and card label; there is no generated title or summary field requirement. Preserve issued-number history even when a note is archived or removed from the current projection.

Canonical transcripts intentionally belong to the selected project's Git-backed repository and can sync to its configured GitHub remote under the established artifact policy. Local save must work offline; remote synchronization is a separate state. Existing transcript restrictions for ticket/Program payloads must not be globally weakened: introduce the explicit meeting-note content type and its policy. Raw audio, private provider traces and source history remain outside the artifact allowlist. Define a note-specific text size budget suitable for long meetings instead of accidentally inheriting the ticket limit.

## Ownership and scope

Relay Runner repository. Own the typed note schema, canonical writer/API, materialization, allocation, catalog and existing artifact history/sync integration. Publish a small shared note identity and segment/update contract for Swift consumers. RR-368 owns recording checkpoints; RR-370 owns agent-facing discovery and references.
