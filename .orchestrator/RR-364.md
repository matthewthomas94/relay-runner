## Description

Implement the foundation's session store using SQLite for structured state and private bounded media files. Include sessions, notes, timed transcript revisions, speaker labels, derived summaries, processing cursors and deletion tombstones. The database and owned audio/checkpoints live under the app's Application Support root; search is derived and rebuildable. Use a single coordinated writer and transactions for metadata/cursors. Publish media manifests only after finalizing the corresponding file; preserve orphan/incomplete-file information for the recovery ticket.

Keep migrations explicit with schema-version checks and a recoverable failure path. Do not delete SQLite WAL/SHM files as a generic response to open errors. Do not copy Anarlog's sync schema or claim filesystem encryption that has not been implemented. Exclude content from logs and backups generated by the app. [Anarlog migration behavior](https://github.com/fastrepl/anarlog/blob/b9146a707f4da2121d3438bce38155b31e5007f1/crates/db-migrate/src/lib.rs), [Meetily DB recovery comparison](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/database/manager.rs).

- [ ] Migration fixtures cover first launch, upgrade, refusal of a newer unsupported schema, failure/rollback and preserving original data; no automatic destructive WAL cleanup.
- [ ] Storage remains outside Git/Relay artifacts; logs contain no meeting text or credentials. Derived search data is local and rebuildable from canonical rows.
- [ ] A durable session deletion marker and generation checks prevent late ASR/generation callbacks from re-creating deleted data; the later retention ticket owns user-facing deletion flow.
