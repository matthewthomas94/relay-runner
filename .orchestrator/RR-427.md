## Description

Spec: `docs/specs/relay-remote.md` (Relay Remote: iOS voice over SSH), committed as `2a64cc0d` on branch `claude/ios-relay-ssh-tcp-spec-ddb8f2`. The spec is not on `main` yet; if the file is missing from your worktree, read it with `git show 2a64cc0d:docs/specs/relay-remote.md`. Read these sections first: Mac-side integration with the voice contract, iOS app, Reachability.

While a phone is the active voice input, the Mac must not also listen through its microphone, the user must see which device is in control, and the Mac must not sleep.

- The bridge module (RR-423) publishes `remote_device` events (`connected`, `active`, `disconnected`, with `device_id` and `device_name`) on the existing `/tmp/voice_state.sock` stream.
- `AppState` suspends the Mac microphone while a device is active by extending `STTEngine.suspendForReferenceAudio()` into a reason-based suspension: reference audio and remote device are independent reasons, and the engine resumes only when no reason remains. A user action on the Mac (push-to-talk, wake word, clicking the microphone) takes control back and resumes the microphone.
- Show `Remote: <device name>` in the notch status and the menu bar while a device is connected, using the RelayMotion label swap.
- Hold a prevent-idle-sleep assertion (`IOPMAssertionCreateWithName` with `kIOPMAssertionTypePreventUserIdleSystemSleep`) while a device is connected and release it on disconnect.

Out of scope: the iOS app (RR-428), the user guide (RR-430).
