## Description
On 2026-11-09 an app-owned Claude session (spool `/tmp/relay-sessions/<session>/`) got no voice turns at all. `/tmp/voice_bridge.log` and `ps` showed three voice bridges running at once:

1. The normal session bridge, launched by the session start at 18:06:27. It wrote commands to `<spool>/voice_cmd_ready`.
2. A bridge launched by the app watchdog's recovery script at the same moment (watchdog fired at 18:06:20, before the session bridge socket was ready at 18:06:41). Its launch had an empty provider session ID (`$5`) and an empty spool dir (`$11`), as the `launchctl print` in the log shows. It started in legacy mode, writing to `/tmp/voice_cmd_ready` and `/tmp/voice_command_state.json` with `voice_target_session_key: legacy`. This bridge owned the mic, so every voice command went to the legacy path and none was claimed or injected into the session.
3. A bridge left over from the previous day (started 2026-11-08 from an older build). The script's "Stopping previous voice session" step never stopped it.

Bridges 2 and 3 both write the legacy `/tmp/voice_command_state.json`, and the log repeats `Could not sync intent inbox state: [Errno 2] ... voice_command_state.json.tmp -> voice_command_state.json`, which fits a temp-file rename race.

The code is `ProcessManager.bridgeRecoveryScript` in `Sources/relay-runner/Process/ProcessManager.swift` (about lines 800-930). When `context.spoolDirectory` is nil, `SPOOL` falls back to `/tmp`. `RELAY_PROVIDER_SESSION_ID` is then read from `/tmp/voice_provider_session_id`, which is missing, so the recovered bridge launches without a session.

## Acceptance criteria
- [ ] Watchdog recovery does not fire while a session's bridge start is still in progress, before its readiness or socket stage.
- [ ] While an app-owned session is active, watchdog recovery never launches a bridge without that session's spool dir and provider session ID. It refuses and logs instead of falling back to `/tmp` legacy mode.
- [ ] Recovery leaves at most one `voice_bridge.py` process for the voice target. It stops bridges from older generations or builds, not only the PID in the bridge PID file.
- [ ] A unit test covers the generated recovery script for an app-owned session context. The launch carries the spool dir and session ID, and an empty context aborts instead of launching legacy.
- [ ] Relevant `ProcessManager` tests pass under `swift test`.
