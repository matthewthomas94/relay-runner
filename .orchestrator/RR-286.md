## Description

Implement RR-273 delivery phase 6 from RR-270's `Worker and lifecycle contract`. Dispatch materializes an immutable ticket/dependency/attachment snapshot from the artifact ref into the isolated worker worktree without tracking lifecycle ticket files on the worker's source branch. Workers commit source changes only and submit structured, bounded outcomes; the artifact writer owns claim, run-summary, retry, verification-blocked, done, and dependency-transition events.

Reviewers inspect source diffs and verification evidence. Only a successful reviewed source merge may publish canonical `done` and advance dependents. Failed/conflicted merges keep the ticket active. Preserve attachments, bounded user-safe run summaries, local capped raw logs, idempotent retries, daemon restart recovery, cancellation semantics, and active snapshot leases compatible with RR-285 retention.

Keep the legacy lifecycle path behind a reversible per-project gate until migration and installed-product verification.

## Acceptance criteria

- [x] Dispatch resolves a confirmed project ID and artifact head, records an immutable snapshot lease, and materializes only the assigned ticket, required dependency summaries, and eligible attachments into the worker worktree.
- [x] Worker source branches contain source changes only; ticket claim/status/run-log files are not required or merged on those branches, and workers submit validated structured outcomes to the daemon/artifact writer.
- [x] Review merges source independently and publishes canonical `done` plus bounded run summary only after accepted merge success; failure, conflict, cancellation, or missing evidence cannot advance dependencies.
- [x] Claim, retry, cancellation, verification-blocked/resume, review, merge, done, and dependency events are idempotent by event/run identity and recover correctly across daemon restart or duplicated delivery.
- [x] Snapshot leases prevent RR-285 archival while any worker/reviewer needs an artifact input and are released on every terminal path without expiring a demonstrably live run.
- [x] Attachments retain ticket ownership and privacy gates; raw logs/traces/hidden reasoning remain local under a cap while only bounded user-safe summaries enter the artifact ref.
- [x] Existing queue-drain, health-check, review retry, merge-conflict, provider auth recovery, and canceled-run behavior remain accurate against canonical artifact state.
- [x] End-to-end Codex and Claude fixtures receive equivalent snapshots and produce equivalent lifecycle/dependency outcomes, with only intentional launch/auth/model/effort differences documented.
- [x] Targeted daemon, workflow, Swift projection, restart, race, and provider-parity tests pass and link the implementation to RR-270 phase 6.

## Rollback boundary

The legacy ticket-on-worker-branch lifecycle remains selectable until migration gates pass. Rollback stops new artifact lifecycle events after draining active runs, preserves all emitted events and source commits, and never fabricates or discards completion state.

## Verification plan

Run controlled workers through success, failure, cancellation, verification block/resume, review rejection, merge conflict, daemon restart, duplicated outcome, and dependency progression. Inspect both source branches and artifact trees to prove ownership separation and lease cleanup.
