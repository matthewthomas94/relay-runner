## Description

Implement the onboarding treatment in the supplied Figma section and treat its screenshots plus every `developer` annotation as authoritative:

- Figma file: `https://www.figma.com/design/IGjwpE5m7vLaCThHgoy0cw/Relay-Runner?node-id=1029-1987&t=c3r6KYViOto3PUW9-11`
- Section: `1029:1987` (`Onboarding`)
- Intro frames: `872:34444`, `880:10298`, `872:29025`, `866:24075`, `872:34824`, `872:35204`
- Permission frames: `1026:1336` (Microphone), `1028:1919` (Input Monitoring prompt), `1028:1533` (Input Monitoring System Settings handoff), `1029:1795` (Screen Recording)

The current `OnboardingIntroController` already reuses the Workspace reveal, but it implements an older treatment. Update it to the Figma sequence and extend the visual language through onboarding permission prompts. The fresh sequence starts from the cursor/brand state, types `Relay Runner /`, animates the blue-to-white halftone/dot field upward through the two supplied positions, erases back to `/`, then types `First thing’s first /` and `I need a few permissions /`. Use the existing notch-to-Workspace reveal geometry, with the supplied black surface, 16-point lower corners, centered 48-point PP Telegraf Regular hero copy, and persistent `Getting started` notch treatment. The dot field is a real animated design element, not a static background placeholder; use an exact exported Figma asset or a deterministic renderer that faithfully reproduces the supplied frames and scales/clips across displays.

Apply the same Workspace treatment to permission stages instead of immediately replacing the experience with ordinary Settings content. The supplied copy and white permission button are authoritative where present:

- `Let’s start with your mic /`
- `Next let’s set up your hotkeys with input monitoring /`
- `Lastly we’re going to need screen recording /`
- `Grant permission`: white fill, `#11161d` 1-point border, 12-point radius, 32-point horizontal and 16-point vertical padding, PP Mori Semibold 16-point/18-point line height.

Accessibility remains part of Relay Runner's guided permission order even though the supplied Figma section does not include a dedicated Accessibility frame. Present it with the same treatment and existing product explanation rather than dropping or silently skipping the capability. Preserve the existing embedded Settings treatment for provider/model/effort/workspace selection, Python setup, Codex/Claude authentication, Ready, and Start Session. This ticket changes their surrounding onboarding presentation only where the Figma depicts the intro and permission stages; it must not delete or weaken those existing outcomes.

Honor every Figma `developer` annotation exactly:

1. Treat `/` as a flashing cursor. Every message transition backspaces the previous message before typing the next; do not crossfade or replace the whole string.
2. The Microphone button triggers the native microphone permission modal.
3. Clicking the Input Monitoring button dismisses/retracts the Workspace treatment before System Settings takes focus.
4. Once Input Monitoring is granted, reopen the Workspace treatment and continue onboarding.
5. Screen Recording opens automatically after the prior permission is granted, and the flow continues this way until all guided permissions are granted.
6. Clicking the Screen Recording button dismisses/retracts the treatment so the permission window can take focus.

The Figma sequence supersedes the older RR-98 phrase order and static cursor behavior. Preserve the safe first-launch sentinel, resume/recovery semantics, multi-display placement, click/key skip for the non-interactive cinematic, VoiceOver labeling, Reduce Motion behavior, and one-shot cleanup. Reduce Motion may bypass the animated typing/dot travel, but it must still expose an understandable static permission prompt and never skip a permission solely because motion is reduced.

Do not regress the RR-179/RR-181 native app drag companion: System Settings-backed permission requests must still show the working black `Drag me` tile, real Finder-compatible app drag, smooth click-through hand demo, correct hand layering, and no green ring. Retract the onboarding treatment before presenting System Settings/companion so the OS surface has focus and is not visually covered. When polling reports a grant, close the permission companion, restore the treatment for the next step, and advance once.

The visual reference was inspected through Figma screenshots at the natural 1728×1117 frame size. Relay Vision could not capture the installed app at ticket-authoring time because Screen Recording was not granted to Relay Runner; do not treat that environmental limitation as permission to skip deterministic visual/layout tests or an installed-app smoke check when the permission becomes available.
