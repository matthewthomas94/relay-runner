## Description

Fix the regression that prevents users from manually scrolling long TTS response bodies in `TranscriptionPill`. The pill already caps long bodies and implements `scrollWheel(with:)`, while `OverlayController` polls the cursor at 30 fps to toggle the otherwise click-through overlay panel. Reproduce the failure through the mounted overlay panel and real hit-testing/event path rather than calling the pill method directly. Determine whether scroll events are lost because `OverlayPanel.ignoresMouseEvents` remains true during pointer entry, a child view such as the body container or animated keycap owns the hit, state transitions replace the target, coordinate conversion is stale, or device delta handling is incorrect. Restore immediate, reliable manual scrolling with both mouse wheels and trackpads while preserving click-through behavior everywhere outside the visible pill and preserving the automatic teleprompter until the user takes control.

## Acceptance criteria

- [ ] A mounted regression shows a long TTS response pill receiving manual scroll input through the real overlay panel, window hit-test, and event-delivery path.
- [ ] Moving the pointer onto a visible long response pill and scrolling immediately changes the body position without requiring a pause, click, repeated gesture, or cursor movement workaround.
- [ ] Both mouse-wheel line deltas and trackpad precise/natural-scrolling deltas move through the full clamped response range in the expected direction.
- [ ] Scroll events over the title, body viewport, and any trailing animated keycap still reach the pill’s manual body-scroll behavior.
- [ ] Manual input cancels the automatic teleprompter once and preserves the user-selected position across same-message waiting, preparing, and speaking transitions.
- [ ] A new response resets manual-scroll ownership to the top/normal automatic behavior; compact pills and non-overflowing bodies do not claim scroll input.
- [ ] The overlay remains click-through outside the visible pill and does not steal scrolling from underlying applications when the cursor is elsewhere.
- [ ] Multi-display movement, pill entrance/exit animation, body resize, keycap layout, and hidden/detached window states do not leave stale mouse interception or break later scrolling.
- [ ] Focused tests cover mounted hit-testing, selective panel interception timing, child-view routing, mouse and trackpad deltas, bounds clamping, same-message preservation, new-message reset, and outside-pill pass-through.
- [ ] Existing pill placement, response preview, keycap animation, and overlay interaction tests continue to pass, and a freshly built/package-equivalent app is manually verified with a long response.
