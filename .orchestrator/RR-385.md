## Description

Start Session should open a usable global assistant immediately without choosing a repository or configuring a workspace. Introduce an explicit global session scope alongside confirmed project scope. Global sessions use a managed working area under ~/Library/Application Support/relay-runner/files, with no dependency on a GitHub connection. Keep the existing central notes library at ~/Library/Application Support/relay-runner/notes and reuse its identities and APIs. Project management remains attached to the actual project repository. This ticket provides startup and local storage foundations; tracked general work, context switching and remote storage are separate dependent work.

## Acceptance criteria

- [ ] A fresh user with no registered projects and no GitHub connection can start a global session with one Start Session action after normal microphone and provider sign-in prerequisites.
- [ ] Global scope is a first-class value; the app does not select an arbitrary recent project, manufacture a user project, or require a project scope token to launch globally.
- [ ] Default general-task output is created inside the managed files area; an explicitly requested project output still uses its confirmed project path. App credentials, operational databases and logs are not treated as user files.
- [ ] Existing global notes remain readable, recordable and recoverable without a selected project; note identities and recovery links survive the change.
- [ ] Global launch does not inherit a previously selected repository cwd, project instructions, project tools scope or pending project mutation authority.
- [ ] Codex and Claude both start globally with their normal subscription authentication flow; missing authentication initiates sign-in and readiness is rechecked.
- [ ] Focused regressions cover fresh startup, stale project configuration, global notes and explicit project startup; installed global startup is verified separately from source tests.
