## Description

The user asked on 2026-11-06 for an audit that finds code, configuration, scripts, docs and tests that are no longer used or relevant, so they can be removed. This spike produces the evidence-backed list; the removals happen in separate implementation tickets after the user has seen it. Do not change anything.

Scope, at the checkout's HEAD (main, 0d212a6a or later):
- Swift: `Sources/` (the app and the five MCP servers) and `tests/RelayRunnerTests/`.
- Python: `services/` and `tests/test_*.py`.
- Scripts: `scripts/`, including `scripts/experiments/`.
- Instruction chunks: `services/instructions/` (full and compact) and the skills `scripts/relay-bridge` installs.
- Docs: `docs/`, `docs/specs/`, `docs/investigations/`, `README.md`.
- Config: keys in `Sources/relay-runner/Config/Config.swift` and `services/config.py` that nothing reads; `.relay-runner.toml` and environment variables that nothing consults.

Out of scope: the custom voices feature, which RR-462 removes (anything matching `custom.voice`, `custom_voice`, `VoiceSampleRecorder`, `kokoclone`, `kanade`); generated files (`Instructions.generated.swift`, the generated blocks in `CLAUDE.md` and `AGENTS.md`, `.orchestrator/`); the iOS app under `ios/` except where the Mac side keeps a protocol path the phone never sends.

Method: for each candidate, establish that nothing references it. Check Swift symbol references, Python imports and string-based entry points (`subprocess`, `-m module`, hook command lines in `services/relay_completion_hook.py` and `scripts/relay-bridge`), shell scripts and `scripts/build-dmg.sh` (bundled file lists), MCP tool names referenced from instruction chunks, Sparkle or launchd plists, and tests that are the only remaining caller (a helper used solely by tests of a removed feature is dead; a test seam used by live tests is not). Use `git log -S` on the symbol to find when its last caller was removed and name that commit. Treat anything reached by reflection, `@objc` selectors, SwiftUI previews or environment-variable switches as "needs a human check", not dead.

Known places to start, from recent history: feature flags and migration code for already-completed one-time migrations (Phonon 2 STT migration, legacy `.pm/` program capture, legacy `/tmp` voice spool paths kept for manual bridges); `scripts/experiments/`; investigation docs for features since replaced; instruction chunks for retired commands; `propose_action` in Relay Actions (retired gesture confirmation, still registered); tile-grid and particle variants reverted in October; onboarding paths for providers or installers no longer supported.

## Acceptance criteria

- The structured report groups findings by area (Swift app, MCP servers, Python services, scripts, instruction chunks, docs, config keys, tests) and, within each, lists every candidate with: path and symbol or key; what it was for; the evidence it is unused (searches run and their empty results, the commit that removed its last caller); a confidence of high, medium or needs-human-check; and the removal risk.
- A separate "checked, still used" list names near-misses with the reference that keeps each alive, so the implementation workers do not re-investigate them.
- Candidates are bundled into at most six proposed implementation tickets, each independently mergeable, with an estimated line count and the tests that must still pass.
- The report names anything whose removal would change user-visible behaviour or on-disk state, so the user can decide those explicitly.
- No files are modified; the spike writes only its structured result.

- Swift findings come from text search, not the compiler or an index. Protocol conformances, @objc selectors, SwiftUI previews and string-keyed dispatch could hide uses. The searches found none for the high-confidence items.
- Older relay-*-mcp helper processes started from a previous bundle could still send 'propose', 'parent_detected' or 'parent_permission_revoked' to /tmp/relay_actions.sock while an update is in progress. The cutover risk depends on how many update windows you want to keep compatibility for.
