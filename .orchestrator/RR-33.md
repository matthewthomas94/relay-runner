## Description

Relay Runner's board is the product surface for distributing work. A Relay Runner session should not end up in a state where the voice bridge is active but there is no usable board for the active working directory.

Today `ProjectResolver` only resolves a board project when `/tmp/voice_bridge.cwd` points at a directory that already contains `.git`; it initializes `.orchestrator/config.toml` for fresh git repos, but returns `nil` for non-git directories. That means a session can be live while the board cannot open or accept tickets.

Make session startup or board resolution guarantee a board-ready project. If the active cwd is already a git repo, ensure `.orchestrator/config.toml` exists as it does today. If the active cwd is not a git repo, implement a safe product decision: either initialize it as a git repo with a board, or present a clear one-action recovery that makes it board-ready. The user experience should uphold the invariant that every Relay Runner instance has a corresponding board users can use to distribute work.

## Acceptance criteria

- [ ] Starting or attaching a Relay Runner session in a git repo with no `.orchestrator/config.toml` initializes the board config automatically and the board opens empty.
- [ ] Starting or attaching a Relay Runner session outside a git repo no longer leaves the board as a silent no-op.
- [ ] The non-git path either safely initializes a repo plus `.orchestrator/config.toml`, or presents one explicit action that does so; the chosen behavior is documented in user-facing copy or docs.
- [ ] The board's no-session prompt remains reserved for genuinely missing/dead bridge sessions, not for "session exists but project is not board-ready".
- [ ] The resulting project can create tickets, bump `next_id`, and dispatch work through the existing orchestrator path once promoted to `ready`.
- [ ] The behavior is provider-neutral for Codex and Claude sessions because it keys off the active `/relay-bridge` cwd, not provider-specific state.
- [ ] Tests cover git repo initialization, missing `.orchestrator` initialization, and the non-git recovery path.
