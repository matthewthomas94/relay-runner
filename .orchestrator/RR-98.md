## Description

Replace the abrupt titled-window entrance on a genuinely fresh Relay Runner launch with the supplied Workspace-style onboarding intro. Reuse the existing notch-to-Workspace reveal primitive rather than building a second approximation: a transient overlay expands from the compact top surface to full width, pulls down into the same black rounded Workspace backdrop, presents a centered cursor-like type animation, retracts completely, and only then constructs/shows the existing key-capable interactive onboarding window.

The supplied 1728×1117 frames establish the visual sequence: a white slash cursor on black, type `First thing’s first /`, erase back to `/`, type `I need a few permissions /`, erase, type `Relay Runner /`, then erase through the supplied `R/` frame back to `/` before retracting. Add a shared `onboardingHero` typography role at approximately 64 points/72-point line height using PP Telegraf Regular (with the normal system fallback) rather than an ad hoc font, and keep the Workspace bottom-corner geometry, screen margin, notch placement, and four-dot visual language. Reserve the active phrase's completed width while typing so partial text grows from a stable leading edge while the completed phrase remains centered. Target a calm approximately five-second sequence: 32–38 ms per typed grapheme, 18–22 ms per erased grapheme, and roughly 500–600 ms phrase holds. The notch/status label for this phase is `Getting started`.

Keep this cinematic narrowly scoped to the automatic, brand-new first launch. Simplified setup recovery, interrupted-flow resume, upgrade/provider-choice recovery, the "no first session yet" reminder, and Settings' manual `Re-run Setup Walkthrough…` action must go directly to the relevant interactive content without replaying several seconds of animation. Write the `.onboarding-started` sentinel before the animation begins so terminating during it resumes safely.

The existing onboarding remains authoritative after the intro: the cinematic replaces its redundant Welcome step and hands the fresh flow to Agent Choice, while preserving provider selection, model and effort normalization, workspace-folder confirmation, microphone/Input Monitoring setup, app-hosted Accessibility/Screen Recording guidance, Python installation, provider authentication, Ready/Start Session behavior, skip paths, and resume persistence. Do not swap the form into the nonactivating reveal panel: its controls and pickers need the current key-window semantics. Do not route the intro through `ProgramBoardOverlayController`, whose project loading and session state are unrelated; reuse the lower-level reveal planner/container or extract only a small shared primitive. Trigger the typing timeline only from the reveal completion callback so it never plays invisibly behind the opening animation. Add an AppState-owned onboarding-notch override with higher precedence than normal one-second session/activity planning; render setup labels using the persistent `.notWorking` four-white-dot presentation, and clear the override on finish or manual close.
