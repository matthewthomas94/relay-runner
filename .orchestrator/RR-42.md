## Description

Build the first read-only Program Board overlay.

This board is distinct from the existing per-project kanban board. It should open as a program-level surface showing registered projects, active agents, blocked/ready/awaiting-merge work, and initiative/project groupings derived from Graphify Core.

Do not replace the existing project board. The local project board should still show the active project's `.orchestrator/` tickets.

Provider parity matters: active agent/run displays should not assume Codex only. Claude-backed projects/runs should appear with equivalent status treatment.

## Acceptance criteria

- [ ] A distinct Program Board UI path exists, separate from the existing project board toggle.
- [ ] The Program Board can open without relying on the active `/relay-bridge` cwd as the only project selector.
- [ ] The board displays registered projects and graph-derived program status.
- [ ] Active runs show provider-neutral state and provider labels where available.
- [ ] Empty states are clear for no registered projects and no active work.
- [ ] The existing project board still opens for the active project and still reads `.orchestrator/`.
- [ ] The UI avoids nested cards and keeps the operational tool surface compact and scannable.
- [ ] Swift/UI tests or a focused manual verification cover opening the Program Board and preserving the existing project board.
