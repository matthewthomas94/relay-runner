## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

`services/relay_completion_hook.py` (1,714 lines) and `services/relay_reply.py` (166 lines) are run as separate processes under `/usr/bin/python3`: the hook on every Claude and Codex hook event with a 2 second timeout (`Sources/relay-runner/Process/ProcessManager.swift` around lines 2355-2404), and the reply helper whenever an agent pipes a reply to `$RELAY_REPLY_HELPER`. The existing tests import these modules and patch their internals, so they cannot check a replacement written in another language.

Write a contract suite, in Python `unittest` under `tests/contract/`, that treats the program under test as an opaque command:

- The command comes from environment variables, for example `RELAY_HOOK_CMD` and `RELAY_REPLY_CMD`, defaulting to the current Python scripts.
- Each case builds a temporary spool directory, FIFO, claim and state files, session binding path and SQLite intent inbox, sets only documented environment variables, feeds stdin, and asserts on stdout, exit code, the lines written to the FIFO, files written, and the rows in the `provider_turn*` tables.
- Cover every mode in the hook's `main`: the Claude events (SessionStart, UserPromptSubmit, Stop, StopFailure, PreCompact, PostCompact), the Codex events (UserPromptSubmit, Stop, PreCompact, PostCompact), `--record-process`, `--record-codex-startup` and `--context-continuation`.
- Cover both providers' payload shapes, including Claude's `prompt_id` standing in for `turn_id`, both transcript token parsers, a stale or mismatched claim, a missing FIFO reader, a locked database, and malformed stdin.
- Cover `relay_reply` acceptance, rejection of a superseded command, and the exact `__ORCHESTRATOR_REPLY__:` line (sorted JSON).
- Include a timing case that fails if a hook invocation takes longer than a stated budget, and record the measured median for the Python implementation in the run log.

Where a setup needs rows that only the bridge writes, create them through the public schema with plain SQL in the test, not by importing `provider_turn_broker`. Write `docs/specs/hook-contract.md` describing the inputs, outputs and environment variables the suite relies on. Do not change the hook's behaviour; if a case exposes a bug, record it in the run log and mark the case as a known difference.

## Acceptance criteria

- [ ] `python3 -m unittest discover -s tests/contract -p 'test_hook_contract*.py'` passes against the current Python scripts.
- [ ] No file in the suite imports from `services/`.
- [ ] Every hook mode and both providers have at least one success and one failure case, listed in `docs/specs/hook-contract.md`.
- [ ] Pointing `RELAY_HOOK_CMD` at a stub that exits 0 with no output makes the suite fail, proving it checks behaviour.
- [ ] The run log records median hook latency for the Python implementation on the worker machine.
