## Description

The app no longer exposes useful background activity feedback when the foreground assistant is not actively speaking/responding.

Observed regression:

- When Relay Runner is in a working/background state, the neutral glyph should rotate even when it is not showing colored activity states.
- Hovering the glyph should expand the notch and show the reasoning/activity trace or equivalent status details inside the notch.
- The hover/status surface should make it clear what background work is happening, including sub-agent activity such as active ticket runs.

The user specifically noticed this while checking the Program Board and background worker state: the neutral glyph appears static, and hover no longer shows the reasoning trace/status that used to be visible.

Investigate the overlay/notch state pipeline, working-state glyph animation, hover affordance, and activity text source. The current active-worker status endpoint can report useful state, for example `RR-118` run `157` as active with activity `Reading source files`; the UI should surface that kind of information when appropriate.

## Acceptance criteria

- [ ] The neutral working glyph rotates while Relay Runner has foreground or background work in progress, even when no colored activity state is active.
- [ ] Hovering the glyph expands the notch and shows a reasoning/activity trace or concise background status inside the notch instead of an empty/no-op hover.
- [ ] Active sub-agent work is represented in the hover/status surface, including ticket id, title or activity, provider/model, and run id when available.
- [ ] The hover/status surface handles no-active-work and stale/unavailable status states gracefully.
- [ ] Add or update tests covering neutral glyph working animation state and hover activity/status content.
- [ ] Provider parity is preserved for Codex and Claude; provider-specific activity labels should normalize to the same user-facing behavior.
