## Description

Add a Sparkle 2 based OTA update path to the Relay Runner macOS app, matching the update model used by Codex: the installed app checks an appcast, downloads a signed update archive, replaces the app bundle, and relaunches.

The first install should continue to use the existing DMG/installer flow. This ticket is only the in-app updater integration. It should not remove DMG packaging, and it should not introduce a custom updater unless Sparkle cannot support a required behavior.

Current facts to preserve:

- Relay Runner is a SwiftPM macOS menu-bar app with `Info.plist` at the repo root.
- Current first-install packaging is `scripts/build-dmg.sh`.
- The app bundles helper MCP binaries and Python services under `Contents/MacOS` and `Contents/SharedSupport`.
- TCC identity and code-signing stability matter; updates must preserve the bundle id `com.relayrunner.app`.
- Provider parity matters: Codex and Claude sessions use the same app, bundled scripts, MCP helpers, and orchestrator daemon.

Implementation guidance:

- Add Sparkle through SwiftPM and link it only to the `relay-runner` executable target.
- Add a small updater controller/service rather than scattering Sparkle calls through views.
- Start the updater from the app launch path for installed/non-installer mode only.
- Add an explicit user-facing "Check for Updates..." action in the menu bar or settings UI.
- Add `SUFeedURL`, `SUPublicEDKey`, and sensible automatic update defaults to `Info.plist`. Use a placeholder appcast URL/key only if CI generation in the next ticket is not yet available, and document that limitation.
- Do not patch the installed `.app` bundle by hand; all bundle changes must flow through source and packaging scripts.

## Acceptance criteria

- [ ] `Package.swift` includes Sparkle 2 and the `relay-runner` target builds with it.
- [ ] The app starts a Sparkle updater only when running as the installed app, not while showing the DMG installer window.
- [ ] Users can manually trigger "Check for Updates..." from Relay Runner UI.
- [ ] Automatic checks/download defaults are represented through `Info.plist` or a documented settings path.
- [ ] `Info.plist` contains the required Sparkle feed/public-key metadata and preserves `CFBundleIdentifier = com.relayrunner.app`.
- [ ] The integration compiles with `swift test`.
- [ ] Tests or a documented verification note cover installed-mode updater startup versus installer-mode suppression.
- [ ] Codex and Claude provider flows are unaffected; update behavior is provider-neutral.
