## Description

Implement the remote publication and deletion transaction for terminal candidates produced by the terminal-only retention planner. A ticket and its eligible Relay-owned attachments may leave local materialization only after the exact project artifact ref has been published to the explicitly selected GitHub remote and independently refetched and verified. Failures keep the candidate locally as a visible temporary overage and support safe retry. This ticket also owns exact-ref fresh-install and second-device recovery.

## Acceptance criteria

- [x] The transaction consumes only eviction candidates selected by the terminal-only planner and never deletes a nonterminal ticket or one of the retained newest 25 Done-or-Canceled tickets.
- [x] Remote cleanup is enabled only after the user selects an existing suitable GitHub remote and explicitly confirms exposure; Relay never creates a repository, guesses or changes a remote, publishes source refs, or force-pushes.
- [x] Before local removal, Relay prepares and validates the ticket, eligible attachments, catalog update, and deletion commit; fast-forward publishes the exact artifact ref; refetches it into quarantine; and proves the archived content is reachable and matches expected identities and digests.
- [x] Only after successful post-push verification may Relay advance the local artifact authority and remove the materialized Markdown and managed attachments. Catalog metadata remains available for history, dependency resolution, and restoration.
- [x] Offline, authentication, non-fast-forward, missing or protected ref, remote deletion, integrity, shallow-object, and indeterminate-push failures keep or restore the local candidate, report a retryable blocked state, and never silently weaken the policy.
- [x] A durable transaction journal makes every crash boundary idempotently resumable, including crashes before push, after push, after verification, during local ref update, and during materialization rebuild.
- [x] Fresh-install and second-device recovery fetch only the confirmed project artifact ref, verify project identity and content, then materialize every nonterminal ticket plus the newest 25 combined Done-or-Canceled tickets without fetching unrelated refs.
- [x] Tests exercise remote races, offline and authentication recovery, divergence, tampering, every journal phase, attachment verification, repeat application, and a project with hundreds of terminal tickets.
- [x] Storage reporting distinguishes removed materialized files from historical objects that remain reachable in the local Git object database; history rewriting and destructive garbage collection remain out of scope.
- [x] Codex and Claude follow the same confirmation, publication, verification, retry, and recovery contract.
