## Description

In the embedded Workspace terminal that hosts Claude Code and Codex sessions, basic macOS text-editing keys don't behave as they do in other apps. The user reports these as not working in the installed app (0.4.65, build 69, built 2026-10-17):

- **Cmd+Left/Right:** jump to the start or end of the line.
- **Option+Left/Right:** jump by word.
- **Shift+Left/Right:** select text.

Fix these, plus the other everyday editing keys listed below, in one pass.

### Current state (verified in source)

- The terminal is SwiftTerm 1.15.0 (`Package.swift`, `Package.resolved`), wrapped by `RelayTerminalView` in `Sources/relay-runner/Terminal/EmbeddedTerminal.swift` (around line 455).
- **Keys the app intercepts.** A local `keyDown` monitor (around lines 599–615) and `performKeyEquivalent` (around line 530) route keys through `navigationShortcutPayload` (around lines 571–597) and `keyCommand` (around lines 665–706):
  - Option+Left/Right already send `ESC b` / `ESC f`;
  - Cmd+Left/Right already send Ctrl-A / Ctrl-E;
  - both as raw bytes, even when the hosted CLI has turned on the Kitty keyboard protocol.
- **Keys SwiftTerm drops.** In SwiftTerm `MacTerminalView.doCommand(by:)`, any selector it doesn't handle prints "Unhandle selector" and sends nothing. That covers:
  - Shift+Left/Right (`moveLeftAndModifySelection:`);
  - Cmd+Shift+Left/Right;
  - Cmd+Delete (`deleteToBeginningOfLine:`);
  - right-Option+Delete (`deleteWordBackward:`).
- **Option as Meta.** Only left Option acts as Meta (`optionActsAsMeta`, around line 721), like Ghostty's `macos-option-as-alt = left`.
- **Existing earlier work.** RR-163 added the Option/Cmd arrow mapping. Its installed-app check of "normal editing shortcuts" was never completed. Commit `fdca1eae` added the Ghostty-style copy/paste/find/zoom/scroll commands. No earlier ticket covers the remaining keys.

### 1. Find and fix the regression first

Cmd+Left/Right and Option+Left/Right are mapped in code but reported dead. Reproduce this in a hosted Claude Code session and a hosted Codex session, find the root cause, and fix it. Candidates to rule in or out:

- **Kitty keyboard protocol.** Once a CLI turns it on, a raw `ESC` byte followed by `b` can be read as the Escape key followed by typing "b". If so, encode these keys in the protocol the CLI has negotiated (Kitty CSI-u, or xterm modified-key sequences), not as raw bytes.
- **The monitor never sees the key.** The local monitor's `event.window === self.window` / `firstResponder === self` guard may fail after RR-395 multi-session tab re-hosting.
- **A host view takes the key first.**

Record the root cause in the Run log.

### 2. Expected key behaviour in the session prompt

Prompt text is edited by the hosted CLI, not the terminal, so each key below must send the right sequence for the CLI to act on. Use the negotiated keyboard protocol where one is active.

| Key | Expected effect |
|---|---|
| Cmd+Left / Cmd+Right | Start / end of line |
| Option+Left / Option+Right (either Option key) | Back / forward one word |
| Option+Delete (either Option key) | Delete the previous word |
| Cmd+Delete | Delete to start of line (Ctrl-U or equivalent) |
| Fn+Option+Delete | Delete the next word (`ESC d` or equivalent) |
| Fn+Delete, Home/End | Keep today's behaviour |
| Shift+Left/Right, Shift+Option+Left/Right, Shift+Cmd+Left/Right | Send the standard shift-modified sequences (xterm `CSI 1;2D`, `CSI 1;4D`, …, or their Kitty forms). Never drop the key. |

Keep right Option composing characters for typed text (for example UK Option-3 = `#`, `testOnlyLeftOptionActsAsMeta`). Only Option combined with an arrow or Delete gets the word behaviour.

**Selection limit.** A terminal cannot highlight text inside the CLI's own input box. Ghostty and iTerm2 likewise only forward Shift+arrows, so any selection is drawn by the CLI. Check whether the current Claude Code and Codex input boxes support Shift+arrow selection when given these sequences, and record the result per provider in the Run log:

- If a CLI supports it, Shift+arrows must select there.
- If it doesn't, the key must at least move the cursor rather than doing nothing, and the limitation is noted in `docs/` where terminal shortcuts are described.

Do not build a terminal-side selection overlay for the CLI's prompt in this ticket.

**Leave unchanged:**

- Cmd+A (selects the terminal buffer, as Ghostty does);
- Cmd+C/V, find, zoom and the Cmd+Home/End / Shift+PageUp/PageDown scrollback commands;
- mouse selection;
- Ctrl-C;
- Backspace.

Undo (Cmd+Z) is out of scope.

**The unsent-prompt tracker** (around lines 893–1030) decides whether there is unsent text, which defers context switches. It must classify every new key correctly:

- navigation and selection keys are not new prompt text;
- word or line deletions are edits;
- Ctrl-U still counts as clearing the line.

This applies in both raw and Kitty modes.
