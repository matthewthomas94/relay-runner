## Description

Relay Runner onboarding should feel like one guided setup run after the user chooses Codex or Claude. The product cannot silently grant macOS TCC permissions, but it can automate everything else and walk the user through each unavoidable permission step inline.

Build a cohesive setup flow that starts from provider choice and drives the user toward a fully ready Relay Runner session:

- Automate provider-specific setup such as bundled Python/voice environment, MCP registration, skill or slash-command installation, board initialization for the active repo, and session command readiness.
- Guide Relay Runner app permissions, especially Microphone and Input Monitoring, with clear copy about what each unlocks.
- Guide parent-app permissions for the selected provider/host, such as Accessibility and Screen Recording for Codex.app, Claude.app, Terminal, or another detected parent.
- Open the relevant macOS prompt or Settings pane for each required manual step, poll for completion, and continue without making the user restart the entire flow.
- Distinguish voice-only readiness from fully armed screen-control/board-hotkey readiness.

The target experience is not literal one-click TCC approval. It is one primary setup action with a guided rail, clear mode/readiness states, and a boring one-click Start Session once setup is green.

## Acceptance criteria

- [ ] After provider selection, the user sees one primary setup action that orchestrates the remaining setup flow.
- [ ] The flow runs automatable setup tasks without extra user decisions: bundled Python/voice environment, provider MCP registration, skill or slash-command install, active repo board initialization, and session command readiness checks.
- [ ] Relay Runner app permissions are guided inline, including Microphone and Input Monitoring, with copy that names activation keys and the `Control+Option` board hotkey.
- [ ] Parent-app permissions are guided separately for the selected provider/host, including Accessibility and Screen Recording where needed for Relay Actions and Relay Vision.
- [ ] Permission steps open the correct macOS prompt or Settings pane, poll for status changes, and explain any required app/session relaunch without dead-ending the user.
- [ ] Users can intentionally skip/defer optional capabilities, but the final state clearly distinguishes voice-only readiness from fully armed screen-control/board readiness.
- [ ] Once the setup is green, Start Session can launch the selected provider with voice bridge, board, MCP tools, and TTS ready without further setup prompts.
- [ ] Provider parity is explicit: Codex and Claude get equivalent setup rails unless a deliberate provider-specific difference is documented in the UI or ticket run log.
- [ ] Tests cover the setup state machine/readiness model, deferred-permission paths, provider-specific copy, and recovery after permissions are granted later.
