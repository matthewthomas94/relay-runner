## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

Final stage, only after every earlier stage has shipped and its rollback switch has been retired.

- Port the bundled per-invocation tools to Rust subcommands with the same arguments and JSON output: `fresh_install_cli.py`, `artifact_history_cli.py`, `artifact_rollout_cli.py`, `artifact_verification_cli.py`, `artifact_migration_cli.py`, `harness_update.py`, `work_style_cli.py`, and keep the wrapper script names in `scripts/` (`relay-ticket-history`, `relay-artifact-*`, `relay-runner-fresh-install`, `relay-work-style`) so generated instructions stay valid.
- Remove Python discovery, the venv, `pip install`, the python-build-standalone download and `services/requirements.txt` from `scripts/relay-bridge`, `scripts/relay-orchestrator`, `scripts/build-dmg.sh` and `VenvInstaller.swift`; onboarding no longer has a Python step.
- Delete the ported `services/*.py` modules and their white-box tests once the contract suites cover them. Keep build-time Python (`services/app_signing.py`, `scripts/build-instructions`, DMG tooling), which never ships to users, and say so in `TESTING.md`.
- Update `docs/fresh-install.md`, `docs/architecture.md`, `docs/troubleshooting.md`, `README.md` and `THIRD_PARTY_NOTICES.md`.
- An existing install upgrades cleanly: the old venv and model cache are handled as documented, with nothing deleted outside Relay-owned directories.
