## Description

Add a chat panel to the right-hand side of the Notes tab, using the daemon route from RR-548. The transcript view is already gone (RR-547).

**Layout of the right-hand panel** (`notesDetailPanel` / `notesDetailContent` and `ProgramNoteDetailPanel` in `Sources/relay-runner/Board/ProgramBoardOverlayView.swift`):
- **Note selected:** title and action row as now; the **Summary** pinned at the top (not inside the chat scroll; if it is long, cap its height and let it scroll on its own); then a **scrollable chat thread** filling the space between the summary and the bottom; then a **text field pinned at the bottom**. The placeholder says what it does, for example "Ask about this note".
- **No note selected:** replace the "Select a note" empty state with the same thread and bottom text field, chatting with the whole library. Before the first message, show a short hint in the thread area, for example "Ask about all your notes" with one line saying a note can be selected to ask about just that note. Placeholder "Ask about your notes".

**Behaviour:**
- Return sends, Shift-Return adds a new line. The field and the send button are disabled while a reply is pending, and the thread shows a pending row ("Thinking…") that is replaced by the answer.
- The user's message appears at once; the reply is appended when the route answers. Errors show inline in the thread with a Retry action and keep the user's message.
- Each scope has its own conversation: each note, and the library. Switching notes and coming back shows that note's conversation again. Conversations live in memory only and are gone when the app quits; nothing is written to the note.
- The thread scrolls to the newest message when one is added. Text in messages is selectable. Long replies wrap; no horizontal scroll.
- Add an `OrchestratorClient` call for the route beside `fetchProjectNote` (`Sources/relay-runner/Board/OrchestratorClient.swift`).
- Use the existing components and tokens: `AppTypography`, `ProgramBoardStyle`, `BoardOverlayScrollView` / `RelayFadingScrollView`, and the existing glass text field style used by the notes search. Use `RelayMotion` for message insertion and respect Reduce Motion.
- Leave the Start notetaker button and the notes list on the left as they are.

## Acceptance criteria

- [ ] With a note selected the panel shows title and actions, the pinned summary, a scrollable thread and a bottom text field, and questions go to the route with that note's id.
- [ ] With no note selected the panel shows the library chat and questions go to the route without a note id.
- [ ] Each note and the library keep separate conversations for the life of the app, covered by a unit test on the chat model.
- [ ] Return sends and Shift-Return inserts a new line; sending is disabled while a reply is pending; an error keeps the question and offers Retry. Covered by unit tests on the chat model.
- [ ] A screenshot of both states is attached to the run log.
- [ ] `swift build` and the board test targets pass; the pre-existing `testSwiftAndShellWritersShareCrossProcessLock` failure is not counted.
