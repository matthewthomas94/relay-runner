## Description

RR-359 recommends a small native meeting app, conditional on this gate. Build a disposable, reproducible native capture/ASR harness in the selected app repository; this is writable implementation work, not a read-only spike. Compare Core Audio taps plus microphone and a pinned FluidAudio/Parakeet engine with Apple's SpeechAnalyzer on macOS 26 where available. Select one baseline engine and OS floor; do not automatically ship both. Use Anarlog/Meetily/Logue as reference implementations and revisit a reduced fork if native work fails the targets. Do not install over Relay Runner, record unrelated meetings or create production UI.

Measure a short clean fixture, accented/jargon fixture, overlap/silence and a 60-minute dual-source fixture, three repetitions each after separate cold/warm setup. Include built-in/wired/Bluetooth device changes, permission denial/revocation, sleep/wake, low disk, crash and concurrent Relay voice/TTS. Use fake or consented data only. Public reports contain metrics, identifiers and sanitized failures; private recordings/references remain outside Git.

Reference: [Apple taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps), [FluidAudio benchmark](https://github.com/FluidInference/FluidAudio/blob/57551cd90e0bbec342766244358bcf08afb05290/Documentation/Benchmarks.md), [Logue timeline](https://github.com/bitwize-ai/Logue/blob/ea61172f33970d40b9f9b5e4c52f30eb82836e58/Logue/Engine/AudioTimelineMixer.swift).
