## Description

Make worker/sub-agent runs visible at both scopes where the user expects to manage them.

The foreground LLM is the orchestrator. Workers do the work. Project boards should keep showing project-local ticket/run state, and the Program Board's In progress column should show active workers across registered projects. Program-level commands should not create a parent workspace `.orchestrator/`; they should resolve to a target project ticket and then dispatch that ticket through the same worker path used by project boards.

This ticket should tighten the product path from ticket to worker:

- project-level ticket promoted to `ready` dispatches a worker and appears on that project board
- program-level command or Program Board action resolves a target project, creates/updates a project ticket, dispatches a worker, and appears in Program Board In progress
- active worker metadata is clear enough to answer "which agent is doing what, in which repo, and for which ticket?"

Provider parity matters. Codex and Claude workers should be represented consistently in Program Board status, with provider/model differences surfaced as metadata rather than separate concepts.

## Acceptance criteria

- [ ] Active worker/sub-agent runs across registered projects appear in Program Board In progress with project, ticket id, title, provider, run id or branch, and current state.
- [ ] Project board In progress placement remains consistent with the same run state used by Program Board status.
- [ ] Program-level ticket creation or command capture resolves to a child project ticket and does not create or require a workspace-root `.orchestrator/`.
- [ ] Promoting or creating a ready ticket from a program context dispatches a worker through the same daemon path as project board ready transitions.
- [ ] Program Board refresh or ready-sweep reconciles stale ready tickets across registered projects without needing each project board to be opened manually.
- [ ] Completed worker runs remain visible as done or awaiting-merge state at the appropriate scope until integrated, so workers do not disappear between completion and merge.
- [ ] Codex and Claude worker runs have equivalent Program Board representation, with provider-specific launch/auth metadata shown only where useful.
- [ ] Tests cover project-board dispatch, program-context dispatch, Program Board In progress aggregation, and the no-parent-`.orchestrator` invariant.
