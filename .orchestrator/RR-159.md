## Description

Prepare the repository for Relay Runner `v0.4.22`, containing the responsive Terminal and Settings Workspace fixes completed in RR-157 and RR-158. Update `Info.plist` from marketing version `0.4.21`, build `25`, to marketing version `0.4.22`, build `26`.

Run the automated release preflight from the worker branch. Validate the plist and release scripts, verify the GitHub Actions workflow parses, confirm generated provider instructions are current (regenerate them only if the repository check reports drift), and run the complete Swift and Python test suites. Keep the change surgical and provider-neutral.

Do not create or push a tag, push any branch, publish a GitHub release, build a local DMG, modify either release repository, or alter the installed Relay Runner app. The foreground release process will push `main`, wait for its packaging workflow, create the annotated tag, and verify the published artifacts after this ticket is reviewed and merged.

## Acceptance criteria

- [ ] `CFBundleShortVersionString` is exactly `0.4.22` and `CFBundleVersion` is exactly `26`.
- [ ] The new version is strictly newer than `v0.4.21`, and no local or remote `v0.4.22` tag/release exists during preflight.
- [ ] `plutil -lint Info.plist` passes.
- [ ] Relevant release shell scripts pass `bash -n`, and `.github/workflows/build-dmg.yml` parses as YAML.
- [ ] `python3 scripts/build-instructions --check` passes; if it initially reports drift, regenerate through the repository script and include only the required generated outputs.
- [ ] The complete Swift test suite passes.
- [ ] The complete Python test suite passes.
- [ ] No provider-facing behavior changes; Codex and Claude remain equivalent.
- [ ] No tag, push, GitHub release, local DMG, update-repository mutation, or installed-app mutation is performed by the worker.
- [ ] The worker commits the version/preflight changes and records exact verification evidence in the ticket run log.
