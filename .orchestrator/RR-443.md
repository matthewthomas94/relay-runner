## Description

When the user names a project in a voice turn, the foreground PM must find it in the project registry or ask how to add it. Nothing is assumed about where projects live; the user is asked for every location.

1. Matching: a read-only Relay Actions tool (next to `Sources/relay-actions-mcp/ActivateProjectTool.swift`) that takes a spoken name and returns exact, basename and fuzzy matches from the registry (display name, folder name, path), case and punctuation insensitive, with an explicit ambiguous or none result. It never mutates anything.
2. Registering: a second tool the PM calls only after the user has answered. Existing project: the tool opens the shared folder picker (previous ticket), registers the chosen folder exactly as Add existing project does (`ProjectRegistryV2Service` in `Sources/relay-runner/Board/ProjectRegistration.swift`), and the session gains access and a scope token (previous ticket). New project: the tool asks for a parent folder through the picker and a name, creates and registers it exactly as Create new project does. No default parent folder, ever.
3. PM behaviour: on no confident match the PM asks one question, existing or new; on an ambiguous match it names the candidates. Write this into the instructions chunk under `services/instructions/` and regenerate the CLAUDE.md and AGENTS.md blocks and the compact payloads with `scripts/build-instructions`. The messenger stays tool-free.
4. The registry remains the single ledger; no parallel list.

## Acceptance criteria

- [ ] Unit tests cover exact, folder-name, fuzzy, ambiguous and no-match results, including names spoken without punctuation or case.
- [ ] The register tool refuses to run without the user's answer in the current turn and never creates folders under an assumed default location.
- [ ] Registering an existing or a new project through the tools produces the same registry record as the Add project menu flows, and the picker uses the shared presenter.
- [ ] Instructions chunk updated and generated outputs are in sync.
- [ ] Behaviour is identical for Codex and Claude sessions.
- [ ] Commit source changes only and submit for independent review/merge; do not install, release, or restart the running app.
