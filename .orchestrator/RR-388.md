## Description

Hide routine session management behind the continuous conversation. Maintain durable bindings among visible conversation, global/project context, provider, provider session identity and active runs. Reuse a healthy compatible session when available; start or resume when needed; save and stop idle underlying processes according to a documented bounded policy. Do not present a fake suspended state if a provider only supports saving and resuming after termination. Existing accepted background work should survive ordinary foreground context changes.

## Acceptance criteria

- [ ] Persist the data needed to restore each global/project context, conversation history, provider resume identity, pending intent state and active run links across switches.
- [ ] Repeated requests and context selections reuse a healthy matching session instead of launching duplicates; incompatible provider/model/cwd changes follow an explicit replacement path.
- [ ] Define and implement bounded idle-session lifecycle behavior. A suspended/resumable context preserves its history and working files, and session status reflects real provider capabilities.
- [ ] Do not terminate sessions owning an active recording, approval, accepted command or worker merely because the visible context changes or an idle timer fires.
- [ ] Session creation, reuse, interruption and termination are idempotent and do not replay already consumed commands or duplicate messenger replies.
- [ ] Codex and Claude have equivalent user-visible lifecycle behavior; any resume/history limitation is documented and shown truthfully.
- [ ] Focused tests cover repeated switches, concurrent launch attempts, idle cleanup, active work protection and persistence failures; separately verify installed provider switching and resume.
