## Description

Retain automatic underlying provider lifecycle management for ordinary registered projects, including the built-in general-tasks project. Persist confirmed project/provider/native-session identity and history needed for reuse or reconnect. Reuse compatible healthy sessions, save and stop eligible idle foreground processes, and preserve accepted background workers. Keep this implementation behind the existing interface rather than exposing a separate global-session concept or conversation surface.

## Acceptance criteria

- [ ] Persist durable bindings for general-tasks and other registered projects, including confirmed project identity, provider/model, native resume identity, history and relevant canonical intent/run links.
- [ ] Repeated selection or Start Session reuses a healthy compatible provider rather than launching duplicates; incompatible changes use the existing safe replacement path.
- [ ] Idle cleanup saves state before terminating eligible foreground processes; recording, approval, accepted input and other protected obligations block cleanup.
- [ ] Foreground selection or idle cleanup does not terminate independently running canonical ticket workers or move their ownership.
- [ ] Creation, reuse, stop and reconnect are idempotent and do not replay consumed commands or duplicate replies.
- [ ] Codex and Claude receive equivalent user-visible lifecycle behavior; resume is used only with a validated native transcript and confirmed current project directory.
- [ ] Focused lifecycle/persistence tests and separate signed-app checks verify both providers under the corrected ordinary-project flow.
