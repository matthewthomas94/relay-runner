## Description

The app now supports Codex and Claude as first-class providers, and RR-20 replaced the General settings target-command/model flow with provider and provider-specific model choices. Some docs still describe the old Claude-shaped setup:

- `README.md` still says General settings have a `Target command` field and one Default/Opus/Sonnet/Haiku model picker.
- `docs/specs/relay-actions.md` and `docs/specs/relay-vision.md` still frame MCP registration/discovery and screen-control usage as Claude-only, even though `scripts/relay-bridge` registers Relay MCP servers for both Claude and Codex.
- `docs/specs/orchestrator-tickets.md` still describes project resolution as "Claude Code session" in at least one place, even though the board is scoped to any active `/relay-bridge` agent session.

Update the docs so future users and agents understand the provider-aware behavior that actually ships.

Scope note: RR-22 is already codifying the standing provider-parity rule in project/workflow guidance. Avoid duplicating or conflicting with that work; focus this ticket on user-facing docs and feature specs that describe existing behavior.
