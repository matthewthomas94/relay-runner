## Description

Prevent Relay voice sessions from speaking two near-equivalent replies for the same user turn.

The current pipeline can play a fast messenger response and later play the authoritative provider completion under different deduplication keys. A simple conversational turn reproduced two distinct played speech events even though the later response added no useful information. Exact text or event-key deduplication is insufficient because equivalent replies may use different wording; blindly suppressing every final is also unsafe because the authoritative result may contain new ticket IDs, action outcomes, errors, decisions, or other facts.

Add command-scoped semantic coverage arbitration at the existing MessengerRuntime and SpeechCoordinator boundary. Track only speech that actually played for the same relay command sequence and ID. When an authoritative final arrives, the existing messenger final-synthesis step should return an explicit realization decision: suppress speech when the result was fully covered, speak a concise delta or synthesis when it adds information, or speak the full final when no usable prior coverage exists. Fold this into the existing final synthesis rather than adding a second remote model round trip.

Keep deterministic coordinator guardrails around the model-assisted decision. A task handoff is not proof that a later task outcome was covered. Interrupted, canceled, queued, stale, or failed speech does not count as delivered coverage. If semantic arbitration is unavailable, times out, or returns malformed data, fail open by speaking the full authoritative final. The provider final must remain visible in the terminal and messenger context even when its second TTS realization is suppressed.

Preserve existing exact-key deduplication, completion-hook correlation, freshness checks, fallback behavior, and Codex/Claude parity. Diagnostics may record the decision and event identity, but must not persist raw user transcripts or reply bodies.

## Acceptance criteria

- [ ] A regression test reproduces a simple conversational turn where a played messenger reply and a paraphrased authoritative final currently produce two spoken replies.
- [ ] When the authoritative final is semantically fully covered by speech already played for the same command, Relay produces no second TTS utterance while the provider final remains visible.
- [ ] When the authoritative final adds facts, decisions, ticket or run IDs, action outcomes, errors, blockers, or next steps, Relay speaks the novel information exactly once without needlessly repeating already-covered wording.
- [ ] A task-like messenger handoff cannot suppress a later substantive result solely because both contain an acknowledgement or similar phrasing.
- [ ] Only utterances that reached the played state count as coverage; queued, interrupted, canceled, stale, failed, and superseded utterances do not suppress a final.
- [ ] Coverage state is isolated by relay command sequence and ID, is cleared or superseded correctly, and cannot leak across rapid consecutive turns or barge-in.
- [ ] Malformed, failed, or timed-out semantic arbitration falls back to the full authoritative final instead of dropping speech.
- [ ] The final coverage decision and any delta text are produced through the existing messenger final-synthesis path without a second remote model call dedicated only to comparison.
- [ ] Codex and Claude app-owned sessions have equivalent behavior across explicit replies, completion hooks, and messenger-failure fallback; any intentional provider difference is documented.
- [ ] Diagnostics expose event identity, realization decision, and suppression reason without logging raw user transcripts or full reply text.
- [ ] Focused SpeechCoordinator, MessengerRuntime, voice-bridge preemption, and completion-hook tests pass, including semantic paraphrase, new-information, interruption, stale-turn, fallback, and provider-parity cases; git diff --check passes.
