## Description

Relay Runner currently creates visible `.orchestrator/*.md` tickets for raw voice-command captures before the foreground orchestrator has classified the command, resolved the target project, or refined the work. In this session that produced parent-workspace `DE-*` backlog cards containing transcript fragments for Relay Runner discussion, which is confusing and inefficient.

Replace the eager visible-ticket path with a private command-capture path. The voice bridge should record a small command event for reliability, preemption, replay, and audit evidence, but raw utterances should not appear on Project Board or Program Board lanes. Only refined, actionable project work should become an `.orchestrator/<id>.md` ticket in the resolved target project.

Keep the hot path fast. The voice bridge should avoid board writes, git writes, expensive classification, or ticket rendering work while it is receiving commands. Intent classification, project resolution, ticket drafting, and Graphify/session-capture enrichment can happen in the foreground orchestrator or an asynchronous layer after the raw command has been safely handed off.

Provider parity matters. Codex and Claude voice sessions should share the same private command-capture semantics, stale-command metadata, and target-project resolution behavior unless a deliberate provider-specific limitation is documented.

## Acceptance criteria

- [ ] Raw voice transcripts are no longer written directly as visible `.orchestrator/*.md` tickets before intent classification and target-project resolution.
- [ ] Conversation, question, status, control, and correction commands do not create board cards.
- [ ] Project-work commands create visible tickets only in the resolved target project after the foreground orchestrator has refined the ticket content.
- [ ] Workspace-root sessions with child projects do not create parent-workspace capture tickets when a child project is active or can be resolved.
- [ ] Relay command metadata needed for preemption, stale-action checks, replay, and TTS tagging remains available without relying on visible tickets.
- [ ] Raw command evidence is retained in a private bounded store, event log, or Graphify/session-capture path with size or TTL controls.
- [ ] The voice command hot path avoids board parsing, git writes, and LLM summarization; tests or instrumentation show this path does not regress command latency.
- [ ] Existing Project Board and Program Board rendering only includes real ticket files, not private raw-command captures.
- [ ] Codex and Claude sessions use equivalent behavior for command capture, classification handoff, target-project resolution, and stale-intent metadata.
- [ ] Add regression tests covering non-work voice commands, project-work ticket creation in the resolved child repo, workspace-root routing, and preservation of relay command sequence/id metadata.
