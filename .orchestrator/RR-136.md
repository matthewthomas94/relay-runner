## Description

Relay voice should use a two-step spoken response shape:

1. After a user command is claimed, provide a quick acknowledgement from the first safe public trace/status event when no better acknowledgement has already been spoken quickly.
2. After normal reasoning, tool use, or orchestration work completes, speak the existing concise outcome summary.

The first acknowledgement must come from the curated public trace/status stream, not from hidden model reasoning, raw worker logs, raw shell/tool output, command transcripts, secrets, or unbounded metadata. It should be short, natural, tagged with the claimed Relay command metadata, stale-safe, and de-duplicated against the later final TTS response.

This is meant to make voice mode feel responsive even when the final answer requires planning or tool work. Example safe acknowledgement copy: "I am checking the project and choosing the route." The final response still owns the actual action outcome, such as created ticket, dispatched worker, review result, or blocker.

## Acceptance criteria

- [x] A claimed Relay command can produce an early spoken acknowledgement from the first safe public trace/status event when no stronger acknowledgement has already been queued within a bounded delay.
- [x] The early acknowledgement path rejects hidden reasoning, raw worker logs, raw shell/tool output, command transcripts, secrets, and unbounded metadata.
- [x] Early acknowledgement TTS is tagged with the same `relay_command_seq` and `relay_command_id` semantics as final TTS, and is suppressed if a newer command supersedes it.
- [x] The final outcome TTS still runs after reasoning/action completion and is not replaced by the early acknowledgement.
- [x] Duplicate or near-duplicate spoken acknowledgements are suppressed so the user does not hear the same status twice.
- [x] Existing public notch trace behavior remains intact; the trace can feed acknowledgement copy without forcing every notch trace to become audio.
- [x] Provider parity is covered for Codex and Claude bridge prompts or code paths, with any intentional difference documented.
- [x] Add focused regression coverage for early trace acknowledgement, stale suppression, final-summary follow-up, duplicate suppression, and unsafe trace rejection.
