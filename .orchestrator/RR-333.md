## Description

Launch a fresh, one-shot continuity agent when RR-332 classifies voice-to-work processing as stalled or recurring. The agent exists to restore normal operation even when it cannot repair the underlying defect. It must run outside the failed foreground session, receive a sanitized incident bundle, and work only through a brokered Relay runtime-recovery interface.

The continuity agent is operational recovery infrastructure, not a second foreground PM. It remains silent, cannot claim user commands, and cannot mutate project source or canonical tickets. It may perform several bounded recovery steps through the broker until health is restored or its recovery budget is exhausted.

## Acceptance criteria

- [ ] Relay Runner launches at most one continuity agent for an active incident and assigns it a distinct continuity-agent actor role, process identity, incident identity, and recovery generation.
- [ ] The agent runs in a fresh provider session with no foreground reply, TTS, messenger callback, command-claim, ticket-authoring, Git, release, deployment, or external-action authority.
- [ ] The agent receives only the sanitized RR-332 incident bundle and the recovery broker interface; it does not receive raw conversation, audio, transcripts, prompts, provider output, credentials, repository contents, screenshots, or arbitrary shell or web tools.
- [ ] The lane supports bounded iterative diagnosis and recovery, a wall-clock and attempt budget, single-flight deduplication, cooldowns, clean termination after stable health, and explicit circuit-open escalation.
- [ ] The configured provider is used by default; any Codex-to-Claude or Claude-to-Codex fallback requires an explicit project or app policy and never silently changes authentication, model, or billing behavior.
- [ ] The parent records sanitized actions, outcomes, health evidence, and the final recovery result without allowing the agent to speak directly.
- [ ] Codex and Claude exercise the same continuity-agent lifecycle and authority tests.
