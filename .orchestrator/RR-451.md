## Description

Add the user-facing switch and enrollment for **True Whisper**, the experimental camera lip-reading input mode built on the `TrueWhisper` library from RR-450. Read that ticket first.

Placement: a new `SettingsSection("True Whisper", badge: "Experimental")` as the last section of the Speech-to-Text page (`STTSettingsTab`), using the same badge treatment as the Custom Voices section on the Text-to-Speech page. Use the existing `SettingsStack` / `SettingsControlRow` / `SettingsDivider` components.

Config: add `true_whisper: Bool` (default `false`) to `SttConfig`, persisted through `ConfigManager` under `[stt]` in `config.toml`, bound in the tab via the draft/Save/Revert flow like every other setting. Templates are not config: they live in `TemplateStore` (`~/Library/Application Support/relay-runner/true-whisper/templates.json`).

Section contents, top to bottom:

1. Toggle row "Read lips instead of listening" with description: "While Caps Lock is held, Relay Runner turns the camera on and recognises the enrolled words from your mouth. The microphone stays off. Only lip geometry is kept; no video is stored." Toggling on when camera permission is not granted requests it through `PermissionsManager`; if denied, show an inline note with an "Open System Settings" button and leave the toggle as the user set it.
2. Enrollment rows, one per word in the fixed vocabulary `stop`, `cancel`, `play`, `replay`: the word, the number of takes stored, and a "Record" button. Recording runs the spike's hands-free flow for that word: open `LipCaptureSession`, wait for a face, then 10 takes of 1.5 s, each cued by the word spoken through `NSSpeechSynthesizer` (or the `say` process the spike used) followed by "3, 2, 1" and a visible countdown in the row; a take with fewer than 6 frames is discarded and retried. Show progress in the row, and a "Stop" button that aborts and keeps the takes already stored. The camera is released as soon as recording ends.
3. A "Clear all takes" button (with confirmation) that empties the store.
4. A readout row: when at least 2 words have 3 or more takes, run `Evaluation.run(permutations: 100)` off the main thread and show "Accuracy n%, chance m%" and whether it is above chance; otherwise show "Enrol at least two words to test".

The toggle is only effective when at least two words are enrolled; say so in the description when it is not.

Provider parity: none; this is app UI. Motion: use the existing RelayMotion transitions for row state changes, and never overlap swaps.

Live camera access cannot be exercised in the worker environment: macOS attributes a worker's processes to the hosting app, which has no camera entitlement until this work ships. Verify with unit tests and injected frame sources; do not add acceptance items that need a real camera. Drive the enrollment flow through the injected `FrameSource` in tests.
