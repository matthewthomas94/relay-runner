## Description

Background: RR-448 (done) scoped porting the Python services in `services/` to Rust. Read its `## Spike report` first; it holds the inventory, interface list, evidence and staged plan. Use `scripts/relay-ticket-history show RR-448` if the ticket has been archived.

`services/voice_bridge.py` (6,262 lines) with `messenger.py`, `intent_inbox.py`, `intent_arbitration.py`, `intent_qualification.py`, `provider_turn_broker.py`, `pm_frontstage.py` and `relay_remote.py` runs as one process, `voice_bridge.py --config <toml> --relay`. Its tests (`tests/test_voice_bridge_preemption.py` and others) import it and patch module globals, so they cannot check a replacement.

Write `docs/specs/voice-bridge-contract.md` and a suite under `tests/contract/` that starts the bridge command from an environment variable (default: the Python bridge) in a temporary directory, with every path redirected through the documented environment variables (`VOICE_FIFO`, `BRIDGE_CONTROL_SOCK`, `VOICE_STATE_SOCK`, `RELAY_SESSION_SPOOL_DIR`, `VOICE_INTENT_INBOX`, `ORCHESTRATOR_PORT_FILE` and the rest), and with three fakes owned by the suite:

- a fake orchestrator HTTP server that records the calls the bridge makes (`/v1/orchestrator-session/*`, `/v1/messenger/outcomes*`, `/v1/runs`, `/v1/program/status`, `/v1/continuity/observation`);
- fake `claude` and `codex` executables on PATH that speak the messenger protocols (Claude stream-json, Codex `app-server` JSON-RPC) from scripted transcripts;
- a fake speech service speaking the speech protocol.

Cover: every FIFO control token (`__TTS_STOP__`, `__INTERRUPT__`, `__CANCEL__`, `__PLAY__`, `__PLAY_ACK__:`, `__STATUS__:`, `__CONTINUITY__:`, `__VOICE_TARGET__:`, `__SKIP_UNCERTAIN__:`, `__ORCHESTRATOR_REPLY__:`, `__RELAY_COMPLETION__:`, `__PROVIDER_TURN_EVENT__:`, `__TRACE__:`), every control-socket command, the spool files and their claim lifecycle, command sequencing and supersession, multi-item turns and work dispositions, reply delivery and de-duplication between the reply helper and the completion hook, multiple sessions and voice targeting, restart with pending replies, and Relay Remote framing on `/tmp/relay_remote.sock` using the shared vectors that `Sources/RelayRemoteProtocol` tests use.

Map each behaviour asserted by `test_voice_bridge_preemption.py` to a contract case or record why it is internal. Do not change bridge behaviour.

## Acceptance criteria

- [ ] The suite passes against the Python bridge for both providers and imports nothing from `services/`.

- [ ] A table in the document maps the existing preemption tests to contract cases, with gaps named.
- [ ] Replacing the bridge command with a stub that ignores input makes the suite fail.
