## Description

Coordinate note recording as an independent mode of the existing app. Bind immutable project and note identity at start, checkpoint accepted progress incrementally, and publish canonical Markdown through the project writer. The note remains project-owned even while remote sync is offline. A bounded local recovery journal/audio checkpoint is allowed as transient working state, never as a replacement canonical transcript database or a Git audio attachment.

Use durable segment/revision cursors so an interrupted save or repeated callback cannot lose acknowledged transcript text, duplicate it, or recreate a finalized note unexpectedly. Batch artifact revisions at meaningful save/finalization boundaries rather than committing every partial hypothesis. Record the implemented checkpoint cadence, maximum unacknowledged interval, disk budget and replay policy; the UI must distinguish live hypotheses, durably saved content and remote sync.

Foreground work sessions and note-taking are mutually exclusive. Start Note Taker ends the existing foreground work session through its established End Session lifecycle, waits for bridge/audio/TTS/UI ownership to be released, and then begins local note capture. Start Session from either recording or paused note mode stops capture, drains the accepted final tail and durably saves the same note to its original project before launching the requested work session. These explicit start actions authorize the switch without a second confirmation. A save or teardown failure blocks the destination mode and preserves recovery state; remote sync alone does not block a locally saved switch. Unrelated daemon worker runs are unaffected.

One authoritative transition owner serializes mode changes and rejects stale callbacks. Snapshot the destination project when the start action is accepted while retaining the source note's original project. Repeat clicks, project changes, start failures and delayed teardown must never leave both foreground modes active or misfile a note.

Within note mode, actual Caps Lock ON pauses capture and OFF resumes the same note. Paused speech from every source is excluded from both retained audio and later transcription; preserve already accepted content and the pre-pause tail. Pause does not finalize, allocate a new ID or launch an agent. Read the actual key state at startup, so Caps Lock already ON starts paused before accepting audio. Route the key exclusively to the active mode; paused notes still own note mode. Synchronize rapid/repeated changes and restore ordinary work-mode key behavior after teardown.

## Acceptance criteria

- [ ] The coordinator owns the shared foreground mode/transition contract and explicit preparing/recording/paused/stopping/saved/interrupted/error states, immutable note-project binding and idempotent control behavior. Recording states never become ticket workflow statuses; work and note modes cannot be active concurrently.
- [ ] Progress is checkpointed during recording at a documented bounded cadence. Kill/relaunch and injected write-failure tests prove that every acknowledged durable segment remains available and replay does not duplicate text; unacknowledged audio/tail limits are measured and surfaced honestly.
- [ ] Stop waits for the accepted capture/ASR tail, durable Markdown publication and recoverable state update before reporting local completion. Double Stop, late partial/final callbacks and crash at each handoff cannot drop, duplicate or regress committed text.
- [ ] Recover interrupted sessions without requiring Codex, Claude, a bridge or a network. Reconcile the last canonical artifact revision with local checkpoints and offer recover/finalize/discard-incomplete-tail outcomes without deleting already saved notes or silently resuming microphone capture.
- [ ] Daemon restart, materialization conflict, unavailable project path, disk full and remote sync failure preserve the last durable note and recoverable checkpoint. Do not redirect content to the currently selected project or mislabel a failed save as complete.
- [ ] Only bounded local recovery audio is retained when necessary. Successful finalization cleans owned temporary audio; interrupted data remains recoverable under a documented budget/cleanup policy. Raw audio never enters the artifact tree, source repository, diagnostic logs or provider prompts.
- [ ] Switching work-to-note uses existing AppState.endSession/resetActiveSessionState semantics and waits for provider/bridge/audio/TTS/UI teardown before local capture starts. Switching note-to-work from recording or paused drains the final accepted tail and durably saves to the original project before starting the requested work session. No extra confirmation and no cancellation of unrelated daemon-dispatched workers.
- [ ] Tests cover long-session save batching, restart/replay, partial/final revision order, UTF-8 and genuine repeated speech. Report durability and throughput evidence separately from RR-372 physical end-to-end validation.
- [ ] One serialized transition identity handles repeat clicks, rapid alternating starts, destination project changes, asynchronous/stale callbacks, launch failures and save failures. At most one foreground mode owns audio/key/UI resources; failed local save prevents work-session startup, pending remote sync does not, and failed startup never silently starts both or revives the old mode.
- [ ] Caps Lock ON pauses and OFF resumes the same note ID. Synchronize with actual key state at startup and after recovery/route changes; a note started with Caps Lock already ON is paused before accepting audio. Paused audio is neither retained nor transcribed later, while pre-pause content and the note identity survive.
- [ ] Only the active mode handles Caps Lock: the ordinary work-session voice toggle must not also fire in recording or paused note mode. Repeated/rapid changes are idempotent, pause is not finalization, and switching/teardown restores ordinary work-mode behavior without replaying stale key events.
- [ ] Publish recorder-driven presentation state for RR-367: active capture maps to expanded orange listening glyph and Taking notes; paused maps to expanded standard white-only glyph and Paused. Preparing/stopping/error/teardown cannot retain a stale Taking notes state or activate normal session overlays.
