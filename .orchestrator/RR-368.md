## Description

Coordinate note recording as an independent mode of the existing app. Bind immutable project and note identity at start, checkpoint accepted progress incrementally, and publish canonical Markdown through the project writer. The note remains project-owned even while remote sync is offline. A bounded local recovery journal/audio checkpoint is allowed as transient working state, never as a replacement canonical transcript database or a Git audio attachment.

Use durable segment/revision cursors so an interrupted save or repeated callback cannot lose acknowledged transcript text, duplicate it, or recreate a finalized note unexpectedly. Batch artifact revisions at meaningful save/finalization boundaries rather than committing every partial hypothesis. Record the implemented checkpoint cadence, maximum unacknowledged interval, disk budget and replay policy; the UI must distinguish live hypotheses, durably saved content and remote sync.

Foreground work sessions and note-taking are mutually exclusive. Start Note Taker ends the existing foreground work session through its established End Session lifecycle, waits for bridge/audio/TTS/UI ownership to be released, and then begins local note capture. Start Session from either recording or paused note mode stops capture, drains the accepted final tail and durably saves the same note to its original project before launching the requested work session. These explicit start actions authorize the switch without a second confirmation. A save or teardown failure blocks the destination mode and preserves recovery state; remote sync alone does not block a locally saved switch. Unrelated daemon worker runs are unaffected.

One authoritative transition owner serializes mode changes and rejects stale callbacks. Snapshot the destination project when the start action is accepted while retaining the source note's original project. Repeat clicks, project changes, start failures and delayed teardown must never leave both foreground modes active or misfile a note.

Within note mode, actual Caps Lock ON pauses capture and OFF resumes the same note. Paused speech from every source is excluded from both retained audio and later transcription; preserve already accepted content and the pre-pause tail. Pause does not finalize, allocate a new ID or launch an agent. Read the actual key state at startup, so Caps Lock already ON starts paused before accepting audio. Route the key exclusively to the active mode; paused notes still own note mode. Synchronize rapid/repeated changes and restore ordinary work-mode key behavior after teardown.
