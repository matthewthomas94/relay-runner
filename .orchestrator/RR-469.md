## Description

Once the general session is running, let the user open more PM tabs in the Workspace terminal. Each tab is a separate foreground orchestrator/PM agent (Claude or Codex) with the same powers as the first: it can talk through work, write and refine tickets on any registered project's board, dispatch workers and review their results. The goal is several PMs writing tickets at the same time.

Context: RR-445 removed per-project sessions and the per-session terminal tabs (`workspaceSessionTabs`, `closeSessionTab`) in favour of one general session. This ticket brings tabs back in a different form: every tab is another general PM, not a per-project session. `EmbeddedSessionRegistry` (`Sources/relay-runner/Terminal/EmbeddedSessionRegistry.swift`) still has the multi-session model and a soft cap of 4 (`maxConcurrentSessions`). Reuse it where it fits.

Scope:
- A "+" control in the terminal tab strip, shown only while a session is running, opens a new PM tab bound to general-tasks with the same instructions, MCP servers and project scope tokens as the first tab. Tabs can be closed; closing the last tab ends the session, as End does today.
- Each tab has its own provider session id, so its conversation history and resume stay separate.
- Concurrent ticket authoring is safe. Two tabs creating tickets on the same board at the same moment get distinct ids, both tickets land on `relay/artifacts`, and neither write is lost. The canonical artifact writer and `next_id` allocation serialise this. Concurrent dispatches and reviews stay correct too.
- Voice and the messenger follow one rule from Required inputs below. Typed input always goes to the focused tab.
- Worker lifecycle notifications go to the tab that dispatched the run.
- The wheel, notch and Relay Remote show the tabs or keep working without them, with nothing broken.
- Codex and Claude behave the same; any difference is documented.

## Acceptance criteria

- [ ] While a session is running, the user can open at least 3 additional PM tabs, switch between them, and close them; closing the last tab ends the session.
- [ ] Each tab can create a ticket, dispatch it and see its review result without help from another tab.
- [ ] A test runs two concurrent create_ticket calls on the same artifact-backed board; both succeed with distinct ids and both tickets exist on relay/artifacts.
- [ ] Voice turns, replies and TTS follow the routing rule chosen in Required inputs; no reply is spoken twice or from the wrong tab.
- [ ] Worker lifecycle updates reach only the tab that dispatched the run.
- [ ] The tab cap is enforced with a clear message; existing single-tab behaviour, End, Keep Awake, notch and Notetaker are unchanged.
