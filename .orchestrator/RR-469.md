## Description

Once the general session is running, let the user open more PM tabs in the Workspace terminal. Each tab is a separate foreground orchestrator/PM agent (Claude or Codex) with the same powers as the first: it can talk through work, write and refine tickets on any registered project's board, dispatch workers and review their results. The goal is several PMs writing tickets at the same time.

Context: RR-445 removed per-project sessions and the per-session terminal tabs (`workspaceSessionTabs`, `closeSessionTab`) in favour of one general session. This ticket brings tabs back in a different form: every tab is another general PM, not a per-project session. `EmbeddedSessionRegistry` (`Sources/relay-runner/Terminal/EmbeddedSessionRegistry.swift`) still has the multi-session model and a soft cap of 4 (`maxConcurrentSessions`). Reuse it where it fits, and raise the cap to 9.

Scope:
- A "+" control in the terminal tab strip, shown only while a session is running, opens a new PM tab bound to general-tasks with the same instructions, MCP servers and project scope tokens as the first tab. Tabs can be closed; closing the last tab ends the session, as End does today.
- Each tab has its own provider session id, so its conversation history and resume stay separate.
- Concurrent ticket authoring is safe. Two tabs creating tickets on the same board at the same moment get distinct ids, both tickets land on `relay/artifacts`, and neither write is lost. The canonical artifact writer and `next_id` allocation serialise this. Concurrent dispatches and reviews stay correct too.
- **Overall limit of 9 tabs**, counting the first one. The same limit applies however a tab or session is started: the tab strip, the wheel, Relay Remote and Relay App `start_session`. Trying to open a tenth shows a clear message and changes nothing.
- **One active tab.** The user picks the active tab in the tab strip or the wheel. Voice turns, replies and TTS go to the active tab only. Typed input goes to the focused terminal tab.
- **Wheel submenu controls the tabs.** Remove the per-session Play / Replay, Record and Stop session controls from the wheel entirely; they are not relocated. The session slot's hover submenu shows one segment per tab plus tab controls instead: add a tab, remove (end) a tab, and turn a tab off (disabled). Clicking a tab segment makes it the active tab. Removing or turning off the active tab moves the active tab to another live tab. Add is disabled at 9 tabs.
- **Submenu size.** With 3 tabs or fewer the submenu keeps its standard size over its own cell. With more, it grows along the arc past its own cell and wraps around as far as the far ends of the History and Workspace cells, enough to hold all 9 tabs at once. Those cells have no submenus of their own, so nothing clashes. Keep the existing liquid submenu morph, Reduce Motion behaviour, VoiceOver labels and keep-the-wheel-open behaviour, and update `docs/session-wheel.md`.
- Worker lifecycle notifications go to the tab that dispatched the run.
- The wheel, notch and Relay Remote show the tabs or keep working without them, with nothing broken.
- Codex and Claude behave the same; any difference is documented.

## Required inputs

- [x] Voice routing: voice goes to the active tab, which the user picks in the wheel or tab strip.
- [x] Provider per tab: every tab uses the provider set in Settings; there is no per-tab provider choice.
- [x] Tab limit: 9 in total, enforced everywhere.
