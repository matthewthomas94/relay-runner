## Description

Improve the visual design and scanability of Program Board ticket cards now that the board can show tickets from all registered projects.

RR-57 made the Program Board show Backlog, Ready, In progress, and Done lanes across all projects or a selected project. The first version is functional, but the cards need a dedicated styling pass so multi-project ticket lists feel deliberate, compact, and easy to read.

Keep this as a styling/refinement ticket, not a behavior rewrite. The design should preserve the existing Relay Runner visual language while making ticket identity, project context, status, priority, dependencies, worker state, and provider metadata easier to scan.

The intended card structure is compact and text-led: show the project name first, such as `Relay Runner`, with the ticket id on that same identity line, such as `RR-13`; put the ticket title on its own line; and reserve the bottom of the card for a short state/status description. Avoid repeating the lane name on every card when the card already lives inside the corresponding lane.

## Acceptance criteria

- [ ] Program Board ticket cards have a clear visual hierarchy for project, ticket id, title, state, priority, dependency/blocking hints, provider, and run/branch metadata.
- [ ] The card identity line shows the project name and ticket id together, for example `Relay Runner` and `RR-13`, without requiring the full repo path in normal cases.
- [ ] The ticket title sits on its own line and remains readable at dense Program Board widths.
- [ ] The bottom of the card includes a concise state/status description when useful, but does not redundantly repeat the lane name on every card.
- [ ] The All-project view makes project context visible without overwhelming project-filtered views.
- [ ] Backlog, Ready, In progress, and Done lanes remain visually consistent with each other and with project-board conventions.
- [ ] Long project paths, long titles, and dense metadata truncate or wrap cleanly without overlapping adjacent content.
- [ ] Empty states and loading/error states still match the refreshed card/column styling.
- [ ] The styling is restrained and work-focused, with no decorative clutter or oversized marketing-style elements.
- [ ] Snapshot, view-model, or deterministic layout tests cover the core card states if the repo has an existing suitable pattern; otherwise document the manual verification path in the run log.
- [ ] Provider metadata for Codex and Claude appears consistently and does not dominate the card.
