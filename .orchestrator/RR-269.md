## Description

Run a time-boxed architecture and product spike for a local-first speech-to-text meeting notes app comparable in workflow to Granola, using the MIT-licensed Anarlog project as the primary open-source reference: https://github.com/fastrepl/anarlog.

Anarlog currently describes itself as a maintained, local-first meeting notetaker built with Tauri, Rust, React, and TypeScript. Its canonical meeting data is stored in local SQLite, transcription can run on-device, Markdown export is supported, and AI processing can use local or bring-your-own providers. Inspect the current upstream source and pin the commit or release used for the assessment rather than relying only on the README.

Define the smallest coherent product: start and stop a recorded session; capture the required microphone and meeting/system audio with explicit macOS permissions and recording state; transcribe locally; let the user take notes alongside the transcript; preserve timing and speaker context where feasible; generate optional post-session notes with a user-selected local or remote model; browse, search, edit, export, and delete locally stored sessions; and recover safely from interrupted capture or transcription.

Evaluate four product and code-ownership strategies: fork Anarlog; selectively reuse its MIT-licensed crates or subsystems; use it only as an architectural reference while building a separate native macOS app; or integrate a bounded notes surface into Relay Runner. Recommend whether the resulting product should live in its own Git repository and how it should appear inside the Relay Workspace without coupling its private meeting data to Relay ticket repositories.

This spike intentionally defers Git/GitHub synchronization, cloud backup, collaboration, and the broader cross-app project-memory/source-management model. It should define only the minimum stable local identifiers, canonical data boundaries, and export seam needed to avoid blocking a later storage design. Do not implement production features or choose a cloud scheme in this ticket.

**Recommended next steps**

- Have the PM obtain an immutable Anarlog source bundle with commit SHA, capture date, LICENSE/notices, lockfiles, model manifests, release/CI files and recent commit/release metadata for another bounded review. Trace capture→VAD→ASR→timed segments→SQLite→editor/search/export, plus model downloads, AI egress, permissions and packaging. Require source-path citations before choosing forked or extracted code.
- MVP journey: create a session; verify the selected local model and microphone/meeting-audio sources; acknowledge recording; Start; see live transcript and autosaved manual notes side by side; Stop both capture streams while final transcription finishes. Offer optional generated notes separately. History supports title/date browsing, local text search, transcript/note corrections, Markdown export and explicit deletion. Missing models permit notes-only use, never silent remote STT.
- Capture contract: the signed app owns microphone and the selected system-audio permission flow. Explain each source and require recording-consent acknowledgment; do not imply this obtains other participants' consent. Show persistent recording state, duration, source meters and Stop even when the main editor closes. Denial/revocation must name the missing source and offer explicit mic-only or notes-only mode; never silently claim a complete meeting. No automatic recording on launch or recovery.
- Local model: UUIDs identify Session, Segment, Note, Speaker, Attachment and Summary independently of titles, paths or tickets. Session holds UTC start/state; segments hold session/source IDs, monotonic start/end offsets, order and text/corrections; notes hold Markdown and optional segment anchors. Speakers are session-local labels, initially unknown; a microphone/system channel is not a person's identity. Attachments reference owned relative media paths. Summaries retain input revision and model/prompt provenance.
- Recovery: journal bounded audio chunks and commit transcript/note checkpoints atomically. Separate capture state from transcription/generation jobs; retain ordered source offsets and gap markers. On restart mark active sessions interrupted, recover durable chunks, and resume ASR idempotently without duplicates or overwriting user edits. Require explicit capture restart. Test process kill, disk-full, sleep, permission loss and route changes; acknowledge that unwritten audio cannot be recovered.
- Privacy/retention proposal: keep transcripts/manual notes until deletion; raw audio is temporary through final transcription unless Keep audio is chosen. Give interrupted audio a visible seven-day recovery expiry. Delete stops pending jobs and removes owned media, transcript, notes, summaries, search entries and temporary data without resurrection. Account for SQLite WAL/free pages; do not promise secure SSD erasure or deletion of user exports, OS backups or provider copies. Exclude content from logs/telemetry.
- Export seam: UTF-8 Markdown with format version, stable session ID, title, UTC date, manual notes, timed/source-labelled transcript and separately labelled generated summary/provenance. Include stable segment anchors and optional relative attachment references; audio is excluded by default. Let the user choose the destination and content. SQLite remains canonical; export is a portable snapshot, not synchronization, and must not automatically become a Relay artifact.
- AI contract: generation is optional, with a chosen installed local model or BYO remote endpoint/model. Show exactly which transcript/notes leave the Mac, to whom and why; exclude raw audio/attachments by default and protect credentials separately. Never silently fall back to remote. Offline failure preserves capture, notes and export. Codex/Claude must share consent, bounded input/output, cancellation and error behavior, using isolated tool-free generation rather than existing agent conversation context.
- Model lifecycle: select a model before capture, disclose license/download bytes/disk needs, verify pinned artifacts and report progress/cancel/failure. Treat weights/cache as replaceable assets separate from canonical sessions. Missing or failed models retain manual notes and recoverable audio under the declared policy. Downloading a model is distinct from sending meeting content; local mode must not upload that content. Benchmark language coverage before advertising support.

Record pinned app/model/OS, cold/warm p50/p95 latency, real-time factor, WER/name/overlap and speaker errors, CPU/GPU, peak memory, download and installed bytes. Run a sustained meeting-length capture with mic plus meeting audio; test speakers, wired/Bluetooth devices, route changes and interrupted recovery. Publish measurements, not polling estimates.

Set numeric latency, quality and memory budgets before benchmarking. Until those gates pass, retain further-evidence rather than a go decision.
