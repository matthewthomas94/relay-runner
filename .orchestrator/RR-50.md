## Description

Make board opening behavior match the new workspace/project distinction.

When the active session is a single project repo, the board should continue opening that repo's `.orchestrator/` board. When the active session is a workspace root, the board should open the Program Board across discovered child projects instead of trying to initialize a parent project board.

If a folder could be both a parent repo and a workspace root, prefer the explicit workspace-root registry entry. The parent repo can still be activated as a project through an explicit project activation path.

Provider parity matters. Board routing should not depend on whether the active session was launched by Codex or Claude.

## Acceptance criteria

- [ ] Board toggle opens a project board for active single-project repos.
- [ ] Board toggle opens the Program Board for active workspace roots with discovered projects.
- [ ] Workspace-root board routing does not create or require a parent `.orchestrator/`.
- [ ] Ambiguous parent repo plus child repos prefers the explicit workspace-root registry state.
- [ ] Explicit activation of the parent repo as a project still allows opening its project board.
- [ ] Codex and Claude sessions route to the same board type for the same active workspace/project state.
- [ ] Tests or targeted UI verification cover project board, Program Board, and ambiguous parent repo cases.
