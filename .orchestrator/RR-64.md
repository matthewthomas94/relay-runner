## Description

Make Program Board ticket cards draggable between lanes where the move is valid for the owning project.

The Program Board currently shows tickets across Backlog, Ready, In progress, and Done, but the cards cannot be dragged the way users expect from board surfaces. Dragging should route through the owning child repo and the same ticket-state paths as the project board, preserving dispatch semantics and dependency safety.

Do not make the Program Board a separate source of truth. It should mutate the child ticket file through the existing daemon/project mechanisms and then refresh the aggregate view.

## Acceptance criteria

- [ ] Program Board tickets can be dragged between lanes when the target state transition is valid for the owning project.
- [ ] Dropping a ticket uses the owning child repo and existing project-board state mutation path; no parent workspace `.orchestrator/` is created.
- [ ] Dragging a backlog ticket to Ready preserves the normal ready/dispatch semantics, including dependency and stale-command guards.
- [ ] Invalid moves are visibly rejected or disabled instead of silently failing.
- [ ] The board refreshes or patches the affected lane data after a successful drop.
- [ ] All-project and selected-project views both resolve drag/drop operations to the correct child repo.
- [ ] Tests or deterministic view-model coverage prove valid moves, invalid moves, and cross-project resolution.
