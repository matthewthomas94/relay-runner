## Description

On the Mac, starting to record is the interrupt: pressing Caps Lock writes `__TTS_STOP__` before capture starts. On the phone this does not happen. `VoiceController.pressToTalkBegan()` (`ios/RelayRemote/Voice/VoiceController.swift:66`) only sets `isListening` and calls `openUtterance()`; it never calls `queue.stopAll()` or `synthesizer.stopSpeaking()` and sends no `control` frame, so the reply keeps playing over the user. Two related faults: `openUtterance` (:127) opens the recogniser while speech is playing, and `recognizer.pauseFeeding()` runs only when playback starts after an utterance is already open (:208-211), so the phone can transcribe its own reply.

The user's rule: **interrupt is not a button**; starting to talk interrupts, exactly like the Mac. Stop, replay and cancel stay as explicit controls.

Work:

1. `pressToTalkBegan()` (and the equivalent start in the hands-free Listen mode) first stops local playback (`SpeechPlaybackQueue.stopAll()` and the synthesiser), then sends `control .stop` through `RemoteSession.send(control:)` so the Mac runs `stop_playback(reason="recording_barge_in")`, then opens the utterance. If the channel is down the local stop still happens.
2. Never feed the recogniser while the phone is playing speech: pause feeding for the whole playback window regardless of ordering, resume when playback ends, and drop any audio captured during playback.
3. Frames for the interrupted reply remain available for Replay (do not purge the last reply on stop).
4. Tests in `RelayRemoteKitTests/SpeechPlayback` and the app's `RelayRemoteTests`: starting push to talk during playback stops the queue, emits exactly one `stop` control, opens the utterance afterwards, and the recogniser receives no audio while playback is active; Replay after an interrupt replays the interrupted reply.

Physical-device checks cannot run in the worker environment. Cover behaviour with the kit, app, Python and Swift unit tests plus the existing loopback tests, and name the manual iPhone check for the user in the run log; do not mark acceptance that needs the phone as verified.

## Acceptance criteria

- [ ] Starting push to talk (or hands-free listening) while a reply is playing stops playback locally and sends one `control stop`; the utterance opens only after the stop (tests).
- [ ] The recogniser is paused for the entire playback window regardless of whether the utterance opened before or after playback began (tests).
- [ ] Replay after an interrupt replays the interrupted reply (test).
- [ ] No new control action is added to the protocol; `interrupt` remains unused by the phone.
- [ ] Kit and app tests pass; run log names the manual iPhone check (talk over a long reply, confirm it stops and the transcript contains only the user's words).
