## Description

Audit and prepare Relay Runner for public open-source release without publishing
it yet. A clean reader should understand the product, trust its privacy claims,
build it, install it, and know the supported Codex and Claude workflows. Preserve
the repository's existing release pipeline rather than creating a second one.

## Acceptance criteria

- [ ] Source, documentation, fonts, icons, models, bundled services, third-party packages, and release artifacts have compatible and documented licensing.
- [ ] Repository history and current files contain no credentials, private endpoints, personal data, machine-specific paths, or unintended local artifacts.
- [ ] README installation, requirements, architecture, privacy, permissions, supported providers, limitations, and build-from-source instructions match the current release.
- [ ] Codex and Claude setup, authentication, model/effort choices, and provider-specific limitations are accurate and intentional.
- [ ] A clean checkout passes the documented build and relevant test/preflight paths.
- [ ] Contribution, issue, security-reporting, support, and release expectations are explicit at an appropriate level for an early project.
- [ ] The public default branch, tags, release assets, update feed, and repository links are internally consistent.
- [ ] Publication, tag creation, release creation, and external announcements remain separate deliberate actions.
