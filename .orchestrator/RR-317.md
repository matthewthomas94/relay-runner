## Description

Fix the final session-controls tutorial handoff after a fresh installed build containing RR-316 still failed physical UAT. The attached sequence shows the tutorial text disappear, the full-size black shell remain on screen, and Workspace content appear in that same uninterrupted expanded presentation. The user correctly reports that the view never visibly closes between the tutorial and Workspace.

The production event route in `AppState` explains why RR-316's delayed opener did not change the visible result. When `sttEngine.boardToggleRequested` arrives on the final tutorial lesson, the polling loop currently calls `toggleBoard(allowDuringFirstRun: true)` first. That immediately presents the real Workspace panel. Only after that succeeds does it call `onboarding.noteTutorialWorkspaceToggled()`, which dismisses the tutorial and schedules RR-316's delayed `showWorkspaceWork()`. One second later `showWorkspaceWork()` finds Workspace already visible, so its normal reveal is a no-op. The existing controller tests exercise the isolated onboarding callback and therefore miss this earlier Workspace presentation.

Treat the final tutorial double-tap Shift as a consumed tutorial event. While `isAwaitingTutorialWorkspaceToggle` is true, do not call the ordinary Workspace toggle at all. Send the gesture only to `noteTutorialWorkspaceToggled()`. That controller must finish the actual tutorial `BoardOverlayPanel` dismiss animation and order it out, preserve the one-second interval added by RR-316 with no Relay Runner full-screen panel visible, then invoke the existing normal `showWorkspaceWork()` route so Workspace creates/presents its own panel and performs the complete closed-to-open reveal. Outside the final tutorial gate, preserve the existing double-tap Shift behavior unchanged.

Do not solve this by swapping content inside an already-expanded shell, making the black surface transparent, shortening the delay, or adding another timer before the eager toggle. Keep the ordered lifecycle explicit and exactly once. Preserve onboarding flags, Redo Onboarding, failure recovery, normal Workspace hotkeys, provider parity, and Reduce Motion.
