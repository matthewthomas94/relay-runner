## Description

Prevent the Program Board from failing after an app update when the Swift UI and bundled Python orchestrator service are out of sync.

Observed after the Program Board lane work landed: the board UI requested the new `backlog_lane`, `ready_lane`, `in_progress_lane`, and `done_lane` program-status queries, but the live orchestrator daemon returned HTTP 400 with the old supported query list (`active_work`, `ready_work`, `blocked_work`, `awaiting_merge`, `stale_runs`, `summary`, `next`). The `.app` bundle on disk already contained the updated `services/program_status.py`; restarting the orchestrator daemon fixed the endpoint immediately.

Manual recovery used:

```bash
/Applications/Relay\ Runner.app/Contents/SharedSupport/scripts/relay-orchestrator --stop
/Applications/Relay\ Runner.app/Contents/SharedSupport/scripts/relay-orchestrator --start
```

The product should not require that manual step on the next build. Add a robust install/launch/update path so the daemon serving `/v1/program/status` is refreshed when bundled service code or supported query schema changes.

Provider parity matters: Codex and Claude sessions share the same orchestrator daemon, so the refresh/restart behavior must be provider-neutral and should not depend on which agent launched the app or bridge.

## Acceptance criteria

- [ ] A new app build or reinstall cannot leave the Program Board UI talking to an older live orchestrator daemon that rejects bundled-supported queries such as `backlog_lane`.
- [ ] Relay Runner detects a bundled service/schema version mismatch, or otherwise restarts/reloads `com.relay.orchestrator`, before the Program Board depends on new daemon behavior.
- [ ] The recovery path is safe around active worker runs: it either preserves/rehydrates run state after daemon restart or clearly defers restart while workers are active.
- [ ] Program Board refresh handles the transient daemon restart state gracefully instead of surfacing a raw HTTP 400 unknown-query error.
- [ ] Deterministic tests cover a stale-daemon/schema-mismatch scenario and prove the board/status path succeeds after the refresh logic runs.
- [ ] The fix is provider-neutral for Codex and Claude sessions and does not patch the installed `.app` bundle by hand.
