## Description

Implement RR-273 delivery phase 9 and run RR-270's complete automated and manual verification strategy against a signed installed build. Add or complete the disposable two-device remote harness, failure injection, permission/access recovery, retention/archive/restore, dirty-source isolation, provider-parity, migration/rollback, fresh-install/reset recovery, and mounted Workspace UI coverage.

Rollout remains evidence-gated: first an explicit per-project opt-in, then default enablement for newly registered projects only, then an offered legacy migration after safety evidence and operational recovery documentation are accepted. Do not enable a later cohort merely because source tests pass. Record exact external blockers as verification-blocked rather than forcing completion.

## Rollback boundary

Every rollout cohort has an independent kill switch that stops new artifact writes/sync only after draining or safely freezing active work. Rollback preserves repositories, artifact refs/history, registry backups, and migration journals and never silently downgrades or discards canonical data.

## Verification plan

Run source suites first, then package and sign the supported build, execute disposable two-device and failure-injection harnesses, perform fresh-install/reset recovery, and capture installed/mounted UI and provider-parity evidence. Source-only success cannot satisfy the installed gate.
