## Description

Fix a mounted regression where an ordinary orchestrator progress reply reaches the **Double tap Control to cancel** playback pill already truncated with an ellipsis. The captured pill displayed `I found three verification-blocked tickets. I am separating their real-world evidence require…` instead of the complete public progress text.

RR-298 preserved full detail for protected lifecycle outcomes while deliberately retaining a compact ordinary-progress path. Extend the contract so compact notch/status text can remain bounded without irreversibly shortening the only user-visible playback/display copy. Also keep progress semantically distinct from an authoritative final: if a final is absent or suppressed, Option replay must not relabel an ellipsized progress fragment as the completed answer.

## Acceptance criteria

- [ ] A regression test reproduces an ordinary public progress message longer than the compact trace limit and proves the current response-pill payload ends with an upstream ellipsis.
- [ ] The event contract carries separate bounded summary and complete validated public detail fields for ordinary audible progress, as it already does for protected lifecycle detail, without exposing private provider or transcript content.
- [ ] Compact notch, status, and list surfaces remain bounded, while the playback pill receives the complete progress text and uses its existing wrapping, scrolling, and teleprompter behavior without an upstream ellipsis.
- [ ] Retained replay preserves the event's semantic role. A progress event cannot be relabeled or presented as an authoritative final merely because no later final was accepted.
- [ ] A missing, stale, interrupted, or suppressed final produces the correct source-command-scoped outcome; it neither discards an eligible complete final nor promotes a lossy progress delta into a completed answer.
- [ ] Newer-command invalidation, cancellation, semantic deduplication, handoff/progress/final ordering, and explicit Option replay remain exact-once.
- [ ] Swift coverage verifies long playback-pill content is complete and accessible at constrained widths; Python coverage verifies full-detail persistence and Messenger/speech realization for both Codex and Claude.
- [ ] A mounted check captures the complete long progress text in the playback pill and confirms its spoken/replayed content matches the retained complete public message.

## Live regression evidence

- The clipboard screenshot shows the mounted playback pill truncating the progress sentence with `require…` while playback is active.
- Speech evidence records the retained item as lifecycle progress with `suppression_reason: lossy_delta`; no authoritative final for the source command appears in the delivery chain.
- Explicit replay then presents that retained progress item through a fallback-final path, making this distinct from the queued-input failure.
