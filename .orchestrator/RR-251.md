## Description

Make the session-controls onboarding practice exchange fully local and deterministic so it teaches recording, send, play, replay, and cancel without launching a Codex or Claude session or waiting for a messenger/orchestrator response. During the tutorial’s “say hi” recording step, accept any non-empty spoken content as completion input but do not publish it to the Relay voice command path. Immediately inject the fixed tutorial reply `Hello, how are you?` into the existing local TTS/message-waiting flow. The first Option double-tap should play that reply. When initial playback finishes and the tutorial advances to the replay/cancellation lesson, the next Option double-tap must both surface the replay/cancellation pill and immediately restart the same audio on that single gesture; it must not consume one gesture for UI state and require a second gesture for playback. Control double-tap should then stop playback and advance the tutorial. Keep microphone/STT and TTS behavior real so users practice the actual controls, while isolating all provider, bridge command, ticket, and external side effects. Apply the same behavior for Codex and Claude.

## Acceptance criteria

- [ ] Entering the session-controls tutorial does not start or require a Codex or Claude provider session, messenger process, orchestrator session, or Relay voice-command consumer.
- [ ] The tutorial can begin recording through the normal Caps Lock control using local microphone/STT behavior even when no provider session is running.
- [ ] When the user sends any non-empty tutorial recording, its transcript is consumed only by the tutorial and is never written to the voice command inbox, FIFO, ready prompt, provider stdin, intent classifier, or ticket workflow.
- [ ] After tutorial send, the local message-waiting state deterministically contains exactly `Hello, how are you?` without invoking a model or network-backed service.
- [ ] The first Option double-tap plays the deterministic reply through the normal local TTS path.
- [ ] After initial playback completes, one Option double-tap both presents the replay/cancellation pill state and immediately restarts the same deterministic reply; no second Option gesture is required.
- [ ] The replay gesture is delivered exactly once: it does not double-start playback, leave a stale play request, or advance the tutorial twice.
- [ ] Control double-tap during the cancellation lesson stops active playback through the normal control path and advances the tutorial.
- [ ] Tutorial startup and response latency no longer depend on provider authentication, model warmup, bridge readiness, or messenger availability.
- [ ] Outside the active onboarding tutorial, session startup, recording delivery, messenger/orchestrator behavior, ordinary TTS replay, and control gestures remain unchanged.
- [ ] Codex and Claude follow the same local deterministic tutorial path.
- [ ] Focused tests prove no provider/session launch and no command publication, assert the exact deterministic message, reproduce the first-tap-pill-without-playback regression, verify single-gesture replay, and cover send/play/replay/cancel plus tutorial resume behavior.
