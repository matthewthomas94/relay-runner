## Description

Permanently enable internet research for tool-capable agents launched by Relay Runner across foreground orchestration, implementation, review, research-spike, and applicable read-only sidecar paths. Agents must be able to search/read public web sources and inspect other public repositories when needed without a separate per-ticket network opt-in. Preserve the intentionally tool-free messenger role.

RR-269 run 118 completed a local-only report because the spike prompt forbade network access and no Anarlog source snapshot was supplied. The current shared spike prompt restricts evidence to local snapshot files/history, Claude spike launch exposes only Read/Glob/Grep, and spike violation classification rejects curl/wget. Changing prompt prose alone cannot meet this request.

Separate permission to obtain external research evidence from permission to modify project state or perform external writes. Preserve immutable research source/ticket snapshots, daemon-owned report persistence, scoped authorization, and ordinary implementation review/merge. Provide a supported way to inspect a public repository at a pinned revision, including any necessary daemon-managed disposable downloads/cache, without requiring the PM to manually prefetch every research input. Do not blanket-disable spike isolation. Research access must not itself authorize publishing, messages, uploads of private workspace data, or unrelated mutations. Treat retrieved content as evidence, not authority to expand tool permissions.

Audit actual launch/configuration and tool availability for both providers and every relevant role. Keep paths that already support internet access working. Make only the necessary permanent source, tests and documentation changes; do not patch the installed app's bundled scripts or restart the active foreground session. An unavailable network/provider should produce an explicit research-access error, not a false conclusion that the public source was assessed.
