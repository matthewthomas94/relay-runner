## Description

Every Relay Runner board should use a ticket prefix derived from the active repo name. A new repo named `mouse-assist` should mint `MA-1`, not `RR-1`; a repo named `client_dashboard` should mint `CD-1`; a single-word repo should use a stable short prefix from that word. `RR-*` is appropriate for this `relay-runner` repo, not as a generic fallback for every board.

RR-21 added repo-derived prefix initialization for fresh git repos, and `BoardProjectConfig.derivedPrefix(forRepoNamed:)` already has focused coverage. This ticket makes the invariant explicit across the broader session-initialization work: every path that creates or repairs a board-ready project must derive the prefix from the active repo/directory name unless the user intentionally overrides `.orchestrator/config.toml`.

This depends on RR-33 because non-git or not-yet-board-ready session recovery needs a defined project/repo name before prefix derivation can be verified end to end.

## Acceptance criteria

- [x] Fresh board initialization derives `prefix` from the active repo name rather than hard-coding `RR`.
- [x] The RR-33 board-ready recovery path, including any non-git repo initialization flow, uses the same prefix derivation rule.
- [x] Hyphenated and underscored names use word initials, such as `relay-runner -> RR`, `mouse-assist -> MA`, and `client_dashboard -> CD`.
- [x] Single-word names use a stable short alphanumeric prefix, and empty/non-alphanumeric names use a documented safe fallback.
- [x] Existing repos with a valid `.orchestrator/config.toml` preserve their configured prefix and `next_id`.
- [x] User-facing docs or copy avoid implying all tickets are `RR-*`; examples either use repo-specific prefixes or clearly identify `RR-*` as this repo's example.
- [x] Tests cover prefix derivation through board/project initialization, not only the pure helper function.
