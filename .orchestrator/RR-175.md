## Description

Improve the naturalness and overall quality of Relay Runner's spoken TTS output.
Establish a representative baseline for the current Kokoro path, compare
on-device improvements against the same material, and create a separate
implementation ticket once the preferred direction is supported by evidence.
STT recognition quality is explicitly out of scope.

## Acceptance criteria

- [ ] Representative narration, short responses, technical language, numbers, and punctuation samples plus listening criteria are recorded before alternatives are compared.
- [ ] The current Kokoro TTS path is baselined for naturalness, intelligibility, consistency, expressiveness, latency, memory, download size, privacy, and packaging constraints.
- [ ] Candidate improvements are evaluated on-device against the same inputs rather than selected from reputation alone.
- [ ] The preferred direction, tradeoffs, and rejection reasons are documented.
- [ ] A cold-start-ready implementation ticket is created only after the target and evidence are clear.
- [ ] Codex and Claude voice-session behavior remains equivalent.
