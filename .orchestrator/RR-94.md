## Description

Add a dynamic-island-style activity surface on the left side of the camera bump/notch. The user wants it to feel like the camera bump expands leftward to show very concise status updates about what Relay Runner or the active agent is doing in the background.

Keep the text short, roughly three or four words, and avoid raw terminal commands. This should be a glanceable companion to existing terminal/worker status surfaces, not a verbose log. Examples of the intended level of detail include states such as listening, transcribing, dispatching worker, running tests, waiting on dependency, or speaking response.

Build on the notch-adjacent placement/status work from RR-93 where practical. Provider parity matters: Codex and Claude sessions should feed equivalent concise activity updates into the surface, with provider-specific launch details kept out of the short display copy.

## Acceptance criteria

- [ ] A compact activity capsule can appear to the left of the camera notch on supported displays.
- [ ] The capsule expands/contracts or otherwise presents as notch-adjacent without occluding menu bar items, system indicators, or the camera notch area.
- [ ] Display text is concise, human-readable, and roughly three to four words; raw shell commands and long agent internals are not shown.
- [ ] The surface updates for the key Relay Runner states that users need background confidence for, including listening/recording, transcription or send, worker/agent activity, waiting, and response playback where those states are available.
- [ ] Codex and Claude sessions use equivalent activity wording and behavior unless an intentional provider-specific limitation is documented.
- [ ] Reduced-motion, multi-display, and non-notched Mac behavior is handled intentionally.
- [ ] Add focused tests for activity-to-short-label mapping and any unit-testable placement/state logic, plus manual verification notes for the notch animation if direct UI automation is not practical.
