## Description

Stream concise, public foreground-agent activity to the notch while the main agent is actively handling a command, and make that main-agent activity take precedence over sub-agent or worker activity. The user should see what the foreground agent is doing when it is reading, reviewing, creating tickets, dispatching, merging, testing, or otherwise performing meaningful work.

Plain bridge monitoring must stay quiet. If the foreground agent is only waiting for the next Relay command, do not show a monitoring activity trace in the notch. In that idle state, the existing worker/sub-agent activity stream should remain eligible to show in the notch.

Keep the stream curated and safe: do not expose raw shell commands, hidden reasoning, full transcripts, secrets, or noisy low-level metadata. Reuse the existing Relay trace/notch pathways where possible rather than introducing a new transport.

## Acceptance criteria

- [ ] Foreground main-agent work can publish short notch activity labels for meaningful work phases such as reading project context, creating or updating tickets, dispatching workers, reviewing runs, merging branches, running tests, building, installing, and preparing a response.
- [ ] Main-agent activity takes precedence over worker/sub-agent activity while it is active or still fresh enough to be useful.
- [ ] Idle bridge monitoring, heartbeat refreshes, and waiting for the next voice command do not appear as notch activity.
- [ ] When the main agent is idle or only monitoring, existing worker/sub-agent activity can still appear in the notch.
- [ ] Public trace messages are bounded and sanitized: no raw commands, raw tool output, hidden reasoning, secrets, or full voice transcripts.
- [ ] Codex and Claude use the same activity categories, precedence rules, and safety filtering even if their underlying agent hooks differ.
- [ ] Stale voice-command protection remains intact: activity from an older claimed command must not overwrite newer command status.
- [ ] Tests cover main-agent-vs-worker precedence, idle-monitoring suppression, worker fallback, and trace sanitization/normalization.
- [ ] Build and relevant Swift/Python tests pass.
