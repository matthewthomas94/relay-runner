## Description

Make committed ticket creation a core Relay workflow guarantee. When an agent is
asked to write or refine a Workspace ticket, it must create or update the
ticket, update the ID counter when minting a new ticket, and commit that
complete ticket-authorship change before reporting the ticket as written or
available on the board. The user should not need to separately ask for a
commit, including when the author is operating from a worktree.

Keep ticket authoring distinct from promotion and dispatch. A newly written
ticket remains in Backlog unless the user explicitly asks to queue or dispatch
it. Before committing, recheck the repository state so an author does not stage
or commit another agent's unrelated changes. On a conflict or dirty overlap,
report the blocker rather than broadening the commit.

## Acceptance criteria

- [ ] A ticket-authoring workflow creates the ticket file and updates the monotonic ID counter in one intentional commit before reporting completion.
- [ ] The same behavior applies when a ticket is authored or refined from an isolated worktree.
- [ ] A newly authored ticket remains in Backlog unless the user explicitly requests promotion; committing does not queue or dispatch it.
- [ ] Before staging, the workflow checks repository status and stages only the ticket and required counter change; unrelated changes are preserved.
- [ ] A dirty overlap, failed commit, or ID conflict produces a clear blocker instead of an incomplete ticket-complete report.
- [ ] Codex and Claude authoring paths follow the same contract.
- [ ] Focused workflow tests or deterministic coverage verify the commit boundary, Backlog default, ID-counter update, worktree behavior, and unrelated-change protection.
