## Description

When the foreground orchestrator queued `RR-118`, the ticket was manually assigned `worker_model: balanced` and `worker_effort: medium`. That bypassed the user's Relay Runner settings:

- `general.subagent_sizing_policy = "user_default"`
- `general.subagent_model = "strong"`
- `general.subagent_effort = "xhigh"`
- `general.model = "gpt-5.5"`
- `general.orchestrator_effort = "xhigh"`

The queueing path should not silently choose generic sizing when Relay Runner is configured to use the user's defaults. Investigate the foreground ticket promotion and board/voice queueing flows so they resolve the configured subagent defaults consistently before a ticket is promoted to `ready` or dispatched.

This should cover Codex and Claude parity. Codex renders effort through `model_reasoning_effort`; Claude renders effort through `--effort`, and any provider-specific differences must remain explicit.

## Acceptance criteria

- [ ] A ticket queued from voice/foreground orchestration with `subagent_sizing_policy = "user_default"` receives the configured `subagent_model` and `subagent_effort`.
- [ ] The same configured defaults are used whether the ticket is promoted through the Program Board UI, voice command flow, or supported local queueing path.
- [ ] The queueing path does not overwrite an explicit per-ticket sizing decision when one is already present intentionally.
- [ ] Codex and Claude provider differences are documented or encoded in tests where relevant.
- [ ] Add or update regression tests covering user-default sizing resolution for queued tickets.
