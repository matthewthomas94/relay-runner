## Description

Represent an agent actively working on a ticket with an animated, amorphous
dot-matrix halo behind that ticket's card in Workspace.

Match the attached design: the active card remains a solid, legible black
surface while a soft blue-purple field of animated dots blooms beyond its
edges. The field should feel organic and alive rather than like a fixed
rectangle, but it must stay visually subordinate to the ticket content.

Reuse Relay Runner's existing `ParticleFieldRenderer` dot grid, palette, and
wave language from the STT/TTS overlays. The reference uses the blue-purple
TTS treatment. Share the real renderer or extract a reusable localized
primitive; do not copy the grid math, colors, or animation into a second
lookalike implementation.

Drive the effect from authoritative worker activity, not lane placement alone.
An item should glow only while `ProgramStatusItem.hasActiveWorker` is true.
Tickets that are merely in the In progress lane but are awaiting review,
stalled, failed, canceled, or no longer owned by a live worker must not keep
the active animation.

## Acceptance criteria

- [ ] A ticket with `hasActiveWorker == true` renders the attached design's animated blue-purple dot-matrix halo behind its card.
- [ ] The halo reuses the shared particle-field grid, TTS palette, highlight, and organic wave motion; no separate hard-coded dot renderer or copied palette is introduced.
- [ ] The opaque ticket card and all text, badges, activity copy, buttons, hover states, and selection states remain legible and interactive above the effect.
- [ ] Dots bloom beyond the card edges in an amorphous shape, remain clipped to the owning work column, and never overlap neighboring columns or obscure another card.
- [ ] The effect begins when authoritative run state becomes active and fades out promptly when the worker leaves the active state.
- [ ] Awaiting-review, stalled, failed, canceled, queued, backlog, and done tickets do not animate solely because they appear in or previously occupied the In progress lane.
- [ ] Multiple simultaneously active tickets each receive the treatment without shared-state flicker, incorrect card association, or one card stopping another card's animation.
- [ ] Scrolling, rapid status refreshes, selection, editing, and drag behavior do not leave orphaned particle layers, duplicate render loops, or stale halos attached to reused cards.
- [ ] Closing Workspace or moving all active cards off screen suspends unnecessary rendering, and the implementation avoids an independent high-frequency timer per visible card.
- [ ] Reduce Motion presents a stable, non-pulsing dot-matrix halo that still communicates active work.
- [ ] Single-project and Program Workspace routes use the same active-card treatment.
- [ ] Accessibility exposes the existing active-worker state without adding noisy announcements for animation frames.
- [ ] Automated tests cover active versus lane-only state, fade lifecycle, multiple active cards, refresh and reuse cleanup, Reduce Motion, clipping, and renderer suspension.
- [ ] Visual verification compares the implemented active card with the attached reference at supported Workspace sizes and backing scales.
