## Description

RR-269 run 115 started after RR-354 fixed branchless artifact lifecycle support, but failed its result contract because two read-only Git commands (rev-parse HEAD and ls-files) used Apple's Git/xcrun launcher. The launcher attempted four /tmp/xcrun_db-* cache creations that the sandbox denied. The worker reported these incidental writes in mutation_attempts, which correctly prevented clean completion. Later reads using /opt/homebrew/bin/git with optional locks and lazy fetching disabled succeeded; the tracked diff remained empty and ticket hash unchanged.

Fix spike launch preparation and worker guidance so routine Git inspection uses a verified read-only-compatible toolchain automatically, without requiring users or workers to rediscover a per-run workaround. Inspect services/orchestrator.py worker subprocess environment, _agent_command, spike workflow rendering, and mutation/result checks. Choose the smallest robust solution: account for macOS launcher behavior and child shell PATH behavior, do not assume Homebrew Git exists on every machine, and produce an actionable preflight blocker if no safe supported path is available. Any preparation belongs to the daemon before the research sandbox, never to writable research execution.

This is a separate issue from the merged RR-354 lifecycle fix. Preserve snapshot isolation, strict mutation rejection, branchless results, and daemon-only ticket/report persistence. Do not reclassify actual forbidden writes as successful research or grant broad writable temporary directories to make the error disappear. Codex currently permits sandboxed commands; Claude spikes expose Read/Glob/Grep only. Maintain those security boundaries and explicitly document provider differences.
