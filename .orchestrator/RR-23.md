## Description

RelayActions and RelayVision are now used from both Codex and Claude sessions, but several shared permission/error paths still speak as if every session is Claude-only. In a Codex session, permission warnings like "the app you launched `claude` from" or "restart your `claude` session" are confusing and make the Codex port feel incomplete.

Backfill the user-facing permission and screenshot failure copy so it refers to the current agent/session generically unless the code can reliably name the provider.

Likely touchpoints:

- `Sources/relay-actions-mcp/PermissionPreflight.swift`
- `Sources/relay-vision-mcp/PermissionPreflight.swift`
- `Sources/relay-vision-mcp/ScreenshotTool.swift`
- `Sources/relay-actions-mcp/ParentProcess.swift`
- `Sources/relay-vision-mcp/ParentProcess.swift`

## Acceptance criteria

- [ ] User-facing permission warnings and errors no longer say `claude` when the same path can run under Codex.
- [ ] Copy clearly explains macOS grants permission to the parent terminal/IDE/app that launched the agent session, not Relay Runner.
- [ ] Restart instructions are provider-neutral, e.g. "restart your agent session" or "restart Codex/Claude" as appropriate.
- [ ] Non-user-facing comments are cleaned up where they would mislead future provider-parity work.
- [ ] Existing parent-process detection behavior is unchanged.
- [ ] `swift build` passes.
- [ ] Grep verification shows no stale user-facing "`claude` session" / "launched `claude`" strings remain in RelayActions or RelayVision MCP sources.
