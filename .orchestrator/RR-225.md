## Description

Add a General Settings toggle equivalent in intent to ChatGPT's `Prevent sleep while running` option:

- Label: `Prevent sleep while running`
- Description: `Keep your computer awake while Relay Runner is running a task.`

The preference should be persistent and off by default for existing and new installations. When enabled, Relay Runner should prevent idle system sleep only while it has real task activity: an acknowledged foreground Codex or Claude turn is active, or an implementation/review worker is actively executing. An open but idle voice session, queued or dependency-blocked tickets, ordinary Workspace use, and response playback alone must not keep the Mac awake.

Use a scoped macOS power activity rather than shelling out to `caffeinate`. Apple's Foundation API exposes `ProcessInfo.beginActivity(options:reason:)` and `endActivity(_:)`; combining a user-initiated activity with `idleSystemSleepDisabled` prevents idle system sleep while retaining a token. Do not request `idleDisplaySleepDisabled`: the display should continue to follow the user's Energy settings. The assertion is best effort and must not claim to override explicit sleep, lid close, low-power, or thermal decisions.

Model the assertion as one idempotent, derived resource across overlapping work. Starting a second task must not create a leak or let the first completion release the assertion early. Release it immediately when the last active task finishes, the preference is turned off, services shut down, or Relay Runner prepares to relaunch for an update. If the process exits unexpectedly, macOS should release the process-owned assertion automatically.

Reuse the existing exact foreground-turn state and provider-neutral orchestrator run records rather than treating `AppState.isRunning` or an open session as task activity. The current app already polls cross-project run state for the notch; share the underlying state interpretation without making sleep behavior depend on whether the Workspace or notch is visible.

## Research notes

- Apple documents `ProcessInfo.ActivityOptions.idleSystemSleepDisabled` as the flag that prevents idle sleep and uses it with `beginActivity(options:reason:)`.
- `idleDisplaySleepDisabled` is a separate, stronger option that keeps the screen powered; this feature should not use it.
- The lower-level IOKit assertion API requires no special privileges, but Foundation's scoped activity token is the simpler fit unless installed-app verification exposes a concrete limitation.
- Power assertions are requests to macOS, not guarantees against explicit or safety-driven sleep.

- https://developer.apple.com/documentation/foundation/processinfo/activityoptions/idlesystemsleepdisabled

## Acceptance criteria

- [ ] General Settings contains a `Prevent sleep while running` toggle with the description `Keep your computer awake while Relay Runner is running a task.`
- [ ] The preference persists through `config.toml`, round-trips through Swift and Python config readers where applicable, and defaults to off without changing existing installations.
- [ ] With the preference enabled, an acknowledged active foreground Codex or Claude turn acquires one idle-system-sleep assertion.
- [ ] With the preference enabled, active implementation and review workers across every registered project acquire the same derived assertion even when no voice session or Workspace is open.
- [ ] An idle Relay session, Backlog or Ready tickets, dependency-blocked work, terminal run states, Workspace loading, recording, and TTS playback alone do not acquire the assertion.
- [ ] Overlapping foreground turns and workers hold one logical assertion until the last qualifying task becomes inactive; completion ordering cannot release it early or leak duplicate activity tokens.
- [ ] Turning the setting off releases an active assertion immediately, and turning it on during an active task acquires one without restarting services.
- [ ] Session teardown, app service shutdown, Sparkle relaunch preparation, normal app termination, and task cancellation all leave no retained activity token.
- [ ] The assertion prevents idle system sleep but does not force the display to remain awake or interfere with explicit sleep and system safety behavior.
- [ ] Assertion acquisition or release failures are logged with bounded, sanitized diagnostics and do not crash the app or create a rapid retry loop.
- [ ] Focused tests cover configuration migration/serialization, toggle changes during work, foreground provider parity, cross-project worker states, concurrent tasks, cancellation, relaunch cleanup, and stale/terminal run data.
- [ ] An installed-app smoke test uses `pmset -g assertions` or equivalent system evidence to verify the assertion appears only during qualifying work and disappears afterward.
