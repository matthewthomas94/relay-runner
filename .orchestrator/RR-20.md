## Description

Relay Runner's General settings currently expose a free-form `Target Command` text field and one generic `Model` picker (`Default`, `Opus`, `Sonnet`, `Haiku`). That lets Claude-specific model choices show even when the session provider is Codex, and it makes the provider/model relationship feel loose.

Replace this with two coordinated dropdowns:

- `LLM Provider`: Codex or Claude.
- `Model`: options that change based on the selected provider.

When Claude is selected, the model picker should show Claude-appropriate choices such as Default, Opus, Sonnet, and Haiku. When Codex is selected, the picker should show Codex-appropriate model choices instead. Changing the provider should keep the current model only if it is valid for the newly selected provider; otherwise reset to that provider's Default.

The selected provider and selected model must drive Start Session launch behavior. A Claude selection should launch Claude Code with the selected Claude model flag. A Codex selection should launch Codex with the selected Codex model flag. Avoid passing provider-specific aliases across providers.

Likely touchpoints:

- `Sources/relay-runner/Settings/GeneralSettingsTab.swift` — replace the text field plus generic picker with the two dropdowns.
- `Sources/relay-runner/Config/Config.swift` and `Sources/relay-runner/Config/ConfigManager.swift` — persist/load the selected provider and model, with backward-compatible migration from existing `general.command` and `general.model`.
- `Sources/relay-runner/Process/ProcessManager.swift` — resolve the selected provider to the correct CLI and pass the correct `--model` value.
- `services/config.py` / orchestrator config handling if the existing Python defaults need to understand the new general provider field.

## Acceptance criteria

- [ ] General settings show an `LLM Provider` dropdown with Codex and Claude options.
- [ ] General settings show a `Model` dropdown whose options update immediately when the provider changes.
- [ ] Claude model options include at least Default, Opus, Sonnet, and Haiku, with CLI values that Claude Code accepts via `--model`.
- [ ] Codex model options are Codex-specific and do not include Claude-only aliases such as Opus, Sonnet, or Haiku.
- [ ] Switching provider resets an invalid previously-selected model to Default for the new provider.
- [ ] Existing configs migrate cleanly: `general.command = "claude"` selects Claude; any other existing/default command selects Codex unless the user had an explicit custom absolute command that still needs to be honored.
- [ ] Start Session launches the selected provider's CLI and passes the selected model only when it is not Default.
- [ ] Bypass-permissions behavior remains provider-specific (`--dangerously-bypass-approvals-and-sandbox` for Codex, `--dangerously-skip-permissions` for Claude).
- [ ] Relay skill install/refresh behavior remains unchanged.
- [ ] `swift build` passes.
- [ ] Manual verification: choose Claude + Sonnet and confirm the generated launch command uses Claude with the Sonnet model; choose Codex + a Codex model and confirm the generated launch command uses Codex with that model.
