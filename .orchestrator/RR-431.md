## Description

In an artifact-enabled project (`artifact_lifecycle = "enabled"` in `.orchestrator/config.toml`), `.orchestrator/` is a projection of `refs/heads/relay/artifacts` and every ticket change must go through the artifact writer. Two daemon paths in `services/orchestrator.py` still write projected ticket files directly with the plain `write_ticket` from `services/tickets.py`:

- `_progress_dependents_locked` (around line 9065; the write at line 9088), reached from the per-completion path `_progress_dependents` (line 9022), which is called after a run finishes (line 9669) with no artifact-lifecycle guard.
- `_promote_unblocked_dependents` (line 9100; the write at line 9121), used by `_sweep_ready_tickets_locked` (line 9160) whenever the caller does not pass an `artifact_lifecycle`. The artifact-aware alternative, `ArtifactLifecycleCoordinator.promote_unblocked_dependents` in `services/artifact_lifecycle.py` (line 841), already exists.

A direct write changes the projected tree without moving the ref, so `ArtifactStore._ensure_materialization_consistent` in `services/artifact_store.py` (line 1043) sees a sha mismatch and raises "materialized .orchestrator was edited manually; use explicit Save/import" (line 1065). From then on every artifact operation fails closed: ticket writes, dispatch snapshots and merge publication.

Observed on 2026-10-24 in relay-runner. After RR-427's run 252 failed and the ticket went back to `backlog`, the projected `RR-427.md` was rewritten to `status: ready` at 13:34, again at about 13:39 and again at about 13:57, each time in `tickets.write` round-trip formatting (an inserted `order: 0`, the sizing rationale unquoted, `artifact_id` and `user_edited_at` moved after the standard fields) while the ref still said `backlog`. Consequences: run 251 (RR-424) ended in MergeConflict with "source merge succeeded but artifact lifecycle publication failed", run 253 (RR-427) failed with "artifact lifecycle snapshot failed", and PM ticket writes were refused until the file was re-materialized by hand. The rewrite recurred every time the ticket returned to backlog, so the board could only be kept consistent by parking the ticket in `ready`.

Required behavior: in an artifact-enabled project no code path may write under the projected `.orchestrator/` except the artifact store's own materialization. Dependency progression and ready promotion must use the lifecycle coordinator's canonical writer, and the per-completion path must either use it or skip when the project is artifact-enabled. Prefer routing every caller through one guarded entry point over adding checks at each write site. RR-418 fixed the Swift app side of this class of bug; this ticket is the daemon side.

- [ ] No code path calls `write_ticket` from `services/tickets.py` on a path under an artifact-enabled project's `.orchestrator/`; the tests assert this with a guard or spy.
