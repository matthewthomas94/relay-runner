## Description

Establish whether Phonon 2 can safely replace Relay's default English recognizer through its existing FluidAudio integration. Relay currently resolves FluidAudio v0.13.6 (57551cd90e0bbec342766244358bcf08afb05290); evaluate v0.17.5 at 0b1f46289fe27d95b5e66ad8be46e64f5ee02ae7, which exposes AsrModelVersion.phonon2. Use a focused harness or prototype and an evidence report. This is implementation mode because the harness and report are committed; it is not a read-only spike.

The agreed policy is Parakeet on macOS 14, Phonon 2 as the default English model on macOS 15+ after validation, and preservation of explicit Parakeet v3 selections for multilingual use. Keep the app deployment target at macOS 14. Do not switch production defaults in this ticket.

Inspect Package.swift, Package.resolved, STT/STTEngine.swift and Notes/FluidAudioMeetingTranscriber.swift under Sources/relay-runner. Review upstream API, decoding, normalization, token timing, resource and binary changes, including NemoTextProcessing. Use the default Neural Engine model from FluidInference/phonon-2-coreml; resolve an immutable model revision and selected file hashes. Do not introduce a separate Fermion runtime, general backend framework, custom downloader, or alternate encoder.

## Required inputs

- [ ] Confirm access to a supported macOS 15+ Apple Silicon test Mac and a macOS 14 test environment for actual compatibility checks.
- [ ] Identify public or explicitly consented command and meeting fixtures with reference transcripts, including Australian English, technical terms, names, numbers, quiet/noisy speech and critical commands; record provenance and permitted local use.
- [ ] Freeze the corpus and acceptance thresholds before comparing results. The specification's numerical targets are proposals, not existing measurements.

## Acceptance criteria

- [ ] A reproducible harness and report record commands, source/runtime/model revisions, hardware, OS, power mode, corpus identifiers, and cold/warm results without committing private recordings or raw transcripts.
- [ ] The candidate builds with Relay's toolchain. The report lists required call-site changes, Swift/toolchain constraints, binary/resources/signing implications and model/runtime attribution; macOS 14 launch and Parakeet transcription are exercised.
- [ ] Real sample-array inference checks short/padded input, six-second note windows, the 15-second encoder boundary, 25-second command chunks and delayed-snapshot overshoot. No unsupported length is silently truncated.
- [ ] Real outputs establish whether whitespace-marked subword assembly, punctuation, token times and confidence remain compatible with Relay's note adapter. Record absent confidence explicitly rather than inventing values.
- [ ] Paired quality and latency measurements compare the configured Parakeet v2 baseline with Phonon on the fixed command and meeting corpora; include v3 cases needed to prove multilingual compatibility is retained. Separate model-only time, first partial, release-to-final, and final-window lag.
- [ ] Audit the existing loader's revision selection, integrity checks, partial-download recovery, cache reuse and preparation concurrency. Identify demonstrated gaps and the smallest remedy, rather than speculating about a new downloader.
- [ ] Commit an explicit proceed or stop recommendation with evidence and unresolved risks. A stop result must not be represented as permission to activate the downstream migration; the next ticket's required-input gate remains unresolved until the PM accepts a viable revision and results.

## Validation boundary

A compiled harness or synthetic test is not proof of live capture, installed behavior, or release readiness. This ticket must not install over the user's app, change the active model, or launch a provider session. Codex and Claude workers use the same local STT evaluation; downstream provider delivery is covered separately.
