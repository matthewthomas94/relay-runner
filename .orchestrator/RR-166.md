## Description

Change the persistent voice messenger so every substantive task/work turn receives an immediate, natural acknowledgement before the foreground orchestrator finishes planning. The acknowledgement must be generated by the messenger from the actual user request and recent public context. It should briefly reflect what the user asked for, explicitly confirm that the orchestrator received or picked up the request, and set the expectation that the orchestrator will return with a plan or next step.

This is a handoff acknowledgement, not planning or execution. The tool-free messenger must not invent scope, promise a particular implementation, claim that a ticket or worker exists before an authoritative event, or replace later orchestrator progress/final speech. Lightweight conversation should continue to receive a normal immediate reply rather than an orchestration handoff.

Fix the event-ordering race as part of the same change. A first orchestrator progress event currently interrupts an in-flight user-turn response. For a task turn, preserve the immediate acknowledgement and process useful progress/clarification/final events afterward, while retaining newest-intent preemption when a genuinely newer user command arrives. Keep the deterministic notch acknowledgement visual-only so it does not become a second spoken acknowledgement.

Update the public messenger/orchestrator contract wherever it still says task turns should be silent or that the notch is the only acknowledgement. The behavior must remain provider-neutral for Codex and Claude.

## Acceptance criteria

- [ ] A task-like user turn prompts the messenger to generate a concise, contextual spoken handoff that reflects the request, confirms the orchestrator received/picked it up, and says the orchestrator will return with a plan or next step.
- [ ] The task handoff is model-generated from the current utterance and recent safe context; production code does not select a canned or hash-based acknowledgement sentence for speech.
- [ ] The messenger still performs no tools, planning, ticket authoring, dispatch, or work, and it does not claim an authoritative action occurred before a corresponding event.
- [ ] Lightweight social/conversational turns continue to get natural direct replies without forced orchestrator-handoff wording.
- [ ] The first orchestrator progress event cannot silently preempt a task acknowledgement already being generated; useful progress, clarification, and final events are handled in order after it.
- [ ] A newer user command still interrupts and suppresses speech for the superseded command using Relay command seq/id currentness checks.
- [ ] The existing deterministic notch acknowledgement remains visual-only and no duplicate canned spoken acknowledgement is introduced.
- [ ] Provider-visible reasoning summaries and authoritative finals continue to speak normally after the handoff, without exposing hidden chain-of-thought or raw tool output.
- [ ] Unit tests reproduce the old silent-task behavior and the first-trace interruption race, then verify the new ordering, conversation behavior, and stale-command suppression.
- [ ] Codex and Claude messenger prompts/backends share the same behavioral contract, and relevant focused plus full Python test suites pass.
