## Description

With several live sessions, mutation authority is checked against the wrong session. `services/orchestrator.py` validates relay commands against fixed `RELAY_COMMAND_STATE_FILE = /tmp/voice_command_state.json` and `RELAY_COMMAND_AUTHORIZATION_FILE` (~179-180). `Sources/relay-orchestrator-mcp/Tools.swift` already reads `VOICE_COMMAND_CLAIM_FILE`/`VOICE_COMMAND_STATE_FILE` from env (~66) but the daemon cannot tell which session a request is from. `services/instructions/orchestration-workflow.md:52` hard-codes `/tmp/voice_cmd_claimed.json` and `/tmp/voice_command_state.json`.

Implement RR-393 slices H and I: have the MCP forward the session key (and/or its spool state and authorization paths) with mutating requests, and have `_validate_relay_command` and authorization resolve that session's files, falling back to the legacy /tmp paths only for manual single-session bridges. Scope `all_work` cancellation to the session. Update the instruction chunks to reference the session's `$VOICE_COMMAND_CLAIM_FILE` and `$VOICE_COMMAND_STATE_FILE`, re-run `scripts/build-instructions`, and commit the regenerated CLAUDE.md, AGENTS.md and compact payloads.

## Acceptance criteria

- [ ] A mutation from background session A carrying A's claimed seq/id is accepted while B has a newer command (test).
- [ ] A mutation carrying B's seq/id from A is rejected.
- [ ] Manual single-session relay-bridge sessions keep working with legacy /tmp paths.
- [ ] Instruction chunks reference the per-session env paths; generated CLAUDE.md, AGENTS.md and compact payloads are regenerated and the generated-block check passes.
- [ ] Identical behaviour for Codex and Claude.
