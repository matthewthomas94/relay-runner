## Description

Make Relay Runner fully hand off to macOS when a permission action opens System Settings. A visible Workspace, including Workspace Settings, must be suspended before System Settings opens so it cannot remain over the requested privacy pane.

Some macOS privacy grants require the affected app process to quit before the grant becomes usable. Before opening a relaunch-sensitive permission pane, Relay Runner must arm a bounded watcher that survives that termination and reopens the exact app bundle automatically. The watcher must not open a duplicate app while the existing process remains alive and must expire if no relaunch is needed.

## Acceptance criteria

- [x] Accessibility, Input Monitoring, and Screen Recording setup suspends a visible Workspace before opening System Settings.
- [x] Microphone setup retains its native in-app prompt flow and does not dismiss Workspace unnecessarily.
- [x] Only relaunch-sensitive permission kinds arm the automatic relaunch watcher.
- [x] If Relay Runner exits while that watcher is active, the exact originating app bundle is reopened automatically.
- [x] If Relay Runner remains alive, the watcher expires without launching a duplicate app.
- [x] Repeated permission actions in one app lifetime do not create duplicate watchers.
- [x] Focused permission, Settings, Workspace, and relaunch tests pass.
- [x] A rebuilt installed app is ready for mounted confirmation of Workspace dismissal and automatic relaunch.
- [ ] The installed app visibly dismisses Workspace before System Settings and automatically returns after a macOS-required Quit & Reopen.

## Verification plan

Run focused Swift tests for the permission coordinator, Permissions Settings, Workspace suspension, and the relaunch guard. Rebuild and install the app, verify installed-bundle identity and daemon health, then preserve the macOS permission-toggle checks as mounted evidence until directly observed.
