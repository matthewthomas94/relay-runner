## Description

Let users choose general-tasks or another registered repository using the existing Projects cards. The app automatically prepares, reuses or replaces the underlying provider session with the selected project's confirmed working directory and scope. Users should not manually manage provider processes. Preserve the necessary conversation continuity internally without adding a Conversation tab, a General mode or a separate context switcher.

## Acceptance criteria

- [ ] Selecting general-tasks or an existing registered project from the existing Projects list selects that project's confirmed identity, working directory and ordinary board.
- [ ] Transitions between general-tasks and other projects do not require manually ending and starting provider processes.
- [ ] Pending transitions keep the committed project selected until safe; cancellation retains it, and successful commitment aligns board selection and provider execution scope.
- [ ] Explicitly authorized unfinished work can continue only after exact source identity and destination readiness are validated; navigation and saved history never manufacture work or replay commands.
- [ ] Existing tickets and workers retain their original repository, run identity and mutation authority across foreground navigation.
- [ ] Both Codex and Claude use their supported native start/resume behavior and preserve relevant history without injecting unrelated private project content.
- [ ] Focused tests cover pending, cancelled and committed transitions plus stale/missing projects; signed-app checks verify general-tasks to project and back using existing Projects navigation.
