## Description

Let a user begin globally, choose or name an existing repository when project work arises, and return to global work within the same visible conversation. Separate the visible conversation, active context and provider execution session. Project ownership must come from an explicit project choice or unambiguous current intent and validated registry identity, not an arbitrary cwd or frontmost editor. Native provider sessions may need attach/resume or replacement because their cwd and startup instructions cannot safely be changed by telling the model to switch projects. Use a bounded user-safe handoff for continuity while keeping project histories and active work correctly scoped.

## Acceptance criteria

- [ ] A user starts globally, requests work in a registered repo, then requests a general action without manually closing and reopening sessions.
- [ ] Selecting an existing repository establishes validated project identity and cwd. New tickets and workers are allocated to that repo; general work remains under General.
- [ ] Ambiguous repository references prompt only the necessary project choice. The app always exposes the active context and allows returning to General.
- [ ] Provider execution is correctly bound on every transition, using real Codex/Claude start/attach/resume capabilities. Replacing an underlying session preserves the visible conversation and reports any unavoidable provider limitation.
- [ ] An in-flight ticket keeps its original repository, run identity and mutation authority after the foreground context switches. Delayed callbacks and tool results cannot write into the new context.
- [ ] Preserve per-context conversation history and working state; pass only the relevant public handoff when crossing contexts, with no automatic full-transcript or private-file injection from unrelated projects.
- [ ] Regressions cover global-to-project, project-to-project, project-to-global, stale/missing projects, pending operations and scope mismatch for both supported providers.
