## Description

Today the phone takes over speech implicitly: on every `hello` the Python server attaches a remote speech sink (`services/relay_remote.py:372`, `SpeechCoordinator.attach_remote_sink` in `services/speech_coordinator.py:406`) and all replies go to the phone as text until the sink expires 300 s after disconnect. The Mac side has a microphone gate for this (`RelayRemoteDeviceSession.apply` in `Sources/relay-runner/Remote/RelayRemoteDeviceSession.swift:101` calling `suspendForRemoteDevice` / `resumeAfterRemoteDevice`, with `IOKitKeepAwake` holding a sleep assertion), but **no Python code ever posts the `remote_device` events it listens for**, so the Mac microphone is never actually suspended.

The user wants this explicit: a **Remote mode** switch on the phone. On means the phone is the primary driver: it owns microphone and speaker for the turn, the Mac stays quiet and its mic gate is suspended, and the Mac is kept awake. Off means everything routes back through the Mac (Kokoro speaks on the Mac, the Mac mic is live) even while the phone stays connected and continues to show text.

Work:

1. **Protocol.** Add a phone-to-Mac frame `remote_mode` with `enabled: Bool` (and `client_id` for dedup like other requests). Add the phone's current mode to `Hello` as an optional `remote_mode` field so a reconnect restores it. Protocol changes go in `Sources/RelayRemoteProtocol/Frames.swift` with the Python twin `services/relay_remote_protocol.py` kept identical, new golden vectors under `tests/RelayRemoteProtocolTests/Vectors/`, and `RelayRemoteProtocol.version` left at 1 because both decoders ignore unknown keys; an unknown frame *type* is rejected by the Python server and logged by the phone, so bump the version only if an older peer would misbehave, and say why in the run log.
2. **Python server and coordinator.** On `remote_mode enabled=true` (and on `hello` carrying it): attach the remote sink as today and **post the `remote_device` `active` event** the Swift gate expects (find the event channel the app already consumes, see `StateEventBus.swift:306` and `AppState.swift:4211`, and the Python side that publishes state events). On `enabled=false`: detach the sink immediately so Kokoro resumes on the Mac, keep the connection and continue sending `speech` frames flagged so the phone shows text without speaking (add `spoken_by: mac|phone` to `Speech`), and post the `inactive` event. On disconnect: post `disconnected`; keep the existing 300 s replay window only while the last known mode was on. Expire the sink on disconnect when the mode was off.
3. **Swift gate.** `RelayRemoteDeviceSession` handles `active`, `inactive` and `disconnected`; `IOKitKeepAwake` holds its assertion only while Remote mode is active. The menu-bar/status label reflects "Remote: <device>" only when active.
4. **Phone.** A clearly visible Remote mode switch at the top of the current main screen (`ios/RelayRemote/DebugView.swift`; a later ticket moves it to Home), default **on**, persisted in `UserDefaults`, sent on connect and on change. When off, incoming `speech` frames with `spoken_by: mac` are displayed, not synthesised, and are acked as played immediately so the Mac's realization tracking stays consistent. `VoiceController` only opens the microphone when the mode is on.
5. **Tests.** Python: `tests/test_relay_remote.py` and `tests/test_speech_coordinator_remote.py` cover attach/detach on mode changes, the posted events and the `spoken_by` flag. Swift: `RelayRemoteDeviceSessionTests` cover the three events and keep-awake lifetime. Kit: codec vectors for the new frame and field; `SpeechPlayback` tests for display-only frames. App: the switch persists and is sent on connect.

Physical-device checks cannot run in the worker environment. Cover behaviour with the kit, app, Python and Swift unit tests plus the existing loopback tests, and name the manual iPhone check for the user in the run log; do not mark acceptance that needs the phone as verified.

## Acceptance criteria

- [ ] With Remote mode on, a remote `hello` or `remote_mode` suspends the Mac microphone gate (unit test on `RelayRemoteDeviceSession` with the posted event) and routes speech to the phone; with it off, speech plays on the Mac through the coordinator's normal path and the phone receives text-only frames (`spoken_by: mac`).
- [ ] Turning the mode off while connected detaches the sink without closing the connection; turning it back on re-attaches without a reconnect (Python tests).
- [ ] Disconnect with the mode on keeps the 300 s replay window; disconnect with it off expires the sink immediately (Python tests).
- [ ] Keep-awake assertion is held only while Remote mode is active (Swift test).
- [ ] The phone switch defaults to on, persists, is sent on connect and on change, and the microphone is not opened while it is off (app/kit tests).
- [ ] Golden vectors round-trip in both codecs; `swift test` for the protocol, shell and app targets, `cd ios/RelayRemoteKit && swift test`, and the Python suite pass; run log names the manual iPhone check.
