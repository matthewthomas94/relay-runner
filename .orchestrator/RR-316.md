## Description

Correct the final session-controls tutorial handoff after the user double-taps Shift. The current flow begins opening Workspace as soon as the tutorial dismissal callback fires, making the tutorial appear to barely close before Workspace replaces it.

The final gesture should produce three distinct, ordered phases: let the tutorial surface finish its complete dismissal animation, keep both tutorial and Workspace fully hidden for one second, and only then invoke the normal Workspace presentation path so Workspace performs its complete opening animation from the hidden state. Do not fake the effect by fading overlapping surfaces or by adding delay before the tutorial has actually finished closing.

Preserve the existing exactly-once completion, retry, persistence, and provider-parity behavior. Respect Reduce Motion by keeping the same close/pause/open ordering and one-second fully hidden interval while using the app's existing reduced-motion presentation behavior.

## Acceptance criteria

- [ ] A valid double-tap Shift on the final tutorial lesson starts the existing complete tutorial dismissal and does not begin opening Workspace while that dismissal is in progress.
- [ ] The one-second delay begins only after the tutorial dismissal completion reports that the tutorial surface is fully closed.
- [ ] During that one-second interval, the tutorial and Workspace surfaces are both fully hidden; no partial, overlapping, or immediately substituted Workspace frame is visible.
- [ ] After the interval, the handoff invokes the existing normal Workspace presentation path exactly once, and Workspace performs its full opening transition from the hidden state rather than appearing partially open.
- [ ] Duplicate Shift gestures or repeated dismissal completions cannot schedule multiple delayed opens or reopen Workspace twice.
- [ ] Onboarding completion flags, notch state, first-run shell state, failed-toggle recovery, manual Redo Onboarding, and the ordered tutorial gates remain correct.
- [ ] Codex and Claude use the same shared close, pause, and reopen sequence.
- [ ] Reduce Motion preserves the fully closed one-second pause and uses the existing accessibility-appropriate close/open behavior without introducing large motion.
- [ ] Focused tests use a controllable scheduler/clock to prove dismissal completion precedes the delay, Workspace remains unopened before one second elapses, and exactly one normal Workspace open occurs after the deadline; the full Swift test suite passes.
