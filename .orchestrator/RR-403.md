## Description

The watchdog script in `Sources/relay-runner/Process/ProcessManager.swift` (~700-780) reads the single `/tmp/voice_provider_session_id`, replays the single `voice_cmd_ready`, and kills with a global `pkill -f voice_bridge.py` (~776, plus `/usr/bin/pkill` uses ~839-895). With several sessions it can replay the wrong command or kill the shared bridge.

Implement RR-393 slice J: make watchdog recovery read the affected session's provider-session file and replay only that session's spool; kill the bridge by its recorded PID rather than pattern; and add end-to-end focus-switch tests covering idle, recording, claimed command in flight, and TTS playing, for both Codex and Claude.

## Acceptance criteria

- [ ] Watchdog recovery for session A replays only A's spool and never touches B's.
- [ ] No `pkill -f voice_bridge.py` remains; the bridge is stopped by recorded PID.
- [ ] Focus-switch tests cover idle, recording, claimed-in-flight and TTS-playing, with no lost or misrouted command, for both providers.
- [ ] Swift and Python test suites pass.
