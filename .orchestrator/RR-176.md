## Description

Add an Agents tab to the notch-opened Workspace that gives the user a graphical,
spatial view of agents currently working. It should make the foreground
orchestrator, dispatched workers, their tickets or runs, and the relationships
between them understandable at a glance.

This should be more than another card list or a duplicate of the Work tab. Explore
an appropriate visual model—such as a compact graph, connected lanes, or another
spatial system—and document the chosen approach before implementation. The view
should answer:

- Which agents are active?
- What is each agent working on?
- Which project, ticket, or run does it belong to?
- Which agent dispatched, handed off to, or is waiting on another?
- What phase is the work in, and where is attention needed?

Reuse existing Graphify Core relationships and sanitized foreground/worker
activity pathways where possible. Do not expose hidden reasoning, raw commands,
full transcripts, secrets, or noisy implementation events. The view belongs
inside the current Workspace tab system opened from the notch; it must not
replace the concise notch status stream or the existing Work and System Settings
tabs.

## Acceptance criteria

- [ ] The product and visual model for the Agents tab is documented with enough detail to distinguish it from the existing Work and Program Workspace views before implementation begins.
- [ ] A new Agents tab is available within the notch-opened Workspace without changing existing Work, Terminal, or System Settings behavior.
- [ ] Foreground orchestrators and dispatched workers are represented as distinct graphical entities with concise, sanitized labels.
- [ ] Agent entities show their current project plus ticket or run when available, provider, activity phase, and whether they are active, waiting, blocked, reviewing, awaiting merge, completed, failed, or canceled.
- [ ] Dispatch, parent/child, handoff, dependency, or waiting relationships are visually legible without requiring the user to inspect raw logs.
- [ ] Selecting or focusing an agent reveals useful detail without turning the primary view into a dense card dashboard.
- [ ] The view updates from existing live activity and Graphify/run state without polling or animation that materially increases menu-bar app resource use.
- [ ] Idle, single-agent, multiple-agent, blocked, stale, failed, and no-project states are deliberately designed.
- [ ] Public-state safety is preserved: hidden reasoning, secrets, raw commands, raw tool output, and full transcripts never appear.
- [ ] Codex and Claude foreground agents and workers receive equivalent visual treatment, with provider-specific labels only where truthful and useful.
- [ ] Keyboard navigation, VoiceOver labels, Reduce Motion, colour-independent state cues, and constrained Workspace window sizes are supported.
- [ ] Focused tests cover state mapping, relationship construction, stale-event handling, provider parity, tab routing, and accessibility; a manual visual verification records representative multi-agent states.
