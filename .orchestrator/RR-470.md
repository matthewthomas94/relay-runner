## Description

Settings currently edits a private draft copy (`@State private var draft: AppConfig` in `Sources/relay-runner/Settings/SettingsWindow.swift:166`) and only applies it when the user presses Save, which calls `appState.saveConfig(draft)`. Revert discards the draft. Make Settings save automatically instead.

- Remove the draft copy and the Save and Revert footer buttons (`SettingsFooterSaveButton` and the Revert `SettingsActionButton`). Each control writes through the existing `AppState.saveConfig` path, so `persistConfig`'s side effects stay exactly as they are: the bridge `reload`, the speech-to-text restart after the current recording (`sttSettingsRequireRestart`) and workspace discovery.
- Text fields save after a short pause (about 0.5 s) or when focus leaves the field. Sliders save when released. Toggles, pickers and dropdowns save immediately. Typing or dragging must not send one reload or restart per step.
- The hotkey capture field (`KeyCaptureView`, used in `STTSettingsTab.swift`) saves when a capture completes. Capture is itself the deliberate act, so there is no extra confirmation.
- Keep the existing `mergingWheelSettingsChange` behaviour (`SettingsWindow.swift:215`) so wheel settings changed elsewhere are not overwritten. With no draft copy, the window just reads the live config.
- Replace the footer buttons with a quiet status: "Saved" after a successful save, or the error if persisting fails.
- Relay App `set_settings` keeps going through the same `saveConfig` path, unchanged. Update its comment in `RelayAppCommands.swift:25`, which names "the Settings Save path".
- Update the docs that describe the Save button.
