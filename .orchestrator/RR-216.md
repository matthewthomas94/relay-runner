## Description

Opening the Program Workspace for the first time after Relay Runner or its local orchestrator starts can exhaust the current transient connection retry window before the service is ready. The Workspace then replaces its content with `Work temporarily unavailable` and requires a manual `Try again`, even though the same request succeeds shortly afterward.

Remove the avoidable startup race where possible. While a healthy local service is still starting, keep the first-open Workspace in a passive loading state and retry automatically without user action. Reuse the existing Workspace particle/dot-matrix loading language, including reduced-motion behavior, instead of flashing a failure panel during normal cold start. Preserve a bounded, actionable error state for persistent or non-transient failures.

## Acceptance criteria

- [ ] A cold start in which the local orchestrator becomes ready after the current retry window succeeds without a manual click.
- [ ] During expected cold-start retries, the first-open Workspace remains in a passive loading presentation and does not show `Work temporarily unavailable` or `Try again`.
- [ ] The loading treatment uses the existing Workspace visual language and respects Reduce Motion.
- [ ] Retry/backoff is bounded, cancellation-aware, and does not busy-loop or leave work running after the Workspace is dismissed.
- [ ] Persistent transient failures eventually show an actionable error with manual retry, while non-transient failures are not retried indefinitely.
- [ ] Background refresh with an existing snapshot preserves usable Workspace content instead of replacing it with the first-open failure surface.
- [ ] Automated tests cover delayed service readiness, retry exhaustion, non-transient failure, cancellation, and the loading-to-board presentation transition.
