## Description

Reduce General → Agent settings to the decisions users actually need:

1. LLM Provider
2. Orchestrator Model
3. Orchestrator Effort
4. A binary sub-agent policy: `Use my defaults` or `Orchestrator decides`

Remove the separate Sub-agent Model and Sub-agent Effort controls. Selecting `Use my defaults` must not reveal any nested options; it means workers inherit the currently selected LLM provider, orchestrator model, and orchestrator effort. Selecting `Orchestrator decides` means the foreground orchestrator can choose provider-appropriate worker sizing for each ticket.

Simplify the persisted configuration and dispatch behavior to match the UI. Legacy `subagent_model` and `subagent_effort` values should migrate safely but must no longer create a hidden third source of worker settings.

## Confirmed reproduction

Confirmed on 2026-07-24 with Codex configured as the provider, Relay Runner's orchestrator model set to `default`, the sub-agent policy set to `user_default`, and the local Codex default set to `gpt-5.6-sol`. Recent strong worker runs, including runs 297 and 298 for RR-210, recorded `model_alias: gpt-5.5`.

The dispatch resolver currently treats the provider-level `default` model as if no inherited model were configured. It then resolves the ticket's `worker_model: strong` tier to the hard-coded Codex alias `gpt-5.5` and launches the worker with that explicit model, overriding the user's Codex default. The same semantic error can affect either provider whenever `Use my defaults` is combined with a provider-level `Default` selection.

## Acceptance criteria

- [ ] General → Agent exposes only LLM Provider, Orchestrator Model, Orchestrator Effort, and one binary sub-agent policy control.
- [ ] The sub-agent policy offers exactly `Use my defaults` and `Orchestrator decides`.
- [ ] Neither policy reveals separate Sub-agent Model or Sub-agent Effort controls.
- [ ] `Use my defaults` launches workers with the selected LLM provider, orchestrator model, and orchestrator effort.
- [ ] When the selected orchestrator model is `Default`, `Use my defaults` preserves provider-default semantics by omitting an explicit worker model override; it must not substitute the ticket's `fast`, `balanced`, or `strong` tier alias.
- [ ] Changing provider, model, or effort immediately changes the effective worker defaults without another sub-agent setting.
- [ ] `Orchestrator decides` continues to honor the provider-neutral or provider-scoped worker sizing recorded for each ticket.
- [ ] The ticket and run audit trail records the provider, model, and effort actually used after either policy is resolved.
- [ ] Existing configurations containing `subagent_model` or `subagent_effort` load without failure, but those legacy values do not override the selected policy.
- [ ] Newly saved configuration no longer relies on separate sub-agent model and effort keys.
- [ ] Invalid or unavailable inherited model/effort combinations fall back through the existing provider-aware normalization and surface the same access guidance as orchestrator settings.
- [ ] Codex and Claude both inherit their own selected model and supported effort values under `Use my defaults`.
- [ ] Automated Swift and Python tests cover the simplified UI, config migration and round-trip behavior, both policy branches, actual worker launch arguments, audit metadata, and provider parity.
