## Description

Make the single-project board's new-ticket affordance a polished, documented baseline that the Program Board can reuse or mirror.

Current context:

- `BoardOverlayView` already renders `NewTicketButton` in each project-board column.
- `BoardOverlayController.handleCreate(in:)` calls `TicketWriter.mint`, writes into the current project, reloads tickets, and opens the editor.
- Saving a ticket in `ready` already auto-dispatches via the existing board save path. This ticket should preserve that behavior.

Scope the work to the project-board path and any small shared primitives needed by the follow-up Program Board ticket. Do not change Program Board creation behavior here except for reusable types/functions that RR-71 can consume.

## Acceptance criteria

- [ ] The project board has an obvious new-ticket control for creating a ticket in the current project.
- [ ] Creating a ticket writes to the current project's `.orchestrator/`, increments that project's `config.toml` `next_id`, and does not touch any workspace parent `.orchestrator/`.
- [ ] The new ticket opens in the existing editor with title and description fields ready to edit.
- [ ] Creating in a specific column preserves the intended initial status; creating in `ready` only dispatches after the user saves a dispatchable ticket.
- [ ] Cancel, save, delete, and board reload behavior still work for newly-created tickets.
- [ ] Any shared helper introduced for creation is covered well enough for RR-71 to build on it without duplicating file-mutation logic.
