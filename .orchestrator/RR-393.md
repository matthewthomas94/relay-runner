## Description

Relay Runner is moving from one session at a time to one session per project, each in its own Workspace terminal tab (see T2/T3). The decision is to keep **one** voice pipeline (STT, voice bridge, messenger, TTS) and route it to the **focused** project's session only. Background sessions keep running but do not speak.

Today the whole voice path assumes one session per machine:
- Fixed `/tmp` paths in `Sources/relay-runner/Process/ProcessManager.swift` (~lines 19–57) and `RelayVoiceCommandDelivery.Paths` in `Sources/relay-runner/Terminal/EmbeddedTerminal.swift` (~1054–1069): `voice_bridge.sock`, `voice_cmd_ready(.meta)`, `voice_cmd_claimed.json`, `voice_command_state.json`, `voice_cmd_manual_ack.json`, `voice_provider_turns_v2.json`, `voice_provider_session_id`, `voice_bridge.cwd/.provider/_heartbeat/_stop_requested`, `voice_in.fifo`, `tts_in.fifo`, `tts_control.sock`.
- `services/voice_bridge.py` (~90–93, 369–407) uses the same paths plus `relay_intent_inbox.sqlite3` and `relay_speech_events.jsonl`.
- `ProcessManager.killBridge` uses `pkill -f voice_bridge.py` (~812–825).
- `services/messenger.py` (~843–863) keeps one `_session_id` passed as `--resume`.
- `AssistantSessionStore` has a single `activeContext`.
- Voice input is written to the single PTY `childfd` (`EmbeddedTerminal.swift` ~3311).

Answer: what state must become per-session versus stay shared, and how focus changes rebind the pipeline without dropping or misrouting a claimed command. Cover:
1. Which files/sockets/inbox rows need a session key, and which can stay global.
2. What happens to an in-flight claimed command, a pending TTS reply, or an active recording when focus switches mid-turn.
3. How a background session's `__ORCHESTRATOR_REPLY__` and worker lifecycle events are captured (badge) instead of spoken, and whether they replay on refocus.
4. Messenger: one messenger re-bound per focus vs one per session; cost and latency.
5. Whether the bridge needs restarting on focus change, or can be re-targeted live.
6. Fit with the voice-turn contract in `services/instructions/` (stale-output suppression, `relay_command_seq`/`intent_id` mutation authority, scoped cancellation).
