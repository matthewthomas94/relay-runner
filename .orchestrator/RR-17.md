## Description

Relay Runner currently synthesizes each spoken assistant response as one Kokoro WAV. Benchmarks on the live app's Python environment show Kokoro load is already warm and WAV conversion is negligible, while synthesis time scales with the length of the spoken response. A short reply takes about 1.2s to synthesize, a medium reply about 2.1s, and a long reply about 3.4s.

Reduce perceived TTS latency by splitting pending text into sentence-sized playback chunks: synthesize and start the first chunk quickly, then synthesize later chunks while earlier audio is playing. Preserve the existing speculative generation behavior, replay behavior, cancel/skip semantics, and overlay state transitions.

## Acceptance criteria

- [ ] TTS playback can begin after the first sentence-sized chunk is ready instead of waiting for the full response to synthesize.
- [ ] Later chunks are synthesized ahead while earlier chunks are playing when possible.
- [ ] Replay still prefers pending or canceled-but-unheard text before replaying the last heard WAV.
- [ ] Cancel/skip stops playback and does not reintroduce the prior interrupt replay loop.
- [ ] Existing TTS replay tests pass, with focused tests added or updated for chunked playback semantics.
