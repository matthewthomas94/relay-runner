## Description

RR-394 gave each project session its own spool (`VoiceSessionSpool`), but the shared voice bridge still targets whichever session launched most recently: `AppState.voiceContextID` is set only on launch (`Sources/relay-runner/App/AppState.swift` ~2442) and on end-of-session retarget (`retargetVoiceBridge` ~1246, which relaunches the bridge daemon). Focusing a tab (`focusSessionTab` ~1212) or a project card does not move voice. The agreed spec routes the single voice pipeline to the focused project.

Implement RR-393 slice C:
- Add a `__FOCUS__` control message on `voice_bridge.sock` (`services/voice_bridge.py` control dispatcher ~3505) carrying the target's session key, provider, provider session id, cwd, spool paths and orchestrator session. Replace module-level targets such as `PROVIDER_SESSION_ID` with a lock-guarded mutable target record.
- `AppState`: whenever the focused live context changes (tab select, project card, `activate_project`), set `voiceContextID` to it and send `__FOCUS__`; do not relaunch the bridge. `retargetVoiceBridge` should use `__FOCUS__` too when the bridge is alive.
- Stop running `relay-bridge --start-daemon` on every session launch when a bridge is already running (`ProcessManager.swift` ~1285); the bridge starts with the first session and stops only on app quit or when the last session ends.
- Bind each utterance to the session focused when recording starts (stamp the session key at segment open, in the app or the bridge, whichever sees it first) and publish only into that session's spool, even if focus changes mid-recording.
- Register and heartbeat an orchestrator session for every live session, not just the bridge target.
- Show which project the next utterance will go to (existing notch/status surface; RelayMotion conventions).

Out of scope: background reply badge, intent inbox partitioning, messenger partitions (separate tickets).

## Acceptance criteria

- [ ] With live sessions A and B and focus on B, a spoken command is delivered to B's PTY and B's spool only (test covering AppState focus + bridge target).
- [ ] Changing focus between live sessions sends __FOCUS__ and does not restart the bridge process (PID unchanged in test).
- [ ] A recording started while A is focused is delivered to A even if focus switches to B before it is published.
- [ ] Launching a second session while the bridge runs does not restart the bridge.
- [ ] Ending the focused session moves voice to another live session via __FOCUS__ without losing a queued command.
- [ ] Works identically for Codex and Claude foreground sessions; Python and Swift tests pass.
