## Description

Relay currently starts AVAudioEngine microphone capture as part of idle awareness. Caps Lock mode drops samples while idle but leaves the hardware capture graph active. Change the ownership policy so microphone capture is active only for an active Claude/Codex voice session or an actively capturing Note Taker session. The user selected this session-level boundary: do not additionally require turning capture off between utterances within an active provider session.

Keep model readiness and keyboard gestures available without acquiring the microphone when Relay starts or sits idle. End Session, actual provider/bridge termination, failed launch, Note Taker stop/failure, and shutdown must release capture when there is no permitted owner. Note Taker pause should retain its existing release behavior. Starting a session must acquire capture in time for normal voice input. Pending model loads, retries, permission callbacks, settings changes, and stale async completions must not resurrect capture after the owner is gone.

The existing STTEngine also owns keyboard gestures, including no-session feedback, Workspace toggle, playback, and onboarding controls. Preserve these without relying on live audio. Coordinate ordinary command capture and Note Taker capture so they do not overlap or restart ordinary capture on note teardown when no provider session is active. Check the explicit Settings voice-reference recorder against the same owner boundary: it must not leave or activate a microphone outside the permitted session types; use a clear existing-style unavailable message if an out-of-session recording action is blocked. Ordinary TTS preview playback does not require a microphone and should still work.

This is a microphone-lifecycle improvement prompted by an audio audit. There is no confirmed relationship to the reported right-speaker crackling. Do not change TTS models, system audio settings, drivers, output volume, unrelated orchestration behavior, or claim this fixes the crackling.

## Acceptance criteria

- [ ] Idle app startup/Workspace/Settings/permission recovery/model readiness does not start microphone capture; model loading and keyboard shortcuts remain usable.
- [ ] Starting a Codex or Claude session (embedded or external bridge) enables command capture; ending the session or failed launch/actual termination releases it. Explicitly account for a deliberately retained live voice bridge during provider reconnect, using canonical session ownership rather than process existence alone.
- [ ] A delayed model load or permission/reference callback completed after stop, replacement, or Note Taker handoff cannot start or resume stale capture. Add deterministic regression coverage with controllable lifecycle dependencies.
- [ ] Note Taker independently captures without a provider session. Pause/stop/error and both mode-switch directions preserve existing save/tail behavior and release microphone ownership correctly; stopping a note into idle does not restart ambient capture.
- [ ] Out-of-session Caps Lock produces the existing session affordance without briefly opening the mic. Workspace/playback/onboarding gesture behavior remains available.
- [ ] Settings reference recording obeys the same session boundary and cannot resume stale command capture after session end; ordinary audio preview remains available.
- [ ] Focused Swift regression tests cover policy and actual lifecycle operations (not only source-string assertions), including provider parity, late startup, and repeated switches. Run the relevant existing capture, AppState, onboarding/gesture, reference-recorder and Note Taker suites and a build as appropriate.
- [ ] Document source/test evidence separately from installed mic-indicator, audible first-word, and crackling verification. Physical UAT is a foreground follow-up; do not falsely mark it performed or touch the installed app from the worker.
