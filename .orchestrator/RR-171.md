## Description

Finish the user-requested component-by-component Settings audit after RR-170's shell styling pass. RR-170 aligned the palette, navigation states, vertical scroll visibility, Save chrome, and custom motion with Workspace, but a comparison of its merged diff against the full audit found concrete Settings-local UX problems still unresolved.

Keep this pass strictly inside the Settings experience and its tests, except for narrowly necessary existing shared style reuse. Do not alter Workspace layout or behavior, daemon/provider/config persistence semantics, onboarding, voice behavior, or the top-level Workspace tabs. Preserve the deliberate historical decision that speech input mode is configured on disk rather than exposed as an in-app picker; do not reintroduce that control. Do not invent audio-device enumeration or other speculative capabilities.

Resolve the remaining issues deliberately:

- The global footer currently spans beneath the sidebar and puts Save at the far edge of a wide Workspace. Make the sidebar a full-height rail and place the fixed save/revert/status area inside the detail plane, aligned with the same readable content grid as its header and rows.
- Give the embedded Settings surface the same single hairline outer boundary as other Workspace panels without adding a nested floating card, duplicate border, or large shadow. Standalone window chrome must remain appropriate.
- Prefer Workspace's quiet, discoverable scroll treatment rather than a permanently visible generic scroller where practical; only the detail pane scrolls and category changes should not strand users at an unrelated deep offset.
- Status must expose Screen Recording alongside Microphone, Accessibility, and Input Monitoring because Relay Vision depends on it and the existing permission model/action path already supports recovery.
- The one-option Input Device picker is a false choice. Present the configured device honestly as read-only system-default/current-device information until real enumeration exists, without changing `input_device` persistence.
- Fix key capture's cancel/state synchronization and accessibility. Escape must reliably restore the displayed binding instead of leaving “Press a key…” highlighted; the field must expose a useful accessibility role, label, value, and action; keyboard activation must work; and the reset-to-Caps-Lock affordance must be named as reset rather than visually implying generic clear.
- Give Settings-local secondary and icon actions a coherent Workspace-derived hover/focus/disabled vocabulary: permission recovery, setup walkthrough, folder browse, skill install/reinstall, stale-banner dismissal, and voice preview should no longer mix unrelated native/default/borderless treatments. Keep native pickers, toggles, sliders, text fields, alerts, and destructive roles familiar.
- Add non-color accessibility feedback for voice preview progress/error and Relay Skills install success/failure. Failures must not remain silent; transient success must have readable/announced text or an equivalent accessible status.
- Label slider values programmatically and disable Particle Field intensity while Particle field is off so the dependency is honest. Icon-only actions need explicit labels and help.
- Make the clean footer quiet and neutral, dirty state purple and actionable, and provide a visible Revert path for discarding the current draft. Preserve default Save keyboard behavior and external-config refresh behavior; do not redesign persistence outside Settings in this ticket.

## Acceptance criteria

- [ ] The Settings sidebar extends through the full Settings height; header, scrollable content, and footer form the detail plane, and footer controls align with the readable detail grid at both Workspace and standalone widths.
- [ ] Embedded Settings has exactly one Workspace-style outer hairline boundary and 16-point panel radius, with no nested outer card or large shadow; standalone Settings retains suitable window chrome.
- [ ] Only detail content scrolls, overflow remains discoverable in the Workspace vocabulary, and changing categories starts the new category at a sensible top position.
- [ ] Status lists Microphone, Accessibility, Input Monitoring, and Screen Recording with existing semantic state text and recovery actions; tests cover the complete ordered list and Screen Recording detail/action intent.
- [ ] Speech-to-Text no longer presents a one-option device picker as an editable choice, retains the current configured device information, keeps conditional key rows, and does not reintroduce the deliberately removed input-mode picker.
- [ ] Key capture reliably exits on Escape/reset/capture, never remains visually stuck, supports mouse and keyboard activation, and exposes accurate accessibility label/value/action metadata plus an explicitly named reset affordance.
- [ ] Permission, setup, browse, install/reinstall, dismiss, preview, footer Save, and Revert actions share consistent Settings-local Workspace-derived chrome and deterministic disabled/hover/focus precedence without altering native destructive alert roles.
- [ ] Voice preview and Relay Skills expose accessible loading/success/failure feedback; failure is visible and not merely logged or silent; feedback does not cause disruptive layout jumps.
- [ ] Speech speed and particle intensity expose accessibility labels and values; particle intensity is visibly and semantically disabled while Particle field is off.
- [ ] The clean footer is neutral and quiet; dirty state is explicit and purple; Revert restores the current persisted config; Save remains disabled when clean and retains the default keyboard shortcut.
- [ ] Sidebar items expose selected semantics without verbose “not selected” labels and support predictable keyboard category navigation with visible, restrained focus.
- [ ] Every change remains confined to Settings source/tests plus this ticket; configuration schema/defaults, services, Workspace behavior, provider behavior, and top-level navigation are unchanged.
- [ ] Focused tests cover pure presentation/state decisions and key regression paths; `swift test --filter SettingsWindowTests`, relevant Status/Settings tests, full `swift test`, and `git diff --check` pass.
