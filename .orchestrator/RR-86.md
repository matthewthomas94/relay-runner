## Description

During the recorded phase, long voice messages sometimes stop recording after a period of time or do not send the entire message. Recording should continue until the user explicitly sends or cancels the message.

Investigate the STT/recording pipeline, including audio buffering, live transcription throttling, Caps Lock/send gesture handling, and any max-duration or buffer-trimming behavior. The final sent command must include the full user utterance, not just the newest buffered segment or live partial. If audio memory needs bounds, implement chunking or transcript accumulation rather than silently truncating the message.

## Acceptance criteria

- [ ] Recording does not stop because of a time limit, silence window, partial-transcription timeout, or buffer rollover while the user is still in the recording phase.
- [ ] The sent voice command includes the full message from recording start through explicit send.
- [ ] Cancel still cancels the active recording without sending a partial message.
- [ ] Live transcription can update during long recordings without replacing the final accumulated transcript with only the latest segment.
- [ ] Add focused tests for long recording/transcript accumulation behavior, using unit-testable components where direct microphone capture cannot be automated.
- [ ] Include a manual verification note for a long dictated command if needed.
- [ ] Verify with `swift test --skip-update` and any relevant Python voice-bridge tests.
