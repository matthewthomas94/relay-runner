## Description

The live activity chip on in-progress ticket cards currently exposes raw execution detail for Codex workers, for example `Running: /bin/zsh -lc ...`. That is technically useful, but it is not a good board-facing status for a person trying to understand what an agent is doing.

Refine the activity summarization layer introduced in RR-12 so shell/tool activity becomes short semantic language like `Reading source files`, `Inspecting TTS replay state`, `Running Swift build`, `Updating ticket run log`, or `Committing changes`. Keep raw command details available in the run log, but make the board chip read like a human progress preview.

## Acceptance criteria

- Codex worker activity chips no longer show raw `/bin/zsh -lc ...` or long command strings as the primary board text.
- Shell commands are classified into short semantic summaries, covering at least file reads/searches, test/build runs, git operations, code edits, and generic investigation commands.
- Summaries stay concise enough for the existing chip UI and continue to truncate cleanly if needed.
- The raw command remains available in logs or diagnostics so debugging detail is not lost.
- Existing Claude activity summaries from RR-12 do not regress.
- Manual verification: dispatch or observe a worker doing several common operations and confirm the chip reads as human-facing progress rather than raw shell syntax.
