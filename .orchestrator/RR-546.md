## Description

RR-532 to RR-545 build the final Relay Remote iPhone design (`docs/design/relay-remote-ios/README.md`) in parallel pieces. This ticket walks the finished app end to end against the design, fixes the seams between the pieces, removes what is no longer used, and brings the documents up to date.

**Do**

1. **Walk the whole flow** on a fresh simulator install, against a Relay Runner built from this branch on this Mac where possible (pairing by pasted code) and against the scripted transport otherwise: splash → permissions → pairing → tutorial → Agents (ready, talking, playing, agent not running, Mac unreachable) → Workspace → Settings → background notification. Screenshot every one of the 28 screens and compare each with its reference image.
2. **Fix inconsistencies between tickets:** spacing, type, icon weight, button heights and positions (primary buttons 52 pt tall with 40 pt below them; hero text at the same y on every onboarding screen; Skip always top right; banners overlaying everything below the status bar; only one primary button per screen; no coloured status pills; brief copy). Fix what is small; list what is not.
3. **Check the wire end to end** with the real Mac side: an utterance addressed to each agent, tagged replies filed under the right chat, per-agent glyph states, start by message, the workspace list, settings get and set, and the temporary "unsupported" handling removed or unreachable now that RR-534, RR-535 and RR-536 have landed.
4. **Remove dead code:** `DebugView.swift` (or keep it behind a debug-only launch argument if it is still useful for development, and say which), the standalone `PairingView.swift` if nothing uses it, the hands-free leftovers, unused preferences and placeholder views.
5. **Documents:** `ios/README.md` (structure, how to add files, how to reach each screen for a screenshot, background behaviour), `docs/specs/relay-remote.md` (make sure it matches what shipped), and `docs/design/relay-remote-ios/README.md` (correct anything the build proved wrong, with a note of what changed and why).
6. **Report** for the user: what matches the design, what differs and why, and a short checklist of what only a physical iPhone can confirm (real microphone and speech, camera scanning, local-network prompt, lock-screen notifications, background survival, playback through Bluetooth headphones).

## Acceptance criteria

- [ ] All 28 screens have a simulator screenshot compared with its reference image, and the summary lists every remaining difference.
- [ ] A fresh install can go from first launch to a spoken or typed exchange with an agent without touching a debug screen.
- [ ] Against the real Mac side: addressed messages, tagged replies, per-agent states, start by message, workspace list and settings changes all work, or each failure is listed with its cause.
- [ ] No hands-free mode, no project picker, no page titles on Workspace or Settings, no "Pair a ring" row.
- [ ] Dead code named above is removed or deliberately kept, and the summary says which.
- [ ] `ios/README.md` and `docs/specs/relay-remote.md` match the shipped behaviour.
- [ ] `swift build`, `swift test`, `cargo test` (in `rust/relay-rs`), `cd ios/RelayRemoteKit && swift test` and the `xcodebuild test` run for the app all pass.
- [ ] The physical-device checklist is in the summary.
