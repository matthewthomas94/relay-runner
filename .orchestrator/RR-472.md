## Description

RR-469 adds multiple PM tabs to the Workspace terminal: a "+" control that opens a new PM tab, closing tabs (closing the last one ends the session, as End does), and an overall limit of 9 tabs. This ticket adds the standard macOS keyboard shortcuts for those actions while the user is on the Terminal tab.

Build on the open-tab and close-tab code paths RR-469 introduces. Do not add a second way of opening or closing tabs.

Scope:
- **Command-T** opens a new PM tab, exactly as the "+" control does. At the 9-tab limit it shows the same limit message as "+" and changes nothing.
- **Command-W** closes the focused terminal tab, exactly as that tab's close control does.
- **Command-W on the last tab asks for confirmation first**, because closing it ends the session. Use a standard confirmation alert (for example "End the session?" with End Session / Cancel; Return or the default button confirms, Escape cancels). Cancel leaves the tab and session untouched. Closing a tab that is not the last one does not ask.
- The shortcuts work only while the Workspace's Terminal tab is showing and a session is running. Anywhere else, and when no session is running, Command-T and Command-W behave as they do today (for example Command-W still closes a window where it does today).
- The shortcuts must work while keyboard focus is inside the terminal view. SwiftTerm must not swallow them or send them to the PTY as input.
- If the shortcuts appear in a menu, the menu items are disabled when they do not apply.

## Acceptance criteria

- [ ] On the Terminal tab with a running session, Command-T opens a new PM tab with the same behaviour as the "+" control, including when the terminal view has focus.
- [ ] At 9 tabs, Command-T shows the limit message and creates no tab and no session.
- [ ] With 2 or more tabs, Command-W closes the focused tab with no confirmation, and the active-tab handover follows RR-469's rules.
- [ ] With 1 tab, Command-W shows a confirmation. Cancel (including Escape) leaves the session running. Confirm ends the session exactly as End does.
- [ ] Outside the Terminal tab, or with no session running, Command-T and Command-W keep their current behaviour.
- [ ] Neither shortcut writes characters or control bytes into the PTY.
- [ ] Tests cover the routing rules (Terminal tab vs. elsewhere, session vs. none, last tab vs. not, limit reached), and the existing test suite passes.
- [ ] Any user-facing docs that list Terminal or tab controls mention the shortcuts.
