## Description

Relay Runner currently lets users choose the agent provider and model, but it does not expose Codex reasoning effort. GPT-5.6 preview introduces a new `max` reasoning level, and existing Codex docs already expose `model_reasoning_effort` for supported models.

Add a Codex-scoped reasoning effort setting once RR-99 confirms the current CLI/app contract. Keep the implementation narrow: this should configure Codex launch behavior and app persistence only, not redesign provider selection.

If `max` is not accepted by the installed/current Codex surface yet, support the documented stable effort set and leave `max` hidden or disabled with a clear preview note in the verification/run log.

Likely touch points:

- `Sources/relay-runner/Config/Config.swift`
- `Sources/relay-runner/Config/ConfigManager.swift`
- `Sources/relay-runner/Settings/GeneralSettingsTab.swift`
- `Sources/relay-runner/Onboarding/OnboardingView.swift`
- `Sources/relay-runner/Process/ProcessManager.swift`
- `services/config.py`
- `tests/RelayRunnerTests/GeneralConfigTests.swift`
- `tests/RelayRunnerTests/ProcessManagerLaunchTests.swift`

## Acceptance criteria

- [ ] App config persists a Codex reasoning effort value with a default/inherit option and normalizes absent or invalid values safely.
- [ ] Settings and onboarding expose reasoning effort only when Codex is selected.
- [ ] Claude launch behavior is unchanged and never receives Codex reasoning-effort flags or config.
- [ ] Start Session applies the selected Codex effort through the confirmed Codex mechanism from RR-99, with shell-safe quoting.
- [ ] Tests cover config load/save, normalization, provider switching, Codex launch output, and Claude launch omission.
- [ ] Provider parity is explicit: this is intentionally Codex-scoped because Claude uses a different model-control surface, and no shared provider behavior regresses.
