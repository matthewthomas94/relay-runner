## Description

Fix the mounted Workspace board regression where pointer state is laggy or
missing and dragging one ticket can move a different ticket from farther down
the column.

The reported reproduction starts with RR-176 at the top of Backlog. The pointer
is placed over RR-176, but dragging it toward Queued can instead capture and
move VQ-1 from much farther down the list. Hover highlighting and cursor changes
are also absent, intermittent, or substantially delayed.

RR-254 and RR-259 added identity-specific routing and mounted-panel coverage for
the first card, but the installed behavior shows that the real pointer-to-card
identity is still incorrect under the complete Workspace hierarchy. Investigate
the event stream end to end, including window and panel routing, scroll-document
coordinates, SwiftUI/AppKit view reuse, card reordering, hover ownership, drag
capture, and drop destination state. Correct the underlying identity/lifecycle
boundary rather than adding another position-specific special case.

The Workspace interaction path is shared by Codex and Claude sessions and must
behave identically for both providers.

## Acceptance criteria

- [ ] A deterministic regression test fails on current `main` by reproducing a pointer-down/drag on the first visible Backlog ticket that captures a different offscreen or later ticket.
- [ ] Hovering any visible card immediately applies hover styling and the correct cursor to that exact card without a click, scroll, tab switch, or window refocus.
- [ ] Pointer-down and drag preserve the selected ticket identity from gesture start through column drop; dragging RR-176 cannot move VQ-1 or any other card.
- [ ] The exact target remains correct for the first, middle, and last visible cards before and after scrolling, snapshot refresh, prepend, reorder, height change, and scope or tab transition.
- [ ] Dragging between Backlog and Queued updates only the intended ticket and does not leave stale hover, cursor, selection, drag, or drop-strip ownership behind.
- [ ] Click, scroll, non-draggable cards, column controls, and drop strips retain their existing behavior while card routing is corrected.
- [ ] Tests exercise the mounted `NSApplication` to panel to scroll-document event path with realistic mouse-move, down, drag, and up events; direct helper or isolated `hitTest` calls alone are insufficient.
- [ ] Focused board tests, the RR-237 board benchmark, and relevant Swift package tests pass without removing RR-254 or RR-259 identity and lifecycle coverage.
- [ ] A packaged-app smoke check verifies immediate hover/cursor response and exact-card drag identity on a populated board, or records the precise macOS permission blocker as an explicit post-merge human check.
