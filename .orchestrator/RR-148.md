## Description

Now that the notch shows the current technical voice state, simplify the app's pill/capsule copy so those pills do not repeat the same state label plus a separator.

For example, when the notch already says the session is listening, a pill should show the actionable instruction, such as `Press Caps Lock to stop and send`, instead of duplicating the technical state first. Apply the same rule to the other voice/status pills in the app: keep useful action or outcome text, but remove redundant leading status labels and their separator when the notch already owns that state.

Do not remove the notch status labels themselves, and do not remove pill text that communicates a distinct action, warning, failure, or result the user still needs to see.

## Acceptance criteria

- [ ] Voice/status pills no longer duplicate notch-owned state labels such as listening before the actionable copy.
- [ ] Separator copy associated with removed status prefixes is also removed, so the remaining pill text reads naturally.
- [ ] The listening pill keeps the actionable instruction `Press Caps Lock to stop and send` without a redundant leading listening label.
- [ ] Other app pills are audited for the same duplicated status-prefix pattern and simplified when the notch already provides that state.
- [ ] Notch activity/status copy remains intact.
- [ ] Non-duplicative pill content, including errors, warnings, confirmations, and user-action prompts, remains visible.
- [ ] Codex and Claude Relay sessions show equivalent simplified pill copy.
- [ ] Tests or documented manual verification cover listening, sending/thinking/response-ready style states, and at least one non-duplicative pill that should remain unchanged.
