## Description

Bring the Notes chat (RR-549) to Workspace History. The chat works on the repository that is selected in the Workspace.

**Today:** `WorkspaceHistoryView` (`Sources/relay-runner/Board/WorkspaceHistoryView.swift`) searches archived tickets with `GET /v1/artifacts/history/search` and shows a selected ticket's detail via `GET /v1/artifacts/history/{artifact_id}`. With nothing selected it shows "Select a historical ticket".

Scope:
- **Daemon:** `POST /v1/artifacts/history/chat` with `repo_path`, `project_scope_token`, `request_id`, optional `artifact_id` and `messages`, answering `{"reply", "artifact_ids"}`. Reuse the notes chat call from RR-548 with a ticket-history system prompt. With `artifact_id`, the context is that ticket's Markdown. Without it, the context is every ticket's id, title, status and date for the repository, plus the full Markdown of the best-matching tickets within the budget, local tickets first.
- Only use ticket text the history detail route can already return without a GitHub fetch. Do not trigger an online fetch or any `confirm_github_exposure` path from chat; if a matching ticket's body is only available online, list it by title and say so.
- **UI:** the same layout as the Notes chat: ticket detail (or the empty-state hint) at the top, scrollable thread, text field at the bottom. Conversations are kept per repository and per ticket, in memory only. Changing the selected repository switches to that repository's conversation.
- Document the route in `docs/specs/orchestrator-http-api.md`.

## Acceptance criteria

- [ ] Questions with no ticket selected are answered from the selected repository's history; with a ticket selected, from that ticket. Both tested with a fake provider.
- [ ] The chat never starts an online archive fetch or a GitHub exposure confirmation, covered by a test.
- [ ] Conversations are separate per repository and per ticket and switch with the selected repository, covered by a unit test on the chat model.
- [ ] The route is documented; `cargo fmt --check`, clippy with `-D warnings`, `cargo test`, `swift build` and the board tests pass (the pre-existing cross-process lock test failure excepted).
