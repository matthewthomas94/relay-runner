## Description

Implement RR-273 delivery phase 8 from RR-270's `Migration and rollback` procedure. Add a previewable per-project migration with preflight manifest, writer freeze, immutable identity adoption, exact artifact-ref bootstrap, optional explicitly confirmed first remote push, reviewed source cleanup, local exclude and rematerialization cutover, run/capture mapping, first retention preview, journaled resume, and verified rollback.

The migration must abort on malformed tickets, missing referenced attachments, active workers, unsupported symlink/submodule inputs, unexpected/foreign artifact refs, project identity mismatch, or unreviewed source changes. It must not combine cleanup with unrelated source work or delete/rewrite registered repositories, artifact history, remotes, or remote branches. Update the supported fresh-install/reset workflow to preserve normal application support, move deliberate reset state recoverably to Trash, and reconstruct projects from their local/configured artifact refs.

## Acceptance criteria

- [x] Preflight freezes artifact mutations and records project/common-dir/default-branch identity, Git status/remotes/refs, active runs, every legacy `.orchestrator` path/blob/attachment hash, registry record, and run/Program references before any cutover write.
- [x] Migration aborts without mutation for malformed/missing/active/unsupported/foreign/ambiguous conditions and presents the exact blocker and recovery action.
- [x] Bootstrap creates an exact orphan artifact snapshot with schema/activity/catalog identity, round-trips every manifest entry, and remains `local_only` unless the user explicitly confirms a verified first normal push.
- [x] Source cleanup is an isolated reviewed commit after bootstrap verification; cutover installs local exclude and rematerializes from the artifact ref without touching unrelated source changes, index state, refs, remotes, or ordinary commits.
- [x] Existing run logs, bounded run summaries, project-scoped captures, dependency identities, and ticket attachments survive mapping; no durable claim is synthesized from missing evidence.
- [x] Migration journal resumes idempotently after interruption and records verified artifact/source commit IDs, manifest digest, registry backup, remote result, retention preview, and exact rollback instructions.
- [x] Rollback before and after source cutover follows RR-270, stops writers first, never auto-deletes artifact refs/remotes, and requires event-ID reconciliation if both storage models received writes.
- [x] Supported normal reinstall preserves app support; deliberate reset moves only Relay-owned app state recoverably to Trash and never edits or deletes registered repositories.
- [x] Disposable legacy/no-remote/valid-remote/foreign-ref/interrupted/rollback/fresh-install fixtures pass for both Codex and Claude session recovery, and documentation links to RR-270 phase 8.

## Rollback boundary

The journal and preflight manifest are the rollback authority. Before cutover, restore the registry backup and stop using the unpushed bootstrap ref; after cutover, restore the exact recorded legacy tree in a reviewed source commit and revert the writer gate. Artifact refs and remote branches are retained unless a separate explicit reviewed cleanup is authorized.

## Verification plan

Use disposable repositories for every migration branch, including dirty/staged source state, active-run refusal, malformed inputs, no remote, existing valid/foreign refs, interruption at each journal step, rollback before/after cutover, reinstall, and destructive-reset recovery. Compare byte-level manifests and Git refs throughout.
