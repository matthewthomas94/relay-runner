## Description

Complete the user-facing Workspace and documentation for the accepted terminal retention policy. The board must show every unfinished ticket and the newest 25 combined Done-or-Canceled tickets locally, while older terminal records remain available through History after verified publication. Provide understandable migration preview, confirmation, blocked-state recovery, storage wording, and installed-app validation without implying that local Git objects were purged.

## Acceptance criteria

- [ ] Workspace copy states the policy accurately: all unfinished tickets are kept locally without a cap, while one combined pool of the 25 most recent Done or Canceled tickets remains materialized.
- [ ] The board renders every nonterminal ticket and the retained terminal 25; older terminal records are discoverable through a distinct History surface with search, detail, dependency summaries, and attachment availability.
- [ ] Badges and status copy distinguish Materialized, temporary safety overage, GitHub-backed but locally reachable through Git, Needs Network, Local Archive Only, missing, and tampered states without using misleading remote-only wording.
- [ ] Users can explicitly restore historical detail or reopen a terminal ticket. Reopen moves it into the uncapped nonterminal working set; viewing history does not silently restore files.
- [ ] Migration presents the exact retained terminal set, deletion candidates, all uncapped nonterminal tickets, estimated materialized-file reduction, selected remote, privacy exposure confirmation, and rollback or retry behavior before apply.
- [ ] Offline, authentication, divergence, interrupted migration, and integrity failures surface actionable blocked states and keep affected ticket files locally until verification succeeds.
- [ ] Documentation removes the 30-day rule everywhere and consistently distinguishes materialized Markdown and attachments from archive catalog metadata, local Git objects, indexes, caches, databases, and run logs.
- [ ] Swift tests cover mixed Done and Canceled ordering, more than 25 terminal cards, unlimited nonterminal lanes, history search and detail, restore and reopen, temporary overage, migration preview, and accessibility and unavailable states.
- [ ] Mounted fresh-install, second-device, offline, failure-recovery, and a 300-plus-terminal-ticket migration UAT are recorded without treating source tests as physical installed-app proof.
- [ ] Codex and Claude receive equivalent Workspace behavior, lifecycle messages, recovery guidance, and verification coverage; intentional authentication differences are documented.
