## Description

Implement RR-273 delivery phase 5 from RR-270's `Retention and materialization policy`, storage accounting, and privacy classification. Retain tickets with qualifying activity in the last exact 30 UTC days plus all active, dependency-relevant, unsynced, conflict, verification-blocked, and worker snapshot-lease exemptions. Archive by one ordinary artifact commit that updates a deterministic catalog and removes eligible head paths only after all referenced blobs remain reachable.

Provide read-only historical search/detail from Git objects, explicit restore through a new ordinary commit, shallow-history deepen behavior, offline availability states, recoverable deletion semantics, and separate working-tree/Git/database/index/cache byte metrics. Archival reduces the materialized working set; it is not privacy erasure or immediate Git-object reclamation.

RR-286 may proceed in parallel and will publish worker snapshot leases. Define a stable lease/exemption contract that either implementation order can consume without weakening retention safety.

## Acceptance criteria

- [ ] `activity_at` uses the max of the RR-270 durable activity sources; exactly 30 days is retained, one microsecond older is eligible, and UTC duration is unaffected by DST or local time-zone changes.
- [ ] Ready, in-progress, verification-blocked, awaiting-review, merge-conflict, unresolved-dependency, pending-sync, unpublished-conflict, pinned, and active snapshot-lease tickets are exempt from archival.
- [ ] Archive planning is deterministic and previewable; one atomic artifact commit updates the catalog and removes only verified eligible head paths after reachability and attachment checks succeed.
- [ ] Injected failure before commit leaves materialization intact, failure after ref update rematerializes from the ref, and missing/unreachable/tampered blobs fail closed without deleting the active copy.
- [ ] Historical search/detail reads archived tickets and attachment metadata without automatically rematerializing them; shallow history deepens explicitly when online and reports unavailable objects honestly when offline.
- [ ] Restore creates a normal idempotent artifact commit, preserves immutable graph identity and attachments, and correctly resolves active dependencies on archived-done versus archived-nondone tickets.
- [ ] Routine Delete is recoverable and warns that Git history remains; exceptional privacy purge remains a separately reviewed, coordinated process with secret rotation guidance.
- [ ] UI/API metrics separately report materialized working-tree bytes, reachable Git-object bytes, run DB/log bytes, derived index/cache bytes, and reclaimable estimates.
- [ ] Automated age, exemption, archive, restore, dependency, offline, shallow-history, privacy, and lease fixtures pass and documentation links to RR-270 phase 5.

## Rollback boundary

Retention starts in preview-only mode. Disabling it stops new archives and restores active materialization from the canonical artifact ref/catalog; rollback never rewrites artifact history or claims that archived data was erased.

## Verification plan

Use a clock-controlled disposable repository with exact boundary timestamps, shallow clones, missing-object injection, active leases, archived dependency graphs, and attachment fixtures. Compare catalog entries, tree/blob reachability, materialized paths, and reported storage layers after every transition.
