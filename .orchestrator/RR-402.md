## Description

`services/messenger.py` `MessengerRuntime` holds one context deque, one current command and one generation counter; the Claude messenger keeps a single `_session_id` passed as `--resume` (~843-863). After focus routing, the messenger would mix context from several projects.

Implement RR-393 slice G: keep one shared messenger runtime with per-session partitions (context deque, current command, generation) and switch partitions on `__FOCUS__`. Codex: start a new ephemeral thread on switch. Claude: keep a per-partition messenger session id (or prefix context into the next ask if a respawn is too slow; measure and choose). Record measured re-bind latency for both providers in the run log.

## Acceptance criteria

- [ ] Context from session A never appears in the messenger prompt while B is focused (unit test).
- [ ] Refocusing A restores A's partition context.
- [ ] Codex and Claude both re-bind on focus; measured re-bind latency for each is recorded in the run log.
- [ ] Only one messenger process runs regardless of session count.
- [ ] Messenger tests pass.
