## Description

Make the Terminal and Settings tabs use the available Workspace width responsively, matching the Work tab's layout behavior. The project and program Workspace shells already provide the shared horizontal gutters, but `EmbeddedTerminalTab` is capped at 1100 points and `WorkspaceSettingsPanel` is capped at 940 points, leaving conspicuous unused space on wider displays.

Remove the workspace-only horizontal caps so each surface expands to the width offered by its parent while preserving the shared `BoardSurfaceLayout.horizontalPadding` gutters, current fixed vertical geometry, dark surface styling, and interaction behavior. Keep the standalone Settings window at its intentional fixed size. Do not add new breakpoints, visual decoration, or unrelated settings/terminal refactors.

## Acceptance criteria

- [ ] Terminal expands to the full width offered by both the project Workspace and Program Workspace shells, inside the same horizontal gutters as Work.
- [ ] Workspace Settings expands to the full width offered by both shells, inside the same horizontal gutters as Work.
- [ ] Neither workspace surface retains an arbitrary finite maximum-width cap that creates unused side space on wide displays.
- [ ] Both surfaces remain usable on narrower supported displays and preserve their existing height, scrolling, toolbar/sidebar, focus, and session/settings behavior.
- [ ] The standalone Settings window remains 720 by 560 points and is not made full-screen or fluid.
- [ ] Provider behavior remains identical for Codex and Claude sessions.
- [ ] Targeted regression tests cover the responsive sizing contract, and the relevant Swift test suite passes.
